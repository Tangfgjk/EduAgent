# G08 离线 Skill 候选与机制评测

日期：2026-10-18。API0.18.0，数据库g08_001；主服务4003。沿用已确认的G07四类受限参数，新增离线开发流程，没有新增外部服务调用。

## 1. 本轮完成的闭环

项目结构化失败/纠正/求助 → 冻结数据与生效策略基线 → SkillEvolutionGraph提出一个参数假设 → 编译Skill diff → 冻结工程样本比较新旧行为 → 管理员开发复核或拒绝 → 学生选择创建普通策略提案 → 原管理员审核/学生确认 → 新任务生效，可撤回/回滚。

本轮的“自动提出”是本机确定性假设生成器，不是接入大模型的语义改进Agent，也不是模型训练。它不自动理解学生讲解，不声称发现学习困难的原因，不修改应用代码/评测参考/系统规则。自动真实发布始终关闭。

## 2. 数据与状态

复用AgentRun和Outbox短事务任务，新增kind=skill_evolution，由现有teaching worker执行；不占模型额度、不创建ModelOperation。图分infer/evaluate两节点，有界执行，无外部网络。失败或取消保留原始输入，不把排队当完成。

迁移g08_001新增三张表：

- evolution_datasets：本项目冻结结构化来源、基线、指纹和运行器签名。
- evolution_candidates：父StrategyVersion、一个受限参数变化、开发假设/来源ID、diff、编译产物。
- evolution_evaluations：冻结语料/消费者签名、新旧实际行为、红队门禁与限制。

三表在SQLite/PostgreSQL均禁止UPDATE/DELETE。复核使用现有追加式ProductionReview(target_kind=skill_candidate)，action区分approve/reject/withdraw/propose；操作LearningInput保留请求指纹与幂等标识。运行视图可以变化，数据、候选和评测不可改写。备份/恢复包含三张表。

阶段：queued → awaiting_review / blocked / no_candidate / failed → approved_for_proposal / rejected → strategy_proposed。可取消未完成任务；已复核候选可撤回，包含已创建提案或激活后的情况。

## 3. 来源与假设生成规则

仅本人正式项目、模拟/成人开发账号，必须已有可生效的四参数策略和明确课程。新来源限当前单元内容版本、同账号来源；不加入临时会话、其他项目原文或外部资料。

指纹覆盖该范围全量事实/自述/人工复核ID、课程版本/修订、父策略hash和指针修订。实际推导读取最多60条近期结构化事实、3条人工数值复核；自述只保留最多3个索引，不做文本理解。同秒按记录ID稳定排序，不凭数组位置判断学习先后。G06的素养材料数量不会当能力分或优化目标。

| 结构化开发信号 | 可提假设 | 限制 |
|---|---|---|
| 数值failed | practice_order=errors_first；已采用时可考虑review_order=due_errors_first | 不说明错误原因，也不等于当前仍不会 |
| 人工数值复核incorrect | question_focus=verification | 人工数值意见不是解释质量或素养评定 |
| 单条实际记录hints_used>=2 | support_mode=step_first | 求助不代表能力低，先尝试提供具体支持 |

每轮只选择一个尚未采用的允许值，不改时长/其他参数凑版本。没有信号或参数已经采用时返回no_candidate；不生成虚构收益、错误率下降或学习评分。

## 4. 冻结评测究竟证明什么

语料放在模块corpus.json，当前4个开发者自编机制样本：开发集有理数/方程，隔离保留集一次函数/勾股数值。候选生成只读数据集，不读取这些样本；评测阶段才加载。heldout只指这套离线过程中的输入隔离，不证明学生从未见过或跨真实学生泛化。

参考值由独立有理数/方程/函数/勾股算术计算核对；脚本按固定参考作答，是工程执行器，不是模拟真实学习能力。新旧策略均实际调用TutorGraph、共用练习/复习排序函数、通用追问安全渲染器和数值验证器，记录：

- 练习集合/顺序是否符合策略，诊断和检测是否保持位置。
- 渐撤或逐级支持的实际首个帮助，以及能否恢复具体帮助。
- 检测阶段帮助是否被拒绝，数值结果是否独立核验。
- 到期复习排序是否生效，通用追问是否采用合法方向。
- 未知预算/关闭验证/Markdown指令等越权候选是否被拒绝。

门禁要求：参考检查和两侧工程执行均通过、红队无失败，并观察到至少一项消费者行为变化。报告learning_gain=null、automatic_publish=false。通过表示“参数改变了规定的行为且工程约束检查通过”，不证明方向正确、教学有效或真实学习增益。

签名包含语料hash、编译器、硬规则、图及相关消费者/验证代码hash。代码或语料变化后旧报告不能继续送审；曾依赖此报告的策略会显示不可用并对后续任务回到默认，需要重新验证。UI变化不改评测真值。

## 5. 审核、采纳和撤回

管理员只能做开发评测复核，不自动获得专业教师资格。复核有revision、报告hash、至少10字依据和幂等保护；不通过报告不能批准。学生不能调用管理员端点。双方可钻取被冻结数据引用的原事实；管理员来源读取只允许该数据集成员，并追加evolution.source_read审计。

复核通过后，学生明确选择“采纳为待审策略”。服务通过可信Adapter把candidate/report/review引用绑定到Planning.start，在不可变输入第一次插入前完成；外部StartStrategy不能注入此内部引用。生成的普通提案仍需原有管理员审核和学生确认，不直接激活。

每次评测复核/采纳/策略确认都会检查来源、课程、基线和签名。资料/账号/来源门禁继续生效。复核撤回后，相关待审版本不能批准；已经激活的历史指针保留，后续新任务使用默认。已开始的任务仍保留G07冻结配置，课程本身的安全撤回仍独立检查。

跨端操作需核对最新修订；过期操作返回冲突，不自动重放为新的批准/撤回。页面提供“刷新改进状态”。

## 6. 仍待后续完善

当前是G08首轮离线、单参数、受控闭环。未实现真实模型语义提案、更广课程结构编辑、真实学生影子/灰度/自动晋升，以及专业量规和真实教学效果验证。语料规模很小，后续需增加冻结题族与独立评阅，不能用这4个工程样本宣布RSI成功。

G09需先明确专业审核责任、真实学生数据授权/保留/撤回/删除、试点范围与效果基线、并发与部署演练。真实模型提案如需新增数据/费用，须另确认范围；现有模型授权不自动扩展。
