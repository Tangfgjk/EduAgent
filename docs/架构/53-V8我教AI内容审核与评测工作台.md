# V8 我教 AI、内容审核与评测工作台

版本 0.12.0，数据库 `v8_001`，目标分支 `V8-20261017`。本文件是既有方向和 50/51 号交付后的增量，旧文档保留。

## 一、我教 AI 开发流程

新增互动包 `math.g9.probability.teach.dev2`，基础题库仍绑定原概率包，旧方程/概率互动版本与两阶段流程保留。

| 阶段 | 学生动作 | 系统行为 |
| --- | --- | --- |
| opening | contribute：提交讲解及候选数值 | 保存原始贡献后展示预设学伴疑问 |
| challenge | conclude：回应疑问并修正 | 保存第二次贡献，核验原题数值；进入另一题验证 |
| verification | verify：独立提交一次数值和依据 | 使用另一道已版本化题目，不提供提示；保存独立数值核验 |
| summary | 查看 TeachReport | 区分原题辅助核验、另一题核验及三次学生贡献 |

本阶段角色仍为固定模板，没有根据学生文字生成真实模型回复。基础题为 `P-PRB-02`，另一题为同包 `C-PRB-02`；后者只在 verification 时公开题面。独立是指本题未提供辅助，不保证学生此前从未见过该题，不据此自动评定迁移、讲解质量、素养或教学效果。

流程复用 LangGraph、幂等输入、gate/revision 检查、内容授权及现有工作队列。新包仅允许 teach 路线；verification 不能再 contribute/conclude，提交后不能覆盖。当前空间的陪学、圆桌与互动仍互斥，其他项目不共享过程。

`ActivityView` 新增 flow、verification_task、verification_check；原 check 保持 `independent=false`，新题检查单列 `independent=true`。事实只记录三次学生表达，模板不进入学生证据；新题不可验证可进入人工数值复核，再通过正确内容来源形成复习记录。新题结果不自动并入主陪学独立检测正确率。

## 二、内容扩充与开发核对

| 新内容包 | 内容 | 数量 |
| --- | --- | --- |
| math.g9.probability.counting.dev1 | 列举基本结果、事件计数、补事件 | 5 题 |
| math.g7.statistics.frequency.dev1 | 平均数、中位数、实验频率与理论概率的区别 | 5 题 |

当前合计 7 个代表性开发单元、35 题；每包仍是 1 诊断、2 练习、2 无辅助检测。年级是编排建议，不是教材专业映射，也不意味着已覆盖七至九年级完整课程。新增题均为自编、未经教师专业审核。只向 synthetic/adult_test 开放，real_student 仍被服务端拒绝。

两个新基础包和新 teach 包必须先保存同版本的“开发核对通过”及至少五字依据，再显式启用。已有旧版本的启用流程继续兼容，但一旦管理员记录“需要修改”，同版本的开放会被撤回。开发核对通过不会自动启用，也没有变成教师审核通过的入口。

## 三、持久化审核模型

迁移 `p0_001 → v8_001` 新增：

- `development_review_scopes`：按 kind、target、version 计算 SHA-256 主键，保存当前 revision。
- `development_reviews`：每次复核追加一条，包含来源类别、目标、版本/报告哈希、结论、依据、审核管理员和时间。唯一键 scope_id/revision；数据库触发器禁止 UPDATE/DELETE。

保存先核对当前来源版本，再用 revision 条件更新实现并发控制。同 revision 的并发提交至多一个成功，其余返回 409。内容启停与内容审核使用相同 ContentApproval 锁，避免撤回和开放互相覆盖。审核会写审计事件，不改写旧意见。

结论分两类：内容为 development_ready / needs_revision；评测为 acceptable / model_issue / reference_ambiguous / runtime_issue。所有记录固定为 development_only，不作为专业教师资质证明。

## 四、评测工作台

管理端 `/admin/evaluations` 展示三个冻结的自编开发报告：单轮真实 DeepSeek 基线、多轮 Fake 工程流程、独立集 Fake 工程流程。数据为历史报告的逐字节副本，随包位于 `seeds/evaluation/reports`，只通过固定注册表读取，不接收客户端文件路径。

工作台展示运行模式、提示版本、报告哈希、逐条输入、开发参考、返回方向/引用/追问、结构/引用/权限检查、耗时及复核历史。可以筛选不符合开发参考的条目，再保存分类和依据。参考不匹配不自动等于模型教学错误；Fake 的固定输出不作为真实模型表现。

复核绑定“报告键 + 执行条目 ID + 报告 SHA-256”。旧报告不覆盖，不把不同语料或重复运行的条目混成一条；来源哈希改变后必须重新复核。接口只允许管理员使用，学生无法读取报告或提交审核。

当前工作台不发起付费调用、不自动修改 Skill.md/harness、不发布提示或模型配置。新增真实运行仍通过既有评测 CLI 执行，审查和冻结后再注册新报告。批量导入、页面运行器和教师专业量规是后续扩展，不在此版伪造完成。

## 五、模块边界与后续扩展

- `activity_catalog / activity_graph / activity_facts`：教学阶段、版本和证据；新流程独立注册，旧包哈希不变。
- `governance/reviews.py`：版本核对、内容锁、复核并发、追加记录和撤回。
- `governance/workbench.py`：冻结报告注册与只读映射，隔离报告文件细节。
- `gateway/development.py`：管理员权限及 OpenAPI 输入/响应契约；前端类型从 schema 生成。
- 管理端共用 ReviewForm，内容开放与评测意见共享记录机制，但不混同教学开放、模型发布及学生策略确认。

模型服务范围、512 输出 token 上限、30/100 日预约次数及无自动重试保持原规则。本轮没有真实模型新增调用，真实 v2 基线和独立集复测仍按 47/49 号计划进行。
