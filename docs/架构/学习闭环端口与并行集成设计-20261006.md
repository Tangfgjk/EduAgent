# 学习闭环端口与并行集成设计

记录时间：2026-10-06 13:30（UTC+08:00）。

## 所有权和依赖

`learning/schema.py`定义事实及推断契约；纯学习算法只依赖契约；`LearningService`管理持久化、授权和消费者；Runtime/API只调用service和纯决策端口。Vendor及Provider不得反向拥有学习状态。

```text
Verifier -> LearningEvidence -> LearningService/Store
                               -> Mastery consumer -> MasteryState/Gate
                               -> Retention consumer -> RetentionState/ReviewTask
State + Gate + prerequisite -> PathRecommendation(proposed)
Trigger -> Policy -> ActionGovernor -> 教学动作 -> 新作答
Path proposed -> draft/Diff -> 学习者签署 -> confirmed
```

`core.MentalStateSnapshot.knowledge_state`是兼容旧界面的投影；主源为learning_states，每次作答从service刷新。Runtime不再调用旧BKTTracer更新长期状态。

## 事务边界

外部验证/LLM在事务外；消费事务锁定数据库，验证授权/内容hash/先前版本，分配序号，追加Evidence、消费、转换、派生状态和兼容快照，一个事务提交。Python重入锁保护同连接，SQLite写锁保护不同连接。独立消费者唯一键不包含算法版本，重建使用独立审计任务。

## Replay语义

固定Evidence集合、全局event_seq、算法和参数版本，显式as_of计算。采集时间和入库时间都保留。晚到事件按event_seq消费，Retention计算时间不倒退：有效处理时间为已有last_review_at与occurred_at较晚者，原始事实不修改。此为处理序列模型，不能宣称重建真实时间顺序。历史可见集合由调用方固定event_seq截止；as_of本身不是数据库采集时间过滤器。

## 兼容及扩展

- 新学习API和独立本地工作台可与旧演示页并存，原型数据不作为效果证据。
- 可替换算法必须声明版本和参数集，并用新状态版本重建。
- 资产版本与数值状态版本分离，未知或不可比资产不生成效果增量。
- 教师修正保留原判定，重建认知状态不自动改已签署计划。
- PostgreSQL适配需保持这些事务和消费契约，再做独立多用户验收。
