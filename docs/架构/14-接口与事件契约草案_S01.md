# 接口与事件契约草案 · S01

日期：2026-10-15。状态：供 S02–S04 实现评审的设计草案，**本文的 `/api/v1` 接口尚未实现**。沿用 12 号产品基准和 13 号工程规划，前端采用 React + TypeScript。现有 `/api/*` 仅作为行为迁移基线。

## 1 现有接口盘点与缺口

根目录启动后，OpenAPI 共包含 15 个操作（根页面算一个操作）。

| 现有接口 | 当前用途 | 正式实现要补什么 |
|---|---|---|
| `GET /` | 旧单页 | 学生、管理端独立入口；React 在 S03 接入 |
| `POST /api/contracts` | 学生目标、期限、初始计划 | 身份、项目范围、计划修订与确认版本；不能接受任意 learner_id |
| `POST /api/sessions` | 探究/检查点会话 | 工作空间归属、持久运行与恢复；当前内存注册表重启即丢 |
| `POST /api/sessions/{sid}/messages` | 同步回合 | 幂等输入、排队任务、并发版本检查、模型失败重试 |
| `POST /api/sessions/{sid}/messages/stream` | 两次 status + 一次 reply | 事件 ID、续传、取消、关口、失败状态；当前是 POST 流，不能直接当 EventSource GET |
| `POST /api/sessions/{sid}/reflection` | 保存反思 | 关口 revision、来源与授权、防重复入证据 |
| `GET /api/mirror/{learner_id}` | 学习模型 | 全局/项目投影、证据钻取；现有活动会话选择不能代表所有项目 |
| `GET /api/events` | 学习事件 | 服务端鉴权、范围过滤、稳定分页与来源标记 |
| `GET /api/governance/hard-rules` | 10 条硬规则与哈希 | 区分公开规则摘要和管理员审计 |
| `GET /api/path/recommend` | 规则推荐路径 | 工作空间上下文、依赖版本、教材/课标来源 |
| `POST /api/path/accept` | 保存确认计划 | 学生确认权限、预期版本、防重复确认 |
| `GET /api/evidence/{learner_id}` | 聚合证据 | 正式/临时、开发/成人/真实学生来源分离；素养缺失/不确定性 |
| `POST /api/evolution/digest` | 生成 L0 沉淀 | 管理权限、幂等任务；沉淀不等于策略已获批或激活 |
| `GET /api/evolution/digest/latest` | 最近沉淀 | 授权范围、可追溯版本与分页 |

运行时另有 `LearningAgent` 的计划确认、反思、升级关口，但目前 HTTP 网关调用的是 `TutorSession`；前端不能误以为这些关口已全部由现有 HTTP API 提供。

## 2 S02 已确认的身份方案

- 管理员创建学生账号；首个管理员通过本机命令初始化，无公开管理员注册接口。
- 初始账号凭据通过命令交互输入，不放在仓库、启动参数或默认配置中。不生成通用默认密码。
- 学生与管理员独立页面；后端依角色和资源归属授权，不能只靠前端隐藏入口。
- 拟采用服务端会话与 HttpOnly Cookie。生产 HTTPS 设置 Secure；开发本机 HTTP 单独配置。状态修改请求做 CSRF 防护；会话失效与禁用账号在服务端生效。
- 自建账号先满足内网试点，不预设学校 SSO，不引入公开学生注册流程。

## 3 Scope、项目与临时路线

### 3.1 数据关系

`account → learner → workspace → conversation → run`。

- `workspace.kind = project`：对应一个正式项目，`project_id` 非空；包含目标、陪学、复习、圆桌、我教 AI 和局部成长证据。
- `workspace.kind = temporary`：`project_id` 为空；会话独立，默认排除在正式成长投影、长期画像、研究与策略晋升素材之外。
- 全局证据仅聚合已授权正式项目；项目归档保留既有事实，但不接受新学习输入。恢复归档显式操作。
- 临时会话转项目不在首版隐式支持范围内。若后续增加，须显式确认迁移范围并保留来源，不能直接改来源标签。

### 3.2 工作空间响应 Schema 草案

以下是**输出**约束；请求不能自行指定 owner、learner_id 或来源。

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "WorkspaceV1",
  "type": "object",
  "additionalProperties": false,
  "required": ["workspace_id", "kind", "project_id", "title", "status", "revision"],
  "properties": {
    "workspace_id": {"type": "string", "format": "uuid"},
    "kind": {"enum": ["project", "temporary"]},
    "project_id": {"type": ["string", "null"], "format": "uuid"},
    "title": {"type": "string", "minLength": 1, "maxLength": 120},
    "status": {"enum": ["active", "archived"]},
    "revision": {"type": "integer", "minimum": 1}
  },
  "allOf": [{
    "if": {"properties": {"kind": {"const": "project"}}},
    "then": {"properties": {"project_id": {"type": "string", "format": "uuid"}}},
    "else": {"properties": {"project_id": {"type": "null"}}}
  }]
}
```

所有 learner/owner 从登录身份与数据库关系导出。管理员跨学生查询必须有明确权限与审计；管理角色不自动获得修改学生作答或代签计划的权限。

## 4 新接口分阶段实现

统一建议前缀 `/api/v1`；学生和管理路由分别鉴权，未来可以共享同一 API 服务。下表是协议方向，具体分页参数和 Pydantic 类型在对应阶段实现并生成 OpenAPI。

| 阶段 | 接口 | 请求或响应重点 |
|---|---|---|
| S02 | `POST /auth/login`、`POST /auth/logout`、`GET /auth/me` | 不回传密码哈希；错误信息避免透露账号是否存在 |
| S02 | `POST /admin/students`、`POST /admin/students/{id}/reset-password` | 创建/重置需管理权限；首个管理员走本机命令 |
| S02 | `POST /admin/students/{id}/disable` | 会话撤销、审计；禁用不等于删除学习事实 |
| S02 | `GET/POST /student/workspaces` | POST 仅允许 kind、title；服务端分配 ID、归属 |
| S02 | `GET/PATCH /student/workspaces/{wid}` | 归属校验；PATCH 使用 expected_revision |
| S02 | `POST /student/workspaces/{wid}/archive`、`.../restore` | revision 检查；归档不能并发接收新作答 |
| S04 | `POST /student/workspaces/{wid}/conversations` | 指定 tutor/roundtable/teach；未完成类型返回明确未开放错误 |
| S04 | `POST /student/workspaces/{wid}/conversations/{cid}/inputs` | Idempotency-Key、expected_revision、输入；返回 202 与 run_id |
| S04 | `GET /student/workspaces/{wid}/runs/{rid}` | 当前运行状态、revision、待处理关口 |
| S04 | `GET /student/workspaces/{wid}/runs/{rid}/events` | SSE；Last-Event-ID 续传；读取前校验身份与 workspace/conversation/run 一致 |
| S04 | `POST /student/workspaces/{wid}/runs/{rid}/resume` | gate_id、expected_revision、学生输入；不能提交管理员审核结论 |
| S04 | `POST /student/workspaces/{wid}/runs/{rid}/cancel` | 幂等停止后续任务；已保存事实不撤销 |
| S05/S06 | 项目目标、计划、错题、复习接口 | 绑定 workspace、内容版本；独立检测与受辅练习分开 |
| S08 | `GET /student/evidence` 与 `GET /student/workspaces/{wid}/evidence` | 全局与局部不同资源；来源、缺失态和置信区间 |
| S09 | 管理端提案审核、学生激活与回滚接口 | 两类权限分离、独立关口、不可变版本谱系 |

S02 不创建假的模型聊天接口或“成功但未执行”的学习功能。S03 页面对于未开放功能应明确展示待接入状态。

## 5 输入幂等与错误

新提交以 `Idempotency-Key` 绑定身份、workspace、conversation 与规范化请求内容；同键同内容返回既有接受结果，同键不同内容返回 409。数据库唯一约束负责最终防重，不能只在进程内缓存。

收到输入先保存输入事实与 outbox，再返回 202。已接受不等于模型已完成；worker 失败进入可查询运行状态。未经授权/版本冲突的请求不进入学习证据，仅保留必要安全审计。

| HTTP | 语义 |
|---|---|
| 401 | 未登录或会话失效 |
| 403 | 已登录但不具备该操作角色，例如学生访问管理操作 |
| 404 | 资源不存在或无资源可见权，避免泄露其他学生项目存在性 |
| 409 | revision 冲突、幂等键内容冲突、归档空间、关口已处理 |
| 422 | 输入 Schema 错误 |
| 429 | 限流或运行配额；不伪装成数学作答错误 |
| 503 | 服务暂不可用；携带可追踪 request_id，不泄露模型密钥与原始异常 |

错误体草案：`{"error":{"code":"revision_conflict","message":"该计划已更新，请刷新后确认","request_id":"…","retryable":false}}`。前端按 code 决定操作，不依赖中文字符串匹配。

## 6 新 SSE 事件契约草案

HTTP 提交与 GET 订阅分开。SSE `id` 对应事件 envelope 的 event_id；seq 是每个 run 内严格递增序号，持久化后才向订阅者发送。重连允许重复投递，客户端按 event_id 去重；投影和计分也必须幂等。

```typescript
type RunStatus = 'queued' | 'running' | 'awaiting_input'
  | 'completed' | 'failed' | 'cancelled';

type RunPayload =
  | { type: 'status'; status: RunStatus; message: string }
  | { type: 'tool_result'; tool_name: string;
      outcome: 'ok' | 'denied' | 'failed'; summary: string }
  | { type: 'awaiting_input'; gate_id: string; revision: number;
      gate_kind: 'plan_confirm' | 'reflection' | 'student_activation'; prompt: string }
  | { type: 'reply'; text: string; evidence_refs: string[];
      verification: 'passed' | 'failed' | 'unverifiable' | 'not_applicable' }
  | { type: 'completed'; result_ref: string }
  | { type: 'failed'; error_code: string; retryable: boolean }
  | { type: 'cancelled'; reason: string };

type RunEventV1 = {
  schema_version: '1.0';
  event_id: string;
  workspace_id: string;
  conversation_id: string;
  run_id: string;
  request_id: string;
  seq: number;
  occurred_at: string; // UTC ISO 8601
  payload: RunPayload;
};
```

这是运行通知协议，不替代 InteractionEvent 学习事实模型。学生订阅不包含原始模型思考、系统提示、密钥、完整工具参数或管理审计。tool_result 只给学生可见摘要；数学裁决正文和审核记录可按权限另查。

待管理员审核的 PlanningGraph 在管理 API 提供对应关口，不能作为学生可提交的 resume 类型。接入时用 Pydantic 的判别联合生成正式 Schema，并由 React 类型生成流程消费，不手工长期维护两套定义。

SSE 只有经过输出检查的 reply 才发送；原始模型 token 不直接转发。旧接口的 status/reply 协议保留为旧行为，不能宣称支持新续传协议。

## 7 数据来源与证据最低要求

业务事件新增来源与版本字段的迁移设计：`source_kind`（synthetic/adult_test/real_student）、`workspace_id`、`request_id`、`content_version`、`policy_version` 和 `strategy_version`。来源由账户、运行模式与可信采集通道决定，学生或模型不能自行改成 real_student。

管理员审核是独立审计/审核事实；不将“人工审核”混为学生行为来源。历史数据未知来源标记 legacy_unknown，默认不晋升真实证据；不能因迁移而补写成真实学生。L2/L3 投影引用原始事件，不引用自己的聚合结果作为新学习证据。

## 8 后续验收场景

S02 覆盖：学生 A 不能读写学生 B；同一学生项目 P/Q 不串记录；临时空间不入正式聚合；禁用账号后旧会话失效；重复创建/归档不产生重复事实；归档与输入竞争有确定结果。

S04 覆盖：输入已接受后重启不丢；重复提交/恢复不重复计分；错误 workspace/thread 拒绝；过期关口拒绝；断流后续传有序；任务取消不撤销已存作答。具体数学闭环与内容审核在 S05 验收。
