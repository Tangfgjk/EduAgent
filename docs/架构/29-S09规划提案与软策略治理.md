# S09 规划提案与软策略治理

日期：2026-10-16。依据 12、13、19、23、25、27 号文档，既有文件保持不变。用户已确认本轮采用固定开发提案，真实模型单独确认。

## 1. Module 与 Interface

新增 `app/modules/planning`，集中提供资料管理、来源冻结、提案、决定、生效查询和回滚。学生与管理员的网关是角色 Adapter，不能用可编辑 JSON 回执替代服务端授权。LangGraph 负责两个持久暂停关口；service 负责数据库、来源、版本、审核角色、检查与激活事务。worker 复用既有 outbox、租约与检查点短事务。

本轮不引入不存在的模型供应商 Adapter，不把网络请求加入业务事务。未来真实模型只能生成受限候选，仍须经过此 Interface 的检查与确认；运行器先按 19 号文档升级长运行与独立持久检查点。

## 2. 真正可调整的参数

| 参数 | 范围 | 生效位置 |
| --- | --- | --- |
| daily_minutes | 严格整数 5–60 | 项目学习计划出现“采用当前策略建议”按钮，学生主动采用后预填，不替学生确认或改已有计划 |
| reflection_focus | basis / verification | 新陪学运行的反思提示分别侧重依据回望、代入核验 |

SoftPolicy 禁止额外字段。资料、候选与导出的 Skill.md 均不能改变硬规则、权限、题库发布、提示阶梯、答案验证、独立检测、数值结果或素养分数。Skill.md 由固定格式渲染，可下载、可读，不写入仓库原有技能文件，也不作为任意指令/代码加载。Harness 是相同受限 JSON，不开放任意 Python、提示词或文件路径。

候选参数来自学生选择的时长和引导重点。固定规划流程收集、冻结和展示来源，不会自动理解课程正文、推断误区或评定教学效果。界面与版本记录均标记 development_template；不称其为真实模型规划或自我进化已完成。

## 3. 课程资料

PlanningMaterial 保存 title、kind、edition、source_ref、body、hash、录入者和时间；正文最多 6000 字。分类支持教材摘录、课标摘录、考纲摘录和自编开发参考。系统不自动下载或验证外部链接，来源字段是录入者声明，所有资料 professional_review=false。

MaterialRelease 单独保存启用与 revision。录入默认未发布；管理员核对正文、来源、版本及开发范围后发布。修改资料须创建新版本，原正文不可覆盖。同一完整请求 hash 去重；发布/停用使用 revision 比较，写审计。学生只可选择已发布资料，一次 1–5 份。

资料只作为字符串数据存储、引用和展示，未执行其中的命令。包含“忽略规则”“直接批准”等文字不会成为治理指令。接真实模型后仍需实施数据/指令分层与输出校验，当前无模型场景不能代替未来模型注入防护验收。

## 4. EvidenceBundle 的边界

只收当前学生的当前正式项目，不自动带入临时或其他项目。包含：

- 本次学习体验：标明学生自述，保存在提案输入中，不生成能力事实。
- 当前项目 L1 学习事实、关联原始输入、自述、人工判断，各类分开引用。
- 所选课程资料的完整不可变版本、发布 revision、来源与 hash。
- 当前策略基线 ID/revision、规则注册表 hash、时间及数据来源标签。

各类学习来源选最近最多 100 条，事实中的推理/反思文本各最多 600 字；参考资料最多 5×6000 字。总数与来源指纹覆盖本项目全量不可变记录 ID。切片不足以评审可退回；不得假称已审阅全部原文。不将 L3 观察或图检查点当作新的 L1 学习事实，不产生素养或掌握度结论。

学生可在原有成长证据界面追溯其原始来源。管理员仅通过策略评审查看该提案冻结的切片，不新增任意跨项目的学生事实读取接口。

## 5. 工作流与授权

1. 学生在正式项目提交学习体验、目标参数和资料引用。只允许模拟/成人开发账号；临时空间和 real_student 暂不开放此开发流程。
2. 服务端授权并锁空间，冻结 Bundle，保存 LearningInput + Outbox，返回 queued。每项目同时一条待处理提案。
3. worker 重验账号、来源、空间、流程版本、资料发布、来源指纹、规则和基线；校验 SoftPolicy，生成不可变 StrategyVersion 与检查点，暂停在 admin_review。
4. 管理员通过专用网关批准或退回，必须填写依据。学生不能访问管理员关口，管理员不能调用学生确认关口。
5. 批准后图暂停在 student_confirm；此时仍未生效。学生可确认或不采纳，并填写理由。
6. 确认的 worker 事务再次检查有效性；图中的候选与冻结版本必须完全一致。更新检查点、运行、激活历史、审计与当前指针，共同提交。

每次决定保存不可变 StrategyReceipt，绑定已鉴权 actor、当前 gate/revision、LearningInput 和 action。排队任务仍绑定学生拥有的运行；管理员回执的真实作者单独保留，不能靠客户端 actor_id 或 role 伪造。相同键与相同请求可回放，不同请求冲突；并发不同键只能接受当前关口一次。

确认前新增事实、自述、人工判断，资料发布 revision 改变、规则改变、策略指针改变，或 7 天期限到达，旧提案不得批准/激活。退回、不采纳、取消仍可收尾当前有效流程。归档只读，确认与取消都拒绝；恢复后重新核对来源。失效或失败不覆盖既有生效策略。

结构检查只保证白名单、引用、版本和权限等性质，不等于逐提案教学回归或学习增益评测。完整工程回归在开发验收中执行，未伪造每个提案的教师评审或效果分数。

## 6. 激活、回滚与已有运行

ActiveStrategy 保存当前指针与单调递增 revision；StrategyActivation 只追加 from/to、actor、理由、幂等键和时间。指针发生 ABA（回到同一版本）也因 revision 变化而使旧提案失效。

学生只能回滚到平台默认或本项目曾激活且仍可用的历史版本；不可回滚到未确认、被退回、其他项目或任意候选。回滚同样要求所有权、活跃空间、revision 和幂等检查。页面展示最近 50 次变更。

已激活后继续学习是正常行为，不因新增事实自动撤销该版本。若引用资料被停用或规则不兼容，后续运行回退到默认策略，返回不可用原因，历史指针不被悄悄改写。恢复资料后仍以相同不可变内容和规则校验决定可用性。

新 TutorGraph 在开始输入中保存有效策略 ID 与反思重点，检查点/view 保留该快照；之后的激活/回滚不改变已开始的运行。S04 已确认计划也不会被修改。教学图升级到 tutor.v2；旧 tutor.v1 可查阅和取消，不能用新教学实现静默续跑。

## 7. 表、迁移与历史兼容

新增 planning_materials、material_releases、strategy_versions、strategy_receipts、active_strategies、strategy_activations。资料版本、候选、回执、激活历史有 SQLite/PostgreSQL 禁止更新/删除触发器；发布状态、当前指针和运行状态可更新。

迁移 s09_001 在 s06_001 后增加表，不移动或重写已有学习事实。JSON 一致备份自动覆盖新表，恢复仍只接受同 schema revision 的空库，不恢复登录会话。旧 schema 的 JSON 不能直接改头部版本后导入，应先在相应旧环境恢复再迁移；升级前保留 PostgreSQL 原生备份。

旧 tutor.v1 事实重建仅在原规则/题库/验证版本完全匹配时继续支持：复跑同一数学逻辑，比较视图前仅移除新增的两个策略展示字段；数学结果与原记录必须吻合才补事实。未知版本仍跳过，不猜测历史。备份恢复后策略可从原审核关口继续，激活与检查点保持同一事务。
