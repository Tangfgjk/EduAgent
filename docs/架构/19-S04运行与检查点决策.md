## 2. 图与事务

图结构：START → propose → confirm(interrupt)。学生确认后 END；学生调整时间后回到 propose，再形成新的确认关口。

HTTP 只做短事务：校验并保存不可变输入、outbox 和运行排队状态，返回 202。任务执行由独立 worker 完成。

当前 graph 是确定性模板，不做网络请求或其他外部副作用。worker 以固定顺序锁定账号、项目、运行、租约，检查 token 和过期时间，执行有界图，再一次提交检查点、草案、事件与任务完成。并发 worker 由 outbox 租约与行锁隔离；SQLite 开发库使用既有 BEGIN IMMEDIATE。

不持久化“running”中间态：当前执行发生在一个很短的模板事务内，对外看到 queued → awaiting_input/completed。长时模型调用时需要引入可观察的 running、超时和心跳。

## 3. 为什么当前把 SqliteSaver 镜像放进业务库

使用官方 `langgraph-checkpoint-sqlite` 的 SqliteSaver，在每次执行中恢复该运行的独立 SQLite 镜像，执行完成后 serialize，再将 base64 镜像存入 `agent_checkpoints`。业务数据库可以是 PostgreSQL 或本机 SQLite；这不是 PostgreSQLSaver。

优点：无需自研 LangGraph 序列化协议；框架真实中断状态可跨进程恢复；检查点与业务事实共同提交，消除本阶段“图已提交但结果没提交”的窗口；既有一致 JSON 备份自然覆盖检查点。

代价：每次复制完整镜像，历史增长会增加成本；持有业务事务期间只能执行短时无 IO 图。此方案明确限定为开发模板基线，不适合作为真实模型或多工具长运行的最终存储。

恢复中断节点会重新执行节点开头，所以 interrupt 之前没有计费、事件写入或其他副作用。关口由运行 ID 与草案代次确定，学生决定经过应用层类型和版本校验，不能任意覆盖图状态。图版本与规则注册表版本一起锁定；版本不匹配时阻止继续，不静默套用新代码。

## 4. 真正模型/工具接入前的必做升级

1. 换成独立持久检查点：PostgreSQL 使用官方 PostgresSaver，并管理其 setup/migrations、连接池、备份恢复；SQLite 可用独立持久 SqliteSaver。禁止把模型调用直接塞进当前原子模板事务。
2. 业务输入与运行任务继续原子接收；模型调用前提交执行状态，释放业务事务锁。每个 thread 保持单写者，使用执行租约、心跳和 fencing token。
3. 检查点与业务库分开提交后，新增 operation_id、幂等结果协调及恢复扫描，测试“图完成但业务未提交”“业务接收但图未推进”等故障窗口。
4. 远程调用设置连接/总时限、预算与可重试错误分类。取消在节点边界重查，已发生的外部调用费用不能撤销。
5. 工具副作用通过幂等执行记录或 outbox 落地；禁止根据 checkpoint 直接重复发送消息、修改策略或写增长证据。
6. 独立运行追踪、结构化审计与观测只输出允许公开的字段；外部追踪默认关闭。模型服务、型号、出网字段与预算由用户确认。

这些是 S05 接模型前的工程门槛。S04 的“计划确认完成”不等同于长运行框架全部完成。

## 5. 本阶段接口与事件

所有接口在 `/api/v1/student/workspaces/{wid}` 下，均须真实学生会话；写操作还须 CSRF 和允许的来源：

| 接口 | 用途 |
| --- | --- |
| POST `/runs` | 目标与时间；Idempotency-Key；原子创建内部 tutor 会话和运行 |
| GET `/runs?offset=0` | 当前项目运行列表，每页 20 条 |
| GET `/runs/{rid}` | 安全运行快照 |
| POST `/runs/{rid}/resume` | gate_id + expected_revision + confirm/revise + 时间 + 幂等键 |
| POST `/runs/{rid}/cancel` | 版本检查后取消；重复取消幂等 |
| GET `/runs/{rid}/events` | text/event-stream；Last-Event-ID 为非负序号，每批最多 100 条 |
| GET `/runs/{rid}/event-history?after=0` | 同一安全事件的 JSON 读取，用于排查与类型契约 |

原 14 号契约是草案。本阶段提供原子“开始目标协商”用例，不额外暴露可创建半成品的 conversation 接口；后续正式多轮陪学再扩展对话输入。

SSE 是有界续传批次，不是持续 token 流。每批重新鉴权，释放事务后返回，浏览器状态变化时用上一序号读取新事件。未来真实模型 token 流需要独立连接管理、断线重连与执行取消设计。

事件：run.queued、plan.proposed、plan.confirmed、run.cancelled、run.failed。数据仅含运行 ID、序号、状态、revision 和时间。草案通过运行快照读取，检查点不对外提供。没有把模型估计或模拟输入转换成素养分数。

## 6. 框架依据

以实际锁定环境 LangGraph 1.2.15、checkpoint-sqlite 3.1.2 的本地源码及运行测试为准。流程设计参照官方 [Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) 与 [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：相同 thread_id、真实持久检查点、Command(resume=...)，以及恢复时节点重新执行的语义。
