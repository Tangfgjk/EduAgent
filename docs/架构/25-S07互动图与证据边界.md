# S07 互动图与证据边界

日期：2026-10-16。依据 12、13、19、21、23 号文档；既有文档保持不变。本次只提供开发活动闭环，不宣称真实模型、专业教学审核或素养测量已经完成。

## 1. 活动与范围

| 路线 | 学生关口 | 模板内容 | 最后保存 |
| --- | --- | --- | --- |
| 圆桌讨论 | 初步数值与思路 → 比较观点、给出数值与依据 | 思路提出者、质疑者、整理者；包含明确标注的待纠正错误 | 过程、数值核验、讨论小结 |
| 我教 AI | 讲解方法 → 回应预设误区、给出数值与依据 | 虚拟学伴的移项符号错误 | 过程、数值核验、TeachReport 讲解记录 |

首个开发活动复用 `P-EQ-01`：`2x−7=5`，不新增未经审核的自由题目。学生先留下表达，系统才展示角色内容。固定角色不会读取学生文字并生成针对性回复，不能把它称为已完成的智能对话。每次活动最多两次学生提交，不自动展开无限对话。

正式项目和临时空间都能发起此开发活动；与 TutorGraph 不同，当前不要求先确认项目计划。上下文为当前空间和这道开发题，不查询其他项目，不调用模型，不把全量学习记录传出本机。今后扩大主题、引入模型和迁移题时，需要保持同一门禁、来源和核验协议。

## 2. 图、输入和运行

`activity_graph.py` 用共享工厂分别构建 `roundtable` / `teach` 两种有界 LangGraph。流程为 `opening → challenge → summary`，两次 `interrupt` 分别要求学生表达和核验。状态只保留当前题、当前活动消息、关口、回合与核验结果。

运行、检查点和事件复用 `AgentRun`、`AgentCheckpoint`、`AgentEvent`；会话类型为 `roundtable` / `teach`。本轮没有修改数据库结构，schema HEAD 仍是 `s06_001`。新增活动类型不是旧计划类型：路由按类型查找运行，跨类型访问返回 404；计划创建的幂等回放也补上类型核对。

发起/续接输入经真实鉴权、同源/CSRF、空间所有权和归档检查后入 `LearningInput + OutboxJob`。续接还校验运行类型、状态、revision、gate、版本与 action。完全相同请求的重复键可回放；旧关口或同键不同请求拒绝。每个空间同时只允许一个陪学或互动活动，覆盖 queued 和 awaiting_input 阶段。

worker 在账号、空间、运行、租约的锁保护下再次检查账号启用、空间状态、内容启用与版本、路线互斥。图检查点、view、学习事实、投影、人工分流和任务完成共同提交。故障全部回滚后重试；取消后排队作业不再执行图。版本由模板、教学规则注册表和数值验证器版本共同确定，旧版本不自动续跑。

仍沿用 19 号文档的短事务限制：官方 SqliteSaver 的内存数据库镜像持久保存到业务库，适用于确定性且无网络 I/O 的有限流程。接真实模型前必须完成独立持久检查点、长运行租约/心跳和操作结果协调，不能在这里直接塞入慢速模型请求。

## 3. 内容与教学规则

互动包 `math.g7.equations.activities.dev1` 与原陪学包分别保存 `ContentApproval`。互动 hash 包含原题快照、角色模板、预设误区及流程版本。原陪学版本未被改写；原题库已经启用也不会自动开放互动包。

管理员在“知识点与题库”查看完整话术和错误设置，单独确认开发使用范围，再启用确定版本。`real_student` 来源仍禁止使用；模拟与成人测试可在启用后体验。停用后禁止新输入，worker 对已排队输入重新检查，历史记录仍可读。

角色讲解经统一 `ActionGovernor` 的 EXPLAIN/nudge 路径，绑定 `MATH.G7.EQ.SOLVE`；数值反馈经 FEEDBACK 路径，保留红线检查和能力归因改写。现有学生贡献之后才开放模板，不输出完整代做方案。独立检测隔离同时在 API 和 worker 通过空间路线互斥落实；无提示复做也不能与互动同时进行。浏览历史不等于防作弊系统，本轮没有宣称跨项目、跨设备的考试监考能力。

## 4. 哪些内容算证据

| 内容 | 保存位置 | 证据用途 |
| --- | --- | --- |
| 学生两次原文与数值 | 不可变 LearningInput；对应 LearningFact | 学生贡献的原始来源 |
| 固定角色观点、预设误区 | 版本化内容包、活动 view/检查点 | 展示互动背景；不单独发布学习事实 |
| 最后数值核验 | 活动 check、第二条学生贡献事实 | 只说明该数值是否符合此题，不证明论证或纠错有效 |
| TeachReport/讨论小结 | 该 run 的最终 view | 过程记录及其边界，不是教学评分报告 |
| 无法核验的数值 | AnswerReview → 追加 FactJudgment | 人工只复核数值，无法判断可保留 unresolved |

活动事实 kind 为 `activity_contribution`，stage 为 roundtable/teach；题目版本继续指向复用的原题版本，payload 额外记录互动版本。学生来源接口返回 activity_version、independent=false、reasoning_reviewed=false。模板不会被转换成学生答案或教师真值。

L2 保留学生贡献的事实引用，但不把它们混入诊断、练习、复做的数值计数；L3 只描述“留下几次学生贡献”，引用学生事实，明确解释质量未评定。全局只聚合正式项目（含归档），临时空间只保留局部记忆。来源可打开原文并追加学生自述，不修改原始输入。

本轮活动数值失败不会自动扩张错题集。无法核验时进入现有数值复核队列；若人工认定数值错误，沿用既有人工回看规则生成原题复习条目。原题复习仍遵守原题包启用与版本检查。

## 5. 保留的后续工作

- 专业 rubric 的设计、审核与校准；讲解、论证和纠错的人工评价工作流。没有这些依据，不生成解释质量分或素养分。
- 根据学生表达的真实多角色回复、受控追问、分歧整理与更丰富的核查工具；真实模型供应商/型号/端点、出网字段和预算仍待确认。
- 多知识点的误区包和迁移题。目前两次表达围绕同一道题，不宣称迁移能力提升。
- S08 成长证据界面的局部/全局统计、趋势和来源钻取。继续将自述、观察、估计、实测和缺失分开。

上述保留项是进入正式教学前的工作，不能用当前开发活动或测试数量代替。
