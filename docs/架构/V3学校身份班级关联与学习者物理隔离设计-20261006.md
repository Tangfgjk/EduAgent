# V3学校身份班级关联与学习者物理隔离设计

记录时间：2026-10-06 20:16；20:23修订共享/隐私边界（Asia/Shanghai，UTC+08:00）。分支：本地V3。当前交付是独立本地学校研究实例MVP，不是完整production SSO/多租户平台或tutor前端。

## 身份来源与数据边界

`app/school/identity.py` 的 `SchoolDirectory` 持久保存tenant、class、account、membership、learner及教师/家长assignment。账户仅通过受信离线操作创建，不提供public注册/换role/自行加入班级。role只读取服务器账户表；请求body里的role等未知字段被拒绝，header中角色或旧用途token不提升权限。

每个account只属于一个tenant；班级键由tenant/class组成。教师和家长只有与学生同tenant且双方当前仍在该class、存在离线批准assignment时才可读取。student只能自己的learner。每次请求先由bearer识别当前服务器account，随后重新查active/role及关联，不缓存身份授权决定。

20:23补充：assignment是必要而非充分条件。teacher/parent还必须经学生显式`WorkspaceService.share`授权对应audience（绑定当前consent版本）；默认拒绝共享，撤销共享或更新consent版本立即阻挡。共享检查与整个读响应在同一SQLite事务中，防止撤回窗口。家长仅能读取最少汇总，不含raw_answer、evidence_refs、artifact/verdict引用或原始证据行；教师在显式teacher共享后可读证据。

Directory保存密码PBKDF2-SHA256（260,000轮随机salt），bearer仅保存SHA-256，不存原token。会话默认8小时，可撤销；账号停用、session过期/撤销或membership移除立即生效。登录有每tenant/username哈希维度的短窗失败限流；不代表生产级分布式防爆破或风控。

学习数据采用**每学习者物理SQLite Store**，文件名hash绑定tenant/learner而非使用请求路径；directory与学习DB分离。只在经过当前角色和assignment检查之后打开对应Store，不接受请求提供database路径或DSN。身份目录中的pseudonym仍属个人数据，不能宣称充分匿名。

## 独立应用与API

`app/school/application.py::create_school_app(directory, learner_root)` 是独立FastAPI应用。它不mount原个人应用，不公开任意内部路由，不接入原8000数据库；CLI默认新loopback端口8012。

| 路由 | 行为/允许角色 |
|---|---|
| POST `/api/school/login` | 服务器核验用户名密码，返回本地bearer |
| POST `/api/school/logout` | 撤销当前bearer |
| GET `/api/school/learners` | 当前tenant/class可见learner列表 |
| GET `/api/school/learners/{id}/state`、`evidence` | student own；teacher assigned+显式teacher共享；parent assigned+parent共享且只summary；当前teaching授权必需 |
| GET `/api/school/learners/{id}/assessments` | student own；只给资产metadata，无题干/答案 |
| POST `/api/school/learners/{id}/consent` | student own；只能teaching/撤回，来源由服务器account派生，不授予research/evolution |
| POST `/api/school/learners/{id}/sharing` | student own；显式audiences与期望revision，教师/家长不能代开 |
| POST `/api/school/learners/{id}/issue`、`hint`、`submit` | student own；内部严格delivery ticket，复用既有学习API验证 |

所有非`/api/school/`的legacy/highpriv路径统一403。教师/家长不能调用学校写端点，即使携带旧`X-Teacher-Token`、`X-Parent-Token`也不能代学生授权/作答或调用旧teacher correction/governance写路径。网页静态/UI和OpenAPI暴露不在该独立服务范围。

服务校验loopback Host（127.0.0.1/localhost/::1），拒绝异源Origin、null Origin和`Sec-Fetch-Site: cross-site`。响应设置`Cache-Control: no-store`及`X-Content-Type-Options: nosniff`。ASGI lifespan关闭已打开学习Store；Directory由外层CLI负责关闭。不是公开服务器部署方案。

内部learning route使用注入`Settings(learner_id=own_learner,assessment_require_ticket=True)`，不读取用户环境DSN/密钥，不允许模拟未来时间。提交沿原有receipt和server-observed delivery历史，不接受客户端自称首次暴露；全校应用也不能声称验证了校外是否看过题。

## SSO和生产边界

`app/school/federation.py` 只定义未来OIDC验证端口及始终拒绝的`UnconfiguredFederation`。没有真实issuer、client注册、签名密钥、audience/nonce/回调白名单和机构映射审批时，不执行联邦登录，也不将外部token role当作学校角色。

未来真正SSO需审查issuer/audience/signature/expiry/nonce，外部subject通过批准的服务器映射建立本地账户/班级/角色。现阶段没有宣称完成学校生产多租户：TLS/外网部署、分布式限流、正式监护关系验证、真实机构审批、账户保留/删除策略、directory备份擦除、UI、PG完整应用backend仍需独立验收。
