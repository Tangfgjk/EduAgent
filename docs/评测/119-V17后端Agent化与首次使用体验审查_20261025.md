# V17：后端 Agent 化与首次使用体验审查

评审基线：`V17-20261025`，提交 `243a3ea`。本轮阅读当前实现、执行离线探针和隔离浏览器走查；不修改业务代码，不提交真实模型或媒体请求。

## 一、总体判断

系统已经是“具有上下文生成、受约束决策及可恢复工作流的教学 Agent 原型”，不是只有模板，也还不是完整自主教学系统。

工程上，LangGraph 状态恢复、异步任务、独立数值核验、项目隔离、模型调用栅栏和可回滚策略已经落地。教学上，可靠识别误区、验证任意自然语言数学、跨常见单元自动设计完整教学、依据真实学习效果改进策略仍有明显缺口。

界面已经能支持熟悉系统的人完成流程，核心活动重新进入侧栏也有帮助。但首次用户仍需理解“空间、课程、单元、计划、策略、课堂”六种对象。主操作位置、跨路线恢复以及能力范围提示尚不足以支持无讲解上手。

**不能把程序测试通过、会生成具体问句、数值通过或有素养雷达图，分别等同于教学正确、个性化教学有效、已经掌握或素养已测量。**

115号旧评估中已经出现的答案泄露检查、活动可用状态和跨课程证据问题，本轮对照发现仍未消除。V17主要改善了页面呈现，不能据此视为这些后端缺口已经修复。

采用LangGraph是真实存在的编排实现；是否再使用LangChain不是Agent化的判据。这里检查的是模型能否依据状态作决定、调用可用能力、获得结果并修正后续行动，以及这些行为是否可靠。

## 二、每项功能实际怎样实现

| 功能 | 当前实现与效果 | Agent 化判断 / 边界 |
| --- | --- | --- |
| 账号、权限、项目和临时会话 | 账号由管理员创建；所有权、分端会话、空间隔离、归档与恢复 | 这是基础服务，采用确定性程序合适，不需要为了 Agent 化而交给模型。真实模型仍限制模拟/成人开发来源。 |
| 主题识别、知识来源与检索 | `knowledge/service.py` 用固定六类节点与关键词匹配；取本地授权资料，外部搜索是单独动作 | 知识入口仍是规则匹配与受限检索，不是任意初中数学主题的语义理解和自动检索规划。 |
| 课程生成与诊断 | 模型生成课程候选；普通题族经 Blueprint 编译，有理数有更细概念、任务与支架设计；真实诊断数值影响生成输入 | 有受约束的 Agent 设计，但大量题面、支持类型、诊断和流程由程序定义。普通六题族覆盖及固定七任务契约不等于七至九年级完整覆盖。 |

| 津津陪学 | `generation/interaction.py` 将当前题、脱敏表达、同题最近两轮、目标和可选练习送入模型，生成具体追问；图状态记录作答与反思 | 已实现上下文回应，不只是模型选模板。但主要由用户主动请求，回答解析以保守数值提取为主，尚不是持续理解讲解的自由教学对话。 |
| 选题、变式、支架 | 模型可选允许的未完成练习、提出参数；程序重算真值，反思后加入最多两道变式。支架依无提示通过/困难记录渐撤与恢复 | 真实决策与执行已接通。边界合理，但“语义误区→补救策略→独立迁移效果→再次决策”的完整闭环尚未形成。 |
| 圆桌讨论 | 同一模型输出提出、质疑、整理三种视角，承接本轮与历史；之后比较、修正、独立验证 | 有上下文生成，但不是三个独立 Agent 相互审议。角色不同不保证观点不同、互相纠错或内容正确；三轮上限明确存在。 |
| 我教 AI | 模型扮演学伴，根据讲解生成具体问题，允许继续回应与修正，最后数值验证 | 已超越预设误区模板。尚未可靠识别讲解完整性、错误概念和解释质量，最终数值正确不能证明“教会了 AI”。 |
| 错题与复习 | 来自原始学习事实；保留原题、提示和未知状态；按策略排序、按固定1/3/7天推进 | 有证据闭环，调度主要是规则。原题复做不等于迁移；复习表达解析与陪学不一致，见B04。 |
| 成长证据与素养图形 | 项目/全局统计、活动日历、趋势、候选材料分布、原文追溯及自述/人工判断分开 | 读模型与可视化已经实现。六类素养展示的是候选材料数量，不是经量规验证的能力画像。 |
| 规划与策略 | 固定开发方式和真实模型建议两条路线；模型读取有界资料与证据，提出受限参数，确认后影响新任务 | 有模型规划与真实消费者，但策略空间仍是时间、反思及四类枚举；不是任意 Skill、自选工具或开放式课程重构。 |
| Skill / RSI | 语义候选、工程与影子评测、预先同意的个人试用；积累六条新事实可自动触发，支持撤回与技术回滚 | 实现的是受限教学策略自调整。Skill.md 来自配置编译，不是修改程序、训练模型或已经获得教学效果验证的自进化。 |
| 互动课堂与 OpenMAIC / 媒体 | 已有生成、导入、安全投影、公式、媒体、课堂答题和进度接口；学生生成受平台与预算授权控制 | 接入和播放器真实存在。当前新示范课稿是自编兼容格式，真实媒体为两图一视频；三段外部配音未通过。还不是一次输入后完整自动产出并验收的课程。 |
| 管理端 | 内容审核、账号、模型与用途配置、预算、策略评审、评价协议和任务记录 | 必要支持能力已具备。应保留权限和费用控制，同时改进准备状态与故障诊断，让正常学生路径少依赖管理员逐次介入。 |

## 三、后端发现：按优先级

### B01 · P1 · 直接答案仍可能通过“追问”检查【本轮复现】

位置：`app/modules/generation/grounded_response.py:24`、`app/modules/generation/interaction.py:123`。

检查先删除中文引号中的内容再匹配答案，但并未证明删除的内容来自学生原文。输入 `help with signs`、引用字段 `help`，模型问句 `“答案是3”，你知道为什么吗？`，完整互动校验接受。这样可以在练习中提前给出答案，削弱苏格拉底引导。该复现不代表诊断或独立检测允许调用模型。

建议：只豁免经过对齐验证的真实引用，检查新增答案及等价措辞；加入引号、中文数字、分数、暗示完整步骤等对抗样本。发布到真实学生前应处理。

### B02 · P1 · 数学语言正确性检查不足【本轮复现】

同一完整校验接受 `负数除以负数一定为负，你能说明依据吗？`。现有显式算术核验无法覆盖自然语言概念；“有引用、有问号、JSON合法”并不保证是合格的教学反馈。

建议：按现有题族建立概念不变量、错因与错误陈述集，给不同输出声明可核验范围；关键概念未通过时回退为不包含数学断言的澄清。专业评阅与独立内容评价仍需补齐，不能以另一个模型赞同代替真值。

### B03 · P2 · 陪学可用状态与活动调用上限不一致【代码确认】

位置：`learning/tutor_service.py:20`、`infrastructure/runtime/model_tasks.py:212`。

公开 `coaching_available` 判断每日额度、练习阶段和提示数；实际预约还限制整个 run 最多三次通用模型调用。三次已用但提示仍可用时，界面仍可能允许提交，后台却返回429。每日不限额也不能消除此限制。圆桌/我教AI已经按模型轮次控制，不能把该问题笼统套到全部活动。

建议：统一服务端能力状态，提供活动剩余量与禁用原因；前端直接使用该状态。固定耗尽不应引导用户反复重试。

### B04 · P2 · 相同答案在陪学与复习中表现不同【本轮复现】

位置：`learning/tutor_graph.py:130`、`memory/service.py:115`。

陪学调用 `interpret('这个答案是3').check('3')` 得到 passed；复习调用 `verify('这个答案是3','3')` 得到 unverifiable。用户刚在聊天中学会的输入方式，到了复习就不再适用。

建议：复用同一保守答案理解契约，并保持“未确定不等于错误”和数值独立核验；补充课堂、活动、复习之间的一致性用例。

### B05 · P2 · 当前目标快照可能混入旧单元证据【代码确认的风险】

位置：`learning/goal_context.py:19`。

取最近六条事实仅限制项目与来源，不按当前单元/内容版本过滤。项目换课后，这些记录被放在当前课程主题旁；虽然保留 content_version，但没有显式说明“旧单元背景”，模型有误用为本目标证据的空间。

建议：区分当前目标证据和项目历史背景，显式带单元关系与时间；策略、RSI和推荐共用该分类，不靠模型猜测版本含义。

### B06 · P1能力缺口 · 主题和教学闭环覆盖仍窄【本轮探针及代码】

位置：`knowledge/service.py:10`、`:31`、`generation/mathematics.py:27`、`learning/graph.py:39`。

“三角形内角和”“圆的切线”“一元一次不等式”“二次函数”均不能进入当前完整生成路径。其中部分回复要求“再澄清”，但真正原因是尚不支持。不同学习目标生成完全相同的三步计划。模型调度的 action 枚举中，变式、选题和部分支持决策有执行消费者，资源主要是导航建议，并未自动完成查资料、备课、检查与后续学习安排。

建议：先将现有功能真实完成度说清，明确支持范围；让计划绑定到当前任务、到期复习和下一次独立检查。按现有主题逐个做完整闭环，再扩覆盖，不需要增加新一级功能。

### B07 · P1验效门槛 · RSI工程验证与教学效果之间仍未接通【代码确认，当前有明确限制】

位置：`skill_evolution/semantic.py:66`、`trials.py:17`、`evidence/effect_studies.py:69`。

自动试用依据工程、影子及解析不变量检查，monitor统计观察与独立数值提交，没有按效果差/学习收益决定保留策略。效果采集平台有前后测、延迟、迁移与固定分组，但尚未校验真实策略暴露和分组一致性；代码也明确 effect_status=not_validated。当前没有教师和真实学生条件，不能要求系统凭空给出有效结论。

建议：先补干预分配、策略实际生效记录、可比题集、基线与候选暴露一致性、预注册停止规则；保留个人试用和撤回。真实教学效果验证必须等专业资源和合适试点条件具备。

### B08 · P2 · 课堂“可播放”与“可自动完成”之间仍有断点【代码及既有真实验收】

位置：`resources/media.py:204`、`:252`，`resources/openmaic.py:70`，`gateway/generation.py:247`，117号验收记录。

外部TTS未通过，生成拒绝、下载错误等统一记成结果未知，缺少安全的供应商状态与错误类别，难以解释和修复。旧文本生成预算关闭、私有课堂开关及单次预算是当前主动限制，不能当作代码不存在，也不能擅自删除。真正缺的是在额度内自动编排课稿、场景、媒体、核验、失败降级与开放状态，而不是增加一个按钮。

建议：记录脱敏的阶段、HTTP状态、供应商request_id和错误码，区分确定拒绝与提交结果未知；完善有文本即可学习的降级，界面只显示“哪些可用、哪些暂缺、是否需要操作”。追加真实调用仍遵守费用授权。

## 四、前端发现：首次用户角度

### U01 · P1 · 主入口埋在空状态和说明之后【隔离浏览器实测】

新建正式项目后进入 `/student/courses`，在873像素高的视口中，主题输入框顶部位于约1753像素。前面依次是全局课程上下文、目标卡片、课程概览、三条尚不能开始的路线和空资源。用户进入“准备课程”，第一屏却看不到输入框。

位置：`frontend/apps/student/src/generation.tsx`、`student.tsx`中的全局 CourseBar。

建议：未绑定课程时首屏只保留“想学什么→尝试诊断→确认课程”主路径，其他内容按进度出现。已有课程时优先显示“继续上次”，新建课程放次要位置。

### U02 · P2 · 导航名称与位置反馈不一致【隔离浏览器实测】

位置：`frontend/packages/ui/src/index.tsx:117`、`student/src/student.tsx:22`。

“主题与课程”未列在 navigation 中，Shell 找不到当前项时回退第一个项，因此该页面包屑显示“学习工作台”。学习计划、单元等隐藏路由也有相同机制。主题/课程与学习计划是必经步骤，却主要依赖工作台深层入口；11个一级导航无分组，Skill等技术名称依然要求用户理解。

建议：将路由标题与侧栏是否展示解耦；保留三大活动直接入口，按“开始学习、学习活动、回顾调整”分组。为“学习安排、教学建议/学习方式调整”等对象给出面向学生的简短解释，明确它们的关系。

### U03 · P1 · 路线互斥合理，但缺少“继续/结束原活动”的就地引导【代码确认】

位置：`learning/activity_service.py:17`、`student/src/activities.tsx:40`、`student/src/study.tsx`。

用户从陪学切到圆桌时，会看到课程匹配和开始按钮，提交后才收到“请先完成或结束当前活动”。模型调用、独立检测和课程切换的限制散在不同位置。后台限制在保护检测隔离，问题是页面没有提前说明当前阻塞任务并给出直接入口。

建议：统一一个学习会话状态卡，显示当前未完成活动；提供“继续该活动”和“结束后切换”。独立检测只给继续检测/明确结束选项，不通过隐藏按钮绕开隔离。

### U04 · P2 · 已精简技术台账，但学习页面仍有重复上下文和开发文案【代码及浏览器】

每个页面重复项目条、课程条和目标跳转；课程页还展示“受限题族、Agent、私有自动检查”等实现术语。陪学的“回答/回应AI”两种模式与另一块AI追问表单并存，用户需要自行判断同一段文字该发到哪里。规划和Skill依然含多个过程解释。

建议：使用可折叠的简短课程头；主页面只保留当前任务、输入、反馈、下一步。收起长期不变的能力说明；遇到限制时显示可执行替代。对话入口说明当前意图，保留可纠正的数值确认，不以“更像聊天”牺牲独立核验。

### U05 · P2 · 未支持与待澄清、未配置与失败没有充分区分【代码及探针】

未支持的主题可能要求用户不断换说法；互动课堂对静态课程没有生成build_id时，准备区域可能只有标题没有动作；无权限、预算关闭和素材生成失败需要用户自己推断。之前绑定必填提示已修复，这是正向改进。

建议：给出准确状态：“本主题尚不支持”“请补充目标”“课堂准备未开放”“本场景暂无配音”，并提供可用主题、回到当前活动或使用现有文字的直接按钮。

### U06 · P2 · 图形更丰富，但容易被理解为能力分数【界面语义风险】

素养雷达实际按候选材料数量并以当前最大值归一化，统计图展示记录或提交数量。虽然已标注“不是能力评分”，雷达轮廓仍容易暗示六维能力。资料数量增加也可能改变其他维度的相对轮廓。

建议：优先用“材料覆盖分布”柱形或矩阵，维度点击后展示具体作品、待评依据与下一次验证任务；若保留雷达，固定刻度并明确单位。无专业量规时继续保留未知，而不是生成分数。

## 五、建议的实施顺序及验收目标

1. **先保证反馈可信与操作一致**：B01、B02、B03、B04、B05。验收包括错误概念/答案泄露对抗集、活动额度前后端一致、同答案跨页面一致、换课证据隔离。先让现有核心活动可靠，不新增功能数量。
2. **再让第一次使用能走通**：U01、U02、U03、U04、U05。对全新账号覆盖“创建项目→输入主题→诊断→确认→开始/切换/恢复”活动。主题输入在首屏可见，每个阻塞都有原因与下一步；需再由真实目标用户做无讲解可用性测试。
3. **最后加强教学闭环与验效**：B06、B07、B08及U06。计划真正安排当前任务；模型决策都有可追溯的执行和结果；课堂可用与生成状态统一；RSI先完成策略暴露与对照验证平台，再谈效果证明。

## 六、本轮证据与限制

- 本轮调用真实 `interaction.validate`，复现引号答案和错误概念可通过；对主题解析、不同目标计划、陪学/复习解析差异执行离线探针。探针位于本机被忽略的 `.local/v17-review/`，不含密钥。
