# 概率追问开发评测集与评价口径

日期：2026-10-17（北京时间）。适用：API 0.11.0 的受限概率追问，提示版本 `probability.followup.v1`。本轮执行“建立开发评测集、验证当前 DeepSeek 追问质量”两项；不自动扩大多轮输入、自由生成或真实学生开放范围。

## 1. 评测目标与样本来源

测量当前模型是否能根据一轮自编表达选出合适的追问方向，并检查结构化输出、原文引用、提示权限和复测一致性。当前学生页面的追问措辞仍取自受限支架，因此不能用本评测声称完成了自由讲解、推理质量评分或教学效果验证。

数据文件：[probability_followup.v1.json](../../seeds/evaluation/probability_followup.v1.json)。

- 24 个主样本，覆盖骰子偶数与摸球颜色两个既有开发练习。
- 覆盖总结果/有利结果计数、等可能条件、比值表达、已有正确思路、含糊表达、无关内容、指令注入、索要评分和虚构身份脱敏探针。
- 提示已使用次数覆盖 0、1、2、3；每次模型追问仍消耗下一层提示，不能突破既有 4 层上限。
- 18 个 development 样本、6 个 reserved 样本。reserved 未用于本轮提示调整，但参考标签公开在仓库，不能称为独立教师盲测。
- 6 个事先指定的关键样本复测一次，共最多预约 30 次。复测样本在模型调用前固定，不按第一次表现临时挑选。

所有输入和参考方向均由开发阶段自编。B09 中姓名、账号和 `example.invalid` 邮箱仅为虚构脱敏探针，不代表真实个人。没有读取、复制或外发当前学生账号的学习记录。

## 2. 参考标签怎么确定

每条样本包含可接受的 `expected_focus` 集合和开发依据 `rationale`：

| 方向 | 开发参考口径 |
| --- | --- |
| clarify | 信息不足、无关或越界要求，先澄清与当前题目有关的思路 |
| sample_space | 基本结果是什么、全部可能结果的计数范围 |
| equal_likelihood | 哪些结果等可能，球/颜色或点数/类别是否被混淆 |
| favorable | 哪些基本结果符合所求条件，有利结果识别与计数 |
| ratio | 已有总数和有利结果数后，如何表达概率比值及依据 |

同一表达可能有多种合适追问，因此允许部分样本有多个参考方向。加载器检查参考方向在当前提示级别下可用，不能把模型不允许输出的方向设成唯一正确项。

**这些是开发参考，不是专业教师金标。** 不匹配先作为待复核案例；经教师复核后可能修订参考、提示或追问集。正式修订另建版本，保留本次数据与结果，不能覆盖原样本来提高原报告分数。

## 3. 指标分开看

| 指标 | 判断方法 | 能说明什么 |
| --- | --- | --- |
| 运行与结构检查 | 生产模型任务状态为 succeeded | 请求完成且现有 JSON/字段校验通过 |
| 原文引用检查 | 非空引用是脱敏后本轮原文的连续片段 | 没有凭空编造该片段；不等于引用充分解释了所选方向 |
| 提示规则检查 | 方向在本轮允许集合内，展示问题与固定支架一致 | 输出没有绕过当前受限动作集合；不等于所有教学安全风险已覆盖 |
| 开发方向匹配 | 以上检查通过，且方向属于参考集合 | 在这一批开发标签下匹配；不是总体准确率或教学效果 |
| 引用长度辅助检查 | 长度至少为 6，短输入则至少覆盖其全部长度 | 发现过短引用的线索；不评价语义相关性 |
| 复测一致性 | 固定 6 对中返回方向是否相同 | 同请求少量复测稳定性；多个可接受方向不同不自动判错 |
| 配对开发匹配 | 两次都满足参考方向 | 比“字面方向完全相同”更接近本轮实际验收口径 |
| 用量与耗时 | 记录实际型号、已知输入/输出 token 与单次请求耗时 | 开发运行观察，不代表正式容量、费用或性能承诺 |

失败、超时、被阻止及结果未知都保留在对应样本分母，不只统计成功返回。用量缺失单独计数，已知 token 合计不能当成完整账单。

## 4. 冻结条件与防止参考泄漏

- 使用原有 `freeze_request`、教学图、模型任务与生产校验器；不写一套更宽松的评测调用协议。
- DeepSeek `deepseek-flash`，关闭思考模式，温度 0.2，最大输出 512 tokens；无自动重试、不发送历史轮次。
- 给模型的内容仅有当前题目、本轮脱敏表达、允许方向和已有提示。样本 ID、参考方向、参考依据、分组和评分结果不进入请求。
- manifest 保存数据文件 SHA-256、题库/提示版本、评测器版本和相关源代码指纹；逐条保存请求摘要、配置 ID、实际返回型号、状态与校验后的结果。
- 本轮不根据第一次输出改写参考标签或生产提示。结果无论是否匹配都保留。
- 评测结果不自动修改 Skill.md、harness 或管理端配置。

## 5. 隔离、额度与中断恢复

独立数据库在 `.local/evaluation/probability-live.sqlite3`，与当前预览库分离；同模式后续运行复用同一个 `eval.synthetic` 模拟来源账号，不能通过重新运行命令重置每日 30 次额度。全站限制仍为 100 次、每次最多 512 tokens。Fake 使用另一份隔离库，不产生外部调用。

每条新建临时空间。前置诊断/练习使用自编题参考数值，以到达指定练习与提示级别；这些自动前置步骤不是学生成绩，不证明学习有效。模型调用使用同一运行器、额度预约和租约检查；按指定 operation ID 执行，避免顺便调用其他待处理任务。

manifest、逐条结果和运行数据库均持久化。明确 `--resume` 时：

- 已保存结果直接读取，不重复请求模型。
- 结果已落库但报告尚未保存时，从原 operation 重建结果。
- pending 可以执行；之前已经领取的 running 只等待租约核对/恢复，过期后保留 unknown，不重新发出请求。
- 数据、源代码或运行模式不一致时拒绝恢复，防止混合不可比较的结果。

真实评测消耗单独开发评测库的额度，不显示在学生预览库的管理账本中；报告明确记录本轮用量。它不代表额外授权真实学生数据或其他厂商调用。

## 6. 如何运行

从仓库根目录运行，默认 Fake，不访问真实模型：

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability.py --max-calls 2
```

真实 DeepSeek 评测显式添加 `--live`，使用已配置的本机密钥；不要把密钥作为命令行参数：

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability.py --live --max-calls 30
```

输出 `.local/evaluation/live-日期时间-标识/` 中的 manifest、逐条 JSON、汇总 JSON 与 Markdown。恢复时使用终端实际返回的目录：

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability.py --live --resume .local/evaluation/<原运行目录>
```

`--publish-prefix docs/评测/<新的报告名>` 可导出新的 `.json` 和 `.md`，不覆盖已有报告。报告仅含自编样本、校验后建议与运行元数据，不导出密钥、完整系统提示或未校验的原始模型正文。

## 7. 后续怎么使用结果

先看格式/引用/规则失败，再复核方向不匹配和复测差异。优先请数学教学人员审核样本、参考方向和追问是否适合；然后增加同义改写、反事实样本、多轮上下文及更复杂表达，另建对照评测。

本轮不建立掌握度、素养或教学成效分数，也不因为样本全部匹配就自动放开自由生成、真实学生或所有数学单元。现有独立检测、数值核验、内容授权与人工复核继续保留。
