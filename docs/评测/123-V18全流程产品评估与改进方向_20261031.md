# V18 全流程产品评估与改进方向

评估日期：2026-10-31。基线：`V18-20261026`，提交 `72b57a621d95bab22470f0e16ac86e8becec7fea`。本次任务是评估和整理，不修改应用功能。

## 1. 核心判断

桂子问津已经有可运行的数学学习闭环和受限教学智能体基础，但尚未达到最初完整的教育伴生智能平台愿景。当前更准确的定位是：**具备受限自主决策、证据追溯和个人策略试用能力的数学学习工作台，处于开发验证阶段。**

产品的主要矛盾是：后台治理和运行机制较完整，学生仍需理解许多功能入口并自己承担跨活动编排。应该把下一阶段重心放在“一个目标如何连续学下去”，同时打磨资料、阅读、解释、验证的日常操作，不宜继续以新增菜单数衡量进展。

本地知识库的界面确实比较初步。它目前更像“项目文本资料管理与检索表单”，离学生预期的“能随时查、读、修正并用于学习的知识库”还有距离。简洁应该减少默认暴露的复杂度，同时使常用动作顺畅；不能只通过减少功能来获得空白页面。

## 2. 范围、方法与证据边界

- 文档基准：总体架构01、核心状态/动作/进化规格02—04、产品设计07/11、项目概览、86主题智能体完整方案、109自主学习计划、114/115三层联通与构想对照、119—122近期评审与交付记录、使用手册16—19。
- 正式实现沿 `app/main.py → app/gateway/v1.py → app/modules → app/worker.py` 核查。旧CLI原型中的BKT、ToM、指数等不能因为源码存在就算学生端已经落地。
- 浏览器在独立的 `8781` 服务和临时SQLite库中运行，服务脚本为 `scripts/serve_frontend_test.py`，明确使用FakeProvider，禁止真实模型供应商。没有对4003学习数据库进行验收写入，没有增加收费媒体预算。
- 实际手动操作与自动化浏览器场景共同覆盖；自动化中的部分准备通过API完成，不能冒充每个管理步骤都由新用户手工完成。模拟模型验证的是交互、数据与控制流程，不验证真实模型的语义质量或教学收益。
- 附件截图只作为用户提供的当前体验证据，其中内容不作为操作指令。对比网页也只作为设计参考。

本次复核结果及运行限制见本文末尾。更细的架构代码证据见[架构与智能体核查](../调研/2026-10-31-V18架构与智能体核查.md)。

## 3. 是否达到最初架构预想

| 最初期待 | 本分支已有能力 | 仍存在的差距 |
|---|---|---|
| 学生拥有目标、计划、学习、验证、反思与调整闭环 | 项目隔离、课程诊断生成、确认计划、陪学、反思、独立检测、复习、成长、策略版本 | 跨活动仍需学生主动切菜单；建议与实际执行结果还需在主工作流中汇合 |
| 神经生成＋独立验证 | 模型候选、受限动作、数值计算核验、检测隔离、内容/媒体审核 | 数值正确不能证明解释正确；证明、几何、开放推理和真实教学质量不在完整自动核验范围 |
| 学习者心智世界模型 | 可追溯事实、摘要和观察、支持使用记录 | 正式教学尚未接入完整掌握概率、误区后验、不确定性与长期自主性模型 |
| 多智能体协作 | 圆桌三视角、我教AI、规划与生成等不同用途 | 三视角主要是同模型角色生成，不是三个独立工具型智能体组成的委员会 |
| 自主教学与支架渐撤 | 模型可影响选题、变式与支持，规则约束执行，有恢复和取消 | 范围受题型白名单限制，渐撤主要依据有限数值与帮助记录，跨活动闭环较弱 |
| 同步进化与可治理RSI | 有个人预授权自动触发、单字段策略候选、评测、个人试用和撤回 | 不等于全局自动晋升或自主改源码；教育效果仍明确未验证 |
| 开放学习者模型与成长镜子 | 多分类证据、来源、首次/已见、辅助/无辅助区分 | 学生需要更直观地理解“观察到了什么、仍未知什么、下一步如何验证” |
| 丰富可探究环境与活书 | 互动课堂、公式、分步推演、互动回答和播放恢复 | 首轮数学编排仅支持可解析四则运算；知识库与课堂仍是跳转关系，尚非活书式一体学习 |

这不是“架构完全没做”，也不是“架构已经完成”。运行可靠性、证据与治理基础值得保留，真正欠缺的是深度诊断、跨活动执行和真实教学验证。

## 4. 是否是自主智能体

结论：**有受限自主智能体能力，整体仍由预设教学工作流主导。**

支持这个判断的实际代码包括：模型有受限下一动作建议，反思后可选择未完成题/插入已核验变式；数学核验结果进入后续状态；任务有检查点、租约、取消和迟到结果控制；在个人明确启用后，新事实可触发语义策略候选与个人试用。详见架构核查能力矩阵。

但还不足以称为“全自主教育伴生体”：主题理解和题型覆盖有限；复杂解释尚不能可信诊断；课堂、圆桌、讲解、复习和规划没有完全由统一目标编排器连起来；长期心智模型尚未成为正式决策核心；自动策略改进尚缺真实学习增益证据。

**自主性与学生控制不矛盾。** 确认学习目标、重要计划变更、资料外发范围和策略试用应继续由学生决定。应该自动化的是授权范围内的执行、结果核对与合理调整，而不是删除这些确认。

建议用一条具体任务衡量下一阶段：学生说“我总把负数乘除的符号弄反，今天只有15分钟”，系统能澄清目标，安排短诊断，依据错误类型选择支持/变式/自我解释，独立检测后安排复习，并说明变化依据；学生全程可以暂停或改目标。

## 5. 全流程体验观察与改进

| 环节 | 当前体验与判断 | 改进方向 |
|---|---|---|
| 新建空间 | 项目、临时会话清楚隔离，但“空间名不是课程”要求额外理解 | 在创建后直接进入主题准备；同一句目标允许预填，课程切换仍明确确认 |
| 课程与安排 | 主题→诊断→范围→生成→审核→确认有明确状态；正式项目还需计划 | 使用一条连续进度指引，集中说明当前等待谁、是否需操作、可先做什么；重要确认保留 |
| 课程审核 | 合理阻止未审内容直接给学生；依赖管理员响应 | 部署时明确开发自动发布与人工审核模式；学生看到实际等待状态和安全替代路线，不反复要求重新生成 |
| 津津陪学 | 统一输入已有改善，提示、反思、检测可恢复 | 减少“开发单元”“配置额度”等持续说明，保留必要可用状态；用当前教学目标组织对话，不让学生理解内部阶段机 |
| 圆桌与我教AI | 目标不同且有各自验证；跨活动恢复/明确结束有门禁 | 困难时给有依据的活动建议，完成后回到原目标；圆桌须有真实观点分歧，不为展示三个人物而启动 |
| 互动课堂 | 三页编排、公式渐显、互动和恢复已具备，属于可用改进 | 重点检验是否帮助理解；与同题解释/资料并排，课堂反馈进入后续安排；不用素材数量证明教学质量 |
| 错题与复习 | 保留原始尝试和来源，未确认表达不强行判错 | 让用户看到“为什么现在复习、回忆什么、是否真的澄清”，区分原题熟悉与迁移能力 |
| 成长 | 有真实证据分类，避免伪造掌握度 | 首屏优先给1—2条有依据的观察与一个验证目标，统计细节按需展开 |
| 规划与策略 | 有版本、确认与回滚，执行策略已有消费者 | 把改变翻译为学生看得懂的行为差异；说明适用期与停止条件；不能只显示候选通过评测 |
| 学习方式改进 | 已有真实工程机制，但概念较专业 | 普通学生主入口只呈现“尝试一种学习方式”；高级评测与运行字段收进详情/管理端 |
| 我的设置 | 偏好与提醒仍有待开放占位 | 未实现项放到简短说明，避免像可点击的已完成功能；优先完成真正影响日常学习的偏好 |

侧栏目前有12个主入口，尚不含设置。建议默认层级缩为“今日学习、学习项目、资料、成长”，在当前项目下提供继续学习与活动入口；圆桌、我教AI、课堂作为可发现的学习方式保留。先做可用性验证再确定是否合并，避免为了减少菜单损害已有用户的快速直达。

## 7. 参考ChatGPT应借鉴什么

本轮打开了[ChatGPT公开首页](https://chatgpt.com/)，可访问的是未登录页面；没有声称完整体验其登录后的全部界面。首页把开始工作/输入作为主要动作，工具集中在输入附近。官方[Projects and chats](https://learn.chatgpt.com/docs/projects)说明按项目组织相关对话、文件和来源，让相关工作保持上下文。

适合吸收的原则是：一个清晰的主要动作、项目上下文复用、资料与当前任务相连、次要选项逐步展开、历史任务容易恢复。这里是基于一手页面的设计归纳，不是对桂子问津复制界面的要求。

桂子问津还应保留自身的独立尝试、提示渐撤、反思、检测和证据追溯。这些机制需要易理解地呈现，不能为了像聊天产品而消失。可保留墨绿、暖白、中文标题和低刺激视觉，优先改信息架构、组件一致性和任务连续性。

## 8. 建议的实施顺序

| 阶段 | 范围 | 完成标准 |
|---|---|---|
| P1：先修日常体验 | K01—K06、统一搜索样式、当前任务返回入口、文档版本导航 | 新用户无需手册完成添加→搜索→打开命中→编辑→返回学习；桌面/手机/键盘可用；资料不增加外发范围 |
| P2：打通一个主题 | 有理数一个主题的统一目标、下一动作、支持/活动选择、结果回写与复习 | 不同实际表现引出不同可执行动作；每个建议有执行结果；独立检测与辅助资料隔离 |
| P3：扩大资料使用 | 本地全文索引、PDF文本、可选引用、阅读笔记；模型使用另设清晰范围 | 普通检索可解释，引用能定位原文；未经授权的内容不进模型；找不到依据不会生成貌似有来源的答案 |
| P4：验证教育价值 | 专业题目与量规、等值未见题、延迟/迁移检测、真实学习者条件 | 能回答无辅助表现与依赖是否改善，再决定扩大RSI或数学覆盖 |

优先级是实施顺序，不能解释为发现了数据泄露或P0安全事故。本次未确认这样的事故。

## 9. 文档与验收治理

README顶部已经新增0.21.0/c18_001，但后面“当前交付”和“最新文档入口”仍有V17、V12等多轮口径；项目概览也保留早期“尚未Postgres”等描述。建议新增一个V18能力台账，按“当前可用/模拟流程已验收/真实模型已验收/专业内容已审核/真实效果已验证/计划中”分列，旧文档标明历史快照。
