## 执行顺序

所有命令均在仓库根目录运行。先只检查，不外发、不发布模型配置、不创建评测账号：

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --check-only
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus holdout --check-only
```

`status=budget_exhausted` 时等待北京时间零点自然重置；`key_missing` 时走原本机密钥维护入口。不要重置计数或更换账号绕过限制。检查返回 `calls_made=0`，不是连通测试。

额度足够后执行基线，先保存实际结果并分析，再执行独立集：

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus holdout
```

两组合计预约 28 次，使用原固定真实评测库/账号和日额度。若当天还有其他预约，完整运行前的检查可能拒绝；实际预约仍由后端事务锁控制。不增加上限或自动重试，不发送真实学生记录。单次最多输出 512 tokens，最多同题 4 轮；输入增加可能提高费用，按服务商账单核对。

若进程中断，使用输出目录恢复，并保持原语料选择：

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --resume .local/evaluation/<基线运行目录>
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus holdout --resume .local/evaluation/<独立集运行目录>
```

恢复校验源代码和语料哈希；未完成运行还核对配置 ID，不重发已完成或已租出的请求。新增代码会使此前运行的恢复检查失败，这是防止混用版本的约束；旧结果文件仍保留，不重写。

1. 保留失败、超时和未知结果及预约，不能从分母删除。分别看运行成功、引用、方向权限和开发参考方向。
2. 查看逐条输入、上一轮关联、返回引用、追问、错误码；报告已新增待复核样本明细。检查引用是否只来自本轮，历史来源是否正确。
3. 对改口场景检查是否仍追旧误区，对矛盾场景检查是否先澄清，对控制组检查是否因前文选择不同方向。格式或白名单通过不能代替语义审核。
4. 不符合开发参考时先复核参考是否合理，标记“模型方向不合适 / 参考有歧义 / 需教师判断 / 运行失败”，不能仅凭枚举不相同断言教学错误。
5. 若需改提示，新增版本及变更理由，保留本版。基线用于定位，独立集用于一次性复测；看过独立集并据此调整后，它也成为开发集，需要再建未使用样本。没有真实失败证据前不为 Fake 的恒定输出调参。
