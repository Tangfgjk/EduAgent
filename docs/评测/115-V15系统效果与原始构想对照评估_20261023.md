# V15 系统效果、测试与原始构想对照评估

日期：2026-10-23。对象：`V15-20261020` 本地工作区，包含尚未提交的三层智能体改动；Git 基点 `5354f70b1c9ca2f2942733fbd59be5d2840f2cf8`。主服务 4003，数据库契约 `r14_003`。

## 1. 结论

**已经形成可以演示和继续开发的教育 Agent 工程原型，尚未达到完整自主初中数学产品，以及经教学效果验证的自进化系统目标。**

现在不能再简单称为“模型只选固定模板”：新通用互动中，模型确实生成追问原文，程序保留通过检查的原文；变式也会被独立计算并插入实际学习流程。旧数据、离线降级和部分规则支持仍保留固定内容，这不等于全部已动态化。

但“能生成、能运行、可追溯”还不等于“解释正确、路径最适合学生、确实提高学习效果”。本轮发现可复现的答案泄露检查绕过、活动额度显示不一致和换课证据混用问题。跨模块目标共享已建立，自动教学决策闭环仍不完整。

本次只增加评估文档与索引，没有修业务代码、迁移数据库、改模型配置或提交推送。测试使用隔离账号/数据库及模拟 Provider；没有新增付费模型或媒体调用。

## 4. Standards：代码质量与正确性复查

未找到适用于本次差异的 AGENTS.md/CONTRIBUTING 等专门编码规范；未据一般风格偏好判定硬性违规。以下是实际行为问题，P2 表示需要修复但未观察到系统整体不可用。

### S1 · P2：引号可绕过直接答案检查

位置：`app/modules/generation/grounded_response.py:29`。

检查先删除所有中文引号内容，再匹配“答案是”等模式，却未确认被删除文字确实来自学生。学生只输入 `help with signs`，独立 `quote` 为 `help`，模型问句为 `“答案是3”，你知道为什么吗？`，完整 `interaction.validate` 仍接受。

影响：当 3 恰为当前题答案时，会违反本应先让学生思考的目标。独立检测门禁仍然存在；本探针不是已证明独立检测可以调用模型。

改进：只豁免核对过的真实学生引用；检查剩余内容及引用是否夹带新增答案，加入措辞、引号、中文数字、分数和完整解法的对抗样本。

### S2 · P2：活动用尽额度后仍展示可聊天

位置：`learning/tutor_service.py:29–32` 与 `infrastructure/runtime/model_tasks.py:212–214`。

接口公开状态只判断每日额度及 `can_hint`，实际预约还限制整个 run 最多三次通用模型请求。隔离 API 实测三次成功后 `coaching_available=true`、`can_hint=true`；第四次提交返回 429 `activity_budget_exhausted`，且错误被标为 `retryable=true`。换到下一题并不会重置整个 run 的次数。

改进：公开每日/活动两类剩余量和耗尽原因，界面禁用不可执行动作并保留预设支持；将确定耗尽和暂时限流区分。若未来需要更长对话，单独调整活动预算设计，不能靠前端隐藏错误或无限调用解决。

### S3 · P2 能力边界：文字数学错误可通过

位置：`generation/grounded_response.py:32–35`。

`负数除以负数一定为负，你能说明依据吗？` 通过当前检查。显式等式核验能处理部分算术表达，无法验证任意中文概念陈述；有问号、真实 quote 不代表数学内容正确。

改进：建立概念规则与错误概念对抗集、逐题族内容质量评价和失败分类。涉及学生理解时保留未知，不用另一个模型的赞同代替独立真值或教师评阅。现有数值核验继续独立执行。

## 5. Spec：设计符合度复查

### P1 · P2：旧课程证据混入当前目标

位置：`learning/goal_context.py:19–30`；对应 109 号 R04/R06 的目标适配与来源正确性。

最近六条事实只按项目及来源过滤，未区分当前单元/课程版本；外发时也不标注每条事实所属单元。隔离探针在已有有理数事实后，将绑定更新为概率课程，快照的主题变为概率但仍携带旧内容版本事实。

这是同项目的语境混用，**不是跨账号泄露**。项目历史可以保留，但应标明“当前目标证据”和“历史背景”，由可追溯映射判断适用性，不能默认旧题通过等于新目标表现。

### P2 · 目标共享不等于决策闭环

`planning/service.py:232` 冻结了 handoff 决策，但 `planning/model.py:61` 使用 `goal_context.external(...,False)`，只保留主题等元数据，丢弃最近教学决策；模型仍能读取既有事实来源，但不能直接承接这次教学调整的理由。

`generation/interaction.py:75–78` 的资源选项主要是种类和可用标记，没有具体资源身份、概念、适用困难；模型说“看资源”后主要提供课程入口，而非执行“选定资源→完成活动→评估帮助→更新安排”。114 号也将其限定为建议入口，不能宣称完整自动资源调度已实现。

改进：建立具备来源和有效期的决策交接契约，传递当前目标下最近有效决定及实际结果；资源用具体 ID、适用概念、权限和完成事件联通。付费生成仍需独立预算，不能自动绕开关闭状态。

### P3 · 调度可变化，但仍是受限课程骨架

`learning/tutor_graph.py:111–116` 仍遍历所有原有练习，`adaptive.py:81–88` 最多补两题。渐撤主要依据数值通过、提示次数与受限建议；当前尚没有经验证的语义误区分类、先修补救与掌握证据模型。

这是安全原型中有意义的真实变化，不是完整的目标驱动重规划。六类数值题族和有理数专用形式不等于覆盖七至九年级常见单元；二次函数、几何证明、图形理解等仍不能全面完成。

### P4 · 深度学习者模型与教学效果 RSI 仍待验证

原始架构 §1、§4 要求可校准学习者状态、真实无辅助后测与自主性增益。当前 `memory/projections.py:52` 明确只提供观察、不使用未经校准 BKT，这比伪造掌握度正确，但远期目标仍未交付。

RSI 已有模型语义候选、单项受限策略、实际消费者、影子机制评测、个人试用和撤回。`evaluator.exercise`、`shadow` 主要运行脚本样本和机制不变量；签名包含新模块不等于样本实际评价了新生成问句、变式教学质量及学习增益。效果平台存在也不等于已经开展有效研究。

## 7. 使用体验复查

聊天截图显示，手机 390×844 下题目与输入框前有空间卡、课程选择、标题、说明和状态等较多内容，学习主操作在首屏以下；桌面也存在相似层叠。成长页本轮完整截图为 1440×9197，图形、摘要、来源与事实长列表同页展开，阅读成本较高。

这些截图是固定测试状态，不代表所有真实用户都遇到相同困难；自动“无横向溢出”测试不能证明易用性。

建议：学习时将“当前题—最近一轮—输入—下一步”放在主区域；课程和开发说明折叠；自动滚动只在符合阅读意图时触发；成长页先给摘要和行动，图形与原文分层钻取。内部 action/support 枚举改为学生可理解文案。用新用户首任务实测操作数与完成时间，而非只凭截图判断。

## 8. 建议下一轮按三步推进

### 第一步：修复明确缺陷，补充失败测试

修 S1、S2、P1：引号答案绕过、活动额度可用状态、换课证据混用。补相同项目跨课程、活动额度耗尽与取消、引用/中文数值/错误前提的回归。

验收：上述四个负向现象按预期阻断或明确分层；正常原文引用仍可用；耗尽时学生仍能作答/获得已有支持；旧历史仍可查，不误归新目标。

### 第二步：完善真实教学决策与体验

将决策 ID、原因、适用目标、资源身份和实际活动结果传入规划与 RSI；教学调度按当前困难选择补练/资源/自测，说明为何继续或恢复支持。完成主任务首屏与成长分层。

建立真实 DeepSeek 多轮自编样本集：相同错误不同表达、纠正前后、重复追问、否定、长文本、请求变式、数学概念错误与泄露攻击；分别记录契约成功、内容正确性、针对性、诱导风险、耗时和 tokens。不要只以 JSON 合法率验收。新费用/数据范围超出既有授权时再确认。

验收：每个调度决定可追溯到本目标证据与消费者结果；资源建议能定位具体可用内容，失败有清晰替代；展示真实模型多轮报告及全部失败样本。

### 第三步：扩大内容并开展效果验证

按知识点逐项补覆盖和独立核验；建立教师审阅量规与保留评价集；条件具备后开展经同意的小规模研究，区分辅助答对、无辅助表现、延迟保持和迁移表现。同步验收部署、备份恢复、数据管理、队列压力与成本对账。

RSI 先保持个人开发试用。只有真实结果及独立评阅支持时，才讨论“哪种策略对谁更有效”的晋升；没有数据时保持待验证。真实媒体另按服务与预算批准后验收。
