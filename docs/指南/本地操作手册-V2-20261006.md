## 启动

在 PowerShell 进入 `platform`，执行 `.\.venv\Scripts\python.exe -m app.main`。服务仅监听 `127.0.0.1:8000`；打开 <http://127.0.0.1:8000/>，未登录会进入本地登录页。原 main 分支深色工作台在 `/` 和 `/learning`，静态原型保留在 `/prototype`。密码只存在被忽略的 `platform/.env.local` 与本地配置文档，不要写入 URL、终端历史、截图或提交。

## 日常流程

新机器需要 Python 3.11 或更高版本，安装 uv 后在 `platform` 执行 `uv sync --locked --extra dev` 恢复依赖；不要上传本机 `.venv`。完整包版本和许可证见[环境依赖记录](本地开发环境与依赖记录-20261006.md)。

新机器默认不启用登录，需在忽略的 `.env.local` 自行配置 `RSI_LOCAL_AUTH_ENABLED=true` 和密码散列 `RSI_LOCAL_AUTH_PASSWORD_HASH`；散列用 `app.gateway.security.hash_password` 生成，不填明文。教师/家长凭据分别是 `RSI_LOCAL_TEACHER_TOKEN`、`RSI_LOCAL_PARENT_TOKEN`。本机既有凭据见忽略的 `docs/本地配置/数据库与登录-20261006.md`，不会随 V2 克隆。优先级为真实环境变量 > `.env.local` > `.env`。

1. “授权”页确认教学用途；研究和自动进化用途默认关闭。
2. “学习”页提交独立作答；提示或答案暴露必须如实标记。
3. “证据”页查看 Evidence、掌握/保持状态和来源；“复习”页完成到期回忆。
4. “计划”页建立目标并查看路径，采纳只生成草案，学习者签署后才生效。
5. 教师先读取作品，再选择匹配 Rubric；修正会产生恢复任务和 `proposed` 计划，不会自动签署。
6. 家长看板只返回汇总，角色协作只返回候选，不写掌握状态。

撤回教学授权会清理页面内容并阻止后续读取，但保留不可变审计事实。

## 测试与浏览器验收

### 会话、项目和家校共享

- 开始会话后保留页面的 Session ID。刷新后输入并点击“恢复会话”；旧版本未持久化的会话不能伪造恢复。
- 项目可添加任务、修改状态、关联 Evidence/Session/来源 ID。保存产生新 revision；冲突时刷新后再修改。归档不删除学习证据。
- 授权页明确选择教师、家长或不共享，再使用用途凭据查询。重新授予教学授权后需重新确认共享；登录本身不是教学同意。
- 学习者可按 Evidence ID 申诉。教师纠正后选择恢复任务并明确执行，失败可以重试；同任务不会重复产生计划。

### 知识与协作

- 按当前知识点检索，查看引用候选的原文、版本、页码或行号。
- 导入文件须在 `platform/seeds/knowledge/`，界面填写相对文件名、来源编号和 OCR 选择；扫描 PDF 在本地解析，不读取任意电脑路径。
- 刷新并选择有效证据，再填写作品、角色和预算。离线模板与配置模型分别标识。
- 圆桌和虚拟学生建议不算真实学习者证据，不自动修改掌握；超预算时应等待，不能伪造身份绕过。

### 回归命令

在 `platform` 执行：`.\.venv\Scripts\python.exe -m pytest -q`、`.\.venv\Scripts\python.exe -m pip check`、`.\.venv\Scripts\uv.exe lock --check --cache-dir .uv-cache`、`.\.venv\Scripts\python.exe -m compileall -q app scripts`、`git diff --check`。浏览器验收执行 `scripts.browser_fixture` 和 `scripts/browser_smoke.cjs`；脚本只接受 localhost，使用独立内存库和合成身份，截图写入被忽略的 `platform/data/browser-acceptance-20261006/`。验收后停止 fixture，不要复制临时库覆盖正式数据。

## 数据与归档

浏览器验收先在终端 A 执行 `.\.venv\Scripts\python.exe -m scripts.browser_fixture`；终端 B 设置 `EDU_PLAYWRIGHT_MODULE` 为已安装的 Playwright 路径，`EDU_CHROME_PATH` 为本机 Chrome 路径，再执行 `node scripts/browser_smoke.cjs`。本机使用应用捆绑包，路径记录在[环境依赖记录](本地开发环境与依赖记录-20261006.md)。新机器可在独立工具目录安装 Playwright，不修改应用运行依赖。两个终端均在 `platform`，结束 fixture 时按 Ctrl+C。

主运行时仍是 `platform/data/rsi.sqlite3`。备份使用 `python -m app.storage.archive_cli sqlite-backup data/rsi.sqlite3 data/backups/rsi-backup.sqlite3`，目标必须是新文件。PostgreSQL 只用于独立证据归档/恢复，默认 `127.0.0.1:5433`，可用 `health`、`export`、`restore` 子命令；生产主存储尚未切换。默认课程含合成资产，标记为 `synthetic_ai_generated`/`demo`/`not_real_evidence`，真实课程通过 `RSI_LEARNING_CATALOG_PATH` 和 `RSI_LEARNING_CATALOG_OVERLAYS` 替换。

## V2 提交和推送

提交前执行 `git status --short`、`git branch --show-current`、`git diff --check`，确认 `.env.local`、`docs/本地配置/`、`platform/data/` 和运行日志没有进入状态。切换、提交、推送依次执行：`git switch V2`、`git add -A`、`git commit -m "feat: complete local learning loop and V2 workbench"`、`git push -u origin V2`。若远程已有 `V2`，先 `git fetch origin V2` 检查差异，不使用 `reset --hard`。

真实 Provider、真实课程和效果校准、正式多租户、PostgreSQL 主存储、生产队列 worker、神经语义检索仍未完成；自动 RSI 和数字孪生继续关闭。

## 故障与停止

- 查看监听：`Get-NetTCPConnection -State Listen -LocalPort 8000,5433`。前台服务 Ctrl+C 停止；后台只终止核实属于本项目的 PID。
- 页面 401：到 `/login` 重新登录；403：检查教学授权、共享版本和用途凭据。
- 来源 409：文件 SHA 已改变，重新导入新版本；不要复用失效引用。
- 8000被占用时，当前终端设置 `$env:RSI_PORT='8001'` 后启动，浏览器也改端口。
- 备份目标存在时换新文件名，不覆盖；归档失败先保留源数据库。
- 测试失败保留命令、时间和输出，修复后先重跑对应测试，再跑全量。
