# V4 功能操作与技术参考

更新时间：2026-10-06（Asia/Shanghai，UTC+08:00）。适用分支：V4；从已发布 V3 基线进行用户授权的本地收口，P0已完成。锁同步后冻结全量824 passed、2 warnings、无skip（71.14秒），隔离工作台20个流程与桌面/手机视口通过；实现已提交推送V4，提交30f262c的远端CI已实际通过，见[最终验收记录](../测试/V4最终集成验收与发布记录-20261006.md)。本文把当前已实现的功能、入口、实现位置和限制放在同一处。

## 0. 边界

当前系统是本地研究型 MVP。它可以验证“作答 → 验证 → 证据 → 掌握/保持 → 路径 → 教学动作 → 新证据”的软件闭环；它不能证明真实教育效果、真人参数校准、教师课程批准、生产多租户、完整 PostgreSQL 迁移或学校 SSO 已完成。合成学习者报告始终使用 synthetic_ai_generated；远程模型没有配置时使用离线模板。

普通学习工作台与个人本地 SQLite 运行在 8000；仿真实验室使用独立 loopback 端口（默认 8001）；学校研究实例使用独立 root 和端口（默认 8012）。不要混用三个实例的数据库、凭据或输出目录。

## 1. 启动与身份

### 普通学习工作台

在仓库根目录执行（PowerShell）：

    cd platform
    .\.venv\Scripts\python.exe -m app.main

浏览器打开 http://127.0.0.1:8000/。若 RSI_LOCAL_AUTH_ENABLED=true，先在 /login 登录；密码只以 PBKDF2 散列存在被忽略的本地配置中。GET /api/auth/status 可检查会话，POST /api/auth/logout 退出。不要把密码、cookie、token 或 .env.local 放入文档、截图或 Git。

### 配置来源

app/config.py 的 Settings.load 按进程环境 > .env.local > .env 的优先级读取配置；同一来源 WENJIN_* 优先于历史 RSI_*，显式空值也覆盖低优先级值。因此进程 RSI_* 仍优先于文件内 WENJIN_*；旧配置不需要立刻重写。新配置推荐 WENJIN_DB_PATH、WENJIN_LEARNER_ID、WENJIN_LOCAL_AUTH_*、WENJIN_ASSESSMENT_REQUIRE_TICKET、WENJIN_LEARNING_CATALOG_PATH 和 WENJIN_LLM_*。正常 Settings.load 默认开启服务器派题凭据；测试夹具才显式注入特例。未配置模型 key 时，Provider 列表显示离线模式。

## 2. 学习者工作台

入口是 / 或 /learning，页面文件是 platform/web/learning.html，样式与交互拆分在 platform/web/workbench/；路由组合在 platform/app/gateway/routes.py、workbench_routes.py、learning_routes.py、dashboard_routes.py 和 qualitative_routes.py。保留原深色风格，六个顶部视图为“陪学、计划、复习、成长证据、设置、圆桌与探究”。教师凭据、Rubric 评审、来源导入和恢复队列不放在学生表单中。

| 功能 | 学习者操作 | 服务端实现与结果 |
|---|---|---|
| 教学授权 | 在“设置”页保存或撤回教学用途 | consent 端点写入带版本授权。撤回后学习、证据、状态和看板读取被阻断；重新授权不会复活已撤回用途。 |
| 选择资产 | 在“陪学”页选择知识点和评测任务 | learning/config 和 learning/assets 从版本化 AssetCatalog 读取题目、KC、Rubric 和提示。 |
| 初诊 | 点击“开始初诊” | diagnosis/next 根据证据、预算和目录蓝图选择任务；资产不足时返回缺项，不随机编题。 |
| 作答验证 | 页面先取题目再提交答案 | assessment/issue 返回内容 hash、版本、有效期和 delivery_ref；submit 验证 ticket、attempt、作答和时间。 |
| 提示 | 点击“请求提示”后再作答 | hint 追加援助历史；hint_level、assistance_mode、answer_exposed 固化到 Evidence。 |
| 会话 | 开始会话，输入作答或消息，刷新后用 Session ID 恢复 | SessionRuntime 编排 5E、Governor、Verifier、快照和审计；相同 attempt 重试返回稳定收据。 |
| 目标与计划 | 输入目标，查看路径，采纳草案，最后签署 | contracts 建立目标；path/recommend 只给建议；plans/sign 才使版本生效；AI 不能代签。 |
| 项目与任务 | 在“计划”创建项目/任务并引用 Evidence/Session/来源 | WorkspaceService 以 revision/CAS 保存，引用受当前学习者权限和目录约束。 |
| 掌握与保持 | 在“成长证据”查看状态和指标，在“复习”查看到期队列 | LearningService.consume 同事务更新 Evidence、Mastery、Retention、Transition、快照和收据。 |
| 定性作品 | 学生提交解释作品，教师在 /teacher 读取并追加 Rubric | artifact 先保存 unverifiable 待评作品；教师 review 追加 supersedes 记录，不能由 AI 代签。 |
| 申诉与恢复 | 学生在“设置”选择证据并说明理由；教师复核后由 /research 操作恢复 | Appeal 和 RecoveryJobs append-only；恢复不能自动改写历史。 |

### 独立职责入口

| 入口 | 本地职责 | 访问与边界 |
|---|---|---|
| /teacher | 教师作品读取、Rubric 与追加纠正 | 输入已有本地教师 token；操作后清空表单，不在学生页保存凭据。 |
| /parent | 家长学习摘要 | 输入已有本地家长 token；操作后清空，只读汇总，不加载原始 Evidence。 |
| /research | 本地来源导入、OCR 选项、恢复队列与明确运行 | 面向当前授权本地操作人；不是学校研究员 RBAC 或 SSO。 |
| /docs | OpenAPI 交互文档 | 用于受权限约束的 API 检查，不替代面向学习者的页面。 |

上述入口是同一本地实例内的职责界面分离，不等于学校租户、身份联合或生产权限系统；学校 8012 实例单独配置。

### 闭环内部顺序

1. 路由校验 learner、授权、题目版本、attempt 和 delivery ticket。
2. SessionRuntime 读取快照和目录，策略提出候选动作。
3. ActionGovernor 执行 R-01 等硬约束；直接给答案会改写为提示或规则解释。
4. Verifier 生成 Verdict，record_attempt 固化援助和来源。
5. LearningService.consume 通过 CAS 和 receipt 处理重复提交及并发冲突。
6. 状态、保持和路径只消费有效证据；撤回或 superseded 记录不能重新成为有效依据。

## 3. 证据、指标与记忆

- LearningEvidence 是一次可追溯作答、作品或教师纠正，关联 learner、KC、assessment 版本、attempt、verdict、援助、授权和时间。
- MasteryState 与 RetentionState 是派生状态，不是学生固有标签；replay 可从有效 Evidence 重建。
- learning/metrics 提供前后、迁移和延迟窗口描述性比较；发展指标把认知变化与自主行为拆开，并固定 not_an_effect_claim=true。
- memory/rebuild 重建受授权学习记忆；人工澄清/撤回由内部 Memory service 执行。
- teacher corrections 是追加纠正，不删除原 Evidence；必须保持 learner、attempt、KC 身份不变。

“成长证据”的四张图使用当前有效证据和已形成状态：BKT 重放轨迹、每题首次独立表现累计通过率、累计辅助比例、逐 KC 掌握估计条图；保持状态在同区域单独用文本展示，不是条图数值。撤回/纠正后按有效证据重算，首次独立样本保留原首次作答血缘，不能因纠正而把后续重试升级为首次独立表现；空数据保留空状态。它们不是原始持久化的历史时间档案，不用随机演示分数、不虚构 Bloom/FSRS，也不证明教学效果。

## 4. 知识检索与协作

学习者入口是“圆桌与探究”；来源导入放在 /research。

| 功能 | 操作 | 实现与限制 |
|---|---|---|
| 知识检索 | 输入问题和 KC，选择 BM25、hashed_lexical、vector 兼容别名或 hybrid | LocalRetrieval 只在固定本地根目录检索；结果带 source/version/chunk/citation；没有神经 embedding。 |
| 来源导入 | 本地操作人在 /research 填相对文件名、source ID、KC，可勾选 OCR | knowledge/import 拒绝绝对路径、越界路径、KC 越界和 source 重绑。 |
| 单角色建议 | 选有效 Evidence、角色和 Provider | roles/review 只返回 candidate report；每天有 turns/tokens/hints 预算，模型不写学习状态。 |
| 三角色圆桌 | 选择角色后召开 | roundtable 组合候选报告，未验证 agreement；不自动签计划或改掌握。 |
| 教虚拟学生 | 输入讲解并提交 | teach-student/lesson 使用固定模板或受控 Provider，固定 no_learning_state_write=true；它不同于 Simulation Lab。 |
| 策略卡 | 查看当前 KC 策略 | strategies 返回 candidate_only，激活需人工审核。 |

governance 路由可检查 source hash、chunk、KC 和 Governor 约束；provenance check 只做候选检查，不执行动作，也不证明语义为真。

## 5. 仿真实验室

启动：

    cd platform
    .\.venv\Scripts\python.exe -m app.simulation.lab --port 8001 --output-root data/simulation

打开 http://127.0.0.1:8001/。页面选择画像、场景、seed 和回合预算后运行；完成后查看报告/结构化轨迹或下载 JSON。新增四张分析图直接读取真实生成的 report/transcript，不把缺失值当零；跨运行比较需满足画像、seed、预算、课程/引擎/画像版本与状态一致性。服务只接受 loopback、同源请求和当前进程 nonce；一次只运行一个作业，HTTP 不能指定 output root。

实现位于 simulation/lab.py、runner.py、learner.py、renderer.py、durable_jobs.py。每次运行独立保存 SQLite、课程/题库快照、manifest、latent、transcript 和 report；隐藏状态不进入真人 Evidence。常用命令：

    .\.venv\Scripts\python.exe -m app.simulation.runner --profile autonomous --scenario baseline --seed 17 --turns 10
    .\.venv\Scripts\python.exe -m app.simulation.experiments --turns 20 --seeds 17 29
    .\.venv\Scripts\python.exe -m app.simulation.assessment --profile autonomous --seed 17

学习增益、逐 KC 状态、提示依赖、Brier/Wilson 和配对差异是合成模型内的描述性结果，不能写成真人认知真值、因果效果或生产吞吐。

## 6. 学校独立研究实例

学校实例是独立 root、独立目录、独立 SQLite 的本地 MVP，不是生产 SSO。创建和启动：

    .\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo provision --tenant demo-school --class-id class-g7 --username learner-demo --role student --learner-id demo-school-learner
    .\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo provision --tenant demo-school --class-id class-g7 --username teacher-demo --role teacher
    .\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo provision --tenant demo-school --class-id class-g7 --username parent-demo --role parent
    .\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo serve --port 8012

创建账号时密码由 CLI 隐藏输入；不要在命令行或文档填写密码。教师/家长必须先关联同租户、同班级，学生再通过 sharing 明确开启共享。教师读取需要关联、当前教学授权和学生共享；家长只能读取汇总，不返回原始答案或 Evidence 引用。完整 SSO、机构关系、正式监护审核和教学前端仍未完成。

## 7. 课程审核、测量与校准

    .\.venv\Scripts\python.exe -m scripts.course_review --build data/course-review.json
    .\.venv\Scripts\python.exe -m scripts.course_review --check data/course-review.json
    .\.venv\Scripts\python.exe -m scripts.course_review --pilot-check data/pilot-protocol.json

课程包包含来源许可、版本/hash、KC/先修、测量蓝图、提示/误区和 Rubric。review_status=pending 不能改成 approved 冒充教师签名；内容变化产生新 hash 并使旧批准失效。learning.calibration 只生成错误率、Wilson 区间和参数候选，promotion_gate 只返回 blocked/manual_review_required/candidate_ready_for_manual_activation，自动晋级和参数写回永久关闭。

## 8. Repository、备份与 Worker

LearningService.for_repository 可接 SQLite 或独立 PostgreSQL 学习域 Repository。PG 使用受控 schema、JSONB、事务、CAS、receipt、outbox 和数据库锁；8000 正常运行仍为 SQLite，不是“有 DSN 就全平台 PG”。

    .\.venv\Scripts\python.exe -m app.operations.cli --database data/rsi.sqlite3 --learner-id demo_student_001 health
    .\.venv\Scripts\python.exe -m app.operations.cli --database data/rsi.sqlite3 --learner-id demo_student_001 backup --root data/backups --filename rsi-20261006.sqlite3 --policy-id local-backup-v1 --policy-approved
    .\.venv\Scripts\python.exe -m app.operations.cli --database data/rsi.sqlite3 --learner-id demo_student_001 worker --max-jobs 10 --max-attempts 3 --deadline-seconds 10

恢复始终写入新的隔离目标，带 quarantine 和空 Consent；不能覆盖现有库、切换运行中的服务或复活旧授权。PG export/restore 需要受控 DSN，错误输出不回显凭据。

浏览器验收使用 Playwright/Chrome。在仓库根目录运行 `node platform/scripts/v4_browser_smoke.cjs`：脚本自行启动隔离 8132 fixture，生成随机测试凭据，不读取 .env.local，不需要手工先启动旧 fixture。可用 EDU_QA_PORT、EDU_QA_PYTHON、EDU_PLAYWRIGHT_MODULE、EDU_CHROME_PATH 指定本机环境；端口必须空闲。实验室另用 `node platform/scripts/simulation_browser_smoke.cjs` 检查。检查桌面/手机视口、原黑色主题、六个标签、职责入口、四成长图、无横向溢出和 page errors。截图写入被忽略的 platform/data，不要对 8000 个人数据做压力测试；旧 browser_smoke.cjs 仅保留为历史 V3 验收。

V4 使用 Ruff 0.15.7、mypy 1.19.1、pytest-cov 7.0.0 增量工程门。严格类型仅覆盖 clock、migrations、trigger_state 三个模块；SQLite 基础 Store/trigger 状态有版本化事务迁移并拒绝未知新版本，不等于全平台数据库迁移。完整仓库类型、完整契约及生产迁移仍需独立验收。

上述三个模块 Ruff/strict mypy 已通过；9项基础/OpenAPI专项通过，模块覆盖率96.30%，门槛85%。安装统一 uv sync --locked --extra dev --no-editable，避免 Windows 中文路径 editable .pth 的 GBK 解码失败；uv run 使用 --no-sync 避免重新同步成 editable。完整命令、依赖变化与未覆盖范围见[V4工程验收](../测试/V4工程基础与增量质量门验收-20261006.md)。

仿真浏览器脚本不会自启 Lab，会实际创建实验；先独立启动隔离端口/输出目录，再通过 EDU_QA_URL 指向它，具体命令见[V4本地操作手册](V4本地最终操作手册-20261006.md)。比较口径不匹配时标为非配对比较，不把两个实际报告解释为因果效果。
