## 一、开始前

请确认使用 Python 3.11、`platform/.venv` 和锁定依赖。普通工作台、仿真实验室、学校实例使用不同端口和数据目录，不能把个人工作台数据库拿去做实验或学校测试。不要在命令行、截图、文档或 Git 中输入密码、token、DSN、API key。

依赖安装统一使用 `uv sync --locked --extra dev --no-editable`，避免 Windows 中文路径下 editable `.pth` 的 GBK 解码问题；运行保持 `platform` 为工作目录。新增dev包及环境同步说明见[V4工程验收](../测试/V4工程基础与增量质量门验收-20261006.md)。

## 二、启动普通学习工作台

在仓库根目录打开 PowerShell：

```powershell
cd platform
.\.venv\Scripts\python.exe -m app.main
```

浏览器访问 `http://127.0.0.1:8000/`。登录开启时先访问 `/login`，登录后进入学习工作台。第一次使用按以下顺序操作：

1. 打开“设置”，明确保存教学用途授权。
2. 打开“陪学”，选择知识点；需要初诊时点击“开始初诊”。
3. 题目出现后独立作答；需要帮助时点击“请求提示”，不要把得到提示的作答当作无辅助表现。
4. 查看验证结果和证据；需要继续学习时查看“掌握与保持”和“到期复习”。
5. 在“计划”建立目标、查看路径建议、采纳草案；确认内容后由学习者自己签署。
6. 在“计划”的“学习项目”记录任务并引用 Evidence/Session/来源；左侧切换已保存项目。引用缺失或已撤回的记录会被拒绝。
7. 退出前使用页面“退出”或 `POST /api/auth/logout`；不要直接复制浏览器 cookie。

### 常见工作流

- **普通练习**：选择题目 → 独立作答 → 验证 → 查看提示/反馈 → 再次作答 → 在“成长证据”检查援助标记。
- **复习**：打开“复习” → 只提交当前到期任务 → 查看新证据和保持状态。
- **定性作品**：选择解释题 → 提交作品 → 等待教师 Rubric 评审；作品在评审前不会改变掌握。
- **教师纠正**：教师打开 `/teacher` → 输入已有教师 token 与 Evidence ID → 阅读作品 → 追加 Rubric/纠正；凭据每次操作后清空。恢复操作人在 `/research` 查看队列并明确执行恢复任务。
- **家长摘要**：学生在“设置”允许相应共享；家长在 `/parent` 输入已有家长 token 后读取汇总；不读取原始答案或 Evidence。
- **申诉**：在“设置”选择要复核的作答并填写理由；申诉不会删除原记录，只会创建待处理记录。
- **撤回**：在“设置”撤回教学用途；页面会清理当前学习视图，后续读取被拒绝。
- **知识与协作**：在“圆桌与探究”检索来源、请求角色候选/圆桌报告或向虚拟学生讲解。来源导入与 OCR 只在 `/research` 操作。

六个顶部标签为“陪学、计划、复习、成长证据、设置、圆桌与探究”，保留原深色风格。成长区四张图展示当前有效证据重放 BKT、首次独立表现、辅助比例和逐 KC 掌握估计条图；保持状态另用文本展示。无数据不会伪造曲线，图不是原始历史档案或真实教育效果。教师/家长/研究入口仅是本地职责分离，不等于学校 RBAC/SSO。

## 三、运行仿真实验室

另开 PowerShell，不要停止正在使用的 8000 服务：

```powershell
cd platform
.\.venv\Scripts\python.exe -m app.simulation.lab --port 8001 --output-root data/simulation
```

访问 `http://127.0.0.1:8001/`。选择画像、场景、seed 和回合预算后点击“开始运行”。作业完成后可查看状态、报告、结构化轨迹、四张分析图，或下载 JSON。比较不同运行前检查画像、seed、预算、课程与模型版本及状态一致；不兼容或缺字段时标为非配对比较，不能据此推断策略效果。停止只在回合间生效；预算停止/超时且存在检查点时可以使用“恢复运行”。

命令行实验适合批量复核：

```powershell
.\.venv\Scripts\python.exe -m app.simulation.runner --profile autonomous --scenario baseline --seed 17 --turns 10
.\.venv\Scripts\python.exe -m app.simulation.experiments --turns 20 --seeds 17 29
.\.venv\Scripts\python.exe -m app.simulation.assessment --profile autonomous --seed 17
```

仿真输出位于被忽略的 `platform/data/simulation*` 目录。它们只用于检查软件闭环、策略敏感性、恢复和候选预校准，不得导入真人 Evidence，不得改写生产参数，不得写成教育效果。

## 四、创建独立学校研究实例

学校实例需要单独 root，示例：

```powershell
.\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo provision --tenant demo-school --class-id class-g7 --username learner-demo --role student --learner-id demo-school-learner
.\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo provision --tenant demo-school --class-id class-g7 --username teacher-demo --role teacher
.\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo provision --tenant demo-school --class-id class-g7 --username parent-demo --role parent
.\.venv\Scripts\python.exe scripts/school_instance.py --root data/school-demo serve --port 8012
```

创建账号时密码由隐藏输入读取。拿到账号 ID 后，用 `assign` 把教师或家长关联到同租户、同班级；学生还必须在自己的 `/sharing` 端点显式打开共享。教师看详细证据需要关联、当前授权和学生共享；家长只看到汇总，不看到原作答和 Evidence 引用。这个实例没有公开注册、学校 SSO 或完整课堂前端。

## 五、课程审核和研究准备

构建和检查课程草案：

```powershell
.\.venv\Scripts\python.exe -m scripts.course_review --build data/course-review.json
.\.venv\Scripts\python.exe -m scripts.course_review --check data/course-review.json
.\.venv\Scripts\python.exe -m scripts.course_review --pilot-check data/pilot-protocol.json
```

检查通过只表示结构和仿真准入通过。`pending` 课程必须由真实教师审核，不能手动编辑 JSON 假造 `approved`。真实学习者招募还需要研究/监护授权、身份隔离、数据保留和删除政策。

## 六、备份、恢复和健康检查

健康检查和备份都针对明确的数据库路径：

```powershell
.\.venv\Scripts\python.exe -m app.operations.cli --database data/rsi.sqlite3 --learner-id demo_student_001 health
.\.venv\Scripts\python.exe -m app.operations.cli --database data/rsi.sqlite3 --learner-id demo_student_001 backup --root data/backups --filename rsi-20261006.sqlite3 --policy-id local-backup-v1 --policy-approved
```

恢复只能生成新的隔离库，并带 quarantine 和空 Consent；不能覆盖已有数据库、切换正在运行的服务或复活旧授权。恢复后的库先做健康检查，再由负责人决定是否用于离线复核。

## 七、测试和问题排查

```powershell
.\.venv\Scripts\python.exe -m uv lock --check
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m compileall -q app scripts tests
.\.venv\Scripts\python.exe -m pytest -q
```

遇到问题时按顺序检查：端口是否被占用、是否使用了正确的 `.venv`、是否把个人 8000 数据路径传给实验/学校命令、是否授权了教学用途、题目是否有有效 delivery ticket、课程/source hash 是否变化。不要按进程名批量停止服务；先查看端口和启动日志。

浏览器验收从仓库根目录执行 `node platform/scripts/v4_browser_smoke.cjs`。脚本自行启动隔离 8132 fixture、生成随机测试凭据、不读取 `.env.local`，结束后关闭自己的 fixture。无需手动启动旧 fixture；8132 被占用时用 `EDU_QA_PORT` 选择空闲端口。Playwright 或浏览器不在默认位置时使用 `EDU_PLAYWRIGHT_MODULE` / `EDU_CHROME_PATH` 指定路径。实验室另执行 `node platform/scripts/simulation_browser_smoke.cjs`。不要使用个人 8000 数据做压力测试，截图放在被忽略的 `platform/data`。

仿真浏览器脚本不自行启动服务，且会创建测试作业。先在独立终端的 `platform` 目录启动隔离 Lab：

```powershell
.\.venv\Scripts\python.exe -m app.simulation.lab --port 8131 --output-root data/v4-simulation-qa
```

另一个仓库根目录终端执行：

```powershell
$env:EDU_QA_URL = 'http://127.0.0.1:8131'
node platform/scripts/simulation_browser_smoke.cjs
```

验收后用启动终端的 Ctrl+C 停止这一个隔离 Lab，不按进程名停止其他服务。不要把脚本指向正在使用的个人实验目录。
