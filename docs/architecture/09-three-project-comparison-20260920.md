## 1. 三案速览

| | OpenMAIC（清华） | Hyperknow（哥大团队） | DeepTutor（HKUDS） |
|---|---|---|---|
| 路线 | **课堂型**：把主题/文档变成 AI 教师+助教+同学的沉浸式课堂 | **自主型**：不等提问，主动把学习目标变成 1:1 AI 课程 | **家教型**：资料驱动的开源 AI 家教 |
| 核心机制 | 四种教学场景（幻灯讲解/测验检验/**可运行 HTML/JS 交互模拟**/项目式学习）；圆桌多角色对话；两阶段流水线（**大纲先审后生成**） | 三件套（问答+结构化章节学习空间+**主动学习流面板**）；Learner's Persona 长期记忆；**从 LMS/大纲抽截止日期反向排程**；诊断先行 | **一个 Agent 循环六种模式**（切换的只是学习目标）；调用外部编程 Agent（@Claude Code，机器可读输出）；**文件化三层记忆 L1 事件/L2 场景小结/L3 画像 + 记忆图谱证据链**（TutorBench：个性化 +10.8%）；可插拔检索（GraphRAG/LightRAG/PageIndex 页码引用）；**开放技能标准 + EduHub 技能市场**；活书（资料编译成嵌测验/闪卡/交互、每页可对话的书）；IM 多渠道触达 |
| 护城河 | 教学内容生成的完成度 | 主动预判的产品节奏 | 工程开放性与记忆可追溯 |
| 相对本方案的局限 | 学习者建模浅、无教学效果验证、无治理 | 画像黑盒、无验证器、无进化机制、闭源 | 无硬约束规则引擎、无教学法状态机、个性化=记忆而非认知诊断 |

## 2. 逐案吸收决策

### 2.1 自 OpenMAIC（教学场景库）

| 决策 | 落点 |
|---|---|
| ✅ 四种教学场景形式化为**教学模式库**（slides_lecture / quiz / interactive_sim / pbl），作为 TASK/ENGAGE 的 `pattern` 载体参数——模式是内容形态，5E 仍是流程骨架（联动"动作=载体×语义"，此为载体维度的扩展） | 03 §2.1 |
| ✅ 生成可运行 HTML/JS 交互模拟 → ENV_OP 新增 `simulator_gen` 工具，产出进验证器 | 03 §2 表 |
| ✅ 大纲先审后生成 → 并入内容审核流：AI 生成的**课程大纲**与资源/题目一样，approve 前不得直接展开生成 | 06 REVIEW_RECORD（已覆盖，09 明确语义） |
| ✅ 圆桌多角色对话 → 派生类型⑤"**圆桌研讨面板**"（教师+助教+不同立场同学多视角辩论），服务高阶认知与多视角思维 | 01 §5.2 |
| ⛔ 不采纳：以内容生成为中心的整体形态（生成≠教学，缺学习者闭环） | —— |

### 2.2 自 Hyperknow（主动学习节奏）

| 决策 | 落点 |
|---|---|
| ✅ 从"被动应答"到"**主动预判**"：TriggerEngine 之上增加**晨间简报**（MorningBriefingJob）——夜间按截止日期临近度 × 薄弱点 × 契约进度生成今日待办，AI 可解释排序依据 | 03 §3.1 扩展；07 UI-05 |
| ✅ **截止日期反向排程**：GoalContract 增加 `external_deadline_refs`（LMS/大纲/考试日历），排程器从 deadline 倒排写入 PLAN_VERSION | 02 §3.1 |
| ⛔ 不采纳：黑盒画像（我们的画像必须走 02 的不确定性显式 + 开放学习者模型，用户有权看懂并纠正每一条判断） | 02 规则 3/5 |

### 2.3 自 DeepTutor（开放工程与记忆）

| 决策 | 落点 |
|---|---|
| ✅ **三层记忆组织**：L1 交互事件（=既有事件流）→ L2 场景小结（**派生的可再生视图**，按学习场景聚合，标注 derived 可重建）→ L3 画像（=02 快照+策略档案）；**记忆图谱**=L3→L2→L1 的引用链，每条判断可钻取到原始证据——这是本方案"可追溯"规则（02 规则③）的成熟 UI 形态 | 02 §3.4；07 UI-10 |
| ✅ **外部编程 Agent 调用**：ENV_OP 新增 `external_coding_agent`（白名单：Claude Code / Codex 等），产出必须过验证器；同时本平台自身提供**机器可读接口与 SKILL 式操作手册**——平台可被外部 agent 驱动（双向互操作，也是进化流水线的编排手段） | 03 §2 表；04 §4 |
| ✅ **技能市场兼容**：SkillEntry 采用开放 Agent-Skills 标准，支持导入导出与社区分发；**外部技能一律 candidate**，过验证器回归+晋升门+硬约束检查才可 active——市场开放，门禁不开放 | 04 §4 |
| ✅ 可插拔检索引擎（GraphRAG/LightRAG/PageIndex 页码级引用）→ L4 检索可插拔；页码引用与 R-06 接地约束同向 | 05 组件图 |
| ✅ 活书 Book：资源可编译为嵌测验/闪卡/交互模块的书，每页可继续对话——课程与资源模块的新资源形态 | 07 UI-08 |
| ✅ IM 多渠道触达（Partners 式）：学伴轻量提醒与提问走 IM 渠道，正式学习仍在工作区（渠道获客，不出治理边界） | 07 §9 |
| ⛔ 不采纳：个性化=记忆的路线（记忆≠认知诊断，L3 我们已有心智模型，更强）；功能平铺无状态机约束的交互 | 02/03 |

## 3. 三案共同盲区 = 本方案的差异化（保持清单）

1. **心智世界模型**：三案均无误区假设分布、不确定性显式、ToM 层与 MWM 对接——本方案 02。
2. **教学法硬约束**：三案交互均无规则引擎与状态机门控（R-01…R-09）——本方案 03。
3. **验证闭环与进化**：三案均无验证器资产化、孪生推演、晋升门与技能结晶——本方案 04。
4. **治理**：三案（尤其 Hyperknow 闭源画像）均无同意管理、最小可见、价值观审定——本方案 L6。
5. **师伴与金标**：三案均无教师伴生智能——本方案 04 §8 / 07 UI-13。

一句话定位（v0.3 后）：**Hyperknow 的主动节奏 + OpenMAIC 的教学场景库 + DeepTutor 的开放工程与三层记忆，运行在本方案的教学法内核与 RSI 进化治理之上。**
