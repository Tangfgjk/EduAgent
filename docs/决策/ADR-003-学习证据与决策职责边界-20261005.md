# ADR-003：学习证据与决策职责边界

日期：2026-10-05

状态：已接受，待实现验收

## 背景

实施计划评审提出：Evidence、模型状态、Memory 与教学决策的语义容易混淆，重复事件与并发消费可能污染长期状态。本决策固定接口职责和持久化纪律，具体字段和测试见[项目实施计划](../进度/项目最终功能清单与一周实施计划-20261005.md)。

## 决策

1. `LearningEvidence` 保存观察和验证记录，Verifier 判定保留方法、版本与不确定性；`MasteryState`/`RetentionState` 是模型推断，路径和动作是建议。Claim Schema 显式区分 observation、inference、recommendation。
2. Learner Model 持有结构化认知状态，Storage 负责持久化。Runtime 通过端口读写；Memory 保存历史、摘要和解释性画像，通过状态版本引用认知结果，不能成为第二个掌握数值源；L3 禁止引用自身作为证据。
3. Mastery 与 Retention 模型、参数版本和消费者独立。V1 的 `partial`、`unverifiable` 不更新这两类数值状态，保留证据/审计/跳过原因。提示后的正确作答不能直接等同于无辅助成功回忆。
4. Gate 根据 AssessmentProfile 返回 mastered、not_mastered、insufficient_evidence、uncertain；有效证据、置信度方法和定性评测要求显式版本化，不能只返回概率比较的 bool。
5. `PathRecommendation` 决定学什么，`TriggerEngine` 判断是否介入，`Policy` 选择教学动作，`ActionGovernor` 裁决能否执行。四者可独立调用和测试：学生主动求助可直接触发介入，不能强制先生成新路径。所有提案/工具请求仍必须通过 Governor。
6. 路径引擎仅创建 proposed 推荐。学习者采纳后形成计划草案/Diff；只有学习者签署使新计划生效。接受、修改、拒绝和签署分别留痕，任何层不得用“自动采纳”绕过 R-02。
7. 消费唯一键为 `(learner_id, evidence_id, consumer)`；事件序号由 Storage 持久化分配。Evidence、消费记录、状态转换与派生快照在一个本地事务中提交；CAS 校验状态版本，冲突后重试，不重复消费。
8. 重建任务显式固定 Evidence 集合、event_seq、算法/参数版本和 as_of；模型升级和判定修正使用新状态版本，不覆盖原事实。外部调用在事务外执行，异步消费通过 outbox 恢复。
9. consent_scope、consent_version 和授权来源从首次记录 Evidence 起保留，teaching 不隐含 research/evolution 授权；消费者检查当前与采集时授权，撤回立即阻止对应用途读取。
10. 外部学习算法依赖方向为 `app -> ports/adapters -> vendor`，禁止 vendor 反向 import app。桂子问津保留自己的 Schema、Storage、Runtime、Policy 和 API。

## 验证要求

- 单独验证路径、介入、动作选择、规则裁决和计划签署；证明推荐不会直接修改生效计划。
- 验证四种 Verdict、Gate 四种状态、提示/回忆资格、跨学习者隔离和模型版本重放。
- 验证重复同 ID 同内容的幂等返回、同 ID 不同内容的冲突拒绝、并发 CAS 和事务故障回滚。
- 验证 Memory 仅引用来源、授权撤回生效、检索和派生动作仍受 Governor 管辖。

## 影响

上述为实现约束，不代表对应代码已完成。各阶段状态仍为“未完成”，通过测试、提交和验收记录后更新。五阶段排期、最小 RAG、Provider、派生角色、教师金标和 30 个回归场景的既定工作量保持不变。
