# V8 管理审核与我教 AI 使用手册

适用：0.12.0 / `v8_001`。账号仍由管理员创建；此前的学生使用手册保留。

## 1. 管理员开放新增内容

1. 登录管理端，进入“知识点与题库”。
2. 点击“核对概率计数与事件”或“核对平均数与频率”，查看题面、参考数值、四级提示和独立检测题。
3. 在“开发内容核对记录”中选择“开发核对通过”或“需要修改”，写明至少五字的核对依据，保存。旧意见保留，保存后可查看历史。
4. 核对通过后，勾选开发测试确认，再点击“启用此内容包”。保存核对不会自动开放。
5. 若后续发现问题，新增一条“需要修改”意见，同版本内容会撤回。关闭并重新打开审核窗口查看最新启停状态；修改后的新内容版本需要重新核对。

这是开发审核，不代表数学教师专业审核。当前不向真实学生来源账号开放。

## 2. 开放新的我教 AI 流程

1. 先核对并启用基础“等可能事件概率”开发单元。
2. 在“新增单元互动审核”找到“概率我教 AI · 讲解与新题验证”。
3. 查看原题、预设误区与另一题验证内容。先保存开发核对依据，再勾选并启用互动包。

旧“概率圆桌与我教 AI · 开发活动”和方程模板仍可单独选择，开放状态互不替代。

## 3. 学生体验我教 AI

1. 登录学生端，选择临时空间或学习项目，先完成/结束该空间正在进行的陪学或互动。
2. 打开“我教 AI”，选择“概率我教 AI · 讲解与新题验证”，点击开始。
3. 写下候选数值与“我的讲解”。先保留自己的想法，再查看学伴的预设疑问。
4. 在“我的比较、纠错与检查依据”中修正自己的解释，提交原题数值，点击“保存修正，进入新题验证”。
5. 另一题验证期间不提供角色提示。只提交一次数值与本题检查依据；刷新仍能恢复此阶段。
6. 查看 TeachReport，分别阅读原题辅助数值核验与另一题验证，以及三次原始表达。另一题未提供辅助不等于已证明迁移能力。

不确定的数值可如实填写，程序无法核验时会进入人工复核，不直接算错。AI 角色仍是模板，不会智能评价文字，也不自动评定解释质量或素养。

## 4. 评测工作台

1. 管理员点击“评测工作台”，选择冻结的评测运行。
2. 先确认“真实开发模型”还是“Fake 仅工程验证”、提示版本和报告哈希。
3. 可勾选“仅显示不符合开发参考的条目”。逐条比较输入、开发依据、引用、追问和各项检查。
4. 选择“本条开发参考可接受 / 模型方向待改进 / 参考方向存在歧义 / 运行失败或结果不可用”，写下依据并保存。
5. 刷新后意见仍在；同一条可追加修正意见，不能覆盖原记录。复核意见不会自动修改模型提示或发布配置。

这里没有“立即调用模型”的按钮。真实多轮复测仍通过既有命令执行并遵守日额度；本版工作台显示三个已冻结报告，未来新报告须审查后注册。

## 5. 升级与运行

升级前停 API/worker 并备份数据库，再在仓库根目录运行：

```powershell
.venv/Scripts/python.exe -m app.manage --env-file .local/database.env migrate
cd frontend
npm ci
npm run build
```

返回仓库根目录，分别启动 API 与两个 worker：

```powershell
.venv/Scripts/python.exe -m app.main --env-file .local/database.env
.venv/Scripts/python.exe -m app.worker --env-file .local/database.env --lane teaching
.venv/Scripts/python.exe -m app.worker --env-file .local/database.env --lane models
```

以上三条分别放在不同终端运行。本机预览已完成备份与迁移，不需要重置数据库、重新建号或重新设置模型密钥。管理入口 `http://127.0.0.1:8000/admin/`，学生入口 `http://127.0.0.1:8000/student/`。
