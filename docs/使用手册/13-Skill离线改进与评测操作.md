# Skill 离线改进与评测操作

适用：API0.18.0，数据库g08_001。学生端4003，管理端4003；本轮全部在本机离线运行，不调用真实模型。

## 1. 先准备基线

1. 使用模拟/成人开发账号，选择正式项目。
2. 确认项目课程，并留下真实操作产生的开发记录，例如某题数值未通过或多次请求帮助。不要为生成候选而故意制造学生效果数据。
3. 在“规划与策略”勾选四项执行参数，生成提案，经管理员审核和学生确认激活。操作详见[12号手册](12-执行策略与Skill版本操作.md)。
4. 如果需要观察错题优先的候选，可让基线保持“原顺序”；已经采用同一个参数时，系统不会重复包装成改进。

没有可生效的四参数基线或课程时会明确提示；临时空间不会启动这一流程。

## 2. 学生生成离线候选

1. 打开左侧[Skill 离线改进](http://127.0.0.1:4003/student/skill-evolution)。
2. 点击“生成离线改进候选”，等待teaching worker完成。
3. 阅读“改进假设”和原值→候选值；展开冻结来源，点击“查看原始材料”核对具体尝试。
4. 展开“冻结机制评测”，比较基线和候选的实际行为。工程通过不是学习效果认证。
5. 来源不足或参数已经采用时会显示没有合适假设，保留当前策略；失败时看原因，不反复重复创建任务。需要放弃未完成任务可取消。

## 3. 管理员复核

1. 打开[Skill 进化评测](http://127.0.0.1:4003/admin/skill-evolution)，选择项目任务。
2. 核对父版本、来源、diff、语料/报告版本、新旧运行与限制。原始材料读取会保留审计。
3. 填写至少10字依据，选择“拒绝此改进候选”或“复核通过，允许生成提案”。工程门禁未通过时不能批准。
4. 这里是开发复核，不能当作专业教师评价或真实收益认定。

## 4. 学生采纳与普通策略确认

1. 管理员复核后，学生点击“刷新改进状态”。
2. 填写采纳理由，点击“采纳为待审策略”。
3. 点击“前往策略审核与确认”。当前策略此时还没改变。
4. 管理员到“策略评审”审核新提案，再由学生确认激活。新任务才应用配置，已开始的任务保留原配置。
5. 可按12号手册回滚到本项目有效旧版本/默认基线。

## 5. 何时撤回或重新生成

管理员可以“撤回评测复核”，包括已经创建策略提案的候选。待审提案将不能批准；若相关版本已激活，后续新任务显示策略不可用并使用默认，历史指针不会删除。

新事实/自述/人工复核、课程或基线变化时，旧候选不能继续采纳。确认最新状态后取消旧任务，再基于新来源生成。运行器/消费者代码或语料升级后也需重新评测。

跨端操作出现“状态已变化”时，先刷新，重新核对修订与依据，再决定；系统不会替你自动重复批准。

## 6. 常见问题

- **为什么没有新候选？** 来源不足，或允许的相应参数已经采用；这不等于学习不需要改进。
- **它理解了我的长篇讲解吗？** 没有。本轮按数值状态、实际求助和人工数值纠正提出开发假设，不理解正文。
- **隔离保留样本通过是否代表学会了？** 不是。当前4个自编样本只验证消费者机制；脚本会按参考答案作答，没有真实学习过程。
- **为什么还要普通策略审核？** 评测复核允许创建提案，正式生效仍按既有双重确认，避免把工程通过直接当发布授权。
- **自动RSI启动了吗？** 没有。自动真实发布关闭，真实模型语义提案、真实学生灰度和效果评估仍待后续。
