# V4 工程基础与增量质量门验收

记录日期：2026-10-06。作用范围：本地研究 MVP 的工程基础与 CI，不代表生产基础设施完成。

## 实现与边界

- `ClockPort`、`SystemClock`、`CallableClock` 统一 aware UTC；触发器与 SessionRuntime 真实接入。模拟时钟仍显式注入，naive 新时间拒绝；旧 V3 continuation 的 naive 冷却时间不猜测时区，保守按当前时间重启该规则冷却，避免本机 UTC+8 偏移导致提前触发。
- `PersistentTriggerState` 按 learner/session/rule 隔离。SQLite 原子冷却 claim；SessionRuntime 在副本中 claim，再与整个 turn 一起 CAS 提交，失败不会提前消耗冷却。会话型冷却没有宣称跨会话全局抑制。
- Store 基础 schema 迁移：v1 采用 V3 旧表并补 event_seq；v2 增加 trigger_state。事务、重复升级、保留事实、拒绝降级、失败回滚已测试。特性模块仍拥有自身 `CREATE IF NOT EXISTS`，不是全平台 PostgreSQL/Alembic 迁移。
- 配置优先级：process > `.env.local` > `.env`；同一来源 `WENJIN_*` > legacy `RSI_*`，显式空值有效。启动端口同样支持两前缀。配置模板区分离线开发、远程 Provider 可选和生产前置。
- OpenAPI contract tests 覆盖 JSON request body schema、strict assessment、aware timestamp、授权、response fields、receipt 幂等与冲突；并非所有 API 的完整逐端点 contract suite。
