# V5 架构愿景与实现差距审计

日期：2026-10-08。范围：本地 `V5` 分支的 `docs/架构`、`docs/需求`、`docs/进度`、`docs/决策` 与 `platform/app`。本报告以源码和可调用路由为实现证据；设计稿、既往验收报告只说明意图和当时的声明。工作区有未提交修改，因此结论针对本次读取的工作树，不等同于远端 V5 提交。未运行全量回归，也未以真人教学效果作判断。

## 1. 最初构想与后续收敛

最初的一句话愿景是贯通“目标设置 → 学习执行 → 反思归纳 → 迭代调整”的自我调节学习（SRL），以无辅助表现、认知层级和自主性为主要成效，并由真实学习数据推动人和智能体的受控进化。[总体架构 §1](../架构/01-总体架构设计-20260916.md#L12-L40) 设想六层体系：产品、心智模型、教学决策、多智能体协作、知识/检索、RSI 进化；学伴与师伴、按需派生角色、知识图谱接地和夜间进化均在蓝图中。[总体架构 §2](../架构/01-总体架构设计-20260916.md#L53-L115)

随后实施范围有明确收敛：V1 不启动自动 RSI，V2 的进化环须满足门槛后才启动；DeepTutor 只裁剪 Learning、Memory、RAG、Provider 参考，不搬入其 Web、Agent Runtime 或学习者状态所有权。[V1 实施方案](../架构/10-V1实施方案-20260926.md#L14-L20)、[ADR-002](../决策/ADR-002-DeepTutor裁剪基线-20261005.md#L8-L15)。阶段一需求特意声明仅先把可验证作答变为长期证据，不能以该阶段要求衡量整个最初蓝图。[阶段一需求](../需求/阶段一学习闭环-20261005.md#L5-L17)。V4 进度与验收将当前产品界定为**本地研究型 MVP**；真人课程/伦理/授权/参数、真实 Provider、生产运维是后续准入事项。[V4 计划](../进度/V4最终研究MVP收口开发计划-20261006.md#L7-L28)、[V4 验收](V4最终集成验收与发布记录-20261006.md#L5-L9)。

因此“没有达到全部最初构想”与“已达到经裁剪的本地 MVP 部分目标”可以同时成立。不能把未来愿景或模拟器验收解释为正式教育服务已上线。

## 3. 对当前“洛必达法则”现象的直接解释

目标文本可作为 `GoalContract` 保存，但课程准入由现有 `AssetCatalog` 决定。之前目标保存与路径推荐之间缺少一致的范围判断；当前工作树已在 `platform/app/learning/goal_scope.py:18-35` 和 `platform/app/gateway/routes.py:106-111,253-266` 增加阻断，避免洛必达目标收到一元一次方程路径。这个修复只防止错误匹配，**没有新增洛必达课程，也没有新增自动课程构建 Agent**。把“目标可输入”“LLM 可调用”“RAG 可检索”组合起来仍不等于任意目标自动变成受验证的学习计划。

本轮后续实施又加入了 `platform/app/learning/course_requests.py`：范围外目标可以登记需求，并对可信本地 Markdown 作精确主题初筛；现有课程的路径也按目标知识点及先修范围收敛。该记录和初筛不能代替新课程的内容生成、数学核验与教师审核。实施细节见[首轮记录](../进度/V5前端与课程需求首轮实施-20261008.md)。

## 4. 判断与优先级

1. **最影响使用者期待的缺口**：自由目标到可执行课程之间缺少目标解析、可信资料采集、知识点/先修图、题目与评测生成、人工审核和发布的完整管线。应先在界面明确课程范围，再设计“范围外目标→候选资料与课程草案→教师审核→可学习课程”的流程；未审核候选物不能伪装为正式教学建议。
2. **Agent 实力需要准确呈现**：现有 Agent 是在确定性规则、有限课程与授权下工作的教学编排器；多角色评议和本地 RAG 已有实质代码，但默认 FakeLLM、顺序角色意见与候选检索无法支持“开放题材多智能体自动教学”的宣传。
3. **验收需分层**：代码/接口通过、本地课程包通过、真人教师审核通过、真实学生成效通过、生产安全通过是五种不同证据。当前可确认前两类的一部分；其余必须按现有准入计划单独完成。

## 5. 界面与导航核查

原页面的左栏“今天的学习、成长总览、复习队列、我的计划”和顶部六个标签有四项重复，而且计划页先展示目标、再展示项目编辑、最后才展示路径建议。对第一次使用者而言，“建立目标后下一步做什么”不够明确。当前工作树已将左栏收敛为目标、项目和独立工作台，把计划页改为“建立目标 → 查看并审核建议 → 可选组织项目”，并在六个主视图加入用途提示；见 `platform/web/learning.html` 与 `platform/web/workbench/workbench.css`。这只是入口与信息顺序的改善，六个页面内仍有较多技术性字段与研究功能，尚未达到[早期界面设计草案](../架构/07-界面设计草案-20260916.md)描述的完整引导式体验。

下一轮产品设计应围绕真实学习者走通一条主路径：授权 → 选择可学习目标 → 独立初诊 → 审核路径 → 学习与复习 → 回看证据。项目管理、检索方式、模型参数和治理入口应按角色及需要逐步呈现；每一页提供明确的当前状态和一个主操作。课程范围外的目标需要单独的“提交课程需求/等待审核”状态，不能继续进入方程计划。
