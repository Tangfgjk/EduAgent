# v3 多轮追问改进与对照验收

日期：2026-10-17；分支 V8-20261017；本次在原 0.12.0 上增补候选提示版本，不改变数据库结构。

## 实现目标与结果

针对真实 v2 的五项不匹配，先保留并复核原开发量规，再新增 `probability.followup.v3`。v3 本次 40 轮全部满足原样本开发参考；新增语料的同批 v2 对照为 8/12。

| 同语料对照 | v2 | v3 | 历史对照 v2 → v3 |
| --- | --- | --- | --- |
| 原 18 轮基线 | 15/18 | 18/18 | 未通过 → 通过 |
| 原 10 轮独立样本回归 | 8/10 | 10/10 | 未通过 → 通过 |
| 新增 12 轮开发回归 | 8/12 | 12/12 | 未通过 → 通过 |

每对已检查语料 SHA256、内容版本、型号、逐条输入、提示层级与参考标签一致。v3 原五个失败样本均通过，没有放宽原标签。全部真实调用通过结构、引用、允许方向与身份探针检查。

详细定义、定位证据、开发量规与边界见 [60 号复核记录](../研究设计/60-多轮失败样本与开发量规复核.md)。相关知识沉淀见 [问题卡](../knowledge-base/20261017-多轮追问历史承接与方向定义.md)。

## 代码变化

- `app/modules/learning/model_coaching.py`：新增 v3，统一识别 v2/v3 为四轮模式。v3 增加方向定义、最新意图优先、唯一指代承接、无依据仍澄清及不继承历史伪指令的规则。
- `app/infrastructure/runtime/model_tasks.py`：v3 通过原有同账号、同空间、同题、同内容、同配置和来源校验收集历史；不引入新的历史来源。
- `app/gateway/model_runtime.py` 与管理端：允许显式选择 v3 候选版，表单仍默认原 v1，不自动发布 v3。旧 v2 仍可选择。
- `app/evaluation/multiturn.py` 与 CLI：加入 `--prompt-version`，默认仍 v2；运行清单准确记录实际版本；恢复时拒绝切换提示版本。
- 新增 `seeds/evaluation/probability_multiturn_regression.v1.json`，12 轮，新增同文不同历史对照和防止过度承接的测试。打包清单包含该文件。

没有按样本句子写标签返回规则，模型仍实际选择方向；不把 expected_focus 或 rationale 发送给模型。输出仍限制为本轮连续引用与允许枚举，实际展示固定问题。题库答案与 v1/v2 的提示语不改变。

## 使用方式

管理端 → 配置与权限 → 模型与运行配置 → 追问模式选择“v3 候选版”，核对开发用途后显式发布。已有暂停状态不因这次开发而自动开放；本机演示 PostgreSQL 当前仍暂停模型。学生端界面无需另选模型。

命令行评测可显式选版本：

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --prompt-version probability.followup.v3
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus holdout --prompt-version probability.followup.v3
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus regression --prompt-version probability.followup.v3
```

这些是会再次产生真实调用的运行命令，不是读取本次结果。查看结果优先阅读冻结报告；无自动复跑或自动发布。

## 局限和下一步

1. 原 holdout 已参与失败定位，本次作为已见样本回归，不再称作未见验证集。新增语料也由同一开发方设计，不是教师盲测。
2. 每条只运行一次，模型 temperature 0.2；全对不能推出多次稳定性或更大课程范围的泛化。模型具体响应也不具确定性。
3. v3 系统提示更长，同批新增语料输入 7780 tokens，对比 v2 的 4490，约增加 73%；当前换得方向匹配改善，但不能据此证明具体提示句的因果贡献。后续应评估精简提示及成本。
4. 运行成功、方向匹配与历史对照均不证明学生掌握、素养或教学效果。专业教师内容审核仍待完成，真实学生仍不在开发调用范围。
5. 新冻结报告尚未加入当前仅注册三份报告的管理工作台。后续可做受控报告登记/对比和专业复核；再推进真实模型“我教 AI”的数据与回应契约。
