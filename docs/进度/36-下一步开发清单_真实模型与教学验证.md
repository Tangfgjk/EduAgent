# 下一步开发清单：真实模型与教学验证

日期：2026-10-17。当前基线：API 0.10.1、数据库 `s09_001`，S10 首批内容包及概率互动样板已交付。本文汇总后续任务，不改变初中数学、学生自主学习、项目隔离和内网试点方向；原有 docs 保持历史原状。

**当前未接真实模型，不自动理解课程正文、学生自由表达或评定教学效果。** 固定模板、数值核验、过程统计与真实教学效果评价须明确区分。

## 1. 当前已完成的基线

- [x] React + TypeScript 学生/管理双端，管理员建号，项目与临时空间隔离。
- [x] LangGraph 有界确定性流程、输入持久化、检查点、人工关口和幂等控制。
- [x] 5 个基础开发内容包、25 题，题库按版本审核启停。
- [x] 方程与概率的圆桌/我教 AI 固定模板、学生贡献和来源追溯。
- [x] 复习、全局/项目证据、学生说明、独立人工复核记录及策略双重确认/激活/回滚。
- [x] SQLite/隔离 PostgreSQL 验收、双端浏览器检查、安装包检查和开发数据库备份。

上述完成项均为当前开发范围，不能据此认定完整三年课程、真实模型智能教学或真实学生教学有效性完成。实现与验收依据见 [35 号文档](35-S10概率互动贯通验收.md)。

## 2. 推荐推进顺序

主线：**模型运行基础设施 → 指定模型适配 → 概率真实陪学 → 真实圆桌/我教 AI → 课程资料理解与规划增强 → 经审核的教学评价 → S11 授权试点。**

数学验证器扩展与课程建设可以并行推进。首个模型样板限定现有概率题及当前可核验范围，不必等待完整三年课程；专业审核和真实试点不能被工程验收替代。

## 3. P0：模型运行基础设施与接入准备

- [ ] 将外部模型调用移出当前短事务；采用持久检查点和明确的操作/结果状态，保留现有项目及账号授权边界。
- [ ] 补齐长任务租约续期、超时、重试、取消、进程中断恢复和重复结果提交处理。
- [ ] 统一模型 Provider 接口，先用可控 Fake 验证，再接已指定服务；不在页面或业务代码中散落密钥和模型调用。
- [ ] 定义结构化输出：学生原文引用、思路理解、可能误区及不确定性、追问/提示建议、所用资料引用。
- [ ] 记录模型、提示、工具、内容、规则与策略版本，以及必要的用量和耗时；限制日志内容，避免记录密钥和无关学生原文。
- [ ] 配置调用预算、最大轮次、超时与失败降级；失败时保留学生已提交内容，提示可重试或使用明确标记的预设支架。

完成条件：重复投递、中断、重启、超时、取消、过期结果及预算限制均有可重复行为验证；外部调用不长期持有业务数据库锁，结果不能串账号、空间或运行。

**需要负责人确认后才能真实调用：** 模型服务商、型号、接口地址、调用预算，以及允许发送的学生数据范围和脱敏要求。已允许指定外部 API，不等于允许向任意追踪或存储服务传输完整记录。密钥仅在本机安全配置，不放聊天、文档或 Git。

## 4. P1：概率单元真实模型陪学

- [ ] 给模型提供当前题目、学生原文、必要的近期交互、提示使用状态及已确认策略；按当前项目构建最小上下文。
- [ ] 使模型针对学生表达追问，例如区分“球等可能”和“颜色等可能”，并引用学生实际说法。
- [ ] 对不明确表述先澄清；误区判断作为待核查假设，不能写成永久能力标签。
- [ ] 将模型建议送入现有教学规则与能力门禁，独立检测不开放辅助提示，提示级别和预算不能由模型自行绕过。
- [ ] 可判定数学结果继续交由程序核验；无法可靠判定的结果进入明确的不确定/人工出口。
- [ ] 页面区分真实模型回复、固定模板、程序核验与人工结论；恢复、取消和失败状态可见。
- [ ] 用自编对话、参数化误区、成人测试及对抗场景核验引用准确性、提示泄露、越权、规则绕过和失败恢复。

完成条件：模型能针对不同学生原文给出有关联的回应；结构化输出和引用可检查；不伪造学生表达，不把模型意见视为数学真值或掌握度。模型评估须有独立核对，不能仅由同一模型自评通过。

## 5. P2：真实圆桌与我教 AI

- [ ] 将固定角色内容逐步替换为受约束的动态观点、质疑和追问，继续保留“学生先表达”的过程。
- [ ] 区分角色意见、数学核验结果和人工审核结论；角色发言不进入学生事实。
- [ ] 让虚拟学伴在限定误区范围内回应学生讲解，保持有限轮次、角色预算和退出条件。
- [ ] 教学评价模型与生成角色分工，评价引用原始证据；多个模型意见一致也不能直接视为教师金标。
- [ ] 逐包完成审核、启停、版本冻结及旧运行兼容，互动结果不冒充无辅助检测。

完成条件：两条路线均能对学生新表达动态响应，来源与角色可追溯，原固定模板可作为明确标记的开发回归/降级方式保留。

## 6. P2：数学验证器和课程内容并行线

- [ ] 先定义整式/表达式等价的受控语法、资源限制、变量与定义域，再实现首个 Adapter；不能用少量数值抽样证明恒等。
- [ ] 扩展解集、多解、无解、分式条件与根式；分别定义可验证、失败及不可验证口径。
- [ ] 应用题逐步记录变量含义、列式、单位、情境检验；最终数值正确不等于建模过程正确。
- [ ] 几何读图/作图/证明保留独立表达协议与人工复核出口。
- [ ] 按 [33 号覆盖台账](33-S10课程覆盖台账.md) 补充单元、知识点/先修、任务、误区、分级提示及独立检测；为变更新增快照。
- [ ] 补齐专业内容审核、教材/课标映射、平行检测与题目难度核对；明确审核责任人。
- [ ] 按包扩展其它单元的互动，避免只新增章节入口而没有可运行任务。

完成条件：每个新范围有对应内容与验证协议，未支持输入明确分流，旧题目和学习事实不被新版本覆盖。

## 7. P3：课程资料理解与规划 Agent 增强

- [ ] 对已审核资料解析、切分、定位段落并保留版本、来源与适用范围。
- [ ] 建立知识点/教材映射及按项目、资料权限过滤的检索，先验证少量人工核对样本，再扩展规模。
- [ ] 用实际检索段落和学习事实生成带引用的受限策略提案；资料正文作为数据处理，不执行其中的指令。
- [ ] 明确资料缺失、冲突、过时和检索不足时的处理，不能编造课程依据。
- [ ] 延续冻结候选、管理员审核、学生确认、激活和回滚；生成的 Skill.md/harness 不自动执行任意代码或修改硬规则。
- [ ] 对资料撤回、来源变化、过期提案和模型注入做真实模型场景验证。

完成条件：每项建议可定位到真实资料与学生证据，停用资料能够阻止不适用候选生效。仅将正文放进提示词不等于已完成资料理解验收。

## 8. P3：讲解质量、掌握与教学效果评价

- [ ] 与专业数学教学审核人员确定评价量规，覆盖基本结果/假设、推理依据、条件、核验与表达等适用维度。
- [ ] 建立人工标注样本、复核流程与分歧记录，再验证模型评价与人工判断的一致性和错误类型。
- [ ] 模型评价先作为带证据的建议，页面显示状态与不确定性；未经审核不自动生成素养分数。
- [ ] 用无提示检测、不同情境迁移题和间隔复测形成学生表现证据，区分辅助后答对与独立表现。
- [ ] 在授权真实试点中记录基线、题目难度、提示使用及其它影响因素，评审产品是否有助于学习；学习前后变化本身不能直接归因于产品。
- [ ] 保持模拟、成人测试与真实学生来源分离，不用交互次数、模型自评或模拟学生成绩证明真实教学效果。

完成条件：量规和样本经审核、评价结果可追溯和纠正、真实证据符合评审口径；满足后才逐步开放能力估计和策略效果判断。

## 9. S11：内网试点准备与真实验证

- [ ] 确定试点硬件、部署位置、预计并发、首批单元、审核及人工支持负责人。
- [ ] 完成 API/worker/PostgreSQL 部署、访问和日志限制、必要的监测告警、配置与版本管理。
- [ ] 在目标环境做并发、故障恢复、备份恢复及升级演练；以实测结果确定容量与耗时承诺。
- [ ] 明确授权、数据采集范围、导出与保留规则，落实内容责任和人工处理流程。
- [ ] 冻结首批场景并完成核心学习路线、红队、内容审核与发布门检查，再开展小范围真实试点。
- [ ] 根据真实基线评审后续策略改进条件；不以现有测试通过数量替代教学验证或 RSI 条件。

工程准备可以提前进行；真实学生开放前的审核、授权与试点条件必须落实。

## 10. 下一次开发的具体起点

先做 P0 的运行器与 Provider 接口设计/实现，使用可控 Fake 验证失败恢复和预算协议；并行请负责人确定模型接入参数。随后将概率陪学作为首个真实模型样板。已有固定模板与数学核验保留为可重复的开发基线。

本清单是后续待办，不表示本次已经接入真实模型、理解课程正文或开展真实教学效果评测。未来进度变更新增验收/修订文档，保留本清单的历史版本。
