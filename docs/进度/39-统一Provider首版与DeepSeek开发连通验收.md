# 统一 Provider 首版与 DeepSeek 开发连通验收

日期：2026-10-17。基于 API 0.10.2；本次未修改数据库结构、已有教学流程及历史文档。

## 1. 模型切换放在哪里

**管理端统一管理服务商、型号、能力、预算与启停；学生端使用已发布配置。**

- 管理端后续提供草稿配置、开发连通测试、发布、停用、历史和回滚。密钥只在服务端保管，浏览器仅得到“是否配置”，不得返回原值或存入浏览器存储。
- 学生端展示适当的模型来源、真实模型/预设支架状态及失败提示。首期不提供任意厂商、型号或密钥输入；未来若允许学生选择学习模式，也只映射到管理员已授权的配置。
- 发布后的配置有独立版本。新任务绑定配置快照，处理中任务保留原版本；停用和紧急切换的规则须在运行器中明确，不能静默跨厂商重发学生上下文。
- 陪学、圆桌、我教 AI、规划可分别绑定配置，先共用 DeepSeek 开发配置，不能由模型自行调整费用或硬性教学规则。

本轮已确定以上产品边界；**管理端配置发布页面、配置持久化和审计尚未实现**，现有页面“模型与运行配置”仍是待开放项。当前通过本机开发命令配置与测试。

## 2. 已实现的接口

入口：[provider.py](../../app/llm/provider.py)。新接口与旧 `app/llm/client.py` 分离，不暗中替换原流程。

- `Provider.generate(GenerationRequest) -> GenerationResult`：异步协议，无数据库依赖。
- 请求包含有限数量的文本消息、输出 token 上限、温度；输入限制为字符数保护，不能视为精确 token 预算。
- 结果包含请求型号、返回型号、文本、结束原因、可选 token 用量、耗时、模拟标记。保留 `length`，不能把截断响应当完整结论。
- `ProviderConfig`：服务商、型号、端点、SecretStr 密钥、超时与单次输出上限。型号可配置，不写死业务代码。
- `ChatCompletionsProvider`：DeepSeek 官方端点与自定义 HTTPS 兼容端点；不开放任意额外字段覆盖请求。兼容端点属于受信运维配置，不接受学生输入。
- DeepSeek 首版关闭思考模式，非流式文本调用。暂不支持流式、工具调用、图片、JSON Schema 原生结构化、自动执行工具或保存推理内容；收到不支持的输出明确失败。
- `FakeProvider`：脚本化文本或故障，带模拟标记；脚本耗尽报错，不伪造成功。
- 错误使用固定代码，避免将上游正文、请求头、密钥和学生原文带入错误消息。缺失用量保留为空，不当作零成本。
- 单次总超时与 HTTP 超时、输出上限；不自动重试、不跟随重定向，不自动跨服务降级。厂商内部 token 计费及网络异常是否已扣费仍以服务商为准。

这是一版文本传输接口，不表示所有厂商、型号和能力均已验收。国内外厂商扩展路线见后续范围文档；Claude/Gemini 原生协议仍需独立适配，不强行作为完全兼容。

官方接口依据：[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。本次核对官方当前型号及思考开关；未来型号可用性、定价和能力需重新核对。

## 4. 本机复测

从仓库根目录运行：

```powershell
$env:WENJIN_PROVIDER = 'deepseek'
$env:WENJIN_MODEL = 'deepseek-flash'
.venv/Scripts/python.exe -m app.llm.probe
```

命令会交互读取隐藏的密钥，仅当前进程使用，不回显、不保存。不要将密钥写进命令历史。程序只输出用量、耗时与是否有文本，不输出生成正文。

可选配置：`WENJIN_PROVIDER_URL`、`WENJIN_PROVIDER_TIMEOUT`、`WENJIN_PROVIDER_KEY`；后者由服务进程环境注入。也支持 `--env-file` 指定本地文件，若使用文件必须放入 Git 忽略目录并限制文件访问。新配置不读取旧 `RSI_LLM_*`，避免旧演示配置意外启用。默认兼容服务必须显式指定 `WENJIN_PROVIDER=openai_compatible`、正确 URL 与型号；不自动推断厂商能力。
