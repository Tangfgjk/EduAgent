# 开发不限次配置与真实多轮评测结果

日期：2026-10-17；分支 V8-20261017。

## 最新决定

用户明确要求开发阶段先不限额，以便继续评测。本决定替代 56 号文档中“等待次日额度恢复”的执行安排；历史文档保留。

此处“不限额”具体实现为取消本项目的**每日调用次数**上限，不代表服务商免费、无限并发或取消单次约束。

- 每账号、全站两个配置值均支持 `0`，含义为该维度不限每日次数。两项都为 0 时 `coaching_remaining_calls` 为 null，学生端在模型可用时显示开发不限次数。
- 只有一项为 0 时，仍按另一项有限额度拦截。计数始终递增，失败和取消不退还预约次数。重新发布有限配置时立即按当日累计值判断，不清空旧记录。
- 管理端发布表单两项默认 0，可改为有限额度再发布。配置仍须管理员显式发布，暂停功能保持有效。
- 自编内容、模拟/成人账号、概率练习范围、最多 512 输出 tokens、单次超时、同题最多四轮及不自动重试保持现有约束；不开放真实学生数据。
- 不需要数据库结构迁移，0 使用现有整数字段表达；旧不可变配置不改写。

## 评测脚本用法

单轮及多轮开发评测 CLI 默认不限每日次数，真实调用仍须显式 `--live`。使用 `--limited-daily` 可选择原账号 30 / 全站 100 的模式；多轮预检检查的是本次计划使用的模式，不会发布配置或预约调用。

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --check-only
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus holdout

# 如需本轮恢复原每日限制
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --limited-daily --check-only
```

不限每日次数不扩大单份语料：当前基线仍固定 18 轮、独立样本 10 轮；单轮脚本仍有每次运行最多 30 条的调度边界。没有后台循环或自动追加评测。

## 失败样本与下一步

1. `M03-2`、`M04-2` 本轮相同：“对，我想继续弄清刚才这一点。”参考分别要求 sample_space / ratio，模型均选 clarify。
2. `M09-2`、`M10-2` 本轮相同：“我仍然想请你围绕上一个问题继续追问。”参考分别要求 favorable / ratio，模型均选 clarify。
3. `M06-3` 已明确询问概率分子的放置，参考 ratio，模型选 favorable。

结论：历史确已进入请求，但还不能证明模型能根据历史区分省略表达。clarify 属于保守且允许的追问，并非数学错误；需人工确认这类参考方向是否应作为硬门禁，以及现有“无法明确指代先澄清”的提示是否过于宽泛。不能为提高分数直接放宽历史冻结标签。

下一步先复核这五项的量规，再创建新的提示版本和配套测试，保留 v2 原实现/配置与历史结果；新版本复测后再决定是否发布。此次没有自动修改 Prompt、Skill.md 或学习策略，也没有扩展真实“我教 AI”的调用范围。
