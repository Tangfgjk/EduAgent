# S09 规划与策略治理开发闭环验收

日期：2026-10-16。仍在 main，没有读取其他分支；既有 docs 保持不变。

## 1. 本轮确认与交付

用户明确选择：先完成固定开发提案与完整审核闭环，真实模型接入另行确认。本轮未配置或调用外部模型。

- 管理端“策略评审”新增课程资料：录入不可变版本、核对发布、停用、查看来源和正文。
- 学生端“规划与策略”可收集当前项目的学习来源、主观体验与所选资料，生成开发候选。
- LangGraph 可持久暂停在管理员审核、学生确认两个不同关口；支持退回、不采纳、取消、幂等与失败恢复。
- 通过学生确认后才激活；保留版本、来源、检查、回执与谱系，可回滚到默认或曾激活的本项目有效版本。
- 展示可读依据、Skill.md 与受限 Harness JSON；可下载该版本 Skill.md，不改写仓库既有技能文件。
- 新陪学实际采用策略指定的反思重点，已开始的运行保留自己的策略快照。计划时长建议由学生主动采用，不修改已确认计划。

## 2. 体验流程

1. 管理员登录独立管理端，进入“策略评审 → 课程资料”，录入有来源/版本的参考，核对后发布。
2. 学生登录、选择正式项目，进入“规划与策略”，写学习体验，选时长/反思重点与 1–5 份资料，生成提案。
3. 管理员在“提案评审”打开项目，查看冻结来源与候选，填写依据并批准或退回。
4. 批准尚未生效；学生查看并填写自己的理由，确认激活或不采纳。
5. 激活后，在“学习计划”可主动采用时长建议；开始新陪学后，反思提示按该版本保存。
6. 在“当前学习软策略”展开激活历史，选择曾激活版本或默认基线并说明理由后回滚。旧陪学不随之改变。

当前课程资料是录入者声明的参考，专业审核状态为 false，不假称已具备教师金标。没有可发布资料时显示空态，不自动填充官方教材、考纲或真实学生记录。

## 3. 能力边界

软策略只允许每日建议时长（5–60 分钟）和反思引导重点。固定候选参数来自学生选择，本轮不会自动理解课程正文、智能诊断或评估学习效果；不生成素养评分、不改变题目真值与考试隔离。

主观信息、原始数值记录和人工判断分开引用。确认前来源变化、资料发布变化、规则变化、基线变化或超过 7 天，旧提案失效，需重新生成。只有当前正式项目参与规划，临时空间不自动晋升。详细实现与后续限制见 29 号架构文档。

## 4. 迁移与运行

API 0.9.0，数据库迁移目标 s09_001。先停 API/worker、备份，再迁移、构建、启动；首次管理员仍由本机隐藏输入命令初始化。本轮不创建正式默认账号或自动发布资料。

```powershell
uv run --locked python -m app.manage --env-file .local/database.env migrate
cd frontend
npm run build
cd ..
uv run --locked python -m app.main --env-file .local/database.env
# 另一个终端
uv run --locked python -m app.worker --env-file .local/database.env
```

TutorGraph 从 v1 升为 v2；旧 v1 历史仍可读、可取消，进行中的旧运行需要重新开始，不能静默套入新实现。事实重建继续核对兼容的旧数学视图；未知版本不自动重放。

本机已停服备份后迁移并启动：备份 `.local/backups/pre-s09-20261016-225712.dump`，schema 为 s09_001，API 为 0.9.0；进程记录 `.local/s09-preview-processes.json`，日志前缀 `.local/s09-`。正式库账号、规划资料、策略版本、激活、学习事实均为 0，没有灌入验收数据。

健康检查通过，学生 `/student/planner` 和管理 `/admin/strategies` 返回 200；未登录的双端资料接口返回 401，worker 错误日志为空。
