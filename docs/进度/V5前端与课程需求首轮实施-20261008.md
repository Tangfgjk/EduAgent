# V5 前端与课程需求首轮实施

日期：2026-10-08。分支：`V5`。本记录描述当前工作树，尚不是完整的最终产品验收。

## 本轮完成

1. 学习工作台参考用户提供的交互演示 HTML，采用暖灰背景、白色卡片、墨绿主色、衬线标题和左侧单一导航。保留真实的陪学、计划、复习、证据、设置、圆桌功能，不搬入参考页的模拟成绩或假按钮。教师、家长、研究页面同步浅色视觉。相关代码为 `platform/web/learning.html`、`platform/web/workbench/wenjin-theme.css` 和 `platform/web/workbench/presentation.js`。
2. 目标覆盖检查返回已匹配知识点和下一步动作。现有课程的学习契约和路径推荐按目标知识点及先修闭包确定范围，避免一个具体目标总是返回整套方程知识点。相关代码为 `platform/app/learning/goal_scope.py`、`platform/app/learning/decisions.py`、`platform/app/gateway/routes.py`。
3. 课程范围外目标可提交为持久的课程需求。系统只检查可信本地 Markdown 是否包含目标主题，保存候选资料哈希、状态和后续审核步骤；重复提交返回同一请求。前端在计划页显示请求状态。相关代码为 `platform/app/learning/course_requests.py`、`platform/app/gateway/routes.py`、`platform/web/workbench/workbench.js`。

## 明确未完成

课程需求是新课程建设的入口，**还不是可学习课程**。当前没有开放网络资料搜索、来源许可核查、Agent 自动生成知识点/题目/提示/评测、教师逐题审核后动态发布的完整链路；也没有洛必达法则的已批准课程。默认 `FakeLLM` 模式不代表真实模型参与课程研究。下一阶段应围绕一门新主题，完成“资料候选 → 课程草案 → 结构及数学核验 → 人工审核 → 版本发布 → 初诊与个性化计划”的纵向闭环，并分别验收教育内容正确性和软件行为。

## 陪学会话布局补充（2026-10-09）

根据用户提供的交互演示，陪学页已改为一张宽幅会话卡片。当前题目、学生想法、陪学回复、题目提示和验证结果都进入同一消息区域；输入框固定在卡片底部。“给我一点提示”调用当前评测题的服务端提示接口并记录辅助情况，验证题目仍调用原发题与评测接口并记录学习证据。“发送”开启独立自由陪学会话，消息流明确标注它可能安排另一道探究题，避免把两套后端选题误认为同一道题。知识点和任务保留在卡片顶部，会话恢复及作答记录收在可展开选项中。桌面隐藏了重复的右侧上下文卡片，手机端增加了消息可视空间。

验收：隔离浏览器 21 个流程通过，1440 px 与 390 px 无脚本错误或横向溢出；`127.0.0.1:8001/` 返回 200。演示截图：[桌面](../图片/V5-陪学会话-桌面.png)、[手机](../图片/V5-陪学会话-手机.png)。截图来自隔离的合成数据浏览器验收，不代表真实学习成绩。
