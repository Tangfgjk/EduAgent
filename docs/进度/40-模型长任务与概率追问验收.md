# 模型长任务、调用额度与概率追问：首版验收

日期：2026-10-17（北京时间）。API：`0.11.0`；数据库：`p0_001`；分支：`V7-20261016`。

本文新增记录，不改写原有 docs。38/39 号文档描述厂商扩展范围与此前独立连通状态；本次将受限模型追问接入概率练习，其他单元、圆桌、我教 AI 和资料规划仍按原有能力运行。

## 1. 本次交付范围

- 持久模型任务：冻结输入、配置快照、额度预约、事务外调用、续租、取消、过期结果拦截和中断恢复。
- 管理端“配置与权限”：DeepSeek/Fake 开发配置发布、额度设置、停用、最近调用状态和已知 token 记录。
- 学生端概率练习：“让 AI 听听我的思路”，可提交当前思路、等待/刷新恢复、查看原文引用和追问、取消本次模型任务。
- 模型选择受限的追问方向，不负责判分，不生成任意教学正文，不给素养评分；程序继续核验数学数值。

**这是受限追问首版，尚非自由对话陪学。** 模型依据学生原文输出结构化的 `quote` 和 `focus`；服务端核对引用确实来自本轮输入，并按当前提示级别验证方向。页面的追问措辞取自受限支架，不能把它描述成模型自由生成的教师讲解。此设计先验证真实模型理解方向与工程闭环，避免任意模型文本绕过现有提示和检测规则。

## 2. 负责人确认的调用边界

| 项目 | 首版规则 |
| --- | --- |
| 场景 | 自编概率内容包 `math.g9.probability.dev1` 的练习阶段 |
| 账号来源 | 仅 `synthetic` / `adult_test`；真实学生来源继续受阻 |
| 外发内容 | 当前题目、本轮思路、此前已开放的提示；首版不发送历史轮次，低于已授权最多 4 轮的范围 |
| 身份字段 | 不组装姓名、账号、项目标题或跨项目记录；已知姓名/账号、邮箱、手机号做基础替换，但不是完整个人信息识别器 |
| 模型 | DeepSeek 官方 `deepseek-flash`，关闭思考模式；另有明确标记的 Fake |
| 输出上限 | 每次最多 512 tokens，可由管理员调低，不能在页面提高授权上限 |
| 每日次数 | 每账号最多 30 次、全站最多 100 次，可调低 |
| 预算日 | 北京时间每日 00:00 切换；按预约日记账 |
| 重试 | 无自动模型重试；异常不自动改投其他服务商 |

学生提交思路时会开放一级预设提示，并预约一次模型额度。模型失败时已有思路与预设提示保留，不伪装成模型回答。诊断、独立检测、其他单元和未开放的来源不能借此获得模型辅助。

## 3. 任务处理与恢复

### 3.1 处理顺序

1. HTTP 短事务核对账号、空间、当前步骤和提示能力，保存不可变输入及 outbox；冻结模型配置、题目/提示版本与脱敏后的请求，同时预约全站和账号额度。重复幂等请求不重复预约。
2. 教学 worker 在短事务推进原 LangGraph 提示步骤，保存检查点和事实，再将关联模型任务从 `waiting` 改为 `pending`。
3. 模型 worker 以短事务领取任务，设置独立租约 token，释放连接后调用 Provider。默认租约 20 秒、每约 3 秒检查/续租，单次调用总等待上限 30 秒。
4. 完成后再开短事务，核对租约、运行 revision、账号来源/启用状态、空间状态、内容授权及停用代次；通过后保存受限建议和用量。

网络等待期间不持有业务数据库事务。学生在等待时仍可以继续作答，但这会改变 revision，使较早的模型追问不能成为当前建议。

### 3.2 持久状态

| 状态 | 含义 |
| --- | --- |
| `waiting` | 思路与额度已保存，等待教学步骤落库 |
| `pending` | 可由模型 worker 领取 |
| `running` | 已领取，可能已发出外部请求 |
| `succeeded` | 结构化结果与引用/方向检查通过 |
| `failed` | 明确失败、输出不可用或教学输入处理失败；保留预设提示 |
| `cancelled` | 学生取消模型任务或结束陪学 |
| `discarded` | 进度、授权、内容或停用条件变化，结果不再适用 |
| `unknown` | 超时、传输异常或领取后进程中断，无法确认远端结果 |

`pending` 任务重启后可以领取；过期的 `running` 任务转为结果未知，不重新调用模型。旧 worker 不能在取消、租约失效或新输入之后提交当前结果。管理员停用后再发布新配置，也不会让停用前的旧任务重新生效。

这是本地结果一致性保证，不是服务商“只扣费一次”的保证。本机取消/断连不保证远端停止生成或计费；未知结果保留额度，不自动重发。

### 3.3 进程分工

建议分别运行教学与模型两个 worker，避免一个慢模型请求占用教学队列。兼容的 `combined` 模式保留给本机排查；单进程模式会等待当前模型请求完成。

```powershell
.venv/Scripts/python.exe -m app.main --env-file .local/database.env
# 第二个终端：
.venv/Scripts/python.exe -m app.worker --env-file .local/database.env --lane teaching
# 第三个终端：
.venv/Scripts/python.exe -m app.worker --env-file .local/database.env --lane models
```

## 4. 额度与用量口径

- 在同一短事务中锁定模型策略、全站额度和账号额度。并发请求不能突破全站/账号次数；额度不足会回滚本次输入与预约，普通预设提示仍可用。
- 次数在预约时消耗，取消、失败、未知结果不返还；Fake 与真实开发模型共享预约账本，切换配置不清零。
- 保存请求型号、返回型号、配置 ID、提示版本、内容版本、请求摘要、输入/输出 token、耗时和错误码；调用与原输入、账号、空间、运行关联。
- 原始模型正文不写入通用日志；只保存通过校验的建议。管理概览不展示学生原文，密钥不进入数据库或响应。
- 管理端“已知 token”是已获得的部分用量合计；另显示缺失用量和费用未知次数，不能将缺失项当作 0。Fake 明确标记为模拟，不产生真实外部模型费用。
- 尚未实现人民币日预算、服务商账单核对或价格版本；次数/输出 token 上限不能冒充精确费用上限。

## 5. 管理员和学生怎么用

### 5.1 本机密钥与发布

```powershell
.venv/Scripts/python.exe -m app.manage set-model-key
```

隐藏输入密钥，保存到 Git 忽略的 `.local/deepseek.key`；部署时可使用 `WENJIN_DEEPSEEK_KEY` 环境变量或 `WENJIN_DEEPSEEK_KEY_FILE` 指定的受限文件。环境变量优先。不要把密钥写进前端、文档、命令历史或 Git。

本机本次已配置密钥文件，并限制为当前 Windows 账号访问；文件存在不代表模型自动开放。数据库初始策略为停用。

管理员进入 **配置与权限 → 模型与运行配置**：

1. 选择 DeepSeek 真实开发模型或 Fake 模拟测试。
2. 核对每次输出、每账号每日次数与全站每日次数。
3. 勾选开发用途确认并发布。
4. 在“知识点与题库”核对并启用概率开发内容；模型配置与题目开放分别管理。
5. 查看最近任务与用量，必要时点击“停用模型追问”。发布新配置生成新 ID，不改写已预约任务的配置；停用会使旧结果失效。

### 5.2 学生概率路线

1. 选择临时空间，或先在正式项目确认学习计划。
2. 在“津津陪学”选择概率单元并开始，独立完成初始诊断。
3. 进入练习，在“让 AI 听听我的思路”填写当前思路，点击“提交思路并请求追问”。请勿填写个人信息。
4. 系统开放一级预设提示，同时处理模型追问；刷新后可继续查看状态。
5. 查看引用和追问，继续数值作答、反思及无辅助检测。模型任务可单独取消；继续作答会使旧建议失效。

额度耗尽、管理员未开放、失败或未知时，仍可沿现有数值核验与预设提示路线学习。圆桌、我教 AI、资料规划尚未因此切换到真实模型。
