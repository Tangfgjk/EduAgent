## 4 启动开发环境

在仓库根目录依次执行：

```powershell
uv sync --locked --extra dev
uv run --locked python scripts/dev_postgres.py
uv run --locked python -m app.manage --env-file .local/database.env migrate
uv run --locked python -m app.manage --env-file .local/database.env bootstrap-admin --username admin
uv run --locked python -m app.main --env-file .local/database.env
```

初始化步骤通过隐藏输入收取两次密码，长度 12–128 字符。`admin` 是命令示例，可以自行更换。不要将密码放进命令参数或聊天。第二次 bootstrap 会明确拒绝。

API 文档：`http://127.0.0.1:8000/docs`；就绪检查：`http://127.0.0.1:8000/health/ready`。本期尚无登录/项目 React 页面，根地址不再显示无认证旧教学页面；原 HTML 演示仍在 prototypes 中。

开发数据库密码为本机随机生成，连接配置保存在忽略的 `.local/database.env`，容器配置在 `.local/postgres.env`。启动器不输出密码或连接字符串。这两个文件需与开发数据卷一起保留，不能在已有数据卷时随意重新生成密码。

`compose.dev.yml` 固定 PostgreSQL 17.11 与已验证镜像摘要。需要暂时停止数据库时执行 `docker compose -f compose.dev.yml stop db`，数据卷继续保留。首次拉取和启动要求 Docker Desktop 可用。

本机开发默认 HTTP；未来内网 HTTPS 部署设置 RSI_COOKIE_SECURE=1，并配置 RSI_ALLOWED_ORIGINS。正式域名与部署负载在后续阶段确认。

## 5 接口使用与事务保证

### 5.1 已实现接口

前缀 `/api/v1`。账号接口为 `/auth/login`、`/auth/me`、`/auth/logout`。管理接口为 `/admin/students` GET/POST、`/admin/students/{id}/reset-password` 和 `.../disable` POST。

学生接口为 `/student/workspaces` GET/POST，`/student/workspaces/{wid}` GET/PATCH，`.../archive` 和 `.../restore` POST。写入体中的 expected_revision 是当前服务端版本；过期版本返回 409。

登录返回 account、csrf_token，并设置会话与 CSRF Cookie。前端后续同源请求携带 Cookie，写请求设置 X-CSRF-Token。CSRF Cookie 可供刷新后的页面读取，登录凭据 Cookie 为 HttpOnly。已登录学生访问管理操作返回 403；猜测别人的空间返回 404。

创建工作空间还要求 Idempotency-Key 请求头（1–128 字符，建议 UUID）。网络重试复用同一个键和原始内容，返回已有空间的当前状态；同键不同内容返回 409，避免刷新或重试重复建项目。归档/恢复仍按 expected_revision 检查，不重复记录已经达到的目标状态。

创建账号的 source_kind 来自服务端 RSI_DATA_MODE，默认 synthetic；浏览器不能修改。只有经过后续试点准备的环境才可切换 real_student，开发数据不能通过改设置被追溯重标。

### 5.2 并发与持久输入

PostgreSQL 每个业务事务先锁定授权账号，再锁定工作空间与会话，使禁用、归档、接受输入具有确定先后顺序。授权和修改在同一个事务内；返回成功前完成提交。SQLite 开发适配用显式事务序列化写入，不能据此替代真实 PostgreSQL 验收。

同幂等键同原始请求只返回既有输入，不生成第二个 outbox；同键不同内容返回 409。归档前已接受的事实保留；归档后不接受新输入，但允许读取已有事实和重放已有接受结果。队列租约过期后换 token 重新领取，旧 token 无法确认完成。

真实学生全局来源查询默认同时排除临时空间和 synthetic/adult_test；开发检查可显式查看开发来源。项目局部查询仍校验归属。当前没有前端成长统计端点；这些过滤是后续 S06/S08 必须复用的持久层规则。

## 6 备份、恢复和旧库迁移

以下操作应在维护窗口停止 API/worker 后运行。逻辑备份含密码哈希和学习原文，需要按敏感文件保存；校验哈希检测损坏，不替代可信来源管理或加密备份。生产级备份保留、权限与恢复演练在 S11 完善。

```powershell
uv run --locked python -m app.manage --env-file .local/database.env backup --output .local/backups/s02-backup.json
```

相同输出路径不会被覆盖。恢复目标必须是已经执行相同迁移的空数据库；不能对已有账号或学习数据的库直接恢复。先为新目标创建独立 env 配置，再执行：

```powershell
uv run --locked python -m app.manage --env-file .local/restore.env migrate
uv run --locked python -m app.manage --env-file .local/restore.env restore --input .local/backups/s02-backup.json
```

验收在 SQLite 和独立 PostgreSQL schema 上分别执行了备份/恢复，检查项目、已接受输入、outbox 与旧数据记录保持一致，登录会话未恢复；再次覆盖及损坏备份被拒绝。

如有真实旧版本 SQLite，指定实际文件；不要把下面的示例路径当作已经存在：

```powershell
uv run --locked python -m app.manage --env-file .local/database.env import-legacy --source data/rsi.sqlite3 --snapshot .local/backups/legacy-first.sqlite3
```

源库以只读方式打开，先用 SQLite backup 保存一致快照，再将原始各表行导入 legacy_records，记录表数量与哈希。同一内容重复迁移幂等；未知表结构拒绝并保留快照。本轮仅迁移测试生成的旧库，没有擅自绑定任何历史 learner 到新学生账号。历史数据进入正式学习投影之前，须单独核实身份、项目和来源；当前保全完成不代表已接入新学习流程。
