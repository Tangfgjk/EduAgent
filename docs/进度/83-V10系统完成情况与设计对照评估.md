# V10 系统完成情况与设计对照评估

评估日期：2026-10-18。评估代码基线：`V10-20261018` 的 `327a460`；该快照已推送至 `Tangfgjk/EduAgent`。本报告及审查后的测试维护作为后续独立提交，不改写快照历史。接口版本 `0.13.0`，数据库版本 `v8_001`。

## 1. 结论

**目前已经形成可运行、可恢复、有权限隔离的初中数学开发系统，能够在自编样题和模拟/成人测试范围内走通主要学习路线；尚未达到最初完整产品和真实学生试点的设计预期。**

已经落地的主干是：独立学生端/管理端、项目与临时空间、计划确认、固定数学学习闭环、概率真实模型追问、三轮我教 AI、模型圆桌、错题复习、来源可追溯的成长证据、有来源规划候选及双重确认、模型任务与评测复核。

差距集中在：七至九年级课程覆盖、数学过程/证明评价、专业教学审核、成长证据的素养展示与测量、跨任务个性化学习者模型、完整运行治理、多 Provider 与真实试点运维。审查还复现了**自由模型追问可携带中文答案的输出门禁缺口**，应优先修补。

不采用“完成百分比”：原始愿景、阶段交付、页面入口和教学效果的工作量及验收条件不同，现有题目/测试数量不足以换算整体产品完成度。

### 框架是否符合最初选择

符合已确认的“LangGraph + 按需 LangChain”方向。新版使用 LangGraph `StateGraph/interrupt`，短图的 SQLite 检查点镜像由业务事务存入数据库，真实模型在独立运行器事务外调用（见 [19 决策](../架构/19-S04运行与检查点决策.md)）。这与 13 中最初建议的原生 PostgreSQL checkpointer 实现不同，已有后续决策，不能写成完全按最初组件清单照搬。

Provider 当前采用自有小接口和 HTTP 适配，尚未直接引入完整 LangChain 模型集成。按需使用的确认允许这一实现；安装框架本身不会补齐认知诊断、教师审核或课程理解。旧 `app/orchestration`、`app/learning`、`evolution` 的样例与新版 `app/modules` 并存，扩展前要明确调用路径，避免把旧演示能力列为正式产品能力。

## 6. 后续建议与完成标准

### 第一优先：补可信边界和可检查性

1. 修复 F01，统一模型可见输出门禁，覆盖中文答案、等价描述、伪问句和不当归因；复验 Teach/圆桌生产任务路径，失败能安全回退，保留学生已提交内容。
2. 对齐管理端实际外发范围说明，拆清厂商型号与提示版本；补可脱敏的错误子码、运行检索/死信和各路线状态，让 PL03、T04/T05 可定位。
3. 组织数学审核者复核当前内容和模型样本，明确未通过项的关闭条件；在专业审核前继续限定开发用途。

### 第二优先：完成最近计划和可用产品体验

1. 完成 68 第二步剩余的成长证据/素养展示：事实、自述、人工判断、待复核推断可分辨；维度能钻取具体来源，未评定保持缺失态，不用次数生成能力分数。
2. 将课程覆盖台账逐项变为可用内容包，每包有知识点/先修、题目/提示/误区、独立验证题和审核真值；扩展多种表达式与过程验证，不能只扩入口。
3. 将受限策略逐步连接诊断、任务选择与复习，形成可解释课程路径；需要扩大软策略 Schema 或模型数据范围时再确认新边界。

### 第三优先：试点与长期愿景

1. 为选定场景补授权/撤回、导出/删除、最小角色权限、部署和备份恢复、实际金额/限流与压测。确认硬件、人数、审核支持和内容后，再批准真实学生试点。
2. 逐家适配常见模型并做协议、用量、取消/超时和业务评测，记录厂商/端点/型号/版本；已授权 DeepSeek 开发数据不能默认流向新厂商。
3. 真实独立前后测、学生自主性指标和教师纠正积累后，再建立学习者模型校准、数字孪生、技能结晶与策略晋升。自动 RSI 仍遵循既有启动条件，不以模拟调用数替代真实学习者、持续时间或教师金标。

产品方向仍与最初的“学生自主学习、证据驱动调整、神经符号分工、人类审核及学生决定权”一致。当前主要问题是已实现范围较窄、教学可信度和试点能力尚未补齐；下一阶段应优先完成上述验收条件。
