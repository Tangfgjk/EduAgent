# V12 下一步完善与验收计划

更新：2026-10-18。基线：API 0.18.0、数据库 `g08_001`，主服务 4003。本文接续 G00–G08 首轮开发，作为后续安排；原始设计和历史验收记录保留。

## 一、方向与当前起点

产品继续面向七至九年级数学自主学习，以课标知识点组织内容，以正式项目隔离长期学习，以临时会话承接短期探索。目标闭环是：诊断理解 → 安排活动 → 学生思考与表达 → 脱离帮助再检验 → 依据证据调整策略。

已具备：双端账号与项目、学习计划、陪学/复习/圆桌/我教 AI、可追溯证据、主题课程生成与审核、文本资源导入、受限策略执行，以及离线 Skill 候选与机制评测。详细范围见[汇报介绍](../汇报/103-V12开发进度与功能实现介绍_20261019.md)。

G00–G08 的“首轮工程实现”不等于最初产品目标全部完成。主要缺口是：课程覆盖窄，长篇讲解语义评阅不足，素养没有专业量规，G08 采用结构化规则而非真实模型语义进化，真实学生效果与试点运营尚未验收。

## 二、第一步：加深已有闭环，先补可验证性

### 1. 扩大内容与评测样本

- 建立“课标目标—知识点—先修—题族—核验器—活动—专业审核”的覆盖台账，明确六个开发 KC 与完整课程的差距。
- 优先把有理数一个主题做深：概念边界、常见误区、不同表示、解释任务、等价变式和延迟检测；再按相同规范扩充其他题族。
- 扩大冻结评测语料，区分开发集、隔离保留集和真实未见测验；以版本和曝光记录防止同题重复被当成迁移。
- 加入漏条件、无解/多解、错误引用、提示泄题、混淆表示、恶意来源和越权策略等失败样本。

实现：沿用 knowledge/generation/learning 模块和版本注册表，为新增题族实现独立核验器；不以模型自评替代数值、条件与专业内容检查。

验收：每个新增题族有通过/拒绝/边界用例；检测题与练习/资源隔离可追溯；无核验器的任务明确标注待人工，不伪造自动通过。语料与覆盖台账可重复生成核对。

### 2. 完善真实交互

- 用经过授权的自编/成人开发样本逐条评阅陪学、圆桌和我教 AI：是否针对当前表达、是否先澄清、是否泄露答案、是否形成有效下一问。
- 保持数学答案独立核验。数值通过、解释合理性与教学适切性分别记录。
- 当前受限意图与模板仍是默认安全展示；自由语义内容须经过独立评测和审核，逐项开放。
- 明确支架状态：首次尝试、逐级求助、自问、恢复帮助、独立检测。检查学生能恢复支持，避免把“少提示”当成唯一目标。

验收：有冻结的多轮样本、逐条人工意见和版本对照；失败意见保留，不能只展示成功个案；同一题曝光不计入未见效果。

### 3. G08 模型语义候选增补

先保留现有规则基线，再通过 Provider 接入受限模型候选。输入冻结项目证据，输出只允许一个白名单参数变化、引用和改进假设；候选必须经过 schema/来源/权限校验、实际消费者评测和原审核流程。

验收：规则/模型来源清晰区分；越权字段拒绝；证据不足可以不产生候选；旧报告在代码/语料/来源变化后失效；评测通过仍不能自动发布。模型理由合理不等于教学收益。

**开始真实调用前需确认**：语义候选新增输入范围、脱敏方式、单次/总 token 和调用预算、评阅责任。既有课程生成授权不自动扩大到新的 Skill 语义评阅数据。

## 三、第二步：建设教学可信度和资源体验

### 1. 专业内容与素养量规

- 确认数学专业审核负责人，制定概念、解法、误区和活动目标的审核清单。
- 给六个素养观察方向定义适用任务、证据要求、等级描述和“证据不足”规则，安排双人评阅和分歧复核。
- 在量规和一致性验证完成前，现有条形继续表示“候选材料数量”，不转换成能力雷达分或综合排名。
- 核对教材/考纲版本、使用权及知识点映射；搜索发现和授权正文继续分开管理。

验收：能从展示结果追到任务、作答、评阅者、量规版本；不同题型可比性有说明；不以字数或提交数代替推理质量。

### 2. OpenMAIC 与课程资源

- 先完善已有文本课堂的公式显示、阅读布局、来源标注和错误处理，保留导入隔离、大小限制和沙箱。
- 设计“课程版本—资源版本—练习阶段”的绑定和撤回提示，检测阶段不展示资源。
- 如需媒体、交互或第二门真实生成课程，单列格式适配、沙箱威胁、生成成本与人工核对方案。

验收：恶意 HTML/脚本不能执行；资源不泄露检测题；撤回阻止新使用，历史事实保留；停止预算后不继续生成。当前首轮 OpenMAIC 预算已停止，服务启动不代表可以再付费生成。

### 3. Provider 扩展与可观测性

现有统一接口与 OpenAI-compatible 适配不能等同于所有厂商已经验收。逐个增加服务商配置、错误映射、结构化输出、超时、用量记录及能力探测；管理端配置，学生端只选择学习任务。

先完善真实 DeepSeek 路线的失败/未知结果、排队进度、取消边界和用量解释，再按实际需求扩展其他厂商。未知计费不记为免费；开发次数为 0 表示不限次数，仍存在费用。

验收：每个厂商有独立适配测试和授权连通记录；切换不改变已开始运行的版本；密钥不进页面、日志、仓库；不支持的能力明确拒绝。

## 四、第三步：G09 小范围试点准备与验收

### 工程工作

- 明确数据分类、可访问角色、保留周期、导出/删除/撤回机制与审计，覆盖数据库、备份、模型与资源记录。
- 建立备份恢复演练、升级回退手册、worker 崩溃/租约恢复、并发隔离、队列积压、预算预警与容量检查。
- 增加端到端异常场景：跨项目访问、资料撤回、审核冲突、网络中断、上游未知、重复点击和失效策略。
- 设计真实无辅助前后测、延迟测与等价迁移任务，记录曝光和帮助；明确样本小、缺失与偏差，不直接声称因果提升。

### 试点前必须由项目方确认

1. 参与人群、规模、负责人、专业审核资源；是否涉及未成年人及对应授权。
2. 外部模型/搜索服务的数据范围、费用上限、用途与撤回安排。
3. 数据保留、删除和备份制度；内网部署、域名、HTTPS 与访问权限。
4. 教学评价设计、停止条件及人工干预责任。

验收：先用隔离测试数据完成工程演练，再按已批准范围做小样本试点；缺少专业审核、数据授权或效果证据时继续标记开发版。自动真实 RSI 晋升保持关闭，另作后续决策。

## 五、推进顺序与完成判定

| 顺序 | 可以立即推进的工作 | 需先确认的工作 | 交付物 |
|---|---|---|---|
| 第一步 | 覆盖台账、冻结样本、规则基线、交互评阅表 | 新语义候选真实调用范围 | 题族核验与失败报告、多轮对照、候选评测报告 |
| 第二步 | 文本资源体验、来源/失效提示、Provider 离线契约 | 专业审核人、量规、媒体与新服务预算 | 专业内容与量规版本、资源验收、厂商适配台账 |
| 第三步 | 隔离数据异常/恢复/并发演练 | 真实试点人群、授权、预算和评价设计 | G09 试点准入记录、运维手册、试点评估 |

每项完成均需代码、操作说明、可重复验收和剩余边界；工程通过与教学通过分别记录。后续任务变更回写本文，原验收快照不覆盖。
