## 3 复现命令

在仓库根目录执行。已验证 uv 0.11.7、CPython 3.13.5；运行时/测试依赖以原有 `uv.lock` 为准，安装使用 `--locked`，本轮未改变锁文件中的版本。

```powershell
uv sync --locked --extra dev
uv run --locked pytest -q
uv run --locked python scripts/check_server.py
uv build --out-dir .local/dist
uv run --locked python scripts/check_wheel.py .local/dist/rsi_platform-0.1.0-py3-none-any.whl
```

日常启动：`uv run --locked python -m app.main`，默认 `http://127.0.0.1:8000`，服务仍展示初版旧页面。智能体终端入口继续为 `uv run --locked python -m app.cli`。

本轮执行环境的沙箱临时目录权限有异常，首次回归出现 50 passed、1 failed、10 errors；改用项目临时目录后沙箱 TestClient 仍阻塞。随后在正常本机进程运行同一回归全部通过，挂起的检查进程已结束。因此不把这些权限错误归因于教学代码。普通本机开发通常不需要额外环境变量；受限运行器需提供可写的 UV_CACHE_DIR/TEMP/TMP，并保证本机线程/回环网络可用。

## 4 安装包修复说明

原配置 `packages = ["app"]` 遗漏动态导入的 `evolution` 以及外部资源。源码目录和可编辑安装会掩盖遗漏。修复前 `check_wheel.py` 明确报告三个缺失路径；修复后从 sdist 构建的 wheel 能脱离源码运行。

为保持旧版本行为，本轮将 seeds 与 web 按旧相对路径打入 wheel，相邻于 app。它们暂时是此项目独占的安装资源，建议使用独立虚拟环境。后续内容服务与 React 构建接管后再迁移资源边界，不在 S01 改写静态页面路由。

配置方法参考 [Hatch 官方构建配置](https://hatch.pypa.io/latest/config/build/)的 packages、force-include 和 sdist 文件选择。分发包不包含 `.env`、demo workspace、真实学习数据或研究原件。

## 5 当前明确的能力边界

- SQLite 可保存学习事件与快照，不能据此声称会话内存状态可重启恢复。持久会话、项目身份隔离与 outbox 属于 S02/S04。
- 现有网关没有正式身份/权限控制，仍仅作为本机开发基线使用。
- SSE 当前是 status/status/reply，无续传、取消或持久运行关口。
- 两个 HTML 原型仍为离线演示；React 双端没有开始实现。
- RoundtableGraph、TeachGraph、PlanningGraph 与真实策略审核/激活没有实现；现有 L0 沉淀接口不替代这些功能。
- 自编开发题、FakeLLM 和成人检查不能计入真实学生效果或素养评分。
