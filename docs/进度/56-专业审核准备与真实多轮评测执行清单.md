## 次日人工启动时的顺序

1. 确认上海时区日期已自然进入次日，固定账号和密钥配置仍有效。
2. 两组先做只读预检；开始整轮前应确保账号和全站预算至少还能容纳 28 次，并避免同期其他评测消耗。预检不预留预算，正式调用仍由运行器执行原有预算校验。
3. 先执行 18 轮基线并检查实际状态，再执行 10 轮独立样本。不因结果差而追加调用，不自动重试。
4. 中断时保存工具输出的运行目录，先检查已有账本；只用同一目录 `--resume`，不新建账号或清空数据库补跑。来源指纹变化时应说明原因，不能改历史 manifest 绕过检查。
5. 汇总真实状态、有效输出、参考匹配、上下文对照、历史污染、失败类型、耗时和 token usage。开发参考匹配不是教学有效性，也不等于教师金标。
6. 报告先保存在忽略的 `.local/evaluation`；审查确认不含密钥和身份数据后，新增冻结报告。当前管理端只读三个显式注册报告，新结果不会自动进入工作台，更不会自动发布策略。

```powershell
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --check-only
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus holdout --check-only

# 仅在日期和额度满足时执行以下两步
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live
.venv/Scripts/python.exe scripts/evaluate_probability_multiturn.py --live --corpus holdout
```

仍沿用既有授权：自编开发题与固定模拟账号、每次最多 512 输出 tokens、当前题与当前输入加最多三条历史成功轮次，不发送身份或跨项目记录，无自动重试。后续真实模型“我教 AI”尚需单独确定允许的数据与响应格式，不能据此自动扩大调用范围。
