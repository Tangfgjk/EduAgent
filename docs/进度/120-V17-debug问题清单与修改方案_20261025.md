# V17-debug 问题清单与修改方案

## 1. 分支与目标

开发分支：`V17-20261025-debug`，从 `V17-20261025` 的 `243a3ea` 新建。

输入依据：119号《V17后端Agent化与首次使用体验审查》及用户本轮提出的成长页长页面问题。119号报告及本方案一起保存在本分支。本轮编写方案，不修改业务代码、不改变数据、不执行真实模型或媒体生成。

目标是把现有功能做得可信、连贯、易发现。保留核心学习路线和原始证据；页面精简不等于删掉教学能力或通过隐藏错误绕过后台规则。

## 2. 成长页为什么需要重新组织

当前 `EvidencePage` 与 `LearningAnalysis` 连续渲染概览、知识点地图、学习表现、复习矩阵、支架时间线、素养材料、规划摘要、阶段统计、日历、趋势、来源记录。每块图表可能有独立价值，但将它们全部并列展开没有表达主次。

用户面临四个问题：不知道共有多少内容；不知道目标内容在哪；看到图形后不知道该采取什么操作；切换范围或追溯来源后难以回到原来的位置。加一个折叠按钮、浮动回顶按钮或锚点目录，只能减轻滚动，不能完成信息重组。

代码补充发现：`learning-insights.tsx` 的“供规划使用的学情摘要”仍直接展示摘要JSON、指纹和来源索引。这是V17精简遗漏，应从学生视图移除，保留供管理诊断使用的数据接口与必要记录。

## 3. 成长页的目标布局

左侧仍只保留一个「成长」入口，页内用五个可见分类组织。默认进入总览，分类点击后仅渲染所选内容，不再将全部图表放在同一个滚动文档中。

```text
成长                         范围：当前项目 / 全部正式项目
                             时间：14天 / 30天 / 90天

总览 | 知识与表现 | 复习与支持 | 素养材料 | 学习记录

[当前分类的内容与操作]
```

### 3.1 分类与现有内容映射

| 分类 | 用户想知道什么 | 展示内容 | 下一步操作 |
| --- | --- | --- | --- |
| 总览 | 最近做了什么、现在该做什么？ | 最多四项简明摘要、一张紧凑趋势图、一项有明确依据的下一步；五类内容的简短说明与入口 | 继续当前学习、查看到期复习，或查看某类证据 |
| 知识与表现 | 练过哪些知识？独立作答和求助后表现如何？ | 二级切换“知识覆盖 / 作答表现”；知识记录地图、按辅助与曝光分组的数值表现、必要的阶段统计 | 查看对应尝试、返回该项目继续学习 |
| 复习与支持 | 哪些需要复习？我什么时候需要帮助？ | 二级切换“复习安排 / 帮助使用”；复习矩阵、支架时间线；详细作答与调度仍进入现有复习页 | 去复习、查看触发记录 |
| 素养材料 | 哪些作品可用于观察数学思考？ | 六类材料覆盖、作品数量、具体讲解/反思/活动材料及待评状态 | 打开材料、补充自己的反思；有权限的评阅另走既有流程 |
| 学习记录 | 某一天、某次尝试发生了什么？ | 月历与筛选后的时间顺序记录列表，来源追溯；记录列表分页 | 查看原始记录，返回原筛选与位置 |

“供规划使用的学情摘要”不再作为一个开发统计模块常驻页面。总览提供“基于这些记录调整学习方式”，跳到既有规划页；在那里展示本次实际采用的依据。学生需要理解建议依据，不需要阅读序列化数据。

### 3.2 操作与视觉规则

- 五个分类在首屏全部可发现。桌面采用固定在内容区域顶部的页内导航；手机采用能同时显示五项的紧凑换行导航，不以隐藏的横向滑动承载核心入口。
- 每个分类顶部只回答一个主要问题。一个视图至多保留两个主要图表，其余用二级切换或“查看详情”进入，不再次堆成长页。
- 一级分类、范围、项目、时间写入URL，例如 `?workspace=…&scope=workspace&view=knowledge&panel=performance&days=30`。刷新、分享、浏览器前进后退均恢复对应状态。
- 从项目内进入时默认当前项目；从明确的“全部项目成长”入口进入时使用全局。标题始终显示实际统计范围，不能只用顶部工作空间选择暗示全局统计属于当前项目。全局继续排除临时会话。
- 总览最多显示少量有来源的计数，不自动生成掌握度、能力分数或未经验证的“你进步了”。无数据显示下一步可做的学习动作。
- 素养材料优先采用有明确“条数”单位的柱形或覆盖矩阵，替换容易被当作能力评分的相对缩放雷达。材料不足显示“尚缺材料”，不能显示能力零分。
- 来源打开为侧栏/对话框，关闭后保留分类、筛选、记录分页和滚动位置。点击某天应查询那天全部匹配记录，不再只过滤当前20条分页而制造“当天没有材料”的假象。
- 日历按月呈现并可翻月，不将90天全部以大按钮铺开。时间窗口和月份之间保持明确关系；超出窗口的月份不可选。
- 范围和时间作为通用筛选固定显示；归档、辅助状态等高级筛选按相关分类展开。数据来源隔离仍在服务端执行。
- 键盘可以访问全部分类；标签与面板关联，切换后的焦点可理解；空状态、加载、出错均只影响当前分类。

### 3.3 组件与数据实现

1. `EvidencePage` 改为范围、URL状态与导航容器；拆分 `GrowthOverview`、`KnowledgeAndPerformance`、`ReviewAndSupport`、`CompetencyMaterials`、`LearningRecords`，复用现有图形计算，避免一次性重写统计口径。
2. `LearningAnalysis` 不再无条件返回全部section。按面板导出或增加明确的视图参数；图形来源选择状态由当前面板管理。
3. 第一阶段复用 `evidence`、`learningInsights` 现有返回值。只启用当前页面需要的查询，取消隐藏分类的固定5秒轮询；通过稳定query key、已有缓存和活动完成后的失效更新保持一致。
4. 当日记录新增/扩展明确的日期筛选接口，返回总量与分页；必须使用原有所有权、来源和时间范围约束。不要从前端当前页假装推导全天数据。
5. 总览计算不另外调用模型；下一步复用统一会话状态与待复习事实。跳转到规划、复习、原始记录时保留范围参数。
6. 记录JSON、指纹、模型/预算信息仅用于管理与诊断。原始证据、接口和审计记录不因界面精简而删除。

## 4. 全部审查问题的整改台账

优先级：P1表示进入更广使用前必须处理的可信度或核心使用障碍；P2表示重要的一致性和可理解性问题。能力缺口单独列验收边界，不用“全部自动化”掩盖尚无条件证明的教学效果。

| --- | --- | --- | --- |
| B01 引号绕过答案检查 · P1 | 只豁免已核对的真实学生引用；检查模型新增内容、数字变体和完整解法；引用不能豁免编造的答案 | `generation/grounded_response.py`、`interaction.py` | 已复现引号样本被拒绝；真实引用仍可用于追问；对抗集覆盖中文数字、分数、等价措辞 |

## 5. 实施顺序

### D01 反馈与状态可信

处理B01—B05，建立可复现反例和跨页面一致性测试。先修输出检查和能力状态，再基于正确状态调整界面，避免前端用隐藏错误代替后端修复。

### D02 成长页信息架构

按第3节拆分成长页、URL状态、数据加载与来源返回，移除摘要JSON，调整素养图形。此阶段不增加新的能力评分、不改变事实来源和统计含义。

### D03 首次使用与核心学习流程

处理U01—U05；统一路由标题、当前学习会话和跨路线恢复。对课程、陪学、圆桌、我教AI、规划页面逐个套用“当前任务—反馈—下一步”的结构，避免再出现成长页式的无层级堆叠。

### D04 教学执行与资源闭环

把B06/B08拆成已有题族与已有课堂路径的可交付事项：主题状态准确、具体学习安排、明确action执行结果、可诊断生成失败和降级。离线通过后才按当前授权安排真实调用；超出原范围或追加收费另行确认。

### D05 RSI验证平台

完善B07策略暴露、对照采集、停止与回滚机制。没有教师及真实学生时，交付可运行验证平台和模拟/成人工程证据，结论始终保留待验证；不把这一依赖写成代码已经证明教学效果。

## 6. 前端专项验收

1. 新用户进入成长页，首屏能看到五类内容及当前范围，不需要先滚到底才能发现功能。
2. 进入任何分类，只显示其主内容；一级切换保持项目和时间，浏览器刷新/前进/后退可恢复；错误URL有确定回退。
3. 从某图进入原始来源再关闭，分类、筛选、分页及位置保持；当天有20条以上记录时不会因当前分页而显示假空状态。
4. 手机五类入口全部可发现，键盘可切换并理解焦点，页面无水平溢出。
5. 真实无数据、筛选无结果、部分接口失败、正在加载分别给出正确状态；一个面板失败不让其他分类全部不可用。
6. 全局继续排除临时会话；不同来源、辅助、曝光状态不混成能力分数；每个图表都能回到现有证据。
7. 关键动作覆盖：继续陪学、去复习、查看材料、跳转规划、查看原始来源、退出后重新进入。每项保留权限、课程和独立检测门禁。

本方案先作为后续开发基线。119号报告中的问题目前仍是待处理状态，不能因建立debug分支或完成本文就标记为已修复。
