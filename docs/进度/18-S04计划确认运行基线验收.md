# S04：计划确认运行基线验收

日期：2026-10-16。分支：main；未读取其他分支。已有 docs 文档保持原状，本文件为新增记录。

## 1. 本次完成

学生端正式项目的“学习计划”接入真实 API 与独立 worker：

1. 学生填写自己的数学学习目标与每天投入时间，提交后先保存输入、运行与 outbox 任务。
2. worker 使用真实 LangGraph StateGraph 生成开发模板草案，调用 interrupt 暂停，保存确认关口。
3. 学生可以修改时间、更新草案，也可以确认或取消。更新后旧关口失效，必须阅读新草案再确认。
4. 刷新页面、重新创建 worker 或备份恢复到新数据库后，可以继续待确认的流程。
5. 展示运行状态与流程事件。SSE 按 Last-Event-ID 分批续传，页面在有待处理/确认流程时每两秒刷新状态。

视觉沿用现有纸白、浅绿和深绿布局。桌面左右展示目标与草案，手机上下排列。学生端与管理端仍是独立应用。

## 2. 明确的能力边界

- 这是 **S04 的开发运行基线**。页面显式标注“流程试运行 · 开发模板”，草案为固定模板，尚未调用真实语言模型。
- 确认表示学生确认计划，不表示已完成学习，不生成题目、成绩、掌握度或素养分数。
- 本轮只开放正式项目的计划流程。临时探索、完整陪学、复习、圆桌、我教 AI、成长证据计算、S09 规划与 Harness 审批仍按既定阶段继续。
- 当前目标协商图是 `plan-setup.v1`，并非 S09 的规划 Agent。不会修改 Skill.md 或教学规则。
- 当前检查点方案仅供短时、无网络副作用的开发图；接真实模型/工具前必须完成 [运行边界决策](../架构/19-S04运行与检查点决策.md) 中的升级。
- 外部模型供应商、型号与预算仍待用户确认；项目既有旧模型配置不视为本轮选型。

## 3. 隔离与可靠性

- 每份计划关联账号拥有的 workspace 和内部 tutor conversation；客户端不能指定 learner_id、thread_id 或切换运行归属。
- 新建计划使用项目范围的幂等键；同键异内容拒绝。同项目最多一个未完成计划，避免多标签页重复发起。
- 确认/调整检查运行版本、revision、gate_id、当前项目状态与登录权限。同键原请求可以安全重放。
- 目标提议和最终确认复用原 ActionGovernor；最终确认只能由学生提交。现有规则仍是早期规则，不能视作已完成内容治理。
- worker 重查账号是否启用、项目是否归档与流程版本；租约 token 防止旧 worker 提交。最多五次失败后显示终态，不无限等待。
- 检查点镜像、业务状态、事件与任务完成在同一事务提交。失败则一起回滚，重试不会留下半份草案。
- 取消保留已接收输入和事件，之后不继续执行该运行。worker 已持有短事务锁时，取消请求可能先遇到版本冲突；刷新后再取消。
- 事件表通过数据库触发器只追加。接口只返回公开状态、草案与安全事件，不返回检查点、模型思维链、密码或数据库连接。
- 即使宿主配置了 LangSmith tracing，本流程仍显式禁用外部追踪。

## 4. 开发运行

在仓库根目录：

```powershell
uv sync --locked --extra dev
uv run --locked python -m app.manage --env-file .local/database.env migrate
cd frontend
npm ci
npm run build
cd ..
uv run --locked python -m app.main --env-file .local/database.env
```

另一个终端：

```powershell
uv run --locked python -m app.worker --env-file .local/database.env
```

学生端：<http://127.0.0.1:8000/student/>。登录后选正式项目，点击“学习计划”。管理员仍通过已有隐藏输入命令初始化，不预设正式密码。

本轮检查时正式库管理员数量为 0。首次试用需要你在本机终端执行下列命令并设置密码，再到管理端创建学生账号；测试账号不能用于正式预览：

```powershell
uv run --locked python -m app.manage --env-file .local/database.env bootstrap-admin --username admin
```

本机 PostgreSQL 已迁移至 `s04_001`。迁移前生成独立 `.local/backups/pre-s04-20261016-173719.dump`；该文件受 .gitignore 排除，不进入仓库。恢复旧版本 dump 应在隔离实例验证，不直接覆盖当前数据库。

S04 的 `app.manage backup/restore` 自动包含新增运行、事件与检查点镜像；登录 Cookie 不恢复。JSON 备份仍只支持相同 schema revision，旧 S02 JSON 不能直接恢复到 S04 空库。
