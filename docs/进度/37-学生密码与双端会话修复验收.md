# 学生密码与双端会话修复验收

日期：2026-10-17。API 0.10.2，数据库仍为 `s09_001`，无需迁移。按本轮要求修改学生密码规则与登录保持；已有文档保留历史原状。

## 1. 学生密码至少 6 位

- 创建学生、重置学生密码的接口与 Identity 服务统一为 6–128 个字符，支持数字及字母等字符，不要求只能输入数字。
- 管理端输入框的最小长度和说明文字同步为 6 位。
- 5 位密码拒绝，6 位可创建、登录与重置；重置后旧会话失效。
- 管理员维护初始化的默认密码规则保持原有要求；不修改现有管理员密码或学生密码。

## 2. 会话问题的复现与根因

修复前运行 `PW_CHANNEL=chrome npm run test:e2e -- session.spec.ts`：普通网页切换返回场景通过；同一浏览器中先登录学生端，再登录管理端，返回学生端后找不到已登录工作台，稳定复现访问状态丢失。

原双端共用 `wenjin_session`、`wenjin_csrf`，登录另一端会覆盖同一 Cookie，退出当前身份还会注销另一端正在使用的会话；同时登录通知共用广播通道。窗口恢复时的身份检查会暴露这一状态变化，因此表现为切回后需要重新登录或切换身份。

排查时依次考虑共享凭据、焦点恢复检查和会话过期。最小双端切换可复现、普通站点往返正常，加上服务端登录/退出路径与 Cookie 定义，确认共享凭据为本次已复现根因。

## 3. 修复协议

| 客户端 | 请求标识 | Session Cookie | CSRF Cookie |
| --- | --- | --- | --- |
| 学生端 | `X-Wenjin-Client: student` | `wenjin_student_session` | `wenjin_student_csrf` |
| 管理端 | `X-Wenjin-Client: admin` | `wenjin_admin_session` | `wenjin_admin_csrf` |
| 既有维护/API 调用 | 不提供该请求头 | `wenjin_session` | `wenjin_csrf` |

前端统一 API 层按页面所在端附加标识并读取对应 CSRF；AuthGate 的广播通道也按端分开。登录、当前身份、退出及业务授权均选用对应会话。提供分端标识但缺少对应 Cookie 时不回退到另一端或旧会话。

请求标识仅用于选择凭据，不能赋予权限。服务端仍核验真实账号角色、账号状态、会话期限及 CSRF；学生请求管理接口继续拒绝。登录界面使用错误角色的凭据返回 403，不创建或覆盖当前会话；未知客户端标识返回 400。

Session 继续使用 HttpOnly、原 SameSite、有效期和 Secure 配置，CSRF 继续独立核对。成功分端登录时清理该浏览器的旧通用 Cookie，避免隐式遗留旧登录。同一学生端的跨标签退出、切换账号通知仍生效，账号切换继续销毁旧私有查询缓存；切换窗口时的有效性检查保留。

## 4. 用户操作与边界

更新后请刷新双端页面并各自登录一次，创建新的分端会话。此后可在同一浏览器同时登录管理员与学生，退出一端不影响另一端。

仍按既有有效期、退出、禁用和密码重置规则失效，并非永久保持登录；同一学生端切换不同学生账号仍以当前学生会话为准，不能继续显示上一账号的私有数据。
