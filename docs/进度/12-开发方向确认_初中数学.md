# 桂子问津初中数学开发方向确认

版本：v0.2，2026-10-15。状态：产品范围、课程组织、开发题库来源和模型访问范围已确认，具体技术方案待评审。本文件新增为后续开发依据，原有基准文档保持原状。本文提出的表结构、验收数量及新增技术组件是开发建议，尚未实施。

## 1 已确认的目标与基准

产品面向七至九年级常见数学单元，以学生自主学习为主要场景，首期在本地或内网开展试点。学生应能自主提出目标，与津津确认计划，尝试解题或探究，在适当提示下检查思路，完成反思和独立检测，并依据证据修订计划。

完整目标包括学生学习工作台、可靠的数学内容和评价、跨会话学习者模型、教师复核与反馈，以及满足既有条件后启动的策略改进。开发顺序以学习闭环和教学可信度为先。北极星延续原设计：无辅助表现增量、认知层级跃迁、学习自主性增益。

本文依次引用 [01 总体架构](../架构/01-总体架构设计.md)、[02 状态 Schema](../架构/02-核心规格_状态Schema.md)、[03 动作与教学规则](../架构/03-核心规格_动作语法与教学法状态机.md)、[04 进化接口](../架构/04-核心规格_进化环接口约定.md)、[06 数据字典](../架构/06-ER图与数据字典.md)、[08 融合裁决](../架构/08-融合方案与优势说明.md)、[10 实施方案](10-实施方案_v1_融合基座与进化就绪.md)及 [11 页面规格](../产品/11-UI设计_v2_Codex风工作台.md)。较早图示与较新裁决有差异时，开发按明确裁决执行并记录依据。例如 10 §2 已决定首期零构建前端，而 §3.1 图示仍提及 Next.js，应以前者为准。

课程组织已确认：先按课标知识点和先修关系建立统一模型，再按需要映射教材版本、年级和章节。课程依据采用教育部发布的 [义务教育数学课程标准（2022 年版）](https://www.moe.gov.cn/srcsite/A26/s8001/202204/t20220420_619921.html?fromColId=204)。首期不依赖指定教材章节顺序。下面的内容域是规划分组，不把同一单元固定绑定到某个年级。

| 内容域 | 七至九年级常见单元 | 需要支持的数学活动 |
|---|---|---|
| 数与式 | 有理数、实数、整式、分式、二次根式 | 运算、等价变形、定义域和错误定位 |
| 方程与不等式 | 一元一次方程、方程组、不等式、一元二次方程及应用 | 建模、求解、检验、解释解的意义 |
| 函数 | 坐标、一次函数、反比例函数、二次函数 | 表格/图像/表达式转换、变化关系与应用 |
| 图形与几何 | 相交与平行、三角形、四边形、全等、相似、圆、图形变换 | 读图、作图、猜想、条件分析与证明 |
| 统计与概率 | 数据收集与描述、统计量、抽样、概率初步 | 数据解释、推断依据与简单随机实验 |
| 综合与实践 | 折扣、测量、校园数据等数学问题 | 提出问题、选择模型、形成作品、检验与反思 |

“覆盖七至九年级”应逐单元交付可用闭环；每个单元必须有知识点、先修关系、任务、分级提示、评价依据和独立检测。仅在导航里列出单元不算完成覆盖。

## 2 页面设计

沿用 11 的项目优先信息架构：左侧学习项目与资料，中间学习任务/对话/画布，右侧教学上下文。主导航围绕“今日、计划、陪学、成长证据、复习、设置”；圆桌、我教 AI、数学探究作为项目内学习方式逐步接入。保留提示阶梯、干预预算、计划确认、反思入口、误区假设和人工出口。

| 页面或工作面 | 首期交付内容 | 完整目标与验收重点 |
|---|---|---|
| 项目导航与今日学习 | 按年级/单元创建项目；最近进度、待复习与未完成任务 | 推荐能说明依据；项目归档和模块关闭不删除学习数据 |
| 目标工坊与计划 | 目标、初始诊断、可修改计划、差异说明、学生确认 | AI 提案经学生确认才生效；拒绝和修改有记录 |
| 数学陪学工作台 | 题干、公式、分步作答、津津对话、提示阶梯、验证反馈 | 学生可先尝试；提示放行遵守规则；作答与对话可恢复 |
| 数学画布 | 坐标与函数图像、基础几何图、表格；记录学生操作 | 图形标注与题目条件一致；图上测量只作为探索证据 |
| 错题本与复习 | 原作答、错误假设、纠正记录、同类题和复习安排 | 错题结论可更正；复习安排可解释、可调整 |
| 阶段检测 | 无辅助检测、提交确认、提交后解析 | 服务端阻止测题提示泄漏；检测与练习记录明确区分 |
| 反思关卡 | 方法讲回、检查依据、预测表现与实际表现对比 | 低负担结构化反思；学生可结束或转人工，出口有记录 |
| 我的镜子与成长证据 | 掌握估计、证据来源、提示依赖、独立检测变化 | 无数据时为空态；估计与实测分开，学生可纠正画像 |
| 设置与数据管理 | 字体、主题、布局、支架偏好、同意范围、导出入口 | 设置不能解除教学硬约束；数据来源和范围对学生可理解 |
| 内容审核与试点治理 | 题目/提示审核、待复核解答、运行问题、人工纠正 | 首期需可用的轻量管理入口；后续扩展教师驾驶舱和师伴 |
| 圆桌与我教 AI | 后续接入多解比较、反例讨论、公开标记的错误示范 | 所有派生动作仍过规则，结论带依据，考试期间受限 |

视觉延续现有品牌、色彩和三栏收纳规则，提供浅色与舒适密度。学生默认看到“检查答案”“查看提示依据”等学习语言；模型版本、调用耗时和技术日志放入开发/治理视图。公式可复制，所有关键操作可用键盘完成；窄屏将右栏改为可展开面板。拍照与语音保留后续入口，接入前先完善文本和公式输入。

每个页面都应验收加载、空数据、失败重试、模型不可用、会话恢复和无权访问状态。测试环境与演示数据显式标记；试点环境数据不足时展示原因。

## 3 功能设计

### 3.1 学习闭环与系统职责

| 环节 | 功能与输入 | 输出与验收 |
|---|---|---|
| 诊断 | 学生目标、年级、已知知识点、小规模诊断题 | 初始估计及不确定性；不足时继续询问，不能给学生贴固定能力标签 |
| 规划 | 先修关系、目标、可用时间、诊断证据 | 版本化计划、理由、任务和检查点；学生确认后执行 |
| 执行 | 作答步骤、请求帮助、修改与数学画布操作 | 适当的任务/提问/支架；Trigger 决定是否介入，策略决定动作，Governor 裁决 |
| 验证 | 题目版本、学生产物、规则和评价标准 | 通过/失败/无法验证、错误位置和可追溯依据 |
| 反思 | 学生自评、策略说明、实际表现 | 反思记录、可复用方法与待核查假设 |
| 调整 | 独立检测、复习结果、学生反馈 | 新计划草案、复习队列和证据更新；重要变更再次确认 |

知识点模型需支持先修边、误区、合法策略族与表征转换。每次新任务关联知识点与题目版本。教师复核和学生纠正通过补偿记录更新后续判断，保留原始过程。

### 3.2 数学评价的边界

| 类型 | 首期判定方案 | 需要保留的边界 |
|---|---|---|
| 数值、表达式、方程 | 受控解析、SymPy、解集/定义域/精度检查 | 分式与根式考虑条件；等价结果不等于所有步骤都合理 |
| 应用题 | 分别检查变量含义、方程、求解、单位与情境检验 | 支持多种正确建模；不能仅凭最终数值判断过程 |
| 函数与图像 | 检查表达式、点、区间、图像结构与解释 | 数值抽样可发现反例，不能单独证明恒等或全称结论 |
| 几何证明 | 条件与结论结构化、依据检查、人工审核的 rubric | LLM 评价是建议；证明无法可靠验证时返回待复核，不判定必然错误 |
| 统计、概率与探究 | 确定性计算 + 对解释/方法的 rubric | 检查假设和数据来源；探索测量不能替代证明 |

LLM 负责提案、话术与解释辅助；确定性程序负责可判定的数学检查、状态转移和规则门控。数学解析执行白名单语法、资源限额和超时，禁止把学生输入当作任意代码执行。符号解集能力可参考 [SymPy 官方说明](https://docs.sympy.org/latest/modules/solvers/solveset.html)，是否完成判定由验证器契约表达。

### 3.3 持续交互要求

每轮提交有唯一请求 ID、会话序号、任务版本和幂等约束。学生作答先持久化，再启动生成与验证；重复提交不会重复计分或提高提示级别。一次会话的并发提交必须排序，不能让两个请求同时修改当前学习状态。

对话流支持取消、重连、状态查询和刷新恢复；生成失败保留已收到的作答，显示可重试状态。课堂状态从数据库恢复，缓存只加速读取。主动介入遵守冷却期与预算；学生求助、拒绝和画像纠正都进入事件流。

模型配置、提示词、题目、规则集和策略都留版本。每个派生角色携带最小上下文、预算、退出条件和结构化结果；复核后的结果才能转成学生可见教学动作。首期先落实怀疑者/验证角色和反思角色，逐步补齐既有派生体系。

## 4 产品与中间件选型

本节为建议选型，延续现有 Python 与 Web 基座。精确版本在首次实现时做兼容验证并锁入依赖文件；开发、测试和试点环境使用同一锁定版本。

| 层 | 首期建议 | 理由与后续引入条件 |
|---|---|---|
| 前端 | 现有 HTML/CSS/JavaScript 工作台，逐步拆分 ES modules | 延续 10 §2 的明确选择；出现明确组件维护/多端需求时再评审 React 等迁移 |
| 数学显示与画布 | KaTeX + 本地 SVG/Canvas 数学画布 | 公式与图形资产本地提供；KaTeX 关闭可信扩展并限制输入，参考 [官方安全说明](https://katex.org/docs/security.html) |
| API | Python 3.11 基线、FastAPI、Pydantic、Uvicorn | 复用已实现的契约和网关；REST 处理业务提交，SSE 传单向生成事件，双向画布协作需要时再接 WebSocket |
| 持久化 | PostgreSQL + SQLAlchemy 2.x + Alembic | 按 06 的实体设计与 10 的迁移路线实现多用户存储；保留存储适配器，SQLite 用于原型与轻量测试 |
| 数学与学习引擎 | SymPy；当前 BKT；受控抽取 DeepTutor 学习逻辑 | 按 Verdict 接口适配掌握与复习；FSRS 参数先标为默认值，真实数据积累后再校准 |
| LLM | 现有 OpenAI 兼容适配器 + FakeLLM；允许接入指定外部模型 API | Provider 可替换；具体服务商、端点和型号在接入前确定，模型须过数学、教学规则、时延与成本评测 |
| 内容检索 | 首期按知识点与已审题库检索；RAG 按 10 的 LlamaIndex + FAISS 默认线按需接入 | 结构化知识点仍是接地依据；索引记录内容与 embedding 版本，不能覆盖原始内容 |
| 异步任务 | PostgreSQL 持久任务表 + 独立 Python worker | 复习/摘要/内容审核任务可恢复；以租约、重试和幂等处理“至少一次”投递 |
| 缓存与消息队列 | Redis 等列为后续候选 | 多进程广播、任务积压或缓存瓶颈被测量确认后选型；缓存不能成为学习事实源 |
| 作品与附件 | 首期本地受控文件目录 + 存储接口 | 数据库保留文件 ID、来源、校验和与权限；需要跨机器存储时再接 S3 兼容服务 |
| 部署 | 开发可单机运行；内网试点建议 Docker Compose + API/worker/PostgreSQL | 本地打包依赖与静态资产，支持备份恢复；浏览器访问与模型访问分别配置 |
| 观测与验证 | 结构化日志、运行 ID、pytest、浏览器端到端测试 | 日志避免重复输出学生明文；跟踪失败率、时延、规则拦截与恢复情况 |

FastAPI 支持多种数据库库，采用 SQLAlchemy 是本项目的持久化建议，并非框架要求，见 [官方数据库说明](https://fastapi.tiangolo.com/tutorial/sql-databases/)。流式响应能力见 [FastAPI 官方说明](https://fastapi.tiangolo.com/advanced/custom-response/)。Alembic 用于版本化结构迁移，见 [官方教程](https://alembic.sqlalchemy.org/en/latest/tutorial.html)；大批量旧数据迁移另写可重入脚本并核对结果。

## 5 数据库设计

### 5.1 建模原则

沿用 06 的领域实体，本节细化首期落库次序和数学内容扩展。学习界面按 `project_id` 隔离，纵向学习者状态按 `learner_id` 累积；知识点跨项目复用。身份资料与学习事件分离，模拟用户和真实用户按数据空间隔离。

ID、外键、时间、版本、状态等可查询字段使用明确列；不同题型的结构化题干、动作参数与心智状态载荷用带 `schema_version` 的 JSONB。JSONB 支持结构化 JSON 存储，见 [PostgreSQL 官方说明](https://www.postgresql.org/docs/current/datatype-json.html)。不能把所有业务关系藏进一个大 JSON 文档。

### 5.2 首期实体与记录粒度

| 数据域 | 主要实体与粒度 | 关键关系或约束 |
|---|---|---|
| 身份与授权 | User、Learner、ConsentRecord；一条同意/撤回记录一个范围变更 | 学习事件使用伪 ID；每次数据使用核对当前授权 |
| 课程知识 | Curriculum、Unit、KC、Prerequisite、Misconception；一条边一个关系 | 教材映射与 KC 分离，先修图校验循环和失效引用 |
| 数学内容 | Question、QuestionVersion、QuestionKC、Hint、Rubric、ReviewRecord | 作答引用不可变题目版本；提示分级；已审版本才可发布 |
| 学习容器 | LearningProject、ProjectModule、GoalContract、PlanVersion、PlanTask | 确认者/确认时间必填；执行绑定已确认版本，调整生成新版本 |
| 交互事实 | Session、InteractionEvent、PedagogicalAction、Intervention、ToolRun | 事件按会话序号排序；请求 ID 去重；动作关联规则裁决与策略版本 |
| 作答与验证 | Attempt、AnswerStep、Artifact、Verdict、TestAttempt、Reflection | 每次尝试独立记录；区分练习/检测及辅助程度；验证关联题目版本 |
| 学习者模型 | MentalStateSnapshot、KCStateProjection、MemorySummary、EvidenceLink | 快照追加；当前态为投影；每条判断能回链 L1/L2，禁止 L3 引用 L3 |
| 复习与计划执行 | ReviewItem、ReviewAttempt、Checkpoint | 复习计划引用算法/参数版本；实际完成与计划安排分别记录 |
| 运行与治理 | PolicyVersion、HardConstraintSet、TeacherCorrection、AuditRecord、Job | 配置变更有谱系；任务有重试状态；人工纠正保留来源 |
| 开发评测 | Dataset、Scenario、SimulationRun、EvaluationRun、EvaluationResult | 生成种子、模型、版本和来源齐全；与真实学习效果数据空间隔离 |

这些是逻辑实体，具体物理表和字段在数据库实施文档中定稿。SkillLibrary、StudentSimulator、EvolutionJob、PromotionGate 继续遵循 04 的契约，随着既有里程碑逐步实现。

### 5.3 关键写入与数据保护约束

事件与快照在日常教学写入中只追加；纠错用补偿事件。访问权限、撤回、匿名化和受控删除走单独治理流程，避免“只追加”阻碍原设计的数据权利。平台账户没有直接修改规则集或批量删除事实的普通业务权限。

同一事务中记录学生提交、事件与任务入队；后续处理结果再追加事件并更新可再生投影。worker 崩溃后可重试，唯一约束阻止重复结果。生成状态应区分已接收、处理中、完成、失败与取消。

优先索引 `(learner_id, occurred_at)`、`(project_id, occurred_at)`、`(session_id, sequence_no)`、`(kc_id, question_version_id)` 和任务状态/租约到期时间。外键、枚举/检查约束及请求唯一性在数据库和服务层双重执行。行级安全可作为多用户隔离的补充，具体策略须测试包括表所有者的绕过行为，见 [PostgreSQL 官方行安全说明](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)。

### 5.4 从现有工程迁移

先迁事件、快照、契约、计划与会话，解决当前内存会话注册表的恢复问题；随后迁题库、作答、审核、复习和作品。存储适配器保持上层教学契约不变。迁移后按记录数、ID、时间、载荷校验和与代表性会话回放核对；备份恢复演练通过后再切换试点。现有 61 个测试通过的记录属于交接历史，开发环境建立后需重新执行。

## 6 缺少真实学生时如何持续开发

开发前期可以依靠可验证的数学内容、脚本场景、规则模拟与人工体验持续推进。真实学生数据主要用于校准学生行为分布、检验教育效果及后续策略晋升。模拟数据能够检验系统是否按设计工作；真实学习增益仍需真实学习者的前后测和撤除帮助后的表现。

### 6.1 建立分层数据与评测工装

| 数据来源 | 如何构造 | 用途和可信边界 |
|---|---|---|
| 人工审核的数学内容 | 自编或获授权的题目、答案、合法策略、误区、L0–L3 提示、rubric | 为验证器与课堂内容提供真值；参数化变体仍需校验适用条件 |
| 确定性脚本场景 | 固定学生输入、事件顺序、预期规则和状态转移 | CI 回归：计划确认、求助、答错、反思、考试限制、重连与重复提交 |
| 参数化学生模拟 | 控制当前知识状态、特定误区、是否求助、是否拒绝等任务行为 | 检验策略覆盖；参数代表假设，不宣称符合真实学生频率 |
| LLM 学生模拟 | 按局部可见信息生成自然表达与多轮反应；隐藏答案和教师意图 | 发现未预想路径与话术问题；评测结果需独立程序/人工核查 |
| 团队与数学教师试用 | 扮演学生完整走闭环，人工纠正内容和交互 | 发现可用性、教学逻辑与评分问题；经验反馈单独标记来源 |
| 后续真实学生试点 | 经授权的小范围学习活动、独立检测和教师反馈 | 校准与效果证据；样本与持续时间不足时报告不确定性 |

不用“能力差、容易受骗”等人格标签构造学生。模拟条件描述为“本任务尚未掌握去括号”“连续两次符号错误”“拒绝当前计划”等可检验状态，并保留随机种子。

### 6.2 冻结回归集与测试隔离

建议先交付至少 30 个多轮核心场景，与原实施方案一致，再扩展到至少 100 个场景；这属于工程覆盖目标，不代表教育效果的统计样本要求。用覆盖矩阵检查年级/内容域、规则、支架类型、任务类型和异常路径，避免数量达标但全是相似方程题。

必须覆盖：无记录的新学生、正常/非标准正确解、概念与运算错误、连续卡壳、直接索要答案、拒绝计划、画像纠正、考试泄题请求、断网、模型超时、重复提交、并发提交、会话重启、撤回授权。每个已交付单元具有审核过的正确例、错误例、等价表达、边界条件、逐级提示和无辅助检测题。

构建集、调参集和冻结评测集按题目模板/场景族分离，参数化同源题不能随意跨集合。冻结集独立版本管理，由项目负责人和数学审核者共同批准变更；单一开发者或自动优化不能为通过测试直接改答案。LLM 模拟与 LLM 评价不能成为唯一真值来源。

### 6.3 数据来源必须随记录传播

原始记录至少标记 `source_kind`（scripted / rule_simulated / llm_simulated / adult_trial / real_student）、`dataset_id`、`scenario_id`、`run_id`、生成种子、内容/模型/策略版本、目的范围与授权来源。派生摘要与报表继承来源；混合来源记录列明贡献者，不能丢失标记。

开发模拟运行进入独立数据库或 schema/数据空间；真实试点写入另一个空间。模拟数据可驱动页面、知识状态投影和功能回放，但不能计入真实学习增益、真实活跃学生数、教师金标数量和 RSI 点火条件。原设计中的孪生 `trust_weight=0` 边界延续执行。

### 6.4 开发阶段的验收门

| 验收门 | 进入下一阶段的依据 |
|---|---|
| 内容可靠 | 交付单元的题目与提示有审核来源；可判定题均过验证；未知结果能正确转待复核 |
| 机制正确 | 冻结场景中的规则、状态转移、来源隔离和证据回链通过；越界套件预期拦截均成立 |
| 交互可恢复 | 刷新、重连、重复/并发提交、模型失败不会丢失已接收作答或重复计分 |
| 人工体验通过 | 团队与数学审核者完整走通诊断→计划→学习→反思→独立检测，问题有闭环记录 |
| 真实试点就绪 | 可用内容、运行环境、数据授权与人工支持入口到位，试点范围经负责人确认 |

上线前需在指定硬件与模型端点测量首响应、完整回合时延、失败率和目标并发，再确认性能门槛。当前未确认硬件和端点，不把交接中单次模型耗时当作性能承诺。

真实试点逐步补充数据；先检验能否使用和是否发生教学错误，再建立效果基线。自动 RSI 继续以 10 §9.3 的五项条件为准：获得 evolution 授权的活跃学习者至少 200 人、持续至少 8 周；冻结回归集至少 100 场景；孪生校准达标；教师纠正至少 500 条；北极星面板稳定产出至少 4 周。模拟数量不能替代这些真实要求。

## 7 开发顺序与完成定义

| 阶段 | 交付物 | 完成定义 |
|---|---|---|
| D0 基线与课程映射 | 可复现开发环境、原测试复跑、知识点/单元清单、内容模板和评测来源规范 | 记录当前能力；每个计划交付单元有负责人、审核路径和验收场景 |
| D1 可靠闭环 | Postgres 核心迁移、会话恢复、审核题库、计划/作答/提示/反思/检测页面、30 核心场景 | 先在现有一元一次方程单元走通，再验证几何与函数代表性路径 |
| D2 三年级单元扩展 | 数与式、方程/不等式、函数、几何、统计概率逐单元内容包与验证适配 | 每个单元按第 1 节的覆盖定义验收；补齐复习、记忆回链和管理复核 |
| D3 内网试点版 | 学生端完整闭环、基础治理/教师纠正入口、监测/导出/备份恢复、人工体验报告 | 在确认的环境通过功能、内容与恢复门；按试点范围逐步接入真实学生 |
| D4 证据积累与进化准备 | 真实独立检测、教师反馈、校准报告与北极星基线 | 满足既有条件后再评审自动进化；圆桌、我教 AI 与数学探究按价值和验证能力扩展 |

每次开发任务应关联页面、教学机制、API/数据实体和验收场景。出现新的技术或产品选择时，新增决策记录，说明对当前基准的影响；涉及方向改变的事项先请负责人确认。本阶段不按日历承诺工期，排期需结合开发人数、内容审核资源和可用部署环境确认。

## 8 已确认决策与接入前事项

2026-10-15 负责人已确认：七至九年级常见单元、学生自主学习为主、本地或内网试点，以及以下三项开发决策。

| 决策 | 确认结果 | 开发落点 |
|---|---|---|
| 课程组织 | 先按课标知识点组织 | 先建 KC、先修关系和单元映射；教材映射作为后续扩展 |
| 内容与审核资源 | 暂无，先建自编开发题库 | 为各内容域建立题目、答案、步骤、误区、分级提示和测试真值；标明开发用途与审核状态 |
| 模型访问范围 | 允许指定外部模型 API | 保留 Provider 适配与 FakeLLM；配置指定服务商端点，并记录模型版本及调用目的地 |

接入前需确定外部模型的服务商、型号、base URL、凭据配置方式和费用预算。当前授权允许指定外部模型 API，不自动确定某个服务商，也不自动授权发送所有真实学生资料。开发阶段优先使用自编题目与模拟交互，真实试点前核对数据授权和最小上下文。

自编开发题库通过程序校验和团队复核支持功能开发；面向真实学生发布前，仍需明确数学审核责任与内容发布流程。后续引入教材原文、外部题库和图片时，单独记录可用来源。
