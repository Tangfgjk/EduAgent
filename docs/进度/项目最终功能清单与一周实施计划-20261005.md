## 3. 最终产品目标

桂子问津最终是一个以自我调节学习为核心的长期教育伴生平台。它必须形成以下闭环：

```text
学习者设定目标
  -> 桂子问津诊断知识与学习状态
  -> 学习者作答、探究、讲解和修订
  -> Verifier 生成可追溯证据
  -> 掌握度与保持度更新
  -> 生成复习任务和学习路径建议
  -> Trigger 判断是否介入
  -> Policy 选择教学动作
  -> ActionGovernor 执行规则裁决
  -> Agent/API/Web 向学习者交付
  -> 新交互再次进入证据链
```

系统最终优化三项北极星指标：

- 无辅助表现增量；
- 认知层级跃迁；
- 学习者自主性增益。

### 3.1 事实、推断与建议的数据契约

```text
Observation / LearningEvidence（观察与验证记录）
  -> Inference / Learner State（模型推断）
  -> Recommendation / Teaching Decision（策略建议）
```

| 契约 | 必需字段 | 语义约束 |
|---|---|---|
| LearningEvidence | `schema_version`、`evidence_id`、`learner_id`、`session_id`、`kc_refs`、`attempt_id`、`artifact_ref`、`verdict_ref`、`verdict_status`、`verifier_version`、`hint_level`、`assistance_mode`、`response_time_ms`、`occurred_at`、`event_seq`、`consent_scope`、`consent_version` | 保存作答及验证发生的记录，不能包含 `p_mastery` 或“学生已掌握”的结论。Verdict 是验证器判定记录，保留方法、rubric、置信度与来源，不冒充客观真理；修正判定追加新事件并引用被修正版本。 |
| Claim | `claim_id`、`claim_type`、`value`、`confidence`、`confidence_method`、`evidence_refs`、`model_version`、`created_at` | `claim_type` 为 `observation`、`inference` 或 `recommendation`；推断和建议必须引用证据或带来源的状态版本，不回写成原始事实。 |
| MasteryState | `learner_id`、`kc_id`、`state_version`、`p_mastery`、`confidence`、`confidence_method`、`effective_evidence_count`、`evidence_refs`、`model_name`、`algorithm_version`、`parameter_set_id` | 结构化掌握状态由 Learner Model 持有，持久化到 Storage，不由 Runtime 或 Memory 再维护一套独立数值。 |
| RetentionState | `learner_id`、`kc_id`、`state_version`、`difficulty`、`stability`、`lapse_count`、`last_review_at`、`next_review_at`、`evidence_refs`、`scheduler_version`、`parameter_set_id` | 与 MasteryState 独立；`retrievability` 和 `forgetting_risk` 必须携带 `as_of` 计算时间，不当作永久不变的字段。 |
| LearningStateTransition | `transition_id`、`learner_id`、`kc_id`、`evidence_ids`、`consumer`、`prior_state_version`、`new_state_version`、模型/参数版本、`event_seq`、`created_at` | 明确哪个消费者将哪些证据作用于哪个状态；若进入策略决策，再关联 `policy_version`、`decision_ref` 和 `action_ref`。 |

学习观测映射策略固定为 `binary-observation-v1`：

| Verdict | Evidence | BKT | Retention |
|---|---|---|---|
| `passed` | `correct` | 更新 correct 观测 | 满足回忆任务资格时更新为成功提取 |
| `failed` | `incorrect` | 更新 incorrect 观测 | 满足回忆任务资格时更新 failure/lapse |
| `partial` | `partial` | 不更新二值状态 | 不作为完整成功或失败，不更新保持度 |
| `unverifiable` | `unverifiable`，审计记录 | 不更新 | 不更新 |

回忆任务资格由版本化配置判断，并检查任务类型、提示/答案暴露和可验证性。提示后的正确作答不能默认为无辅助成功回忆；不满足资格时保存证据和跳过原因。学习观测策略与保持度消费资格分别记录版本，后续支持 partial-credit 时新建策略版本，不覆盖历史解释。

### 3.2 掌握门控与评测配置

知识点由 `KnowledgeComponent{kc_id, domain, kc_type}` 描述；评测方式由 `AssessmentProfile{profile_id, version, gate_mode, threshold, min_evidence_count, min_confidence, rubric_ref, qualitative_requirements}` 描述。`gate_mode` 为 `quantitative`、`qualitative` 或 `hybrid`。DeepTutor 的四种类型只作为默认配置映射。

`MasteryGateResult` 必须包含 `status`、`probability`、`confidence`、`confidence_method`、`effective_evidence_count`、`evidence_refs`、`assessment_profile_ref`、`gate_version` 和 `reason`。

| status | 判定条件 |
|---|---|
| `insufficient_evidence` | 有效证据量或规定的定性/迁移证据不足，即使掌握概率高也不能放行。 |
| `uncertain` | 置信度缺失、未达门槛、证据冲突或评测不可验证。 |
| `not_mastered` | 证据足够且可信，但规定的定量或定性要求未通过。 |
| `mastered` | 该评测配置要求的全部条件满足。 |

默认定量门槛可设为 0.9，但必须连同最小证据量、置信度方法和参数集一起版本化。当前 BKT 的区间是启发式估计，不能直接当作已校准的统计置信度；阶段一应定义确定的可信度计算口径，标明 `heuristic`，验证其单调性和边界。定性判定须保留 rubric 各维度、证据和评估器版本，低置信度不能由 LLM 一票判为 mastered。

### 3.3 幂等、顺序与事务边界

- 消费唯一键为 `(learner_id, evidence_id, consumer)`，BKT 与 Retention 各自消费一次；同 ID、同内容重试返回既有结果，同 ID、不同内容拒绝并审计。算法版本不混入线上幂等键，升级重算使用独立重建任务和新状态版本。
- Storage 分配并持久化唯一递增 `event_seq`，以序号确定重放全序；`occurred_at` 保留真实发生时间，`ingested_at` 记录入库时间，禁止仅按 timestamp 或运行时内存计数排序。
- 同步本地消费以一个事务完成：Evidence 入库、消费记录、LearningStateTransition 追加、派生快照写入。任一步失败全部回滚。没有状态更新的 Evidence 仍写审计/跳过记录。
- 并发更新采用 `prior_state_version` 的 CAS 检查；冲突后重读状态重算，重试不得产生重复消费。受控仓储接口内部不能在每个步骤独立 commit。
- 外部 LLM、检索和网络调用在事务外完成，不保持数据库事务等待网络；如后续改异步消费，使用持久化 outbox 和可恢复消费者，不声称跨网络事务原子性。
- Replay 固定 Evidence 集合、事件序号、算法/参数版本和显式 `as_of`。重放不得读取当前时钟、实时 LLM 或未保存参数；晚到和修正证据触发版本化重建，原始事件不覆盖。

### 3.4 北极星指标的操作化定义

| 指标 | 计算与呈现口径 | 必须保留的数据 |
|---|---|---|
| 无辅助表现增量 | 比较同一学习者在同一 KC、相同 rubric 与可比难度的无提示前测、后测和迁移任务表现；有提示作答不进入该指标。展示样本量、窗口、任务版本和不确定性，缺数据显示“暂无数据”。 | `assessment_id/version`、`assessment_kind`、`kc_refs`、`assistance_mode`、`hint_level`、`answer_exposed`、`score`、`rubric_version`、`difficulty_band`、时间、Evidence refs。 |
| 认知层级跃迁 | Verifier 或教师按版本化 Bloom rubric 评估作品，聚合同一学习者可比任务窗口的层级分布变化；一次高层级题目不直接代表永久跃迁。LLM 打标是估计，须保留评估器版本、置信度和人工复核记录。 | `bloom_level`、`rubric_ref/version`、`assessor_type/version`、`confidence/method`、`artifact_ref`、`window_start/end`、`sample_count`。 |
| 自主性增益 | 展示独立完成、适当求助、自我检查、学习者计划调整、反思质量和支架依赖的行为分解；少求助本身不能代表高自主性。合成指标只作为教师/治理端版本化估计，学生端无排名。 | `attempt_before_help`、`help_request/reason`、`self_check`、`plan_change_actor`、`reflection_rubric`、`scaffold_usage`、无辅助结果、Evidence refs。 |

阶段一确定并保留字段，阶段三呈现真实证据与缺数据状态，阶段五验收指标查询链和口径说明。只有真实、可比的前后测支持效果判断，演示数据不作为教育效果结论。前测、后测、迁移测和延迟测分开计算；同 KC 版本、rubric 版本、难度档和比较组才能配对。每侧至少两个独立题目样本是当前展示门槛，不是教育研究所需样本量；正式效果研究须独立确定样本量、难度校准、人工复核与群体差异方案。时间窗、样本数、排除提示/答案暴露、评估器置信度和来源必须同时展示。禁止把描述性增量宣称为教学动作的因果效应。

### 3.6 知识与评测资产、冷启动和动作归因

知识资产保存 KC ID/version、课程来源、学段、类型、先修版本引用和审核来源。Assessment 保存 ID/version、KC 引用、rubric 引用、难度档、Bloom、比较组与校准状态；rubric 维度与权重也独立版本化。先修图必须无环、引用版本存在。拆分/合并 KC 使用新资产和映射迁移记录，不覆盖历史 ID；演示资产不能冒充已审核的课程资产。

冷启动按先修拓扑顺序选择诊断题，题目选择确定且可重放；无证据、猜测、跳过、提示和答案暴露不能解释为掌握。明确最大任务预算与提前停止条件；不足状态产生诊断或学习建议，并通过计划草案和学习者签署进入执行。初诊完成只表示初始准备信号，不等于 MasteryGate 通过。

新证据保存 `action_id`、`policy_version`、支架类型、提示等级、答案暴露与任务版本，能关联教学动作前后的可比无辅助作答与延迟复习。教师或学习者纠错追加修正事件，状态重建保留任务失败/重试、版本差异和影响范围；纠偏后的路径重新提案，不静默改变已签署计划。

### 3.5 Consent 与长期状态所有权

`consent_scope` 从阶段一首次记录证据时就必须存在，分别表示 `teaching`、`research`、`evolution`；同时保存 `consent_version` 和授权来源。未授权用途默认关闭，教学授权不能推导出研究或进化授权。消费者检查当前有效授权与事件的采集授权，撤回后立即阻止对应用途的读取/导出，不仅隐藏 UI 入口；留审计但不得继续消费已撤回用途的数据。

Learner Model 是 `p_mastery`、Retention 和 Gate 结果的唯一结构化状态所有者。Memory L1 是事实历史；L2/L3 保存派生摘要、解释性画像和长期上下文，可以引用结构化状态版本，但不能复制成另一个可独立更新的 KT 数值源。L3 不得引用 L3 为自身证据。

## 5. 五阶段工作拆分

### 阶段一：1A 学习核心闭环

**状态：部分完成；本地定量核心验收通过。** Evidence/事务/幂等/CAS/重建、四状态Gate、Retention、资产校验已实现。真实课程、定性评估、参数校准未完成。

**目标：** 把一次 Verifier 判定变成可验证、可重放、可审计的学习状态变化。

**实施任务：**

1. 先新增 Adapter Test，不先复制 DeepTutor 代码。
2. 定义 `LearningEvidence`、`MasteryState`、`RetentionState`、`LearningStateTransition` 和 `ReviewTask` Schema。
3. 实现 `platform/app/learning/mastery_port.py`：
   - `passed -> correct`；
   - `failed -> incorrect`；
   - `partial -> partial`，第一版不更新二值 BKT；
   - `unverifiable` 只入审计。
4. 实现 `platform/app/learning/gates.py`：证据数量、置信度、掌握概率和 qualitative/hybrid gate。
5. 实现 `platform/app/learning/review_port.py`：稳定性、可提取度、遗忘风险、lapse 和 next review。
6. 依照第 3.3 节实现 Evidence 唯一消费、全序事件号、事务原子性与 CAS；通过故障注入测试确认中间失败不留半成品。
7. 固定 BKT 与保持度模型的算法版本、参数集 ID 和 replay 规则。
8. 将 Claim、AssessmentProfile、MasteryGateResult 和 Consent 契约落成 Schema；记录北极星字段、定性评测置信度方法和保持度消费资格。
9. 实现版本化 KC/Assessment/Rubric 资产目录、引用校验、无环先修图、演示与审核/校准状态；明确资产创建、修订、拆分/合并审核流程。

**交付物：**

- 三个 Learning 端口模块；
- 至少 12 类单元测试和 1 条黄金路径集成测试；
- 一条“失败 → 提示 → 多次有效作答/无辅助回忆 → 满足门控 → 安排复习”的可回放样例；通过次数由冻结参数决定，不假定答对两次就掌握；
- `LearningStateTransition` 事件示例。

**验收标准：**

- 新增测试全部通过；
- 旧有 R-01 至 R-10 和 61 项基线测试不回归；
- 同一 Evidence 重放结果一致；
- 重复 `evidence_id` 只产生一次状态变化；
- `unverifiable` 和 `partial` 不污染第一版长期二值状态。
- 概率很高但证据不足返回 `insufficient_evidence`，缺失/冲突置信度返回 `uncertain`。
- 并发重复消费仅更新一次；事务各步骤失败全部回滚；固定 `as_of` 后保持度重放一致。
- 原始 Evidence 中无掌握结论，未授权用途默认不能读取或消费；提示后作答与无辅助回忆分开记录。

### 阶段二：1B 决策集成与长期状态骨架

**状态：部分完成；本地决策集成通过。** Path/Trigger/Policy职责独立，signed范围按真实先修编排，unknown保守阻挡。完整Memory与全课程图谱未完成。

**目标：** 让掌握度和保持度真正影响“学什么、何时介入、如何介入”。

**实施任务：**

1. 将 `MasteryState` 和 `RetentionState` 接入 `PathRecommendation`。
2. 第一版只实现三种决策：
   - 掌握度低：`LEARN` 或 `REMEDIATE`；
   - 掌握度高但遗忘风险高：`REVIEW`；
   - Gate 为 mastered、遗忘风险低且先修满足：`ADVANCE`。
3. 加入 prerequisite 检查，形成最小路径图；缺少先修证据时补诊断或补练，不能以单个 `p_mastery` 越过 Gate 晋级。
4. 按 [ADR-003](../决策/ADR-003-学习证据与决策职责边界-20261005.md) 冻结 `PathRecommendation`、`TriggerEngine`、`Policy`、`ActionGovernor` 的接口边界；分别传递证据和版本引用，不以一条硬编码串行链替代独立端口。
5. 建立 L1 InteractionEvent 的最小字段：learner、session、KC、evidence、verdict、model、policy、state versions、consent。
6. 为状态变更增加 prior/new 版本与事件序列号，固定相同时间戳下的重放顺序。
7. 接入确定性冷启动诊断：先修未知优先探测，区分不会、猜测、跳过和支架依赖；预算耗尽或资产不足保留 unknown；第一版计划必须从诊断/学习提案进入签署流程。

**交付物：**

- PathRecommendation v2；
- 三种路径决策及其解释文本；
- L1 事件 Schema 和 replay runner 初版；
- 1B 集成测试。

**验收标准：**

- 给定同一学习者和 Evidence 集合，路径结果确定且可解释；
- 推荐只能产生 `proposed`，不能直接修改学习计划；
- 每次路径决策可追溯到 Evidence 和状态版本；
- Trigger、Policy 和 Governor 能分别测试。
- 学习者签署才使计划版本生效；采纳推荐不等于自动签署，修改和拒绝留痕。

### 阶段三：1C Agent、API 与工作台交付

**状态：本地V1软件验收通过，生产部分完成。** 明确授权、作答/复习/指标/计划签署、旧会话恢复和消息全链事务已接入；深色页面与15项浏览器流程通过。

**目标：** 把阶段一和阶段二的结果接回现有 Agent、网关和 Web 工作台，完成最小可用纵向切片。

**实施任务：**

3. 增加复习队列 API 和路径推荐 API 的真实数据源。
4. 在计划页展示推荐原因、来源证据和 Diff；采纳、修改、拒绝均留事件。

- 端到端测试和演示脚本。

**验收标准：**

- 学习者完成一次作答后，页面能看到证据、掌握状态和复习任务；
- 推荐采纳必须经过计划 Diff 和学习者签署；
- 所有动作仍经过 ActionGovernor；
- 页面显示的高层判断可以钻取到原始事件。
- 跨时间复习完成确实生成第二轮 Evidence，改变保持状态及下一轮路径；重试不重复消费。

**接口和权限要求：**

- `RetrievalPort.retrieve(query, context) -> list[RetrievedEvidence]`，结果含 `source_id`、`source_version`、`chunk_id`、`text`、`citation`（页码或行号）、`score`、`grounding_status`、`kc_refs`。引用必须可打开；未接地或冲突结果不能直接作为教学结论。
- Provider Registry 注册 provider/model/config 及能力、超时和回退策略；generation provenance 保存 provider、model、客户端/模板版本和请求关联 ID，密钥只从本地配置读取，不进事件或仓库。离线用 FakeLLM 测试，外部调用记录独立 smoke 结果。
- 三类派生角色报告必须含角色/模板版本、授权工具、输入 evidence refs、turn/token 预算、起止状态、产物与审查结论。越权、超预算和超时可测试。
- 依赖方向为 `app -> ports/adapters -> vendor/deeptutor`，vendor 禁止反向 import app；抽取前核对确切提交与许可证，适配后的契约仍由桂子问津所有。

**交付物：**

- DeepTutor Learning 适配器或等价自建实现；
- Provider Registry 初版；
- 可导入并检索实际 Markdown/PDF 的最小知识库；
- 三种派生角色模板及生命周期报告；
- 第三方许可证和来源清单。
- 教师金标 API、最小复核入口、追加修正与审计用例。

**验收标准：**

- 上层模块不直接依赖具体模型厂商；
- 检索结果不能绕过 Verifier 和 KC/KG 接地；
- 派生角色没有越过 Governor 的权限；
- 外部源码、版本、许可证和本地修改可追溯。
- 实际样本文档导入、检索、引用定位和 KC 接地测试通过；缺数据、未接地、越权和解析失败有明确结果。
- 教师纠正保留原作答和判定；未授权角色不能读写金标。

### 阶段五：治理、回归、本地交付与剩余缺口归档

**状态：本地回归与交付通过，真实治理部分完成。** 42冻结场景、22红队、全量424项与15浏览器流程通过；校准治理纯端口通过，真实教育效果/群体差异/参数晋升尚未验收。

**目标：** 形成可交付、可回滚、可继续开发的 V1 检查点。

**实施任务：**

1. 验收首版至少 30 个冻结回归场景，覆盖 R-01 至 R-10、七类支架、学段、双循环黄金路径和异常路径。契约冻结时确定模板，随各工作包积累并持续执行，最终冻结版本与覆盖映射。
2. 建立红队越界测试：诱导给答案、绕过计划签署、伪造 Evidence、隐私越界、考试模式越权。
3. 校验所有事件包含 learner、KC、Evidence、模型版本、策略版本和状态前后版本。
4. 完成 SQLite replay 验证，记录 PostgreSQL 迁移剩余差异。
5. 完成 Web 关键流程的可用性、权限和无障碍检查。
6. 更新开发状态、阶段日志、测试说明和未完成清单。
7. 生成最终 V1 检查报告，明确“已完成、部分完成、未完成、暂不启动”。
8. 形成本地差异检查点、测试报告和回滚说明；当前不 commit、不 push，提交/推送需要后续用户明确指令。
9. 验收前后测、迁移测、延迟测指标链；缺数据、不可比、提示污染、时间倒序和跨学习者隔离均测试。建立人工抽样复核、错误率/群体差异检查与参数校准晋升方案，真实样本不足时教育效果结论保持未验证。

**冻结场景格式：** 每条包含 `scenario_id`、`scenario_version`、`initial_state`、`input`、`expected_decision`、`expected_rule`、`expected_evidence`、`expected_state_transition`、`rubric`、参数版本、固定时间和来源。Schema/状态/硬约束用确定性断言，教学表达可辅以 rubric 与人工复核；不能仅用 LLM-as-judge 验收规则和数值状态。场景集变更须新版本、差异与审阅记录。

**重点用例：** 四种 Verdict、重复 Evidence、同时间戳、晚到/修正证据、原子回滚、并发 CAS、证据不足、置信度不足、高掌握高遗忘、先修缺失、L3 来源、R-01/R-02/R-09、用途撤回、未接地检索与派生角色越权。一个场景可覆盖多项，但覆盖映射必须可检查。

**交付物：**

- 30 场景冻结回归集；
- 红队测试报告；
- V1 验收报告；
- 更新后的进度、日志和变更记录；
- 可继续开发的本地差异检查点与运行说明（未提交）。

**验收标准：**

- 核心测试、集成测试、回归测试和红队测试结果有记录；
- 失败项有明确负责人、依赖和下一步，不被隐藏；
- 可从任意关键结论回放到原始 Evidence；
- 未满足治理条件时，RSI 自动进化保持关闭。

## 6. 并行工作包与验收映射

| 工作包 | 可并行开发 | 集成前置 | 阶段与验收证据 |

## 7. 依赖关系与执行纪律

```text
Verifier
  -> LearningEvidence
  -> MasteryState / RetentionState
  -> PathRecommendation
  -> Trigger / Policy
  -> ActionGovernor
  -> Agent / API / Web
  -> 回写 InteractionEvent
```

执行时遵守以下顺序：

1. 先写测试，再写适配器，再接外部源码；
2. 1B/1C 和外部端口允许以冻结契约并行开发；集成验收按 1A → 1B → 1C，不能用 Web 原型替代核心状态验收；
3. 事实事件先落库，摘要和画像只能作为派生状态；
4. 所有推荐先是 proposed，必须经过学习者确认；
5. 所有 LLM 输出、工具请求和派生角色动作必须过 ActionGovernor；
6. 每次验收门通过后更新本文件、阶段状态与带时间开发日志；
7. 发现依赖阻塞时推进独立任务，未完成范围明确登记，不跨层堆临时代码；测试通过后删除本轮确实无用的临时代码，保留仍被调用的兼容路径。
