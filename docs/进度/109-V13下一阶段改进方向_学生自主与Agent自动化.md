# V13 下一阶段改进方向：学生自主使用与 Agent 自动化

日期：2026-10-19。适用范围：七至九年级数学自主学习，本地/内网开发。实现基线：API 0.19.0、数据库 `g08_001`、主服务 4003、独立 OpenMAIC 服务 4004。

**本文是后续实施方案，不代表这些改进已经上线。本轮只整理文档，不修改代码、运行配置、模型预算或开放范围。** 当前仍仅完成模拟/成人开发验证，专业教学质量和真实学生学习效果尚未验证。

## 1. 新阶段的产品目标

学生输入学习目标后，系统能理解意图、澄清范围、诊断基础、安排课程与互动、按学习过程调整支持，再用独立检测形成下一轮建议。普通学习在平台已配置的权限、来源和预算范围内自主完成，不要求管理员逐项代操作。

教学主线保持：**诊断当前理解 → 安排合适活动 → 学生完成思考 → 脱离 AI 再检验 → 依据证据调整**。苏格拉底追问与支架渐撤共同服务这条主线：随着独立表现稳定，减少步骤代做，增加学生自问、解释与验证；遇到困难可以恢复支持。不能简单把“更多追问、较少提示”当成更好教学。

原始设计继续有效；后续执行顺序以本文为准。[102 号计划](102-V12下一步完善与验收计划.md)与[87 号路线](87-下一阶段开发路线与验收清单.md)中的剩余项合并到本文，不因重新规划而视为完成。

## 2. 当前起点：已经做了什么，仍缺什么

1. 学生端与管理端独立；账号、正式项目/临时会话、陪学、复习、圆桌、我教 AI、证据、规划策略已具备首轮工程闭环。
2. 有 DeepSeek、Tavily 和 OpenMAIC 的真实开发接入。服务连通不等于完整教学产品验收。OpenMAIC 首轮生成预算目前已停止。
3. 现有固定开发单元为 7 个、35 道题。早期生成课程只覆盖有限知识点与数值题族。
4. 新增有理数教学 Agent 样板：支持 7 类概念目标与 11 种受控数学形式，模型可设计多概念任务和活动问题，程序独立生成/核对数学内容。目标识别、可用题型、支持决策仍有规则和白名单限制；尚不能泛化为任意初中数学课程。
5. 新样板的一次真实生成数值核验通过，但解释中出现“相反数位于原点两侧”的零例外缺失，课程仍待审核，不能作为语义质量已通过的证据。见[107 号验收](107-有理数教学Agent动态课程开发验收.md)及[108 号真实记录](108-有理数教学Agent单次真实开发记录.json)。
6. 成长证据已有全局/项目隔离、提示与独立表现分组、支持轨迹及候选素养材料展示；没有可信的自动素养评分或教学效果结论。

“真正发挥 Agent 优势”应体现在：依据当前目标和证据选择工具、决定是否澄清、调整后续任务、说明下一步依据，并能停止或恢复。保留安全规则、数学核验和教学阶段约束是必要的；不能把固定模板换成一次模型长文本就宣称完成自动化。

## 3. 学生完整使用流程与页面收敛

### 3.1 学习主路径

新建空间并说出目标 → 必要时澄清 → 在对话中做少量诊断 → 确认简明学习安排 → 开始陪学/课堂 → 按需要进入圆桌或我教 AI → 独立检测 → 反思与复习 → 查看证据和下一步建议。

- 工作空间保存目标、课程版本、活动上下文与策略快照，名称只作展示，不依据名称暗中绑定课程。
- 创建空间后立即显示“说说你想学什么”或“继续上次学习”；后续主按钮由真实状态决定，不让学生猜菜单顺序。
- 诊断数量随目标与不确定性调整，不永远固定两题；有理数样板现有规则只是起点。
- 课程正文和媒体可渐进准备；已有可用活动先开始，媒体生成不阻断整个学习过程。
- 刷新、换页、取消和失败后可恢复；清楚区分临时会话与正式项目，允许在明确告知后转为正式项目。

### 3.2 导航建议

学生主导航收敛为 **学习空间、开始/继续学习、复习、成长、我的**。具体名称在实现时用真实任务走查确定，避免再增加一套并列入口。

| 现有内容 | 后续位置与默认呈现 |
|---|---|
| 项目、临时会话 | 学习空间列表与固定空间切换器 |
| 主题、课程、数学单元、学习计划 | 当前空间的目标/课程页；单元库为辅助选题入口 |
| 陪学、圆桌、我教 AI | 学习页的模式/活动切换，保留各自教学流程 |
| 错题、到期复习 | 复习页，突出今日应完成任务 |
| 成长证据、规划建议、Skill 改进 | 成长页中的证据与下一步建议，进阶详情折叠 |
| 偏好、账号 | 我的 |

旧链接继续定位对应活动，保留空间和课程上下文。减少页面展示项不删除底层审计记录。

圆桌默认只展示当前主题、视角对话、学生比较输入与下一步。完成后再显示小结；往期讨论放历史抽屉；“互动流程记录”等实现细节进入进阶详情。陪学与我教 AI 采用相同的信息层级原则。桌面为主兼顾手机，提供键盘操作、明显焦点、可读错误提示和非纯颜色状态。

## 4. 学生自主使用与自动检查

### 4.1 权限重新分工

**管理员一次配置**：可用模型/来源、课程范围、调用和媒体预算、自动开放条件、共享资源库、专业量规、异常处理和停用能力。

**学生日常决定**：学习目标、是否开始生成/观看课堂、是否接受计划、何时请求提示、切换活动、停止、恢复、接受或撤回个人策略建议。费用或时长明显增加时，显示可理解的预估与确认，不能展示后端技术参数要求学生判断。

**系统自动完成**：身份/项目校验、来源授权、预算预占、内容结构/数学/安全检查、状态提示、可复用资源查找、异常归档及版本留痕。

### 4.2 自动开放规则

| 自动检查结果 | 学生体验 | 后台处理 |
|---|---|---|
| 已覆盖题族，结构/条件/数学/来源等规定检查均通过 | 私有课程/资源直接可用，显示检查范围 | 记录自动开放依据，抽样检查 |
| 有歧义或某项无法核验 | 澄清、提供可用部分、改选任务；不能显示“已全面核验” | 标记限制，必要时排队复核，不阻断其他可用学习 |
| 数学错误、越权、来源撤回或安全失败 | 拦截相关内容并给替代路线 | 异常处理，禁止管理员简单点通过绕过硬性检查 |

共享课程发布、专业评分量规、全局策略推广等仍需相应审核。初期自动开放只适用于已建立验收门槛的私有开发内容，按题族逐步扩大；不能一次删除所有审核按钮就直接开放所有模型内容。

新增开放记录须区分 `system_auto`、`student_confirm`、`admin_exception`，保留检查版本与原因，兼容现有人工审核历史。自动检查的覆盖能力必须先验收，再迁移对应人工关口。

### 4.3 预算与失败体验

平台预算是预先设置的运行边界，学生可在边界内自主决定，不能自行扩大额度、解除来源限制或接触密钥。分别核算普通对话、课程、搜索、媒体任务；缓存命中应说明资源来源与版本。保留幂等、取消、并发预占、未知计费状态与人工对账，禁止失败后无限重试或重新创建课堂。

**本文不重开当前已停止的 OpenMAIC 预算，也不扩大此前真实模型和资料发送授权。** 新媒体服务和新调用范围在实施前单独确认；已有资源播放、界面整理及离线适配可以先做。

## 5. 对话式陪学：理解自然语言，独立判断数学

### 5.1 交互设计

以一个持续对话框为主界面：顶部简洁显示目标和当前题，消息区呈现学生回答、反馈、追问和提示；底部统一输入框，可点“给我一点提示”“检查思路”“继续”。提示及恢复支持都体现在同一条对话中，无须切换多个表单。

支持流式显示、发送状态、停止生成、失败恢复、刷新后恢复，以及“刚才说错了”的更正。每条消息绑定空间、课程版本、题目、轮次和任务；防止旧题回复覆盖新题、重复发送重复计费、迟到消息串项目。

### 5.2 理解与核验的职责

处理链：原文 → 回答意图/答案片段提取 → 歧义检查 → 规范数学表达 → 独立数学核验 → 分开呈现答案与解释反馈 → 决定后续追问。

- 简单格式可确定性解析，复杂表达由模型输出受限结构；保存原文片段、候选答案、否定/改口信息、单位、对应题目及模型/规则版本。
- 模型负责理解表达，不直接决定参考答案。现有安全数学核验器继续扩充，不执行学生或模型代码。
- 不能用“提取第一个数字”或模型自报置信度作为正确性依据；存在冲突时先确认学生最终答案。
- 数值正确、推理合理、表达充分是不同状态。证明、作图与长篇解释超出核验范围时明确“尚不能判定”，不得默认错误或自动认可。

| 输入示例 | 应有行为 |
|---|---|
| 参考答案为 3；学生说“这个答案是3” | 提取 3 并独立核验，不因中文前缀拒绝 |
| “不是3”“题目里有3” | 不把 3 直接当最终答案 |
| “3或5” | 明确候选/多解语境，不能命中一个就判对 |
| “刚才写3，现在改成4” | 使用明确更正后的答案，保留修改记录 |
| “答案3，因为1+1=3” | 最终值与理由分别反馈，指出理由矛盾 |
| 3cm 与 3cm² | 按题目维度检查，不能只比较数字 |
| 上轮算出3，本轮问新题 | 使用新题上下文，不复用旧答案 |

“独立检测”阶段关闭教学提示与答案泄露；技术澄清不得偷偷给解题步骤。未理解输入不计作数学错误。对话中的支持量、答案曝光与任务来源写入证据，用于区分有辅助表现和独立表现。

## 6. Agent 从课程生成延伸到学习过程

沿用 LangGraph 编排与统一 Provider，按需使用 LangChain 适配，不因接入框架就宣称具备自主教学能力。

| 角色/模块 | 可作决策 | 约束 |
|---|---|---|
| 目标与诊断 | 识别目标、澄清、选择下一道诊断 | 初中数学、授权知识图谱、题族能力声明 |
| 课程规划 | 依据先修/诊断生成活动顺序、选择表示和问题 | 所有任务经过相应核验，版本可恢复 |
| 陪学与活动 | 追问、提示级别、圆桌/我教 AI 的时机 | 不代替独立检测，不泄露保留题 |
| 资源 Agent | 检索、复用、提出/执行课堂生成 | 来源、版权、权限、预算及资源安全 |
| 评价与证据 | 汇总可观察表现、识别未确定项 | 数学核验独立，语义/素养评价需量规 |
| 规划与 Skill 改进 | 对后续任务提出有依据的策略调整 | 受限 DSL、隔离评测、可撤回 |

由编排器维护当前学习阶段、待办活动与失败恢复；工具层校验参数、身份和预算。输出可理解的行动摘要、来源与结果，不要求展示模型内部思维链。同一模型扮演多个角色不算多位专家共识。

先实现“从已核验任务池中动态选题/调整支持”，再逐步加入按需生成并核验新变式。更改后续安排应保留旧版本、变更原因和学生选择；不原地改写正在进行的独立测验或参考答案。课程覆盖扩展应有知识点—题族—核验器—专业审核台账，不能只放开关键词白名单。

## 7. 完整 OpenMAIC 课堂接入

### 7.1 当前实现与边界

当前固定上游为 `THU-MAIC/OpenMAIC` v1.2.0，提交 `a9da60b3b4adb429369c0da13d5637a904ead2b0`。上游提供课堂生成与场景数据；我们的适配器、模型预算代理、安全导入和学生入口是项目自建层，见[原接入核对](../调研/85-OpenMAIC教学资源生成接入核对.md)。

当前学生资源把场景转换成受限文本卡片，未保留完整播放器。用户看到的重复标题、原始 LaTeX 和粗糙排版是转换/展示层缺口。当前已审核的《负数乘除与运算顺序》包含三个文本场景，可作改造样本；不能把它描述成完整媒体课堂已可体验。

### 7.2 完整目标与实施层次

1. **先修复已有资源**：区分课堂标题、场景标题与正文，去除结构性重复；安全渲染数学公式并提供可访问文本；改善阅读宽度与滚动。使用已有资源验证，不重新花费生成预算。
2. **保留原始课堂结构**：版本化保存原场景结构和受控资源清单，适配上游画布/幻灯片布局、文字、公式、SVG/图形及分页。可复用上游播放器的部分先核对依赖与许可，再封装；不直接嵌入拥有后台权限的原站管理页面。
3. **接入媒体与播放**：图片、讲解音频/旁白、字幕、视频资源的显示、暂停、音量、进度、重播与断点恢复；支持手机阅读和媒体加载失败后的文本降级。对固定上游实际支持的生成类型建立能力矩阵；上游不提供的能力需独立适配，不能把“可播放导入视频”写成“已能自动生成视频”。
4. **接入课堂互动**：场景内问题、练习和回应与当前项目、题目和轮次绑定；接收互动结果，经自己的核验服务处理，再驱动后续活动。课堂播放完成仅是学习过程事件，不直接证明掌握。
5. **打通学生自主入口**：学生在当前学习中选择“生成/观看讲解课堂”，系统先找可用版本，再在配置范围内排队生成，自动检查后开放；进度、取消、失败替代路线都在学生端，不要求每门私有课堂等待管理员操作。

以上五项共同构成 R05 完成条件；仅美化文本卡片不能关闭“完整课堂体验”任务。

### 7.3 数据与安全

- 保存原始产物、规范场景、资产清单、可用媒体类型、核验报告、课程/项目绑定和版本；异步任务沿用租约、幂等、状态与预算记录。
- 原始 HTML/脚本与媒体 URL 都视为不可信。播放器使用受限沙箱、CSP、网络允许列表和独立无业务凭据的资源域；禁止读取学生/管理员会话、任意导航、注入模型密钥和任意外部请求。
- **4003 与 4004 端口不同不等于 Cookie 隔离**。正式嵌入方案必须验证域名、Cookie 范围和凭据发送行为，不能仅依赖端口。
- 消息桥校验来源窗口、资源版本、会话能力凭据和事件结构；沙箱产生不透明来源时不能用“接受所有来源”替代校验。学生答案和播放器事件仍需后端鉴权与独立核验。
- 带权限的短时资产链接、资源撤回、跨项目访问和缓存隔离需要专门验收；原始素材版权与授权随版本保存。

## 8. 规划与策略：默认资料复用，减少操作

当前策略提案的 `material_ids` 至少一份已发布资料，且“知识来源”和“规划参考资料”是分离的结构；因此学生学习过课程后仍可能被要求另选资料。此约束需在产品、接口、数据库规则与验收中一并调整，不能只隐藏上传按钮。

后续以统一 `ReferenceBundle` 提供：平台预装且已授权的课标/考纲与教学原则版本、当前课程目标和知识来源、当前项目证据摘要，以及学生可选补充资料。管理员维护公共基准一次，学生无须每次重复上传或选择。

- 为不同来源记录类型、授权、适用范围、版本及引用片段，兼容历史材料快照；不能伪造资料或把旧提案补成不存在的引用。
- 有可用默认资料时自动关联，允许学生查看与替换；无可用资料时，仍可依据实际过程提出可撤回的既有策略建议，明确依据有限。
- 涉及新课程事实、教材对齐等必须有来源的主张，缺失来源就降级、澄清或请补充，不能编造引用。
- “学习安排”和“规划策略”在页面上汇为当前空间的学习安排与调整；执行层仍区分课程任务与软策略，避免同一目标重复填写。
- 经评测的低风险个人策略可在学生预先选择的自动调整范围内生效，提供变更摘要与撤回；全局规则、硬性检测和预算不允许个人策略修改。去掉重复审核，保留冻结版本与回滚。

## 9. 成长证据：图形服务于判断下一步

图形必须能回答“做了什么、在哪种帮助下、哪里还不确定、下一步做什么”，而不是增加装饰性图表。

| 图形 | 数据与用途 | 不可作出的结论 |
|---|---|---|
| 学习日历与任务进度 | 真实活动日期、完成状态、时长口径 | 活跃天数等于掌握 |
| 知识点覆盖图 | 课程版本、已接触/已练习/独立检测记录 | 未覆盖等于能力为零 |
| 独立/辅助表现趋势 | 显示题量、分母、题型与提示/答案曝光情况 | 不同题与不同支持条件直接比较学习增益 |
| 易错类型与复习矩阵 | 有版本的错误分类、到期与复测记录，保留未分类 | 模型猜测的错因就是事实 |
| 支持渐撤轨迹 | 提示级别、恢复支持、独立尝试和任务难度 | 少提示必然教学更好 |
| 素养证据分布 | 六类候选材料，可点开学生解释和原始任务 | 候选材料数量就是素养得分 |

全局与项目视图共用时间范围、项目/临时会话、来源与辅助条件筛选，时间口径明确为北京时间。图表点选应打开证据并可发起合适的后续活动；空数据显示“证据不足”，不画成低能力。提供文字摘要、表格与非纯颜色区分。

素养能力图/雷达评分须等专业量规、样例锚点、人工复核一致性和不确定性表达建立后再开放。可先做明确标注“材料分布”的图形，不把它命名为“能力诊断”。延迟复测和迁移任务要区分原题曝光与真正未见任务。

## 10. Skill RSI 实现核查与后续方案

### 10.1 本次代码核查结论

**已实现受限教学 Skill 的离线改进工程闭环；尚未实现模型语义驱动、经教学效果验证的自动 RSI。** 这里的 Skill 是教学策略 Markdown/DSL，不是开发工具的 `AGENTS.md` 或 Codex 技能文件。

| 核查点 | 实现与证据 | 判断 |
|---|---|---|
| 证据生成候选 | [graph.py](../../app/modules/skill_evolution/graph.py) 根据数值错误、提示等规则，选一个受限枚举调整或无候选 | 规则已实现，没有模型语义分析 |
| 候选离线评测 | [evaluator.py](../../app/modules/skill_evolution/evaluator.py) 使用四个冻结自编样本，检查实际消费者、隔离、核验与边界 | 工程机制可验，不证明学习效果 |
| 版本与审核 | [service.py](../../app/modules/skill_evolution/service.py) 冻结数据/候选/评测，审核、采用、撤回；采用后仍走规划审核确认 | 闭环已实现，重复人工关口需收敛 |
| 体现在 Skill 并执行 | [compiler.py](../../app/modules/planning/compiler.py) 编译 Markdown 与严格 DSL、哈希一致，由练习/复习/支持/追问等消费者读取 | 已有真实参数执行，不只是展示文档 |
| 自主发布与效果 | 评测结果明确 `automatic_publish=False`、`learning_gain=None` | 自动发布、教学增益未实现/未验证 |

现有四类受限调整为练习顺序、复习排序、支持方式、追问重点，另有时长与反思重点。版本冻结与回滚不应改写已开始任务。当前没有模型权重训练、任意改源码或自主修改数学参考答案。

### 10.2 新闭环

证据与失败模式 → 模型提出可解释改进假设和受限 DSL 差异 → 冻结评测 → 影子运行 → 小范围个人试用 → 监测/撤回 → 再形成下一轮候选。

1. 候选必须说明哪条证据支持哪项变化、预期改变什么行为和可能副作用；无足够证据可不提出候选。
2. 语义改进需补教学场景、常见误解、错误追问、泄题、错误渐撤、含混表达和来源攻击样本；开发集与保留集隔离，不能让候选读取保留题答案。
3. 先验证执行正确与不退化，再观察独立作答、解释、延迟复测与迁移；对话更长、点击更多或模型自评更好都不算教学增益。
4. 个人、低风险且通过相应门槛的参数候选，在学生授权范围内试用并能撤回；全局推广与新的策略字段另设评审，不重复每个普通学习动作的审核。
5. 硬规则、预算、访问控制、核验器、评测真值与源码不允许自改。不能把现有四个工程样本通过后直接开启自动发布。
6. 记录候选/父版本、证据、评测语料与消费者签名、试用范围、实际执行和回滚原因。被新代码或语料变更使评测失效的候选必须重新评测。

## 11. 工程架构与数据契约

保留当前 FastAPI、模块化服务、SQLAlchemy/Alembic、PostgreSQL、React/TypeScript、统一 Provider 与 LangGraph。按职责演进现有模块，避免为每个角色再造一套权限/任务/预算系统。

| 契约/模块 | 关键内容 | 依赖关系 |
|---|---|---|
| ConversationTurn / AnswerInterpretation | 消息、原文片段、候选、单位、否定、更正、题目/轮次、版本 | 对话层调用理解器，核验器独立 |
| MathCheck / TeachingDecision | 数学结论与覆盖范围；支持/追问/下个活动及依据 | 不把教学建议当数学真值 |
| NextAction / LearningAgenda | 当前阶段、可执行下一步、阻塞与恢复点 | 驱动工作台与学生引导 |
| ReferenceBundle | 来源、授权、片段、版本、撤回 | 课程与策略复用，不重复上传 |
| ResourceManifest v2 | 场景、布局、资产、媒体能力、检查和播放状态 | OpenMAIC 适配、沙箱与学习事件桥 |
| ReleaseDecision | 自动/学生/管理员的开放依据、门槛版本 | 权限与审核迁移统一留痕 |
| SkillExperiment | 候选差异、冻结评测、试用范围、观察与回滚 | 规划编译和真实消费者 |

所有学习记录保留账号/项目归属、课程/题目/策略版本、来源、运行 ID 和时间。数据库迁移须保留旧课程、人工审核和既有深链接；新增聊天、播放器事件不能绕过现有权限隔离。原始解释、模型建议和独立数学结果分别存储，避免后续把建议当事实汇总。

按可交付闭环推进，不先承诺固定日期。每阶段记录实现项、未完成项、真实调用与费用边界、回归范围和可复现演示。

| 阶段 | 完成内容 | 依赖 | 验收目标 |

| R00 自主运行基础 | 自动开放分级、权限/预算/状态契约、旧审核兼容、任务恢复 | 现有权限/任务系统 | 自动通过、澄清、拦截三条路线；学生不能越权扩额，旧审核可查 |

| R07 语义 Skill 改进 | 模型候选、扩展评测、影子/个人试用与回滚 | R03、R04、R06 | 候选影响实际消费者、边界违规被拒、失效评测不能发布，效果未知明确标注 |

**第一批建议启动 R00/R01，并接 R02 自然语言数值答案与 R03 默认资料包。** 先消除“不会下一步、答一句话不识别、总等管理员”的日常阻塞。R05 的已有资源展示可同步从离线样本开始；完整媒体生成需要独立配置与预算，不让这项等待阻塞前一批开发。

第二批完成 R04 与 R05 的完整学习/课堂链路，第三批深化 R06/R07 并逐项推进 R08。图形的基础展示可以前移，但不能提前宣称量规或效果已验证。

### 12.1 端到端验收场景

预先完成一次平台配置后，模拟学生新建“有理数”空间 → 用自然语言说明目标 → 根据诊断确认安排 → 以“这个答案是3”回答并请求提示 → 接着上一轮解释 → 进入圆桌与我教 AI → 观看包含布局、公式、媒体和互动的课堂 → 完成无辅助检测 → 查看证据图形 → 接受/撤回个人策略 → 查看 Skill 候选依据和评测。

普通、已覆盖的私有学习路线中，**逐项等待管理员的次数应为 0**。超出授权、质量不足、来源撤回或预算停止时有可理解替代路线；不能为满足“0 次”而放宽检查。整条流程须由真实页面与接口验证，不能只用静态演示替代。

同时验收：否定/多答案/改口/单位、零与边界条件、重复请求、取消与未知计费、跨项目与临时会话隔离、播放器凭据/外联、媒体失败、旧版本恢复、策略撤回、资料撤回、保留题泄露和不确定性表达。

记录首次可学习时间、生成等待与恢复成功率、必要操作数、自动开放/异常比例、答案提取错误与澄清比例、核验覆盖、单任务成本及可追溯性。先建立基线与失败分类，再制定有依据的性能指标；这些运行指标不替代学习效果评价。
