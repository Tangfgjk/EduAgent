# G00 与 G01：可信输出、动态内容与显式课程绑定

日期：2026-10-18；对应 [87 路线清单](87-下一阶段开发路线与验收清单.md)。G00、G01 已完成本阶段的开发范围并通过验收；后续 G02–G09 仍按依赖推进。

## 1. G00 实现

### 模型文字与展示文字分开

新增 `learning/output_gate.py`，版本 `intent-renderer.v1`。概率我教 AI 和圆桌仍由模型引用学生原话、选择讨论方向；未经语义核验的自由问句不直接展示，由方向和角色映射到受限安全问题。正常追问结构继续通过，中文答案、文字算式、伪问句即使通过旧正则，也会被替换。原有数字、注入等结构拒绝继续生效。

同一门禁同时用于新结果与旧结果读取，包括活动结束后的历史追问；不重写数据库中的历史记录。`rendering_mode`、`diagnostic_code=unverified_prose_replaced` 和页面说明公开当前展示方式，不将安全模板称为已理解学生解释的自由生成。

这个边界没有解决任意数学文本的语义验证，后续开放自由内容须经过 G03/G04 的内容核验和评测。原冻结真实报告保留，不能将其质量结论直接套用于新的展示策略。已有概率陪学本来就采用方向映射，不扩大其模型范围。

学生输入、调用预约、已知/缺失用量、未知费用、失败不自动重试和独立检测隔离保持原机制。模型不能批准自己的内容、评分或教学效果。

### 契约与范围

新增 `content_contracts.py`：TopicIntent、SourceReference、TaskSpec、ActivitySpec、GeneratedContentSpec、ValidationReport、CurriculumDraft、ResourceManifest、SkillCandidate。

| 契约 | 当前实际约束 |
|---|---|
| TaskSpec | 有界参考数值可解析；诊断→练习→检测顺序；练习四级支架；检测无提示 |
| ActivitySpec | 指向同包练习与另一道检测；仅已实现的 teach/roundtable 流程；不接受任意角色 HTML/脚本 |
| ValidationReport | 明确结构检查与数值比较范围，专业审核和解释审核不能自标为真 |
| ResourceManifest | 仅产物元数据契约，固定待审核；未接 OpenMAIC，不执行资源 |
| SkillCandidate | 仅既有学习时长、反思方向；固定待审核，不执行任意 Markdown 指令 |

管理端“配置与权限”展示按用途的数据范围、输出限制、共用预算、单次 tokens 和未来用途禁用状态。当前四条开发用途为 coach、teach、roundtable、planning；搜索、整课程生成、资源生成和 Skill 进化没有因为增加契约而获准真实调用。0 次数上限仍表示不限次数，不表示免费或无限 tokens。

**数学边界**：程序只比较有界有理数表达式与参考值。参考值可解析不证明题意正确、参考答案正确、条件完整或证明有效；结构登记结果为 `unverifiable / structure_only`，不是数学检查通过。专业判断、解释质量、掌握和教学效果仍未自动评定。

## 2. G01 实现

### 统一仓储与不可变版本

新增 `ContentRepository`，封装旧静态包和数据库登记内容。新内容不需要修改 `PACKS`、`ACTIVITY_PACKS` 或 worker 的单元常量。旧静态 ID、内容 hash、教学版本计算不变，旧检查点继续读取。

| 新表 | 用途 |
|---|---|
| generated_content_versions | 内容规范、版本 hash、来源、结构验证记录与登记者 |
| task_versions | 各版本完整题目及参考值，仅管理员/内部运行读取 |
| activity_versions | 指向父内容版本的活动规范与独立版本 hash |
| curriculum_versions | 工作空间自己的主题、课程名称和有序单元快照 |
| course_bindings | 当前课程、当前单元与并发 revision |

前四张表在 SQLite/PostgreSQL 均有更新/删除拒绝触发器。变更内容须使用新 ID 登记新版本，不能覆盖已有学习来源。登记入口串行保护课程与活动共用的 ID 命名空间。

仓储在业务边界显式使用 session。教学图只接收已解析的不可变内容；陪学把内容快照留在私有检查点中，活动图闭包持有已解析版本，不将数据库 session 传入图节点线程。公开 DTO 不导出参考答案、私有内容快照或尚未出现的检测题。

### 登记、审核、开放

管理端新增 JSON 登记界面及登记状态列表；接口为 `POST/GET /api/v1/admin/dynamic-content`。样例是 `examples/dynamic-content.rational.json`，仅演示自编内容登记机制，不是模型自动生成的新课程。

登记 → 查看题目/来源/提示 → 保存版本化开发核对依据 → 分别发布陪学与活动。登记不能自标专业审核/数学通过或直接启用；新增动态内容全部要求开发审核，`needs_revision` 会按原机制撤回已开放版本。真实学生仍拒绝使用开发内容。新版圆桌与我教 AI 均检查父陪学内容是否仍开放。

当前数据库登记的是**共享开发内容库**，只允许管理员登记自编或已授权开发素材；不承载私有学生生成产物。G03 必须再引入任务/产物 owner、来源权限和私有生成队列，不能把这个全局库接口直接用于学生上传记录。

### 显式课程绑定

学生全局上下文增加“学习主题 / 课程名称 / 当前课程单元”。主题由学生填写，单元必须从已开放的内容中明确选择，不按项目名称猜测。更改主题或课程产生新课程快照；切单元只更新绑定 revision，并留下审计。

所有学生页共享同一上下文。陪学使用当前单元；圆桌、我教 AI 只匹配该父单元，支持同父单元的明确活动版本链接；没有对应内容时显示缺口并禁用开始。进入新单元不能绕过后端绑定检查。更名不改绑定，刷新可恢复，不同空间独立。

复习、成长和规划仍保留本项目历史范围，不会因切单元删除/伪造旧证据；这不表示 G06 的知识点学情分析或 G07 的课程策略自动调整已经实现。复习历史其他单元时以该条原始来源为准。

课程确认/切换使用空间锁和 expected_revision；冲突返回 409。进行中的陪学、圆桌、我教 AI、策略任务须先完成或取消再调整。归档空间只读，跨账号 404，课程 ID 不能从其他空间导入。

**兼容口径**：学生页面的新学习须先确认课程；旧项目不会自动写入绑定。旧静态 API 客户端仍可按原方式明确传 unit_id，已存静态运行可继续；动态内容 API 必须有绑定。绑定存在后，静态和动态的新学习都必须符合当前单元。该兼容入口不代表已根据历史自动确认课程。
