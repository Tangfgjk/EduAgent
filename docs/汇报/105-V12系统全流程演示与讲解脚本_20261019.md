# 桂子问津 V12：系统全流程演示与讲解脚本

**演示日期：2026-10-19；编写依据截至2026-10-18。** 适用应用0.18.0、数据库`g08_001`、V12开发版。本文件按现场顺序编排，可一边操作一边讲解。

本文件是演示脚本，不是已经执行的彩排记录。文中的“应看到”是检查目标，具体账号、课程、历史记录和任务状态请在演示前核对。

2026-10-19界面增补：学生“主题与课程”顶部先展示“当前课程与学习路线”和资源，随后是“准备新的主题课程”；管理端先展示流程和预算，课程按项目分组。需要调整生成开关时展开“生成用途与知识资料设置”。审核、学生确认和独立预算流程不变。

教学Agent增补（API0.19.0）：第三幕可勾选有理数Agent，输入“有理数”后选择“相反数、绝对值与距离”，填写“区分二者并用数轴核对”。宽泛主题先澄清；模型可设计5–11项任务和目标化活动，审核页可展开“Agent教学设计”。旧课程仍按原样展示。新流程详见[15号手册](../使用手册/15-有理数教学Agent与动态课程操作.md)；一次真实探针数值通过但语义待修订，不作为已审核演示课程。

## 一、先记住这条主线

**管理员准备 → 学生建立项目 → 输入主题与诊断 → 生成并审核课程 → 确认计划 → 陪学 → 圆桌 → 我教 AI → 复习 → 成长证据 → 规划与策略 → Skill 离线改进 → 管理和评测 → 总结。**

全程用一个正式项目串联，建议主题为**有理数混合运算**。学生端和管理端分别放在两个浏览器标签页，切换时说清正在扮演哪个角色。

产品定位可以这样开场：

> 桂子问津面向初中数学自主学习。今天我会用一个项目演示：学生如何从一个学习主题出发，生成和确认课程，通过陪学、讨论、讲解留下学习证据，再让这些证据影响下一次教学策略。当前展示的是模拟或成人开发流程，专业教学评价和真实学生效果还需要后续验证。

## 三、第一幕：管理员准备教学环境

### 3.1 账号与双端

**操作**

1. 管理端进入“学生账号”，展示已有演示账号。
2. 需要展示创建时，新建一个开发账号：填写显示名、登录名和至少6字符密码；密码在投屏前输入或暂时隐藏投屏。
3. 切到学生端，用对应学生账号进入“今日学习”。

**讲解词**

> 学生端负责学习，管理端负责内容、账号、模型配置和审核。首个管理员通过本机命令初始化，后续学生账号由管理员创建。学生不需要接触模型密钥或服务商配置。

**实现说明**

双端是独立React页面，共享类型与基础组件；FastAPI在服务端检查身份和角色。界面隐藏按钮之外，接口也检查权限。登录会话持久化，切换标签页不应重新登录。

**应看到**：学生端是学习导航，管理端是治理导航；创建的账号可正常登录。切到其他页再返回时会话仍有效。

### 3.2 内容与开放开关

**操作**：管理端“知识点与题库”打开一个有理数开发单元，展示题面、参考数值、提示、检测及开发核对记录；再展示“配置与权限”的已发布模型状态。

**讲解词**

> 系统保留七个静态开发单元作为稳定基线，另有主题生成课程。内容和模型能力分别开放，陪学包启用不代表所有旧互动包自动具备。接下来主线使用生成课程，把三类活动统一到相同课程上下文。

**实现说明**：内容有版本和审核状态，课程与活动经过独立门禁；数值核验、人工意见和发布回执分别保留。

这一幕只展示已经核对过的内容；没有检查就不现场勾选“通过”。开发核对不等于数学专业教师审核。

## 四、第二幕：学生建立自己的学习项目

### 4.1 建项目和临时会话

**操作**

1. 学生端“项目与会话 → 新建学习项目”，输入“有理数混合运算·汇报演示”，保存并进入。
2. 指出左侧“当前工作空间”和页面顶部项目名称。
3. 悬停铅笔和归档图标，展示“重命名”“归档（保留记录，可恢复）”提示；主项目先不归档。
4. 如需实际展示归档/恢复，创建一个单独临时空间，归档后在“已归档”中恢复，再切回主项目。

**讲解词**

> 正式项目用于长期目标，临时会话用于短期探索。陪学、复习、讨论和规划都有项目归属；切换项目不会把原来的学习上下文带进来。归档是停止新增并保留记录，之后可以恢复。
>
> 项目名可以自由取，例如“补基础”，因此系统不会仅靠名字猜课程，接下来会明确确认课程和版本。

**实现说明**：后端校验账号所有权、空间状态和请求版本；课程绑定与空间名称分开存储。临时过程保留在局部，不自动并入正式项目长期画像。

**应看到**：新项目初始没有学习证据，这是正常状态；切换空间后列表和上下文随之变化。

## 五、第三幕：主题、诊断、课程生成与审核

### 5.1 输入主题并完成诊断

**操作**

1. 在主项目进入“主题与课程”，输入`有理数混合运算`。
2. 点击“解析主题并准备诊断”。展开来源与范围，阅读两道实际诊断题。
3. 按屏幕上的具体题目填写数值和依据，点击“保存诊断并查看课程范围”。**生成内容可能变化，不要照抄固定答案。**
4. 展示“本轮课程范围”，选择本轮重点，例如“说明法则与前提”，点击“保存本轮重点调整”。

**可用输入示例（依据/目标，不是题目答案）**

> 我先辨认运算顺序，再分别检查符号和绝对值；最后估计结果是否合理。

只在确实符合本题操作时使用这句话。

**讲解词**

> 我们先把主题映射到当前可支持的知识点，再通过少量问题了解本轮输入。学生可以调整学习重点。当前准备页已经展示材料，因此这次诊断是课程准备信息，不作为严格的无辅助前测。

**实现说明**：主题解析、知识来源登记和诊断结果进入持久化流程。当前自动题族有六类，含糊或不支持的主题会澄清/拒绝，不强行套用别的题。

### 5.2 发起生成，等待时介绍架构

**操作**：点击一次“确认范围并生成课程”，展示排队/处理状态。

**等待时讲解**

> 请求先落库，再由模型worker通过统一Provider调用DeepSeek。教学流程由LangGraph编排，API、教学worker和模型worker分开，所以离开页面不会重新创建调用。模型产出只是候选，之后还有结构检查、数学核验和人工审核。
>
> 课程生成最多4096输出tokens/次、每课程最多6次调用，含至多一次明确内容修复；这些是开发上限，不代表每门课程一定使用全部调用。失败和未知结果会保留，系统不盲目重试。

**应看到**：生成成功后进入内容待开发审核。若出现明确校验失败，展示原因；不要为了演示强行发布。等待过久时记录任务状态，按备用方案切到项目B，明确告诉观众稍后回看。

### 5.3 管理员审核，再由学生确认课程

**操作**

1. 切到管理端“课程生成与资源 → 项目课程候选”，按主项目定位任务。
2. 展开完整候选，依次看来源、目标、题目条件、参考数值、提示、检测/活动安排和独立核验报告。
3. 确认无误后填写至少十字审核依据并发布；例如实际核对后可写“已核对本次数值参考、运算条件和检测隔离，限自编开发演示”。有问题则退回。
4. 回学生端刷新，点击“确认使用这份课程”，指出顶部课程名称/版本。

**讲解词**

> 这里有两种不同判断：程序能核对当前支持范围内的计算和条件，但讲解是否适合教学仍需人工检查。管理员发布后，学生确认使用，课程才成为当前项目的学习上下文。

**实现说明**：课程候选、核验报告、审核回执和绑定版本分别保存；课程是当前空间的私有上下文，不会自动复制到其他账号。

**应看到**：陪学、圆桌、我教AI围绕同一课程，不要求反复挑无关单元。

### 5.4 穿插资源与外部搜索（有准备材料再展开）

**操作**：展示课程页已有“当前课程资源”；没有资源时，到事先确认可访问的历史项目/管理任务展示已有OpenMAIC文本样例，说明它的归属，然后切回主项目。

**讲解词**

> Tavily用于在指定站点发现知识资料，搜索结果不自动成为授权教材。OpenMAIC用于教学资源生成，已经完成独立Docker服务和一门三场景文本课堂验收。当前只导入安全文本，不执行原始脚本；不是完整媒体课堂。
>
> OpenMAIC首轮预算已停止，今天展示已生成资源，不现场重开生成。新项目没有资源也会如实显示为空，不假装已有资源自动共享。

**实现说明**：资源走独立适配、压缩包检查、文本提取、人工审核和沙箱预览；检测阶段不展示资源。搜索范围、资源预算与主模型日额度分别管理。

## 六、第四幕：确认计划，完成一次陪学

### 6.1 由学生确认目标和时间

**操作**：进入“学习计划”，目标填写：

> 能说清有理数混合运算的顺序，分别检查符号与绝对值，并独立核对结果。

选择每天15分钟，点击“生成计划草案”。阅读后可将时间改为20分钟，点击“更新草案”，再点“我确认这份计划”。

**讲解词**

> 学习目标与时间由学生确认。这里是计划流程关口，与刚才的模型课程生成、后面的策略版本是三个不同对象；当前计划草案使用固定开发流程，不能说它自动理解了完整教材。

**实现说明**：LangGraph暂停等待确认，状态和输入持久化；重复提交有幂等和版本校验。只有API而没有教学worker时，请求会排队。

### 6.2 陪学：先独立尝试，再逐级支持

**操作**

1. “津津陪学 → 开始开发单元”，指明当前课程和本任务策略信息。
2. 诊断题按题面独立填写数值及依据；指出此阶段提示不可用。
3. 练习题先提交自己的尝试；需要时点“给我一点提示”，再看下一级提示。
4. 页面如出现已开放的AI追问入口，可提交当前困惑，例如“我不确定这一步的符号判断，应该先检查什么？”，等待一次回复。
5. 按页面继续，填写简短反思，例如“下次先标出运算顺序，分开核对符号与绝对值”。
6. 完成无辅助检测，查看学习小结。数值答案按实际题面计算，不预设固定结果。

**讲解词**

> 陪学先保留学生自己的尝试，再提供支持。答案与解释分别记录，程序独立核验数值，不让模型自己出题又自己判定全部正确。现在的追问方向可由模型选择，展示仍受控，不能当作已经具备完整解释评分。
>
> 生成课程支持“先自问，可恢复具体支持”：满足已有无提示通过等条件后，后续练习首次帮助先邀请学生提出检查问题；如果仍困难，可以恢复具体提示。渐撤不是拒绝帮助，也不会改成检测时提供答案。

**实现说明**：TutorGraph控制诊断、练习、反思和检测阶段；支持决定、提示次数、内容版本和原始提交写入事实。模型任务与独立数学核验分开，输出经过门禁。旧静态单元不因为这个策略自动升级为渐撤课程。

**应看到**

- 诊断/检测阶段没有提示与资源；练习可以逐级求助。
- 提示使用有记录，数值错误/不可验证有不同反馈。
- 小结表示本轮发生的过程，不自动宣称“已经掌握”或“教学有效”。

**现场节奏**：本路线应完成当前任务后再切换活动。如时间不足，明确结束当前任务后展示备用项目的已完成记录，不留下一个进行中的任务再硬开圆桌。

## 七、第五幕：圆桌与我教 AI

### 7.1 圆桌讨论：比较思路

**操作**

1. 当前陪学结束后进入“圆桌讨论”，核对同项目、同课程。
2. 开始活动，先按实际题目填写自己的答案与依据。
3. 阅读三种视角，指出哪些在检查条件、哪些在检查表示或结果。
4. 提交自己的比较和修正，完成验证题，展示过程小结。

**讲解词**

> 圆桌让学生比较观点、寻找依据，再形成自己的判断。三种视角来自同一个模型的不同设定，不是三位独立专家；系统不会因为多数意见相同就认定数学正确。最终数值验证仍由程序独立完成。

**实现说明**：ActivityGraph保存学生原始贡献、讨论内容、修正与验证；不同来源分开记录。模型选择受限讨论方向，活动与课程版本绑定。

**应看到**：有学生自己的表达和修正记录，而不只是AI之间对话。未审核课程或同空间已有活动时，系统会阻止新任务。

### 7.2 我教 AI：把方法讲清楚

**操作**

1. 圆桌完成后进入“我教AI”，开始同课程活动。
2. 按题目给出数值和自己的讲解；可使用这样的表达结构：

   > 先说明已知与所求，再说明运算法则及适用条件，最后解释怎样核对结果。

3. 使用已开放的模型追问，阅读问题后补充依据；通用活动最多三轮。
4. 保存修正并进入另一题验证，查看小结。

**讲解词**

> 这条路线让学生从“我能算”走向“我能说明”。AI根据当前输入选择针对性追问方向，学生有机会修正自己的说明。当前系统不把长篇文字自动评成推理正确；独立数值验证与讲解质量分别看待。

**实现说明**：活动状态限制轮数和上下文，记录每轮讲解、追问和修正；验证任务与帮助隔离。题目只要展示过就记曝光，取消也不会把“已见”重新当成“首次独立”。

**应看到**：多轮状态能恢复，讲解和修正可追溯，最终有独立验证记录。模型没有回应时查看状态，不重复建立多次相同付费任务。

## 八、第六幕：错题、复习与成长证据

### 8.1 错题与复习

**操作**

1. 打开“错题与复习”，查看当前项目安排，打开一条错题或辅助后通过的来源。
2. 展示原答案、提示使用与日期；需要时追加学生说明，说明这是自述。
3. 如存在可复做任务，按页面完成一次无提示原题复做。
4. 新项目没有到期项时，展示“尚未到期”；可切到同账号历史项目演示已有到期记录，或在允许情况下展示提前复做。

**讲解词**

> 学习记录不只是聊天历史，也会形成可追溯的复习安排。默认1/3/7天是开发规则，提前复做单独记录，不会伪装成已经完成到期复习。原题再次做对，也不等于通过未见题迁移检验。

**实现说明**：不可变学习事实是原始依据，记忆和列表由事实派生。人工意见与学生说明追加保存，不覆盖原始作答；复习排序可以调整，间隔不随策略随意改变。

### 8.2 成长证据：每张图都能回到材料

**操作顺序及讲法**

| 操作 | 当场讲解 |
|---|---|
| 切“当前空间局部”，选择日期和来源 | 这里先只看当前项目；模拟和成人数据的含义分别保留 |
| 看知识点卡，点击一条来源 | 有记录说明发生过学习活动，不等于整个知识点掌握 |
| 看学习表现分组 | 有无提示、首次/已见曝光、提前/到期复做分开，避免混为统一正确率 |
| 看支架时间线 | 能看到什么时候求助、先自问、恢复支持；旧事实缺字段则不猜测 |
| 看数学素养条形，打开材料 | 六方向是候选材料覆盖，当前均未评定，没有能力分 |
| 打开原始来源，再看自述 | 机器事实、学生体验和人工数值意见是不同类型的信息 |
| 切“全局宏观” | 仅汇总本人正式项目，临时空间不自动混入；归档和日期也影响范围 |
| 查看供规划使用的摘要 | 规划引用有截止时间和来源指纹；不是无限读取全部聊天 |

**实现说明**：evidence/memory模块按账号、空间、来源、时间和版本聚合；原始来源支持钻取。当前知识图仅六个开发KC映射，素养材料计数不是正式量规。

**注意**：若刚追加自述，要在生成后续策略/离线候选前完成；候选冻结后再改来源可能使其失效。

## 九、第七幕：用证据调整实际教学策略

### 9.1 提出普通策略

**操作**

1. 确认回到正式主项目，结束所有当前学习活动。
2. “规划与策略”填写本次体验，例如：

   > 这次我容易漏看运算顺序，需要把符号判断和检查依据分别说明。

3. 选择每日15分钟、反思重点，以及1–5份已发布参考资料。
4. 勾选“调整执行策略（需审核与本人确认）”。为后续离线改进保留可比较基线，可采用：练习原顺序、复习到期时间优先、支持先自问可恢复、追问依据与适用前提。
5. 如需展示真实规划调用，明确勾选“使用已开放模型生成有来源的候选”；否则保留固定开发提案，说明本次是本机路径。
6. 点击“生成开发策略提案”，查看冻结来源、学情摘要、参数差异和Skill。

**讲解词**

> 证据不会直接改写教学。这里把学生体验、客观参考和实际过程冻结成提案，再决定是否调整。真实规划模型当前只建议时长和反思重点；四项执行策略在这条手动提案路线由学生选择，不能说已由模型全面自动优化。

**实现说明**：planning模块冻结有界来源并编译白名单配置与Skill.md，校验参数及指纹。当前新增学情摘要保存在本机，不因展示而无限扩大外发数据。

### 9.2 管理员审核、学生确认、新任务验证

**操作**

1. 管理端“策略评审”打开该提案，核对来源、课程、差异和Skill，填写依据后通过。
2. 切学生端，阅读并确认激活，展示“当前学习软策略”和版本。
3. 打开下一次新任务的“本任务冻结的执行策略”，核对版本/指纹；如已启动新任务，完成或结束后再继续G08。
4. 展示Skill.md导出内容即可，先不实际回滚或修改课程。

**讲解词**

> 四类策略已经接到实际消费者：练习与复习排序、生成课程支持方式和通用追问重点。它们不能删题、改检测、改数学核验或扩大预算。管理员通过后仍由学生确认；每个新任务冻结开始时版本，后续回滚不会悄悄改写旧任务。

**应看到**：审核后未确认时尚不生效，确认后有版本；新任务快照可查看。若没有同版本错题，错题优先也可能与原顺序相同，这是正常结果。

## 十、第八幕：Skill 离线改进的完整闭环

### 10.1 冻结来源，生成单参数假设

**前提再核对**：正式项目、已绑定课程、有效四参数基线、同项目/来源/内容版本实际记录；没有其他待处理候选。

**操作**：学生“Skill离线改进 → 生成离线改进候选”，等待教学worker。展开“改进假设”“查看冻结来源与原始材料”“冻结机制评测”。

**讲解词**

> 目前这一步是本机结构化规则，不调用真实模型、不自动理解长篇讲解。系统从数值错误、求助和人工数值纠正提出一个参数变化；没有足够证据或参数已采用，就可以不产生新候选。
>
> 我们先做可核对的小变化，而不是让模型直接任意改写教学规则。每个候选保留父版本、来源指纹、差异以及编译后的Skill配置。

**应看到**：例如原序→错题优先的单项差异，或如实显示“无合适候选”。不要承诺每次必有相同候选。

**没有候选时**：展示来源不足/参数已采用的原因，使用预先准备的既有候选继续介绍；既有候选属于哪个项目就明确展示哪个项目，不能拿其他项目报告冒充主项目结果。

### 10.2 对比机制，不宣称学习收益

**操作**：展开一个开发样本和一个隔离保留样本，展示baseline/candidate实际行为、工程门禁、版本与报告哈希。

**讲解词**

> 新旧策略运行了实际的排序、支持和追问消费者，并检查检测隔离、数学参考与越权字段。当前只有四个自编工程样本，脚本按参考答案作答，因此这里证明的是机制能否正确执行，不是学生成绩变好了；学习收益字段仍为空，自动真实发布关闭。

**实现说明**：SkillEvolutionGraph执行候选与评测，数据集/候选/评测表保留不可变产物；语料、编译器和消费者代码签名参与校验，变化会使旧报告失效。

### 10.3 两层审核与学生确认

**操作**

1. 管理端“Skill进化评测”，选中候选，核对diff、来源与报告。
2. 填至少十字真实依据，点“复核通过，允许生成提案”；门禁不通过则不能批准。
3. 学生点“刷新改进状态”，填写至少十字理由，点“采纳为待审策略”。
4. 点击“前往策略审核与确认”；管理员到“策略评审”审核这份新普通提案。
5. 学生核对后确认激活，再展示新版本与后续新任务快照。

**讲解词**

> 第一层复核确认候选具备进入提案流程的开发依据；第二层仍是原有的策略审核和学生确认。评测通过不会自动上线，系统保留人的决定权和完整谱系。

### 10.4 最后再展示回滚/撤回

完成上述流程后，可在“规划与策略 → 查看激活历史与回滚”选择有效旧版/默认基线，填写理由，演示后续新任务恢复；也可仅展示入口。

管理员的“撤回评测复核”会使关联提案/策略受到门禁限制，保留历史。**回滚、撤回和新增事实不要插在候选冻结到采纳之间**，否则旧候选可能因基线或来源变化失效。若希望同时演示两条操作，分开使用已有样例，并先说明影响。

## 十一、第九幕：管理与评测工作台

依次快速展示：

| 页面 | 展示操作 | 实现与讲解重点 |
|---|---|---|
| 运行记录 | 定位刚才项目的一条任务，查看状态、事件、用量 | 长任务落库、租约恢复、幂等提交；取消不能追回已产生的外部费用 |
| 内容与解答复核 | 打开已有不可验证样例；无样例则展示入口和空态 | 人工数值复核追加保存，不覆盖原答案，不等于解释/素养专业评分 |
| 评测工作台 | 选已有报告，展示条件、版本对照和逐条人工意见 | 只比较可比条件，语义失败保留；不把接口成功率当教学效果 |
| 课程生成与资源 | 回看刚才课程状态、来源与审核记录 | 课程可撤回，来源/版本门禁影响后续使用，历史记录保留 |
| 配置与权限 | 回看服务与额度状态 | 统一Provider在管理端配置，学生只关注学习；密钥不返回浏览器 |

这一段主要读历史和状态。不要为演示随意暂停他人任务、撤回正在使用的内容或重开已停止预算。

## 十二、结尾：用闭环收束

可以这样讲：

> 今天演示了一个主题如何形成项目课程，学生如何通过陪学、比较观点和讲给AI听留下可追溯证据，以及证据如何经过审核影响下一次策略。后台用LangGraph编排可恢复流程，用独立程序核验支持范围内的数学答案，用版本与审核控制内容和策略发布。
>
> 当前我们已经形成首轮可运行的工程闭环，但课程覆盖仍有限，素养展示仍是候选材料，Skill改进还是规则驱动的离线机制验证。接下来先深化题族和多轮评阅，再建设专业量规与资源体验，最后做数据授权、运维和小范围真实试点。

如被问“现在是否都自动完成”，回答：

> 课程候选和部分交互已经使用真实模型；数学核验、审核与学生确认仍是独立环节。Skill离线改进目前采用结构化规则，不是已经通过教学验证的自动RSI。

## 十三、现场异常与备用路线

| 现场情况 | 操作 | 可以这样解释 |
|---|---|---|
| 课程生成一直排队 | 查看运行记录和worker，切同账号备用项目B，保留原任务 | 长任务异步处理，先看已有结果，稍后回到新任务 |
| 模型超时/上游未知 | 不自动重试，不重新连点；展示已保存结果 | 未知状态和费用单独记录，不当作零成本失败 |
| 课程数学校验失败 | 展示报告；按明确失败规则决定一次修复或使用备用课程 | 这是核验拦截，不能为赶进度绕过审核 |
| 静态有理数缺少互动 | 使用已审核生成课程，先完成/结束当前任务 | 静态陪学包与互动包独立，生成课程提供统一上下文 |
| 圆桌/我教AI不能开始 | 检查当前空间、绑定、审核与未结束任务 | 同空间依次学习，避免检测被其他活动帮助污染 |
| 没有到期复习 | 展示未到期状态/历史到期记录 | 新项目刚创建，不修改时间伪造到期 |
| 新项目图形空白 | 先完成实际作答，或注明切到历史项目 | 图形来源于事实，不从项目名称凭空生成 |
| Skill没有候选 | 检查基线/证据，展示既有合法样例 | 没有证据不强造优化，参数已采用也不重复包装 |
| 旧提案/报告失效 | 展示原因，刷新；另择有效样例 | 课程、事实、基线或签名改变后，旧依据不继续发布 |
| 状态冲突 | 两端刷新并重核修订，不重复批准旧状态 | 并发保护保留，不绕开版本检查 |
| OpenMAIC不能预约 | 展示已有文本导入与预览 | 首轮预算停止，服务可用不等于获准再次生成 |

### 15分钟精简版

1. 1分钟：双端与产品定位。
2. 3分钟：主题输入、已有诊断/生成任务、管理员审核回执与课程绑定。
3. 4分钟：现场一道练习与求助；展示已完成圆桌/我教AI记录。
4. 2分钟：成长证据切换范围、钻取一条原始材料。
5. 3分钟：展示有效策略、Skill diff、冻结评测与完整确认记录。
6. 2分钟：运行工作台、实现架构和下一步。

提前生成的课程和历史记录直接说明是“已保存的开发样例”；精简版不声称现场新走完全部步骤。

### 常见追问

- **为什么选择LangGraph？** 教学是带状态、确认关口和恢复需求的多轮流程；图编排配合数据库和worker可持久运行。LangChain按需适配，当前核心模型调用通过自有统一Provider。
- **为什么不是完全自由对话？** 当前要明确课程范围、保留学习证据并独立核验数学；未核验自由文字仍受输出门禁约束，语义教学需逐步评阅开放。
- **怎样知道学生真的学会了？** 当前只能展示数值与过程事实，不能据此认定教学效果。正式结论需要专业量规、无辅助测验、延迟和未见迁移评价。
- **RSI完成了吗？** 已有受限候选、实际机制评测、人工复核和策略生效闭环；真实模型语义进化与真实收益验证尚未完成，自动真实发布关闭。
- **没有真实学生，前期怎么开发？** 使用明确标记的自编题、模拟/成人操作、冻结语料和隔离回归，先验证机制；这些不替代后续真实试点。
- **OpenMAIC接到了什么程度？** 独立固定版本服务、一门三场景真实文本生成、安全导入与预览；媒体与完整交互课堂未开放。
