## 2026-10-18：离线候选跨端验收需按来源ID和最新修订定位

状态：已解决；模块：skill_evolution/e2e；关键词：`report_sha256`、同秒排序、`revision_conflict`、跨端撤回。

### 现象

G08首次浏览器验收中，最后一条来源有时是诊断而非错误练习；学生采纳后管理端立即撤回也可能仍携带旧修订。

### 定位过程

核对固定测试输入、冻结来源与两端阶段：事实按秒级created_at和ID稳定排序，同秒记录的数组位置不是语义顺序。学生采纳又递增修订，旧管理端视图不能直接代表服务器新状态。

### 根因

验收脚本把数组最后一项当作目标材料、把另一个端的操作完成当作本端同步完成，依赖了未保证的排序和时序。

### 解决方案

按题号/状态选择具体来源；明确等待管理端新阶段及策略worker完成后再撤回。保留revision/hash门禁，并提供真实用户可见的刷新入口，不自动重放冲突决定。

### 验证方法

最终skill-evolution.spec.ts与strategies.spec.ts同批6场景通过；后端保留幂等、来源失效、报告hash及不可变性检查。工程通过仍不等于学习收益。
