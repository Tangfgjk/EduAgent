## [S10-TEST-001] 证据范围契约不能沿用记忆接口的名称

### 现象

新包完整学习、复做均成功，但 8 个跨数据库场景在证据范围断言处失败：预期 `project`，实际 `workspace`。

### 定位过程

检查 `EvidenceOut`，其范围枚举为 `global / workspace`；记忆接口采用不同范围名称。失败与数学包、持久化或空间隔离无关。

### 根因

新增测试错误地把记忆接口的局部范围名称套到了成长证据契约。

### 解决方案

按实际 OpenAPI/Pydantic 契约修正新测试为 `workspace`；未修改既有接口。

### 验证方法

完整后端 293 项通过，最终 S10 专项 15 项通过。避免为了迎合错误测试改变已存在的 API 名称。

## [S10-ENV-001] 多工作目录下要同时校验解释器和相对路径

---
module: frontend-tooling
category: 01

difficulty: 1
status: 已解决

keywords: [python.exe not recognized, cwd, no exported member]
---

### 现象

在 frontend 目录调用项目根的相对 Python 路径，编辑脚本未执行；后续类型检查报告尚未导出的目录接口和类型不存在。

### 定位过程

先检查命令执行目录和解释器路径，确认文件编辑没有发生；API 类型生成成功不代表此前独立脚本执行成功。

### 根因

根目录的 `.venv`、以根为基准的文件路径与 frontend 工作目录不匹配。

### 解决方案

将文件编辑放回项目根目录执行；前端命令在 frontend 内单独运行，并检查每个执行结果。

### 验证方法

TypeScript、双端构建、OpenAPI 一致性与 Chrome 22 项、Edge 4 项浏览器验收通过。
