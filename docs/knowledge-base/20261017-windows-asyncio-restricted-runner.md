# Windows 受限运行器中 asyncio 初始化挂起

状态：已解决（运行环境处理）；日期：2026-10-17；分类：环境；关键词：asyncio、socketpair、Proactor、accept。

## 现象

Fake 专项评测在受限终端中不推进，连不访问模型的最小异步程序也会挂起。

## 定位过程

使用 `faulthandler.dump_traceback_later(5, exit=True)` 检查最小 `asyncio.run(asyncio.sleep(0))`。栈停在 Windows socketpair 回退的 accept，调用来自 Proactor 事件循环自唤醒管道初始化。同一命令在获准的普通本机执行环境中立即打印完成；评测在该环境中也完成。

## 根因

证据定位到受限运行器与 Windows 本机 socketpair 初始化的环境交互，发生在业务异步任务开始前；并非模型延迟。尚未定位到具体 Windows 策略条目，因此不将其描述为某一防火墙规则错误。

## 解决方案

需要本机循环网络能力的测试通过获准执行环境运行，不改应用事件循环、不清空数据库、不绕过模型输出校验。停止时只处理经确认属于本项目的评测进程；保留中断目录，新 Fake 运行独立验收。

## 验证方法

同一最小复现正常退出；新 Fake 18 次尝试完成，真实专项 18 次尝试完成，26 项后端测试及 Chrome 工作台验收通过。真实任务失败仍照实保留，环境恢复不等于模型结果全部通过。
