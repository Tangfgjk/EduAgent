## 现象

用户报告学生端在浏览器切到其它页面再返回需要重新登录。新增最小浏览器测试：普通网页往返正常，但学生与管理双端在同一浏览器切换账号后，原学生工作台无法访问。

复现命令：在 frontend 下设置 `PW_CHANNEL=chrome` 后执行 `npm run test:e2e -- session.spec.ts`。修复前结果为 1 通过、1 失败，学生端返回后的 `.app-shell` 可见断言失败。测试最初还需经过旧“退出并切换账号”界面；补齐实际操作后，在预期位置稳定复现。

## 定位过程

按可能性检查共享 Cookie、焦点恢复刷新、会话过期。普通往返与刷新通过，双端登录切换失败；检查服务端确认两端使用同名 Cookie，并且旧界面的身份切换会调用退出注销当前会话。浏览器恢复时重新读取身份，才显示凭据已被另一端覆盖。共享广播通道也会传播无关端的状态刷新。

没有通过关闭焦点检查掩盖该问题；也没有把未复现的其它环境一概归因于过期。

## 根因

页面路由已分端，身份凭据与登录通知仍共享。浏览器 Cookie 按同源和路径共享，并不会因为页面位于 `/student` 与 `/admin` 自动隔离。

## 解决方案

- 浏览器请求明确标识客户端端别，服务端选择学生/管理员各自的 Session 与 CSRF Cookie，登录时校验真实账号角色。
- 当前身份和退出也使用对应会话；错误角色登录不产生新会话，不覆盖已登录身份。
- 同端广播通道继续通知退出和切换账号，跨端广播分开。
- 成功分端登录清理浏览器旧通用 Cookie；维护/API 无标识调用保留既有协议，分端请求不回退借用旧或另一端凭据。
- 保留服务端权限、CSRF、有效期、禁用/重置撤销和前端按账号隔离的私有查询缓存。

## 验证方法

Chrome 全套 28 项、Edge 相关 12 项通过。新增四个浏览器场景覆盖其它网站标签页返回、同标签外站后退、双端并行登录及独立退出、6 位学生密码建号与重置；原同端跨标签身份切换仍可使旧账号数据退出显示。

后端完整 326 项、最终身份专项 9 项通过，包含两种数据库、分端 Cookie/CSRF、错误角色、旧凭据清理和密码重置撤销。前后双端及后端三个层面的学生密码最小长度统一为 6；管理员默认初始化规则保持原值。

预防：身份协议需覆盖“同角色跨标签切换”和“不同角色并行使用”两种场景，不能只按路由或单浏览器单账号验证。
