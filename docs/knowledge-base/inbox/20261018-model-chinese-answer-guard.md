# 模型追问可用中文数词携带答案

## 现象

2026-10-18 V10 系统审查发现：`teach_coaching.validate_proposal` 与复用它的圆桌校验可接受 `你把二除以五得到五分之二作为最后结论的理由是什么？`。即使学生本轮只说“我只按颜色分成两类”，仍可通过引用、方向、问号、字符和禁词检查。这句话已经给出当前概率练习的数值结论，不应仅因表面为问句就视为安全追问。

## 定位过程

使用本地手工构造 JSON，直接经过两个生产校验入口，不调用模型、不读取学生数据。快照 `student_text='我只按颜色分成两类'`、`allowed_focus=['ratio']`，引用命中该文本。Teach JSON 包含 quote/focus/question；圆桌 JSON 包含 quote/focus/voices，其中 proposer 使用上述问题，另外两席提供不同的普通问句。两个入口均返回成功。本机结果保存在 `.local/v10-static-probes.json`。

## 根因

现有正则拦截阿拉伯/全角数字和符号，禁词检查覆盖部分措辞；中文数词、答案的语义等价表达不在约束内。圆桌同样依赖这个校验。引用真实只证明 quote 在来源中，不证明生成 question 没有新增答案。模型结果没有再次经过 `activity_graph.govern_text`，该函数本身也主要依赖动作元数据，不能独立理解答案语义。

## 解决方案

待实施。优先考虑让模型输出受限追问意图，再由已审核模板渲染；若保留自由追问，需统一输出门禁、与当前题答案/步骤的等价表达检测和人工复核/安全回退。单纯增加中文数词正则仍不能覆盖同义表达、拆分和隐含答案。补齐中文答案、文字算式、伪问句、歧视归因和注入场景后，再评审自由文本开放范围。

## 验证方法

用上面的输入验证修复前可放行、修复后拒绝或安全回退；再通过 Teach 与圆桌的实际任务完成路径确认不向学生渲染。保留正常中文追问作为负对照。当前只复现了输出校验缺口，没有证明线上发生过此输出，也不推断真实模型必然给出同样文本。
