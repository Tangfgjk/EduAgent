# Edge 原始教学等待超时尚待归因

## 现象

49 号验收记录中的 Edge 故障流程曾停留在诊断后的 queued 状态并超时，随后复跑通过。

## 定位过程

2026-10-17 新增实际 Worker 故障注入测试，确认并修复了“领取后维护失败空占租约”的风险，另补齐嵌入循环异常恢复。这两种风险能够造成相同等待症状，但原始发生时没有相应服务端证据，不能确认就是同一原因。

## 根因

原始单次 Edge 超时未确定。已确认的租约缺陷另有已解决记录，不能据此把本条改为已解决。

## 解决方案

已增加安全的任务领取、失败、耗时和周期恢复日志，以及页面等待状态。后续若再现，保留测试时间、页面 queue 状态与对应内部 job 日志，关联是否发生维护异常、重试退避、进程退出或锁等待。不要采集学生文本、cookie、密钥或数据库连接串。

## 验证方法

原浏览器路径使用隔离 Fake 重跑，并保留独立输出目录。再次出现相同症状时用新增日志定位；即使连续通过，也只表明本次未复现，不证明原始根因已确定。
