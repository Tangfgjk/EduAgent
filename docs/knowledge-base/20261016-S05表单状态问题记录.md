### [前端-状态-002] 答题与反思组件重复 key 导致换题残留输入框

#### 问题现象

完整陪学中，从第一道练习保存反思进入应用题后，题干已变，但页面残留上一题的禁用答案框。浏览器填入新答案时一直等待可编辑元素。

#### 定位过程

1. 后端 30 种多轮路径与数据库测试通过，当前题目、阶段和能力字段均正确。
2. 浏览器失败快照显示同一个卡片内存在两个 `math-answer` 输入框，其中旧框保留答案 6 并处于 disabled 状态。
3. 检查渲染代码发现 AnswerForm 与 Reflection 两个兄弟组件都使用 task_id 作为 key。
4. 改为带组件用途的不同前缀后，完整学习与手机临时流程通过，旧框消失。

#### 根本原因

React 的 key 必须在同级兄弟中唯一。两个不同组件的 key 相同，造成更新时无法可靠地对应和卸载旧子树；并非后端没有放行下一题。

#### 解决方案

`frontend/apps/student/src/study.tsx` 分别采用 `answer:<task_id>` 与 `reflection:<task_id>`，保留同题内输入状态，换题时正确创建新表单。

#### 验证方法

Playwright 完整项目学习闭环在进入应用题后断言 `#math-answer` 只有一个，并且可编辑；继续验证未知提交、人工复核、反思和两道检测。Chrome/Edge 完整回归均通过，不采用延长等待时间掩盖重复 DOM。
