### [FE-CACHE-001] 身份确认后项目查询停留在加载状态

---
module: 前端身份与查询
category: 04
tags: [react, query, auth, lifecycle]
difficulty: 3
status: 已解决
date: 2026-10-16
keywords: [正在读取你的工作空间, removeQueries, cold reload]
---

#### 问题现象

浏览器登录后创建项目可成功，但刷新后侧栏选择器禁用，正文持续显示「正在读取你的工作空间」。故障重试与其他学生的深层页面也受影响。第一轮 7 条浏览器流程中有 5 条失败。

#### 定位过程

2026-10-16：以真实 HTTP + 临时 SQLite 复现，观察 Playwright 快照发现认证成功但业务查询不再结束。类型检查与构建通过，接口单独可用，问题集中在前端挂载时机。

#### 根本原因

身份确认后先渲染了业务页面，随后父层 effect 用 removeQueries 清理业务缓存，连新页面刚发起的查询一起删除。账号隔离和查询清理时机耦合，首次载入/刷新也被当作需要清理的账号切换。

#### 解决方案

身份查询使用外层 QueryClient；业务页面使用以 account.id 为 key 的 PrivateQueries。退出或换账号时整个私有实例卸载，新账号获得新实例，不在挂载后的 effect 中删除正在读取的业务查询。查询键继续含账号，项目上下文继续按 workspace_id 区分。

#### 验证方法

保留原失败的创建/刷新、跨学生、错误重试流程；补充跨标签页换账号。Edge 与 Chrome 各 8 条浏览器流程通过，两个独立生产构建与 TypeScript 检查通过。

### [ENV-DOCKER-002] Docker Desktop 已启动但 Linux 引擎尚未就绪

---
module: 开发环境
category: 01
tags: [docker, postgres, timeout]
difficulty: 2
status: 已解决
date: 2026-10-16
keywords: [dockerDesktopLinuxEngine, The system cannot find the file specified]
---

#### 问题现象

Docker CLI 无法连接 Linux 引擎命名管道，PostgreSQL 全量回归等待连接。

#### 定位过程

2026-10-16：确认前端隔离服务与本机 SQLite 回归可运行；Docker Desktop 进程存在不代表引擎已就绪。启动检查后请用户查看 Docker 状态；用户启动后重新检查引擎与项目容器。

#### 根本原因

外部开发环境未就绪，并非角色/空间接口错误。原 PostgreSQL 连接未设显式短超时，等待不够明确。

#### 解决方案

用户启动 Docker；运行本项目 dev_postgres.py 恢复容器并等待健康。应用与 PostgreSQL 测试控制连接补充 connect_timeout=5。先完成本机回归，再补真实 PostgreSQL，未将跳过项记为通过。

#### 验证方法

引擎版本 28.3.2，项目容器 healthy；完整后端回归 97 passed、无 PostgreSQL 跳过项。
