# 新互动包引入后的旧验收假设

## 现象

V10 完整后端回归首次为 551 通过、2 失败；同一个目录测试在 SQLite/PostgreSQL 中固定要求 3 个互动包。完整 Chrome 验收中，原方程圆桌测试也在点击禁用的开始按钮时超时。

## 定位过程

目录实际返回四个 ID，新增的是单独发布的概率圆桌包。浏览器失败快照显示：测试只启用了方程模板，页面默认选择新版概率圆桌，因此开始按钮正确保持禁用。手机我教 AI 已显式选择旧包，正常通过；桌面圆桌缺少同样选择。

另有手机计划测试超时：trace 只执行到登录后“打开导航”，尚未进入计划流程，最终快照仍在今日学习。该测试的 prepare 没有像其他登录 helper 一样等待应用就绪，可能在登录重定向期间打开抽屉，随后被 pathname effect 关闭。补充等待 `/student/home` 与应用壳后复验；这不是计划取消已执行后丢失记录的证据。

## 根因

测试把目录数量和页面默认内容当成稳定的业务契约。新增合法包和默认入口变化后，旧测试没有明确它要验证的内容版本。没有发现因此绕过发布门禁或泄漏未启用题目。

## 解决方案

目录断言明确核对四个包 ID，继续检查未启用任务隐藏；旧互动浏览器测试在两种路线都明确选择原方程包；计划测试先等待登录重定向完成。业务默认选择仍保留，尚未启用默认包时的提示与可用性改进另列评估待办。

## 验证方法

目录、发布与隔离专项 24 项双数据库回归通过；最终完整回归与浏览器复验结果见 [V10 系统评估](../进度/83-V10系统完成情况与设计对照评估.md)。该修正没有把模型输出拒绝或语义问题改成通过。
