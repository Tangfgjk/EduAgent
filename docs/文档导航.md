## 目录职责

- `总览/`：项目级总览、交接、基线说明。
- `架构/`：长期有效的架构与领域规格；修改必须同步代码和测试。
- `需求/`：可执行需求、验收条件和范围边界。
- `进度/`：里程碑、完成度、风险和下一步。
- `决策/`：需要长期保留的架构决策及其理由。
- `指南/`：运行、开发、部署和新成员指南。
- `研究/`：原始研究资料、外部参考和实验设计；原始资料不直接作为实现规范。
- `测试/`：测试策略、冻结回归场景和质量门槛。
- `日志/`：按日期记录开发日志；运行时数据库和本地日志不提交到 Git。

## 命名规范

- Markdown 文档：`主题-YYYYMMDD.md`；有稳定顺序的规格使用 `NN-主题-YYYYMMDD.md`。
- 研究资料：`主题-来源或用途-YYYYMMDD.扩展名`。
- 代码包使用 Python 标准小写下划线命名；测试文件使用 `test_主题.py`。
- 时间后缀表示文档版本或归档日期，不代表内容自动最新；最新状态以 `总览/` 和 `进度/` 为准。
