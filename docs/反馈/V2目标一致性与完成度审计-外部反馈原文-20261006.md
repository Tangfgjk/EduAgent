# 桂子问津（EduAgent）V2 分支目标一致性与完成度审计报告

> 审计对象：`Tangfgjk/EduAgent` 仓库 `V2` 分支  
> 审计基线：`c975def2c105538f06cc461251e13fbfeb2fa6fe`  
> 对比基线：`v1/20261005-phase1-foundation`  
> 审计日期：2026-10-06

## 1. 总体结论

V2 总体上**符合桂子问津原始项目目标**，而且相比 V1，已经从“教育 Agent 设计原型”明显推进到了“本地可运行、可测试、可回放的个性化学习系统原型”。

V2 没有走向“让大模型直接回答更多问题”的路线，反而强化了几个原始原则：

- Evidence-first，而不是 LLM-first；
- 长期学习状态由 LearningService / Storage 持有，而不是由 Agent 私有保存；
- 掌握度与保持度分离；
- Path / Trigger / Policy / ActionGovernor 分层；
- AI 只能提案，计划必须由学习者签署；
- R-01～R-10 继续在代码层执行；
- Memory、发展指标和校准结果都明确区分事实、推断和建议；
- 自动 RSI 继续关闭。

当前本地软件主链已经可以形成：

```text
学生作答
  -> Verifier
  -> LearningEvidence
  -> MasteryState / RetentionState
  -> Mastery Gate
  -> PathRecommendation
  -> Trigger
  -> Policy
  -> ActionGovernor
  -> Agent / API / Web
  -> 新 Evidence
```

仓库记录的本地验收为：`424 passed`、42 个冻结回归场景、22 项红队、15 个浏览器流程。需要强调：当前 V2 HEAD 没有 GitHub Actions 状态检查，因此这些属于仓库记录的本地验收，而不是远端 CI 独立重跑结果。

建议将 V2 定位为：

> **“学习闭环已完成本地软件验证的研究平台 MVP”，不是最终生产级教育产品，也不能声称真实教育效果已经被证明。**

## 3. 与项目初衷的一致性

### 3.1 不是普通聊天机器人

符合。

V2 将 LLM 从“学习状态事实来源”降级为候选内容生成器，而把长期认知状态交给 `LearningEvidence -> LearningService -> MasteryState / RetentionState`。

`LearningEvidence` 明确禁止直接携带 `p_mastery`，红队测试也验证伪造 mastery 字段会被拒绝。

这一点与项目原始思想高度一致。

### 3.2 长期陪伴学习者

部分完成，但基础已经形成。

目前已有：

- 持久会话；
- 页面刷新恢复；
- Evidence；
- Mastery / Retention；
- 复习任务；
- 计划版本；
- 项目版本；
- Memory L1/L2/L3 来源视图；
- Replay / Recovery；
- PostgreSQL 独立归档。

但是“长期陪伴是否真的提高学习质量”仍没有真实纵向数据验证。

### 3.3 让学生越来越独立

机制层符合，效果层未验证。

目前已有：

- R-01 防过早完整答案；
- R-07 主动提示预算随 autonomy 递减；
- R-02 保证计划最终由学生签署；
- R-10 保证探究过程所有权；
- autonomy 行为分解指标；
- 无辅助作答过滤。

特别值得肯定的是，当前没有贸然制造一个未经验证的 autonomy 总分，而是先记录 independent attempts、help request、reflection、revision、self-check 等行为。

但目前仍只能说“实现了促进自主性的机制”，不能说“已经证明学生自主性提升”。

### 3.4 完整 SRL 闭环

本地软件层已基本形成：

```text
目标
-> 诊断
-> 计划
-> 执行
-> 作答与反馈
-> 反思
-> 状态更新
-> 路径与复习
-> 下一轮学习
```

V2 最大突破是补齐了：

```text
Verifier
-> Evidence
-> State
-> Decision
```

这让 SRL 不再只是 UI 流程，而是真正进入了学习状态更新。

### 3.5 可追溯学习证据

完成度较高。

Evidence 已包含 learner、session、KC、attempt、verdict、verifier version、assistance、consent、assessment、rubric、policy、event sequence 等信息；LearningStateTransition 又记录 prior/new state、算法版本、参数集和 evidence refs。

这已经是 V2 最扎实的能力之一。

## 4. Learning 核心评价

### 4.1 LearningEvidence

阶段性完成。

已经形成明确 V1 契约，并落实：

- `passed` 可进入二值 BKT；
- `failed` 可进入二值 BKT；
- `partial` 不更新二值 BKT；
- `unverifiable` 只审计；
- assisted observation 不作为独立掌握证据；
- correction 不覆盖原事实。

这与之前确定的设计完全一致。

### 4.2 BKT / Mastery

算法基线完成，真实校准未完成。

当前参数仍是默认值：

```text
P_LEARN = 0.15
P_GUESS = 0.20
P_SLIP  = 0.10
```

因此不能称为“已训练好的 KT 模型”，更准确应称为：

> 默认参数 BKT 基线。

后续需要真实学生数据做 KC 级参数校准，再决定是否升级 AKT/SAKT 等模型。

### 4.3 Mastery Gate

本地 V1 完成度较高。

当前 Gate 不仅看 `p_mastery`，还检查：

- 有效 Evidence 数；
- distinct assessment；
- confidence；
- qualitative evidence；
- AssessmentProfile。

输出不是 bool，而是：

```text
mastered
not_mastered
insufficient_evidence
uncertain
```

这是合理设计。

### 4.4 Retention / Review

工程基线完成，参数效度未验证。

当前为确定性的 `exponential-v1` 调度器，包含：

- stability；
- difficulty；
- lapse；
- retrievability；
- next review；
- forgetting risk。

这不是标准 FSRS，也没有真实学生校准。

后续应继续保持 RetentionScheduler 可替换，而不是直接将当前参数固化成教育规律。

## 5. Path / Trigger / Policy / Governor

这一层目前架构边界比较清楚：

```text
Path           -> 接下来学什么
Trigger        -> 现在是否值得介入
Policy         -> 如果介入，怎么教
ActionGovernor -> 这个动作是否允许
```

### PathRecommendation V2

设计合理，目前只使用：

- mastery；
- forgetting risk；
- prerequisite。

输出：

```text
DIAGNOSE
REMEDIATE
REVIEW
ADVANCE
```

并且只生成 `proposed`，不能直接修改计划。

这一点应保持，不建议现在再加入过多 deadline、affect、interest 等权重。

### ActionGovernor

仍然是核心优势。

R-01～R-10 都在代码层。

但生产上仍有两个明显缺口：

1. R-05 当前主要还是极简 regex；
2. R-06 当前主要依赖 `grounded_to_kg` 元数据，仍属于“元数据接地”，还不是强语义接地。

未来应让 RAG Source -> KC Mapping -> Action provenance 形成不可伪造的链。

## 6. Memory

当前为**部分完成**。

`learning/memory.py` 已经支持：

- L1 来源；
- L2 session 派生摘要；
- L3 行为摘要；
- state refs；
- fingerprint；
- 来源变化检查。

值得肯定的是，Memory 没有维护第二份 mastery 数值。

但是目前 L3 还不是成熟长期画像，缺少：

- 长期偏好；
- 稳定策略；
- 长期误区；
- 近况和长期特征分离；
- consolidator；
- dedup / merge；
- 人工纠正。

因此不建议对外表述为“三层长期 Memory 已完成”。

## 7. RAG

本地最小实现完成，语义检索未完成。

已有：

- Markdown；
- PDF；
- 中文 OCR；
- source hash；
- chunk；
- BM25；
- hashed feature vector；
- hybrid；
- citation；
- KC refs；
- path confinement。

这已经是不错的离线最小检索系统。

但当前 `vector` 并不是 neural embedding，而是 hashed lexical feature。建议 API 将：

```text
vector
```

改名为：

```text
hashed_lexical
```

避免后续开发者误以为已经有语义向量检索。

真正未完成的是 embedding model、semantic benchmark、reranker、真实课程大规模索引和自动/半自动 KC grounding。

- fallback；

- provider/model provenance；

## 9. 计划与学习者控制权

这一块完成效果很好。

`plans.py` 已实现：

```text
proposed
-> draft
-> modify
-> sign
-> confirmed
-> superseded / rejected
```

只有学生 `sign()` 才真正生效。

这是真正把“问津，而后自渡”和 R-02 从设计原则变成了事务级机制。

建议以后教师建议、恢复任务、自动路径建议全部复用这一生命周期，不允许任何旁路直接改 confirmed plan。

## 12. 数据库与可靠性

### SQLite

作为单机 Runtime 已比较成熟：

- BEGIN IMMEDIATE；
- CAS；
- receipt；
- rollback；
- replay；
- session restore；
- concurrency test。

### PostgreSQL

当前完成的是：

> PostgreSQL 独立 Evidence/State 归档与恢复。

不是：

> PostgreSQL 主存储迁移完成。

源码本身也明确 PostgreSQL 是 archive boundary。

下一阶段若要生产化，应抽离：

```text
Store Protocol
EvidenceRepository
StateRepository
SessionRepository
AuditRepository
```

然后实现真正的 PostgresStore。

## 18. 最终判断

### 是否符合项目初衷？

**符合，而且整体一致性较高。**

V2 没有偏向“AI 帮学生完成更多”，而是强化了：

- 学习者控制权；
- 脚手架渐撤；
- 独立学习证据；
- 长期状态；
- 可回放；
- 规则治理；
- 无辅助测量。

### V2 最大成果是什么？

不是 RAG、登录页或 PostgreSQL。

真正最大的成果是：

> **把“学习行为 -> 可验证证据 -> 学习状态 -> 教学决策 -> 安全行动 -> 新证据”从设计文档变成了实际代码。**

### V2 最大不足是什么？

不是缺功能，而是：

> **大量机制目前只证明“软件能工作”，还没有真实学生数据证明“教育上有效”。**

这应该成为 V3 所有开发决策的核心判断标准。

## 19. 推荐 V3 一句话目标

> **V3：从本地可验证学习闭环，进入真实课程、真实学生、真实效果证据阶段。**

V3 的成功标准应逐渐从：

```text
424 tests passed
```

转向：

```text
真实课程通过教师审核
真实学生数据完整
BKT / Retention 完成校准
无辅助后测可计算
迁移任务可计算
自主性行为可追踪
教师纠正可回流
安全与隐私可审计
```

最终才开始真正检验桂子问津的核心命题：

> **教育智能体能否在长期陪伴中逐步减少自己的帮助，让学习者越来越能够独立完成。**
