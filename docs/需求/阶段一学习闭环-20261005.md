# 阶段一学习闭环需求

更新时间：2026-10-05

## 目标

把一次作答的 `Verdict` 转成可长期计算的 `LearningEvidence`，并让掌握门控、保持度调度和学习路径推荐共享同一条证据链。阶段一不做自动进化，不把 DeepTutor 的产品、Web、Agent Runtime 或按路径隔离的学习者状态整体搬入。

阶段一拆成三个可独立验收的子阶段：

```text
1A 学习核心：Verdict -> LearningEvidence -> 掌握度/掌握门控/保持度
1B 决策集成：MasteryState + RetentionState -> PathRecommendation -> Trigger -> Policy
1C 交付集成：Policy -> ActionGovernor -> Agent/API/Web -> 新的 Evidence
```

当前只进入 1A，不以 Web 或 Agent 集成是否完成作为 1A 的完成条件。

## 目标模块

```text
platform/app/learning/mastery_port.py
platform/app/learning/gates.py
platform/app/learning/review_port.py
```

### `mastery_port.py`

- `passed` 映射为 `correct`。
- `partial` 映射为 `partial`。
- `failed` 映射为 `incorrect`。
- `unverifiable` 只审计，不更新 mastery 或 retention。
- `partial` 保留为有等级的证据，但在第一版二值 BKT 中不更新状态；它进入诊断、误区分析和后续人工/定性评估队列。
- `LearningEvidence` 是事实源，必须携带稳定的 `evidence_id`，重复消费同一 ID 不得重复改变状态。
- Evidence 只保存观察和验证记录，不携带 `p_mastery` 或已掌握结论；验证器判定保留方法、rubric、版本和置信度。Claim Schema 显式区分 observation、inference、recommendation。
- 观测映射策略记录为 `binary-observation-v1`；`partial` 和 `unverifiable` 均不更新保持度。成功/失败只有满足版本化回忆任务资格才更新 Retention，提示后作答不能默认为无辅助成功回忆。

### `gates.py`

- 知识点类型与掌握评测方式分离。DeepTutor 的 MEMORY/PROCEDURE/CONCEPT/DESIGN 只能作为默认映射，不能成为桂子问津的固定知识本体。
- 定量掌握门控至少同时检查 `p_mastery`、有效证据数量和置信度；证据不足时返回 `insufficient_evidence` 或 `uncertain`，不能直接返回 `mastered`。
- 概念、设计、证明和探究类知识点使用 `quantitative`、`qualitative` 或 `hybrid` 评测配置；解释、迁移和 Feynman-style 任务都是定性证据来源，不允许由单次 LLM 判断一票决定。
- Gate 与教学策略解耦。
- 结果必须携带 evidence 和 provenance。
- `MasteryGateResult.status` 为 mastered、not_mastered、insufficient_evidence、uncertain；保留评测配置、证据数量、置信度方法、版本和 reason。当前 BKT 区间为启发式估计，不能冒充已校准的统计置信度。

### `review_port.py`

- LearningEvidence 转成 RepetitionState。
- 计算 retrievability、forgetting risk 和 next review。
- 输出可供 PathRecommendation 消费的 ReviewTask。
- `MasteryState` 与 `RetentionState` 分开建模：掌握度回答“会不会”，保持度回答“能保持多久”。
- Evidence 是唯一事实源；RepetitionState 和 ReviewTask 是可删除、可由 Evidence 重放重建的派生状态。
- 保持度调度器使用稳定性、可提取度和 lapse 等通用语义，不在接口层绑定某个外部项目或 FSRS 实现。
- 时间相关结果记录显式 `as_of`；Mastery 和 Retention 可以分别重建和替换模型，不以 Memory L3 维护第二套数值源。

## 消费与持久化契约

- 唯一消费键为 `(learner_id, evidence_id, consumer)`；同 ID 同内容重试返回既有结果，同 ID 不同内容拒绝并审计。
- Storage 持久化分配 `event_seq`，保留 `occurred_at` 与 `ingested_at`，按序号重放；晚到或修正证据触发新版本重建。
- Evidence、消费记录、LearningStateTransition 和派生快照在同一本地事务提交；失败全部回滚，CAS 校验 prior_state_version。外部调用在事务外执行。
- Replay 固定 Evidence 集合、算法、参数版本和 as_of，不读取当前时钟或实时 LLM。升级重算使用独立任务和新状态版本。
- 阶段一的 Evidence/InteractionEvent 必含 consent_scope、consent_version 和授权来源；未授权用途默认关闭，撤回后阻止对应用途读取/消费。
- 北极星计算字段从首次证据采集保留，测量定义见[一周实施计划第 3 节](../进度/项目最终功能清单与一周实施计划-20261005.md)。

## 决策层职责边界

```text
PathRecommendation：接下来学什么？
TriggerEngine：现在要不要介入？
Policy：如果介入，采取什么教学动作？
ActionGovernor：这个动作是否允许执行？
```

1B 的第一版只使用三个信号：`mastery`、`forgetting_risk` 和 `prerequisite`。截止日期、情绪、自主性等信号留到后续版本，避免在证据不足时引入不可解释的权重。

职责边界正式记录在 [ADR-003](../决策/ADR-003-学习证据与决策职责边界-20261005.md)。晋级需要 Gate 为 mastered 且先修满足；采纳推荐形成草案，学习者签署后才生效。

## 必须先写的测试

1. 四种 Verdict 映射测试。
2. BKT 阈值前后掌握门控测试。
3. CONCEPT/DESIGN 在 quiz 全对但没有 qualitative pass 时不得通过。
4. 成功回忆提高 stability，失败增加 lapse 并提前复习。
5. 时间流逝使 retrievability 下降。
6. 相同 evidence replay 得到相同状态。
7. unverifiable 样本不改变长期状态。
8. 相同 `evidence_id` 重复消费不会重复更新状态。
9. 同一时间戳下按事件序号重放顺序稳定。
10. 有效证据数量不足时，即使 `p_mastery` 较高也不能直接判定掌握。
11. 固定模型与参数版本后，重放结果完全一致。
12. 端到端黄金路径：失败 -> L1 提示 -> 多次有效作答/无辅助回忆 -> 满足掌握门控 -> 安排复习；所需次数由冻结参数决定，不保证答对两次就掌握。
13. 并发重复消费与 CAS 冲突重试只更新一次。
14. 事务步骤故障注入确认 Evidence、消费记录、转换和快照全部回滚。
15. 同 ID 不同内容冲突、晚到/修正证据和跨学习者隔离。
16. 提示后作答与无辅助回忆分开消费，partial 不更新保持度。
17. 缺失/冲突置信度返回 uncertain，未授权用途和撤回后消费被拒绝。

## 完成标准

- 适配器测试先于外部源码导入。
- 所有新增接口有单元测试和最小集成测试。
- 事件字段能追溯到 learner、KC、verdict、Evidence ID、策略版本、模型与参数版本和状态前后版本。
- `LearningStateTransition` 记录 `evidence_ids`、`prior_state_version`、`new_state_version`、KT 模型版本、保持度模型版本和创建时间。
- 既有 R-01 至 R-10 测试不回归。
- 文档和代码路径使用 `platform/` 与 `docs/` 新结构；`docs/` 下的目录和 Markdown 文件使用中文命名。
