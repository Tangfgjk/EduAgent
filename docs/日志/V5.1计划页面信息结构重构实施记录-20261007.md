# V5.1 计划页面信息结构重构实施记录

更新时间：2026-10-07（Asia/Shanghai）  
版本标记：V5.1 / 计划模块第二阶段  
状态：本地实现与定向验证完成  
前置版本：V5.0 项目化计划模块第一阶段  
范围：重构学生端“计划”页面的信息结构，补充项目目标、成功标准、截止日期、任务与里程碑的可视化编辑；不宣称已完成自动任务回写或真实教学效果验证。

## 1. 本次目标

本次改造将原先混排的“目标、项目编辑、路径建议、草案”整理为四个顺序明确的工作区：

1. 项目概览：项目名称、说明、截止日期、当前阶段、待复习数量。
2. 目标与成功标准：学生目标、逐条成功标准、截止日期，以及建立或更新操作。
3. 计划进度：任务完成数、里程碑轨道、当前阶段、今日项目任务和到期复习。
4. 计划提案与签署：路径建议、计划版本、Diff、采纳、修改、拒绝与签署。

设计意图是让“项目是什么、我想达成什么、我走到哪里、下一步如何决定”按学生理解顺序出现，而不是让学生先面对技术引用和零散操作。

## 2. 已完成内容

### 2.1 四区计划页面

计划页已经重组为以下区域：

| 区域 | 当前展示 | 当前操作 |
|---|---|---|
| 项目概览 | 当前项目名称、说明、截止日期、当前里程碑、待复习数 | 切换项目、打开项目编辑区 |
| 目标与成功标准 | 目标文本、每行一条的成功标准、截止日期 | 建立目标或更新当前项目目标 |
| 计划进度 | 任务完成数、里程碑状态、今日任务、到期复习 | 查看项目执行位置 |
| 计划提案与签署 | 推荐说明、路径节点、版本列表、Diff | 生成建议、采纳、修改、拒绝、签署 |

项目基本信息、任务、里程碑和高级引用被收纳到可展开的“项目基本信息、任务与里程碑”区域，避免干扰计划主线。

### 2.2 目标、成功标准与截止日期

新增目标契约编辑能力：

- 创建目标时可提交目标文本、多个成功标准和截止日期。
- 成功标准采用“一行一条”的学生可编辑输入，保留为结构化 SuccessCriterion 记录。
- 截止日期作为项目目标契约的考试／项目截止信息保存并在项目概览显示。
- 已建立目标的项目显示“更新目标”；更新会保留同一目标契约的计划版本引用，不会覆盖或删除历史计划版本。
- 每次更新写入学习审计记录，目标修改后页面提示学生重新审阅计划建议。

默认成功标准仅在学生未填写时生成，避免空目标没有可检查的完成条件。

### 2.3 项目进度与今日任务

计划进度区当前使用项目内已有事实生成，不填充演示成绩：

- 总进度：已完成任务数 / 项目任务总数。
- 当前阶段：选择第一个未完成里程碑；若均完成则显示最后一个里程碑已完成。
- 里程碑轨道：待开始、进行中、已完成三种状态。
- 今日任务：优先显示项目中的待办和进行中任务，再显示当前项目范围内到期复习。
- 待复习数：来自当前项目的复习接口，而不是其他项目的全局队列。

“今天要做什么”目前是对已有任务与到期复习的呈现，不包含自动排程、推送提醒或自动改变任务状态。

### 2.4 任务与里程碑编辑

项目编辑区支持：

- 添加、修改、删除里程碑；
- 设置里程碑状态：待开始、进行中、已完成；
- 添加、修改、删除任务；
- 为任务选择所属里程碑；
- 设置任务状态：待办、进行中、完成。

服务端继续校验：任务引用的里程碑必须存在；同一项目内任务和里程碑 ID 必须唯一。归档项目沿用 V5.0 的只读保护。

### 2.5 项目范围与学生决定权

本次页面重构继续使用 V5.0 的项目范围规则：

- 切换项目后，目标、计划、任务、里程碑、复习摘要和路径建议按当前项目刷新。
- 路径建议是候选；采纳后先形成草案，仍需学生签署才成为有效计划。
- 修改目标不会静默改写已签署计划；学生应基于新目标重新审阅或修订计划。
- 学习者长期掌握与保持模型仍是学生级模型；项目页展示的是当前项目范围内的执行与证据视图。

## 3. 数据与接口增量

### 数据模型

- SuccessCriterion 新增 description，用于保存学生可读的成功标准文本。
- ProjectContent 的 milestones 与 ProjectTask.milestone_id 被用于计划页面的进度展示和编辑。
- GoalContract 继续作为项目目标的唯一契约载体；PlanVersion 继续保留项目归属和生命周期状态。

### 接口

新增：

~~~text
PUT /api/contracts/{contract_id}
~~~

该接口用于更新当前项目中的目标文本、成功标准和截止信息。它会校验：

- 当前学习者拥有该目标契约；
- 目标契约属于请求中的项目；
- 项目处于活动状态；
- 请求具有教学用途授权。

既有创建目标、路径建议、计划草案和签署接口继续携带 project_id。

## 4. 验证结果

已执行：

~~~text
python -m compileall -q app
node --check web/workbench/workbench.js
node --check web/workbench/presentation.js
python -m pytest -q tests/test_project_context.py tests/test_plan_lifecycle.py tests/test_learning_workbench.py
~~~

结果：15 项测试通过。

本轮自动化验证覆盖：

- 项目 A、B 的目标、计划、证据、会话不串数据；
- 目标创建时保存多个成功标准和截止日期；
- 当前项目目标可以更新；
- 一个项目不能重复创建活动目标；
- 路径建议只能采纳到当前且具有目标契约的项目；
- 已归档项目的历史可读、计划和会话写入被拒绝；
- 计划生命周期仍保持单一当前有效计划。

## 5. 尚未完成

下列能力不属于本次已完成范围：

- 自动依据作答、测评、复习结果完成项目任务或推进里程碑；
- 按截止日期自动生成每日或每周排程、提醒、偏离计划重排；
- 按成功标准自动计算可信达成度；
- 计划 Diff 的逐条评论、逐条批准和教师协同审阅；
- 将聊天、考试、作品和圆桌结果一键转化为任务或里程碑证据；
- 真实课程负荷、教师审核和学生样本上的效果验证。

这些内容应作为下一阶段“执行计划与跨模块回写”实现，不能因为计划页面已有进度显示而标记为完成。
