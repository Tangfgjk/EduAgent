# V3正常执行链来源与最终输出安全加固

建立/验证时间：2026-10-06 20:15（Asia/Shanghai，UTC+08:00）。本地 `V3`，基线 V2 `c975def`。本轮继续完成本地工程缺口，未提交或推送，不操作个人8000服务或真实学习者数据。

## 修复目标

此前 provenance/check 可以验证候选，但正常 SessionRuntime 仍只依赖 `grounded_to_kg` 元数据；LLM 在 Governor 之后自由润色最终文本也没有语义保留证明。本轮在正常教学 API 执行链实际修复，而非只加一个演示检查入口。

## 实施

- 新增 `app/governance/runtime_sources.py`：每次 Runtime 会话装配来源 guard，冻结可信题库与 AssetCatalog 的 SHA-256。恢复的持久 bank 必须与当前显式冻结配置相同；配置变化或状态被篡改时拒绝，不能拿新来源默默解释旧版本。
- TASK/QUESTION 逐一对照服务器 canonical item ID、KC、stem、题目答案与 AssetCatalog assessment；未知题、改题干、改KC、改难度或伪造引用拒绝。答案只是服务器验证信息，不写入公开回复来源摘要。
- HINT 的阶梯、form 与具体文本必须来自冻结 item 提示或既有确定性通用提示；提示类型和参数键也受约束。把完整答案写成L0提示、自造“可信知识”文本不能通过。
- FEEDBACK/EXPLAIN 只能匹配服务器内置 policy 对当前验证状态产生的确定性模板；当前模板在调用可替换策略前生成。不因为任意策略/模型声称熟悉KC就允许自由正文。
- 明确区分 `frozen_course_asset`、`server_policy_template` 与 `server_system_template`。系统规则说明、支持性反馈及安全fallback是服务器自有模板，不被冒称检索或教师审核内容。来源元数据明确 `local_software_asset_not_teacher_approved`。
- 来源 guard 绑定完整动作内容；在 `_execute` 和 `_render` 再核验，Governor之后的 payload 改动不能执行或显示。现有 R-01/R-05/R-07/R-09 优先约束仍有效。
- denied fallback 若二次裁决仍 deny，最终转 WAIT，不执行第二个被拒动作。原代码存在二次deny仍执行的风险，本轮已修复。
- 移除正常 TutorSession 中的自由 LLM polish 分支及不再使用的状态字段/import。最终回复为已治理的确定性模板；模型仍可提供经schema验证的结构化感知候选，但不直接写学生看到的最终正文。
- SessionRuntime 提供 `bank_factory` 注入：新建用可信显式题库，恢复使用已持久 bank 并验证来源hash。create_app透传由主集成实现。原 `policy_factory`、`clock` 接口保留。

## 边界与后续

这不是基于regex的“全部语义安全检测”，而是避免不受信自由模型文本进入最终执行链。模型语言变体若要重启，必须使用有限模板ID或经验证的严格语义不变表示，不能重新接上不受控自由润色。

本地合成/原始软件课程的来源完整性不等于真实教师批准、真实教育真值或真实课程准入；真实课程审核包仍按课程准入独立验证。保留局限：R-05危机检测仍是有限原始规则；学校身份体系、研究审批、外部Provider合规、备份删除政策仍是外部/生产验收。

本轮不增加依赖，不安装软件，不改变硬规则注册表，不把模拟画像变成真人证据。
