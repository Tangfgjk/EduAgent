## Memory人工纠正

新增 `platform/app/learning/memory_review.py`，作为内部服务端口，不新增 learner 自称教师的 API。复用现有 `MemoryService.get` 的当前授权及来源有效性检查，新增 SQLite `memory_annotations` 表：`annotation_ref`、`learner_id`、`view_id`、`payload`。主体映射及授权由受信调用方提供，不公开真实资料。

- 注释绑定 learner、view、完整 source fingerprint 和实际 evidence/event refs。缺少来源、跨人引用、来源指纹不匹配、无受信审核人 verifier、未来/早于快照的审核记录均拒绝。
- 人工操作只能 `clarify` 或 `retract`，追加修订通过 `supersedes` 串联，不能覆盖既有记录。相同 ID 同内容幂等，ID 冲突和分叉修订拒绝。
- 注释与 `learning_audit` 在同一事务提交，audit 写失败整笔回滚。服务重启后可重建同一注释投影。
- 投影保留原 `source_memory` 不变，人工注释为独立字段；不改 evidence、event counts、mastery 或 retention，不复制第二套掌握模型。
- 证据纠正使旧视图/注释失效，必须从当前证据重建；旧注释不自动搬到新 fingerprint。撤回当前 teaching 授权后读取和新增注释都阻挡。
- `describes_personality=false` 与 `modifies_learning_state=false` 为固定契约，禁止将注释转换成长期人格、自动画像或认知能力评分。自然语言注释仍需实际教师审查，固定字段不代表能自动识别所有不当文本。

隐私删除清单需要覆盖 `memory_annotations`（learner_id）；本实现已通知主任务加入统一治理，不能用追加历史为理由豁免删除。完整 SSO/租户和长期画像不是本轮交付。
