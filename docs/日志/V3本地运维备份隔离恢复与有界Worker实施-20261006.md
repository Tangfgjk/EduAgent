# V3本地运维备份隔离恢复与有界Worker实施

建立/验证时间：2026-10-06 20:15（Asia/Shanghai，UTC+08:00）。本地分支 `V3`。本轮仅实现和测试可演练的本地运维端口，未在用户真实数据库、8000服务、PG归档或真实workspace执行操作。

## 架构与交付

新增 `platform/app/operations/local.py` 和 `app/operations/cli.py`，无新增依赖。所有本地操作者功能独立于学生API；没有自动停止、切换或重启服务。

### SQLite在线备份

`backup_online` 在既有 Store 锁下使用 SQLite online backup，不直接拷贝一个可能含WAL未提交数据的文件。要求：已分配隐私官、当前教学Consent、非隔离/撤回状态、显式已批准本地备份保留政策，且只含当前主体的数据。检查所有learner_id/learner_pseudo_id列，不漏掉未在learners主表登记的他人记录。

操作者预先提供存在的可信目录；仅接受单个ASCII `.sqlite3` 文件名，不接受路径穿越或任意外部目标。数据库和manifest均以独占方式建立，现有文件或manifest绝不覆盖。备份执行integrity_check，记录SHA-256、时间及政策ID。失败只移除本次独占创建的新文件，不删除其他文件或原数据库。

manifest不含姓名、学习者ID、作答原文、密码或异常正文。备份未加密，需由本机权限和已批准保留政策保护；不宣称跨机器访问安全或法律合规。

### 新库隔离恢复

`restore_new_quarantined` 只从可信目录读取经操作者指定可信hash的备份，并只恢复到一个不存在的新文件。检查备份SHA和SQLite完整性、再次核验拷贝期间源hash、拒绝混入他人数据；绝不覆盖运行中的数据库或自动切换服务。

新库所有非deleted主体自动设为quarantined，新增空Consent版本。即使备份拍摄时是active，较晚的撤回也不会被“恢复旧备份”自动复活；必须由政策负责人复核最新撤回/删除信息，受信隐私官恢复访问，并重新取得明确Consent。deleted墓碑不被恢复激活。

这不是完整备份删除策略：仍需组织明确历史备份销毁、映射表、文件与PG归档、外部模型及法律保留政策。本端口不擦除任何这些材料。

### 只读健康报告

`health_report` 只读执行quick_check和聚合队列状态，不含证据正文、学习者ID、路径、配置或凭据。CLI health 使用SQLite `mode=ro`，不实例化Store或进行schema迁移。报告明确continuous_monitoring=false、production_readiness_claim=false。

### 有界纠正Worker

`run_worker_batch` 只处理分配主体的pending/failed纠正outbox，最多100 jobs、最多10 attempts、批次调度截止最多60秒。SQL带LIMIT而非全量读取后再切片。调用已有RecoveryJobs事务：失败rollback、记录不包含异常正文的retry状态、完成收据不重复签署；只提出plan，绝不自动替学生签署。

deadline是批次调度上限，不是中断某个SQLite事务的硬实时期限。每次处理前检查Consent/隐私，撤回/隔离立即阻止继续使用；没有外网调用或无限轮询服务。

## 操作方法

以下是模板命令，不是本轮对用户数据库执行的记录。先确认当前目录为platform；`<...>`必须替换成操作者明确审核的值，不把凭据写入命令或文档。

```powershell
# read-only health（无需政策批准，但本机文件访问仍由操作者负责）
.\.venv\Scripts\python.exe -m app.operations.cli --database <数据库绝对路径> --learner-id <当前主体> health

# 可信目录必须先存在；policy-id代表真实操作者审定的本地保留记录，不能假写法律审批
.\.venv\Scripts\python.exe -m app.operations.cli --database <数据库绝对路径> --learner-id <当前主体> backup --root <可信备份目录> --filename v3-20261006.sqlite3 --policy-id <本地批准记录ID> --policy-approved

# SHA从之前经信任确认的manifest取得，不从待恢复的陌生文件重新“自证可信”
.\.venv\Scripts\python.exe -m app.operations.cli --database <源数据库绝对路径> --learner-id <当前主体> restore --root <可信备份目录> --backup-name v3-20261006.sqlite3 --destination-name staged-v3-20261006.sqlite3 --sha256 <manifest可信hash> --policy-id <本地批准记录ID> --policy-approved

.\.venv\Scripts\python.exe -m app.operations.cli --database <数据库绝对路径> --learner-id <当前主体> worker --max-jobs 10 --max-attempts 3 --deadline-seconds 10
```

CLI为有本机文件权限的受信运维者端口，不是网络身份验证。backup/worker以Store开启已有数据库，可能应用既有兼容schema迁移；health为纯只读。Worker CLI默认使用现有默认课程图，定制课程需通过代码端口显式传入匹配课程graph，不能把默认图声称为真实定制课程策略。
