# V5.0 项目化计划模块第一阶段实施记录

更新时间：2026-10-07（Asia/Shanghai）  
版本标记：V5.0 / 计划模块第一阶段  
状态：本地实现与定向验证完成  
适用代码：V4 本地研究 MVP 的项目化工作台增量，不代表真实学生试点、课程效果或生产发布。

## 1. 本次目标

本次增量落实“项目优先”的第一阶段：

> 每个学习项目拥有独立的目标契约与计划版本；切换项目后，只读取和写入当前项目的计划内容；同一学生的长期学习者模型仍在授权范围内累计。

本次不把“项目隔离”理解为复制多份学习者模型。项目 A、项目 B 的原始作答、会话、计划和任务默认分开；学生级掌握、保持与自主性模型仍由既有学习服务维护。

## 2. 已完成内容

### 2.1 项目与目标契约的强关联

- GoalContract 已携带 project_id。
- 新建目标契约必须提供一个已保存、属于当前学习者且未归档的项目。
- 同一个项目不能重复创建活动目标契约；避免同一项目同时存在多套相互竞争的目标。
- 按项目查询“最新目标契约”时，会先验证项目归属，不能借查询读取其他项目内容。

### 2.2 项目与计划版本的强关联

- PlanVersion 已保留 project_id，并从所属 GoalContract 派生。
- 路径建议采纳、草案、签署、修改和拒绝都通过项目范围校验。
- 计划读取会核验请求中的项目与计划版本所属项目一致。
- 每个目标契约仍由 PlanService 保证同时最多一份 confirmed（当前有效）计划。
- 学生采纳路径时，保存的是学生当前提交的路径内容；服务端不会重新生成建议并覆盖学生刚做的修改。

### 2.3 当前项目上下文

- 顶部项目切换后，计划工作区按当前项目读取目标、计划工作区、复习摘要、证据与项目会话。
- 获取路径建议时，前端会传递当前项目，而不再只按 learner_id 请求。
- 没有选择项目时，学生不能新建陪学会话、建立目标或获取路径建议；页面给出“先创建并选择学习项目”的提示。
- 新产生的作答、会话、交互事件、解释性作品和项目证据可携带 project_id；未归属历史数据不被自动塞入新项目。

### 2.4 归档项目的只读边界

归档不等于删除。归档项目的历史计划、证据和会话仍可查看；但服务端拒绝下列新写入：

- 创建目标契约；
- 创建会话或继续发送会话消息；
- 创建项目内作答、解释性作品、发题凭据或提示记录；
- 采纳路径、签署计划、修改计划、拒绝计划；
- 在归档状态下编辑任务、计划内容或其他项目资料。

项目可以恢复为活动状态；恢复请求不得同时夹带其他内容修改，防止借“恢复”绕过只读保护。

### 2.5 项目任务与里程碑的数据准备

ProjectContent 已增加 milestones；每个 ProjectTask 可以通过 milestone_id 关联一个项目里程碑。

当前阶段只完成数据约束：

- 里程碑 ID 在单个项目内必须唯一；
- 任务引用的里程碑必须存在；
- 任务、证据、会话、来源引用继续沿用项目内唯一性校验。

里程碑时间轴、进度环、自动完成规则和“今日任务”面板属于下一阶段，尚未作为已完成能力记录。

## 3. 数据与访问规则

~~~text
Project
├─ GoalContract：项目目标、成功标准与截止信息
├─ PlanVersion[]：proposed / draft / confirmed / rejected / superseded
├─ ProjectTask[]：项目任务，可关联 milestone_id
├─ Milestone[]：项目阶段检查点
└─ 项目活动引用：会话、作答、作品、测评、复习等带 project_id 的记录
~~~

规则摘要：

| 规则 | V5.0 第一阶段结果 |
|---|---|
| 一项目一套活动目标 | 已实现：重复建立活动目标会返回冲突。 |
| 一项目一份当前有效计划 | 已实现：每个目标契约的 PlanService 保证最多一份 confirmed。 |
| 新建目标、路径、计划动作需项目 ID | 已实现：目标、路径采纳和计划签署／修改／拒绝使用项目范围校验。 |
| 项目切换影响计划上下文 | 已实现：计划工作区和路径建议使用当前项目。 |
| 长期学习者模型按人累计 | 保持原设计；未拆分成项目私有副本。 |
| 归档项目可读不可写 | 已实现：历史可查看，新的学习或计划写入被拦截。 |
| 旧数据自动补标 | 未实施；保留为未归属历史记录，避免猜测归属。 |

## 4. 涉及的实现位置

- platform/app/learning/project_scope.py：项目存在、所有权与归档只读校验。
- platform/app/core/schema.py：目标契约、计划版本和交互事件的项目归属字段。
- platform/app/learning/workspace.py：项目任务、里程碑、归档／恢复的内容边界。
- platform/app/learning/plans.py：计划版本生命周期与单一有效计划约束。
- platform/app/gateway/routes.py：目标、路径、计划、会话的项目范围接口校验。
- platform/app/gateway/learning_routes.py：项目内作答、发题和提示写入的归档保护。
- platform/app/gateway/qualitative_routes.py：项目内解释性作品写入的归档保护。
- platform/web/workbench/workbench.js：当前项目传递、空项目阻断和路径请求。
- platform/web/workbench/presentation.js：项目切换后计划工作区的同步刷新。
- platform/tests/test_project_context.py：双项目隔离、路径采纳、归档只读回归测试。

## 5. 验证结果

已执行：

~~~text
python -m compileall -q app
node --check web/workbench/workbench.js
node --check web/workbench/presentation.js
python -m pytest -q tests/test_project_context.py tests/test_plan_lifecycle.py tests/test_learning_workbench.py
~~~

结果：15 项测试通过。

覆盖点包括：

- 项目 A、B 的目标、计划、证据和会话不串数据；
- 项目 A 不能重复建立活动目标；
- 路径建议只能采纳到存在目标契约的当前项目；
- 访问另一个项目的会话会被拒绝；
- 归档项目的计划与历史仍可读取；
- 归档项目不能修改计划或继续写入会话消息。

本地服务已按新代码重启，并确认学习配置接口在 http://127.0.0.1:8000 正常响应。

浏览器自动冒烟脚本未运行完成：当前 Node 环境缺少 Playwright 依赖。该限制不影响上述 Python 接口测试、静态语法检查和本地服务启动；在补齐 Playwright 后应再执行完整浏览器回归。

## 6. 未完成内容与下一步

本次是第一阶段，不应误认为计划模块已完整完成。下一阶段建议进入“执行计划”能力：

1. 为任务补充类型、截止时间、完成规则与证据引用。
2. 在计划页实现今日任务、里程碑时间轴、项目进度和成功标准进度。
3. 将初诊、练习、测评与到期复习结果回写到项目任务。
4. 基于当前项目有效证据生成“是否调整计划”的候选建议；仍由学生决定是否签署新版本。
5. 再接入陪学、复习、成长证据和圆桌的完整项目内工作流。

## 7. 边界声明

- 课程资产和默认参数仍是本地研究 MVP 的演示资产，不能据此宣称教学效果。
- 归档只读不等于彻底删除；数据删除、授权撤回、项目归档是不同操作。
- 本次没有自动把旧作答、会话或考试记录归入项目，避免将不确定归属写成事实。
- 学生级教学授权、硬规则和考试模式限制仍属于跨项目治理层，不能被单个项目设置绕过。
