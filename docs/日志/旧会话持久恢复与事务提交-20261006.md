## 问题与结果

旧 API 通过进程内字典注册 TutorSession。create_app 或服务进程重启后原 session_id 无法继续；即使已有 attempt 收据，消息链中 Verdict、LearningService、事件、快照和收据仍存在多个独立 commit，故障后可能留下半回合。

新增 `platform/app/orchestration/runtime.py` 的 `SessionRuntime`，网关会话创建、普通消息、SSE 消息、反思和镜子统一读取持久化运行状态。新增 GET `/api/sessions/{sid}` 返回公共 UI、会话类型和轮次，不返回题库答案、完整运行状态或快照载荷。

TutorSession 新增 `export_state` / `restore`。版本 `tutor-runtime-v1` 保存当前题、题库版本载荷、签署契约引用、快照、题目索引、已布置集合、检查点队列、提示阶梯、预算、辅助/答案暴露、评测种类、正确/错误/挫败 streak、轮次、5E 阶段、Verdict、待反馈、动作引用与 Trigger 冷却时间。恢复不执行 constructor，不重复建会话或固化快照。

## 准备与提交边界

1. 在 Store 锁内检查当前 teaching 授权、取得数据库令牌并通过 SQLite backup 复制到独立内存数据库；复制后再次核对令牌。
2. 释放生产 Store 锁，在副本恢复并运行感知、Verifier、Policy、Governor、润色。副本允许沿用现有 LearningService 和 Store 的内部提交，生产数据库此时无写事务，不等待模型网络调用。
3. 从副本生成严格白名单 changeset。只包含 learners、sessions、event_clock、verdicts、learning_evidence、learning_states、evidence_consumption、learning_transitions、learning_rebuilds、learning_audit、events、snapshots、runtime_sessions、gateway_receipts。数据库 Schema、契约、计划、授权和外部数据不会通过 changeset 复制回生产。
4. 生产 `BEGIN IMMEDIATE` 后重新检查当前授权、同连接 total_changes 与跨连接 PRAGMA data_version；按显式主键核对基线。append-only 表只允许 INSERT，learning_states / runtime_sessions 才允许 CAS 更新，禁止删除或重写事实，Schema 不一致则拒绝。
5. Evidence、消费、转换、Verdict、事件、快照、会话延续状态与稳定收据在同一个生产事务提交。任一步故障全部 rollback；数据库期间发生写入返回 409，客户端用同 attempt_id 重试。

生产没有整库覆盖或表替换。event_seq 由副本按冻结基线计算，生产 CAS 确认基线未变后才能插入；不同会话冲突保守拒绝并重新准备，不能覆盖全局序号。

## 幂等与授权

收据键 `(session_id, attempt_id)`，内容 hash 覆盖 text/answer。相同内容直接返回原响应，不重新感知、判分、更新状态或写事件；不同内容返回 409。准备快照前后均检查已有收据，处理竞争完成与快照捕获间的窗口。

客户端省略 attempt_id 时生成并在响应返回 ID，但跨请求重试必须复用该 ID。送入 Evidence 的 attempt 标识加 session_id 命名空间，使不同会话复用 answer1 等客户端键不会误合并成同一次作答。

授权检查在恢复、收据返回、快照捕获和最终提交执行；模型计算期间撤回后，准备结果不能提交，也不能通过旧收据继续读取。拒绝后不会自动重新授予权限。

## 代价与边界

这是本地 SQLite V1 的正确性方案：每回合复制数据库及比对白名单表，数据量增长时内存/延迟随数据库规模增加；全数据库写令牌导致不同会话也可能保守冲突。后续可拆成显式 prepare/commit 端口及更细粒度状态 CAS，保留本轮事务与重启测试。

新增机制只能恢复已保存 `runtime_sessions` 的会话。实现前的旧数据库会话仅有 metadata 和事件，不能可靠恢复缺失的当前题/阶梯状态；返回 404 要求重新建立会话，不从不完整日志猜测学生状态。

本轮没有安装额外包，也没有新增需密码服务。整个方案继续使用已记录的 Python、SQLite、Pydantic/FastAPI 环境。
