# V3来源治理与隐私边界实施

建立/验证时间：2026-10-06 18:00（Asia/Shanghai，UTC+08:00）。分支：本地 `V3`，基线 V2 `c975def`。本记录仅描述本地工程能力，不表示学校生产部署、真实研究伦理批准或完整删除合规已完成。

## 范围与架构

新增 `platform/app/governance/`，与教学算法、模拟器分离；使用现有 Store 连接和锁，不安装新软件或依赖。持久表为 `governance_privacy`、`governance_reviews`、`governance_source_reviews`。HTTP 入口在 `gateway/governance_routes.py`，由主网关安装。

1. `authority.py`：不可由 JSON 或 `X-Role` 指定的服务器主体，限定 learner / teacher / privacy_officer 与明确学习者集合。无管理全体学习者的通配权限。
2. `provenance.py`：来源版本 hash、服务器索引 chunk、审核过的 KC 映射与完整 action hash 一起验证。服务器私有收据绑定动作 ID、actor、params、全部元数据；模型自称 `grounded_to_kg` 或复制旧收据不能通过严格上下文。
3. `service.py`：安全审核候选、隐私状态、删除清单和隔离实例删除端口。审计不复制原始学生文字或模型输出。审批候选不允许执行被拒动作。
4. `core/rules.py`：GovernorContext 可选 provenance validator 和安全审核 sink。严格上下文验证 QUESTION/HINT/EXPLAIN/TASK/FEEDBACK；旧静态模板保持兼容。不改硬规则注册表，不绕过 R-01/R-09 等约束。
5. `orchestration/runtime.py`：在副本中写 R-05 人工审核候选，以正常 changeset 一起提交；提交失败回滚，重试收据不产生重复候选。`session.py` 只读取可选 Store 回调，不连接隐含外部服务。
6. `learning/service.py`：隐私状态阻挡授权使用，重新写 teaching/research Consent 也不能绕过 quarantined / withdrawn / deletion_requested / deleted。

引用解析来自服务器当前索引，不接受客户端提交的 chunk 文本、citation path 或可信标志。源文件改变、消失、重新导入不同版本、同一文件 hash 被改绑 KC、未知 KC、伪造 chunk、重复引用均拒绝。收据有容量限制，服务重启后必须重新绑定，不作为长期签名或教育真值证明。

## 本地操作入口

本机学习者由 `settings.learner_id` 绑定。教师身份使用既有服务器配置 `RSI_LOCAL_TEACHER_TOKEN`；请求 Header 为 `Authorization: Bearer <本地教师令牌>`，不可在提交文档中写真实令牌。local auth 已启用时仍须通过原有本地 cookie 登录。privacy_officer 只可由受信服务器 `principal_resolver` 注入，无公开角色创建接口、无默认删除权限。

| 入口 | 用途/权限 |
|---|---|
| `GET /api/governance/privacy/{learner_id}` | 学习者本人的生命周期状态；不跨身份 |
| `POST /api/governance/privacy/{learner_id}` | learner 可 withdraw/request_deletion；teacher 可 quarantine；restore 需受信隐私官 |
| `GET /api/governance/privacy/{learner_id}/deletion-plan` | 只读清单，始终 dry_run，不擦除文件或备份 |
| `GET /api/governance/reviews/{learner_id}` | 已分配教师/隐私官检查 R-05 候选 |
| `POST /api/governance/reviews/{learner_id}/{review_id}` | reject/request_revision/approve_candidate，意见不可覆写，均 may_execute=false |
| `POST /api/governance/sources/{learner_id}/{source_id}/review` | 教师对真实索引版本 approve/reject，服务器绑定当时 KC 映射 |
| `POST /api/governance/provenance/{learner_id}/check` | 候选动作与 source_id/source_version/chunk_id 来源检查并经过 Governor；不执行、不签发客户端收据 |

隐私操作示例 JSON 为 `{"operation":"withdraw","reason_code":"learner_requested"}`。reason/rationale 使用简短 ASCII 代码，不粘贴姓名、原文或联系方式。撤回立即阻止普通 `/api/` 读写，但保留认证与治理入口用于查看状态及提出删除。恢复访问不自动恢复旧授权，仍需新的明确 Consent。deletion_requested 不能被静默 restore。

## 删除策略与安全演练

没有公开 HTTP 执行删除接口。受信离线 `execute_isolated_deletion` 必须同时满足隐私官分配、明确 deletion_requested、人工批准的 policy_id、isolated_instance=true。默认 `DeletionPolicy()` 拒绝执行。

只清理当前连接的单学习者数据库行；不接受任意文件路径，不删除 workspace 文件、SQLite 文件、日志、备份、PG归档或外部 Provider 数据。发现其他学习者、未纳入清单的新表、全局 digest 无明确保留边界时拒绝，不部分删除。故障时事务回滚。保留政策批准范围内的最小伪名 tombstone，`compliance_claim=false` / `backup_erasure_verified=false`。伪名不是匿名，tombstone 保留本身需真实政策审核。

本轮删除演练只在 `Store(':memory:')` 测试夹具进行，未读取、导出、删除用户本机数据。

## 未完成与不可宣称
