# V3服务器测量派发与援助历史可信链实施

记录时间：2026-10-06 20:23（Asia/Shanghai）。分支 `V3`；用户授权本轮验收后提交推送，仅V3。

## 问题与采纳

此前 AssessmentIn 只接受客户端 hint_level / assistance_mode / answer_exposed，自报零援助不能证明独立测量。合理采纳审计要求：由服务端派题、保存提示/暴露/历史，再同Evidence一起消费。不能用此功能证明平台外无人帮助，字段 history_scope 明确 server_observed_only。

## 实现

- 新增 `app/learning/assessment_delivery.py`，`assessment_deliveries` 持久保存学习者、题目精确版本、授权版本、24小时有效期、first_exposure、尝试编号、此前派发和Evidence引用、提示阶梯及消费收据。
- `/api/learning/assessment/{learner}/issue` 使用服务器时间和不可预测delivery_ref；issuance_id同内容重试稳定，内容变化409。显式仿真实例才允许模拟时间，不从普通.env开放模拟时钟。
- `/hint` 使用不暴露答案的固定提示；提示等级只能升不能降；已消费凭据不可再请求提示。提交时客户端不能隐藏服务器已记录援助。
- `/submit` 绑定题目/学习者/Consent版本/时间，凭据只允许一个attempt。稳定重复attempt仍返回原收据；换答案需新凭据，并保留重复暴露事实，不计独立测量。
- Evidence与派发消费同属LearningService事务。在receipt检查点再次检查援助与Consent，验证期间发生变化就回滚Evidence、状态和收据。发题/提示使用BEGIN IMMEDIATE，跨两个SQLite连接也不能同时宣称首暴露。
- 普通 `Settings.load()` 默认 RSI_ASSESSMENT_REQUIRE_TICKET=true。显式注入的历史夹具Settings默认保留旧API兼容，但新增Evidence标记 independence_verified=false，并排除描述性前后测指标；不是可信研究入口。
- 严格模式题库列表、诊断选择不提前下发测量题stem，派发后才展示。Web保留原黑色风格，先获取凭据再显示题目，支持服务器提示、已提交修改后的新尝试、异步选择竞态与撤回清空；SimulationClient也通过issue接口获取凭据。
- 纠正Evidence保留original_verifier_details，指标不能借教师追加纠正洗掉援助/重复暴露历史。隐私删除库存纳入assessment_deliveries。

## 边界

服务器首暴露不是认知真值：无法知道截图、别的账户、平台外辅导或先前生活经验。formal research仍必须经过课程/学习者/采集授权和可信历史验证回调；没有凭据的历史记录不回填“独立”。BKT保留历史本地练习兼容，不把其估计或重复练习称为真实教育效果。真实参数和自动晋级未启用。
