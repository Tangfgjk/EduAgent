# V5.2 计划执行系统实施记录

更新时间：2026-10-07（Asia/Shanghai）  
版本标记：V5.2 / 计划模块第三阶段  
状态：本地实现与定向验证完成  
前置版本：V5.1 计划页面信息结构重构  
范围：将项目计划中的任务从可手动勾选的文本项，升级为具有来源、规则、证据与自动回写边界的执行对象。

## 1. 本次目标

本阶段落实如下原则：计划任务可以由学习者、计划或系统产生，但是否完成必须由任务声明的规则决定。

- 学生自建任务：如反思、整理错题原因、完成作业；默认由学生手动更新。
- 计划生成任务：路径建议被采纳为草案时，把路径节点物化为项目任务。
- 系统提醒任务：当前项目出现到期复习时，生成项目内的复习提醒任务。
- 验证通过、测评结果处理和教师确认等自动完成条件，只能由服务端的相应事件触发；浏览页面、打开聊天或发送普通消息不会完成任何任务。

## 2. 已完成内容

### 2.1 可执行任务数据模型

`ProjectTask` 现保存以下执行字段：

| 字段 | 用途 |
|---|---|
| `task_id`、`project_id` | 任务及其项目归属；保存时服务端固定为所在项目，拒绝跨项目归属。 |
| `title` | 学习者可读的任务名称。 |
| `type` | `manual`、`practice`、`assessment`、`review`、`reflection`。 |
| `status` | `todo`、`doing`、`done`、`skipped`。 |
| `due_at` | 可选截止日期。 |
| `milestone_id` | 可选关联的项目里程碑。 |
| `assessment_ref` | 可选关联到具体版本的练习／测评资产。 |
| `evidence_refs` | 令任务完成的学习证据引用；同一任务内不允许重复。 |
| `completion_rule` | `manual`、`verified_submission`、`assessment_finalized`、`teacher_review`。 |
| `created_from` | `learner`、`plan`、`system`，用于区分学生自建、计划生成和系统提醒。 |

项目内容仍校验任务 ID、里程碑 ID、任务证据引用的唯一性；任务引用里程碑或测评版本时也会在服务端校验。

### 2.2 三类任务的生成方式

1. **学生自建**：项目编辑区新增任务默认是 `manual` 任务、手动完成规则、学习者来源；可设置类型、截止日期、关联测评和里程碑。
2. **计划生成**：学生采纳路径建议生成草案时，路径节点会创建为项目任务：初诊节点为测评任务，复习节点为复习任务，其余节点为练习任务。重复采纳同一路径不会重复创建同 ID 的任务。
3. **系统提醒**：刷新当前项目复习队列时，服务端依据项目内有效证据的到期复习状态，创建确定性 ID 的 `system` / `review` 任务。再次同步不会重复创建。

计划和系统生成任务会保留其来源字段；其完成规则不可在页面中改写。

### 2.3 完成规则与服务端回写

服务端在学习证据成功写入后检查该证据所在项目的未完成任务：

- `verified_submission`：仅当关联作答版本匹配且验证结论为 `passed` 时完成。
- `assessment_finalized`：仅在诊断、前／后测、迁移或复习测评已交卷并完成结果处理、且结果不是 `unverifiable` 时完成。
- 复习系统任务：仅在提交对应的到期复习任务后完成。
- `manual`：不会被作答、页面浏览或聊天事件自动完成；学习者可以自行标记反思和开放任务。
- `teacher_review`：当前保留为明确的数据规则，尚未接入教师确认界面，因此不会被普通作答自动完成。

自动完成时，服务端将造成完成的 `evidence_id` 追加到任务 `evidence_refs`，并以项目版本的 CAS 写入更新。若并发更新冲突，会重新读取后有限重试；无法满足规则时保持原状。

为避免绕过规则，项目编辑接口拒绝将既有非手动任务从未完成直接改为 `done`。归档项目继续完全只读，不能接收自动任务、作答或任务修改。

### 2.4 计划页面与项目编辑体验

项目任务编辑器新增：

- 任务类型、截止日期、关联练习／测评、完成规则、里程碑和证据数量；
- 对自动任务禁用状态手动“已完成”选择，并说明其会在满足完成规则后自动完成；
- 支持“已跳过”状态；
- 在同一项目任务列表中编辑和查看学习者、计划、系统三类任务。

采纳路径后，页面会重新读取项目和概览，使新生成任务立即进入当前项目的计划进度。复习刷新会同步系统提醒任务到当前项目。

## 3. 访问与事件边界

```text
学习者创建／编辑项目任务 ──────────> manual 规则可手动完成
路径建议被采纳 ────────────────────> plan 任务（待完成）
项目内复习到期 ────────────────────> system review 提醒（待完成）
验证通过的作答 ────────────────────> 匹配的 practice 任务完成 + evidence_refs
测评交卷并完成处理 ────────────────> 匹配的 assessment 任务完成 + evidence_refs
打开页面／发普通聊天消息 ──────────> 不改变任何任务状态
```

所有自动回写都要求学习事件携带当前 `project_id`，并先执行项目存在、归属、活动状态和教学授权检查。因此一个项目的作答不会完成另一个项目的任务。

## 4. 接口与实现位置

新增或扩展的关键位置：

- `platform/app/learning/workspace.py`
  - 扩展 `ProjectTask`；
  - 阻断通过项目 JSON 直接完成自动任务；
  - `complete_tasks_for_evidence` 根据验证结果回写任务；
  - `add_plan_tasks` 物化已采纳路径；
  - `sync_review_tasks` 创建幂等的系统复习提醒。
- `platform/app/gateway/learning_routes.py`
  - 作答和教师纠正落库后触发项目任务完成检查；
  - 新增 `POST /api/learning/reviews/{learner_id}/sync`，把当前项目到期复习同步为提醒任务。
- `platform/app/gateway/routes.py`
  - `POST /api/path/accept` 在接受路径后创建计划生成任务，并返回其 ID。
- `platform/web/workbench/workbench.js`
  - 扩展项目任务编辑器；
  - 采纳路径后刷新项目；
  - 刷新复习时同步系统提醒任务。
- `platform/tests/test_project_task_execution.py`
  - 覆盖自动完成、手动任务边界和系统复习提醒幂等性。

## 5. 验证结果

已执行：

~~~text
python -m compileall -q app
node --check web/workbench/workbench.js
python -m pytest -q tests/test_project_task_execution.py tests/test_project_context.py tests/test_plan_lifecycle.py tests/test_learning_workbench.py
~~~

结果：17 项测试通过。

本轮新增验证覆盖：

- 直接编辑项目 JSON 尝试完成练习任务会被服务端拒绝；
- 一次验证通过的项目内作答会完成匹配的练习任务与测评任务，并写入完成证据；
- 反思／手动任务不会因作答完成，仍由学生手动更新；
- 系统复习提醒只会创建一次，保留来源、截止日期、复习类型和验证通过完成规则；
- 既有项目隔离、归档只读与计划生命周期回归测试继续通过。

## 6. 尚未完成

本阶段不代表完整的任务调度或教学闭环。以下能力仍待后续实现：

- 教师确认任务的教师端操作和审核日志界面；
- 自动推进里程碑、自动判断整个成功标准是否达成；
- 按任务负荷、截止日期和学习节奏生成每日／每周排程；
- 计划偏离诊断、重排建议和学生签署新的计划版本；
- 任务与聊天、作品、圆桌探究结果之间的一键创建／关联；
- 通知推送、跨设备提醒、真实课程与真实学生样本上的效果验证。

本地浏览器端的完整端到端自动化仍依赖 Playwright；当前环境未安装该依赖。本记录的“完成”仅指静态前端语法检查、接口／服务层测试和随后本地服务加载检查。
