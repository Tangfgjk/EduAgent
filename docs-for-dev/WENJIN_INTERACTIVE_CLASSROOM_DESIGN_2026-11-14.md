# 桂子问津互动课堂落地方案

日期：2026-11-14。本轮只设计，不实现业务代码。依据本地 OpenMAIC 1.4.0 和当前桂子问津源码；没有把文档里的功能描述当作已实现事实。

## 1. 定位与完整交付目标

互动课堂是现有学习项目下的教学方式，不是另一套课程平台。用户可以从主题或上传资料出发，确认课堂大纲，进入课件/白板讲解，在课堂中随时提问、做题、获得帮助，刷新或换会话后继续，并把真实学习表现回写现有诊断。

资料上传可选；不依赖内置单元。项目大纲与课堂大纲不同：项目大纲定义学什么，课堂大纲定义本次怎么呈现。课堂不得悄悄修改项目目标或课程知识点。

完整目标包含图文课件、白板、随堂互动、语音、导出和可选视频；分批实现并单独验收，不把第一批图文版称为全部完成。

## 2. 本地源码核查与取舍

| OpenMAIC入口 | 已确认的机制 | 桂子问津处理 |
|---|---|---|
| lib/server/generation/run/plan.ts | 资料分析可选→研究→大纲→确认→角色→逐场景内容/动作/旁白 | 保留分步与检查点思路；在Python后端实现，确认由学生操作；不启用超时自动确认 |
| lib/server/generation/run/runner.ts、store.ts | PostgreSQL持久任务、租约心跳、恢复、服务端事件流 | 借鉴语义，不复制TypeScript存储层；接现有PG与账号上下文，独立课堂worker |
| packages/@openmaic/dsl、renderer | 场景/课件内容契约及渲染组件 | 优先评估课件渲染子集，锁定版本，以适配器接入；不要求引入完整编辑器依赖 |
| lib/classroom/use-classroom-session.ts | 每堂课挂载时重置临时媒体、画布、白板状态，所有权单独确认 | 保留会话边界思想，服务端做真实授权；防止切课残留旧课内容 |
| lib/classroom/progressive-load-policy.ts | 区分加载中/不存在/错误，有限重试 | 直接借鉴交互规则，避免失败后无限转圈 |
| lib/classroom/generation-permission.ts | 生成和重试共同检查课程所有权，未知权限拒绝执行 | 统一服务端验证账号/项目/课程/资源，前端仅控制展示 |
| components/whiteboard、scene-renderers/quiz-view.tsx | 白板与课堂测验展示 | 拆分纯展示组件适配桂子问津样式；题目答案、判分、证据交给现有后端 |
| lib/classroom/complete-summary.ts | 按场景汇总及防止旧快照的统计串课 | 保留版本一致性；总结增加知识目标、受助状态和下一步，而不只显示正确率 |
| 角色编排、自由画布编辑、PBL、课堂分享、账户系统 | 完整平台能力，依赖面广 | 首轮不搬入；当前课堂不做自由排版编辑器、公共课程市场或PBL |

不能复制单个看起来可用的组件就认为持久化已接通。例如quiz-renderer.tsx中的局部答案状态不能替代当前系统的作答任务和证据存储。

本地OpenMAIC为MIT许可；实际移植时保留相关许可证/版权和来源记录，逐项检查素材、字体、第三方依赖的许可。源码已存在不代表其所有依赖可直接运行。

## 3. 桂子问津已有能力保留

- 用户登录、学生个人模型、工作区和项目隔离。
- 项目知识点、目标、资料及版本；既有资料解析与检索。检索服务不可用时明确说明，不宣称已联网研究。
- 津津陪学的持久会话/轮次、任务登记、评分及帮助请求/交付记录。
- 独立/受助证据、BKT诊断、个人训练、计划版本及撤销。
- 现有视频模块 deeptutor/agents/video_lesson 和 VideoLessonViewer 可作为扩展适配对象；其runtime生成Remotion浏览器播放包，不等于已提供可下载MP4，视频导出必须另外实现和验收。

新增课堂服务调用这些能力，不重复维护第二份掌握度、聊天历史或密钥。训练任务与课堂生成可以共享租约工具，但不复用同一张训练业务任务表。

## 4. 用户流程

1. 项目页/知识点页点击“进入课堂”，已有课堂优先显示“继续第N页”。也可选择多个现有知识点生成一堂短课。
2. 准备页仅三项：学习目标、时长、资料范围（可选）。高级选项收起；显示可用的语音/视频服务，不承诺未配置的能力。
3. 智能体结合目标、诊断与来源生成课堂大纲，展示每段目标、内容形式、预计时长及将出现的互动。学生可改或确认；无需管理员审核。
4. 确认后逐场景生成并校验。第一段就绪可开课，后续后台生成；遇到未就绪页显示进度、重试或返回，不能自动跳过关键内容。
5. 课堂按需暂停：提问、随堂测验、白板操作。学生提交或明确跳过后再继续；跳过不记错误，播放完成不记掌握。
6. 结束显示学了什么、哪些能力有证据、哪些待核查；选择独立核查、继续陪学或稍后再学。

## 5. 页面布局

项目内增加“课堂”入口，避免再加一长列全局导航。

- 顶部：返回项目、当前目标、课时进度；生成/学习/查看资料的状态明确。
- 左侧：章节和场景目录，可收起；展示生成中、可播放、待作答、已浏览等真实状态。
- 中央：唯一主舞台，展示课件/白板/测验/模拟；默认适配现有桂子问津主题色。
- 底部：上一页、播放/暂停、下一页、语音开关、“问津津”、显眼的帮助按钮。开课前明确语音状态，不突然出声。
- 右侧：学生提问时打开上下文对话，关闭后舞台恢复宽度。引用和诊断详情放抽屉；不常驻任务日志、模型参数与角色列表。
- 小屏：目录、提问用互斥抽屉；键盘操作、字幕、减弱动画、无语音使用均可完成。

## 6. 智能体职责及状态

后台课堂编排器持久化状态与预算，不把一段自由生成的文字当成可执行课程。

- 设计智能体：输入目标、诊断、来源；输出结构化课堂大纲与场景目标，说明为什么选这种讲法。
- 内容智能体：为指定场景生成内容、白板动作、旁白与引用，只能写该场景草稿。
- 校验器：校验结构、知识点引用、题目、答案泄露、资源完整性。确定性校验优先；模型自评通过不等于事实正确。
- 津津导师：课中接收当前页、时间点、问题和帮助记录，调用现有陪学工具回答/提示。
- 教学决策：依据学生回答决定继续、换讲法、加例子或建议核查；只能执行允许的课堂动作。影响项目大纲的调整进入原规划服务，不直接改表。

流程：draft → preparing → outlining → awaiting_confirmation → generating → ready/partially_ready；失败、取消、重试为明确分支。课堂运行单独保存scene_id、动作/播放位置、题目等待状态、恢复点与资源版本。

角色可先顺序执行以控制费用；不为显示“多Agent”默认启动多个AI同学。角色有不同输入、工具权限和输出契约才算职责分离。

## 7. 核心数据与接口边界

采用ClassroomService统一接口：prepare、confirm_outline、generate_scene、retry_step、load、resume、ask、submit_answer、finish、export。

- Classroom：owner/workspace/project、目标知识点集合、资料快照、课堂版本。
- LessonVersion：已确认大纲、来源版本、场景顺序、脚本/内容哈希；发布版本不原位覆盖。
- Scene：稳定id、类型、目标、内容块、白板动作、引用、题目引用、旁白与资源引用、校验状态。
- GenerationRun/Step：幂等键、输入版本、状态、租约token、attempt、检查点、错误/重试/取消、模型引用；不保存密钥。
- ClassroomSession/Attempt：所属用户、场景版本、对话/轮次、任务、回答、帮助、判分来源与恢复点。
- Artifact：所有者、课件/音频/视频类型、版本、生成状态、受控读取地址；大文件存文件系统，元数据在PG。

生成任务拥有PG租约，所有写入核对租约token；失去租约停止生成。场景提交和检查点原子落库，避免崩溃后重复场景或重复计费；外部服务已收费但响应丢失仍需记录不确定状态，不能承诺绝不重复计费。

流式进度只传事件和编号，断线按游标补读；不能依赖浏览器存活才能生成。新版本不使正在作答的旧题失去来源，先保存旧任务再选择切换。

## 8. 课堂怎样进入诊断

观看、点击、播放时长仅是学习活动。课中答题先登记任务与来源再呈现，服务端判分；正确答案不预发给浏览器。

- 刚看过对应讲解或答案、使用提示：标记受助/已暴露，不算独立训练样本。
- 自由提问和自述：保存对话，不生成正误标签。
- 模型评分：待核验；题目无可靠答案时不能强行判定。
- 独立核查：使用未展示答案的新任务，记录展示/帮助历史；通过现有诊断资格规则才参与个人训练。
- 事件重复提交必须幂等，不能重复增证据。课堂与普通陪学只引用同一份证据事实。

## 9. 资源实现与取舍

完整能力按三个批次交付，但三个批次都属于该功能的计划范围：

A. 图文互动课堂：主题/资料两种入口、大纲确认、结构化课件、白板、暂停问答与测验、断点恢复、诊断回写。先完整可用，不是只画界面。

B. 语音与可带走课件：学生配置TTS后生成配音，字幕与场景同步；失败降级文本。导出PDF/PPTX保留公式与来源，明确不同格式的交互损失。首版课件采用阅读/再生成编辑，不做自由画布。

C. 模拟与视频：优先安全的预定义参数化模拟，再评估生成代码。接入现有Remotion动画播放器、受控视频渲染/导出；浏览器可播放与下载视频分别验收。

个人语言模型不自动获得管理员TTS/图像/视频服务。资源默认按需生成，展示调用前的范围/上限，缓存绑定内容哈希、模型/声音版本和所有者；提供取消与单步重试。没有媒体服务也能完成A批完整课堂。

## 10. 验收与交付顺序

1. 契约、表结构、服务端隔离与恢复测试；OpenMAIC渲染子集验证后锁定适配范围。
2. 完成A批并验两种真实主题：不上传资料；上传文档有引用。覆盖刷新/进程重启、网络中断、题目幂等、失败重试与A/B账号隔离。
3. B批验收语音开关/字幕、单页重生成、导出公式、断点与费用隔离。
4. C批验收模拟预测→操作→解释、沙箱约束、视频播放/下载与失败降级。
5. 每批进行桌面/小屏实际使用，检查是否知道当前任务、下一步、怎么求助；不只看生成成功率。

关键教学验收：不能靠看完课件得到掌握；不能把课中受助表现记为独立；诊断能够回到确切课堂页/题目/原对话；换回陪学能接着同一任务学。

## 11. 默认建议与后续确认

建议按A→B→C实施，优先单人课堂（学生+津津），保留后续可选AI同学扩展点；不提前建设课堂市场、实时多人教学或完整PBL。生成大纲须学生确认，不由管理员审核。

后续需要使用者配置媒体服务，并在移植前决定renderer子集的依赖锁定；这些不是当前必须回答才能确定方案的问题。当前不修改OpenMAIC，也不把其数据库迁入桂子问津。
