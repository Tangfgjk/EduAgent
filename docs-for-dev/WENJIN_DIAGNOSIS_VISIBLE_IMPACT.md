# 诊断导入的可见反馈与一键核查

日期：2026-11-09。基于第三步已有结果导入，改善用户看不到变化的问题。

## 用户看到什么

1. 导入成功立即显示来源、日期、覆盖、未映射与未测项，以及具体建议核查的项目目标。未测和未映射可能重叠，界面明确说明。
2. 项目首页「继续学习」附近显示同一份最新导入的影响摘要，无需展开底部管理区。新导入和撤销通过项目限定事件刷新摘要。
3. 「开始一次核查」或「先听讲」先重新读取最新摘要，验证结果仍有效，再保存学习顺序并进入新的学习会话。自动发送带目标、来源和概率的请求，学生无需复制文字。中文界面开场明确请求中文说明和出题。
4. 陪学页顶部显示引用依据；现有原生评分产生新证据后，显示导入后的本地表现、辅助情况、已观察能力和下一步缺口。
5. 「查看来源与映射」在项目页直接展开导入区，在陪学页返回项目对应位置。

## 数据与行为边界

只读影响投影位于 `diagnostic_impact.py`，API 为 GET `/api/mastery-paths/topics/{path_id}/diagnostic-impact`，沿用用户/工作区隔离。提交导入的返回值增加 impact，陪学 state_summary 同步返回 import_impact。

摘要针对最新导入记录。已撤销、超过当前 90 天策略或大纲变化时没有核查行动。未测/未映射不参与建议；所有必要本地能力已经通过时不强制额外核查。多个报告不平均概率，不把一次点击或导入当成掌握。

后续表现只取映射目标在导入时间后发生、有效且当前范围匹配的真实结构化观察。旧回答和作废记录排除；不同辅助状态保留。显示「导入后发生」而非「因导入提升」，不作因果归因。没有学生实际评分记录时不显示虚构的核查完成结果。

自动开场复用 useMasteryOpening 和原有持久化会话/任务工具；请求存储按项目限定，等草稿就绪后发送，严格模式重复渲染不重复发送，发送暂被拒绝时保留请求。刷新已有有消息会话不重新开始测试。点击前再次核对服务器最新导入状态，过期的摘要不会自行恢复已撤销参考。

## 验收

184 项后端联合回归通过；15 项前端交互测试通过，覆盖摘要、辅助后续表现、不活跃结果无行动、草稿就绪后只发一次、不同项目不泄漏开场。前端类型和代码检查通过。

真实浏览器在原有模拟验收项目看到 0.35 来源和建议；点击核查只发出一个 study 请求，携带正确项目、来源和概率。实际模型回复说明了模拟/未核实性质和为何核查，并注册了二元一次方程定义的解释题；后端 next=answer_pending。没有替学生作答或人为制造通过记录。首次实测模型按原回答语言设置输出英文，随后开场增加明确中文要求；不因此修改用户全局语言配置。

原始分数、外部概率和本地能力仍分离。此改动不执行第四步外部模型，不增加管理审核。
