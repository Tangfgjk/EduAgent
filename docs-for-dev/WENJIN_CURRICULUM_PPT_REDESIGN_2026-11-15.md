# 共用项目目录的详尽自学课件改造

日期：2026-11-15。本文替代此前“再次生成课堂目录、固定短课、强制白板与测验齐备”的相关设计；描述目标与实施方案，不代表功能已经实现。

## 用户明确的新要求

直接使用项目“章节与学习”已有的章节/知识点目录；为这些目录项生成对应PPT内容。PPT用于详尽讲解和自主学习，学习后通过津津陪学提问、测验和巩固。上传可选、无内置单元。内容篇幅不设产品页数上限。

## 源码确认与根本调整

- 当前LearningProgress.modules及各模块knowledge_points就是已确认的学习目录，模块具有稳定id、order、objective，知识点具有稳定id和先修关系。
- projects.chapter_spec/generate_chapter已有按模块组织的章节材料、来源快照及内容签名，可以复用，不能简单把章节全文粘贴到PPT。
- classroom.create/generate另起课堂大纲；Outline限制16场景、minutes短课偏好、validate_outline强制slide/whiteboard/quiz覆盖，与新要求不符，必须改造。
- 当前Page仅有content/steps/narration等字段、PPT导出只是文本框。需要结构化视觉课件契约，不能仅通过换配色解决。

## 唯一目录，多个学习载体

项目 → 章节（模块）→ 知识点，是唯一课程树。讲义、PPT和陪学均引用相同module_id/objective_id，排序以确认后的项目目录为准。

每个知识点之下的多个幻灯片是内容页，而不是第二套知识点目录。允许内部规划页型和叙事顺序，但不再让用户确认第二个课程大纲，也不得擅自增加、删除、重排学习目标。

可以按知识点生成、按章生成、生成缺失课件、合并导出。项目已有目录可直接开始；没有目录时先完成原项目目录协商，而非在课堂另造一套。

## 详尽且适合自学的内容

根据知识类型选择必要环节：前置知识、概念/定义/适用条件、直观解释、关系图、推导/原理、完整例题、正反例、易错点与检查方法、知识联系和总结。不是机械地每个知识点套相同页数。

例：“代入消元”可以有含义、为何能消元、四步流程、第一道例题逐步推导、每步理由、常见符号错误、方法适用条件、总结等多页；足够解释后再结束，不按固定5页或15分钟裁剪。

“详尽”落实为更多有目的的页面，而不是一页全文。必要解释、推导理由和例题过程必须在课件正文可读，不能只藏在备注或配音；备注承载额外讲述和延伸。学生下载PPT/PDF后不依赖在线聊天也能理解主线。

无产品页数上限并不意味着无限任务：后台按知识点/小批次生成，使用检查点与继续生成，技术批量大小仅约束单任务，不截断最终内容；学生可暂停、取消或只生成一章。明确展示已准备范围，避免把部分内容标为整章完成。

## 视觉内容与输出契约

建立TeachingDeck/SlideSpec：来源目录项、学习目标、页型、元素、公式、示例步骤、讲解文本/备注、引用、版本。页面元素支持标题、要点、定义卡、正反例对照、流程/连线、表格、坐标图、数学公式及必要图片。

优先适配OpenMAIC DSL/渲染与PPT导出的合适子集，保留相关许可与来源；不能把它的账号/数据库整套引入。网页课件、PPTX、PDF和视频应消费同一份内容/布局契约，导出不能重新退化为按字符分段的两文本框。

例如：公共解用两条直线与交点；代入法用逐步公式与理由标注；方法选择用对照表；易错点用错误步骤与修正步骤并排。图形应帮助理解，不为装饰随意生成图片。

## 页面与学习接续

“章节与学习”作为主要入口：同一目录项下提供阅读讲义、学习PPT、进入陪学；已生成显示继续上次第N页，未生成显示生成该知识点/该章。互动课堂可保留为同一课件的播放/配音/实验视图，不保留重复目录。

课件正文为主舞台，左侧仍是原项目目录；各知识点可展开其内容页。当前来源、生成详情和资源下载按需展开，避免占据主阅读区。

每页提供“这页没看懂”“围绕本页提问”“学完了，检查一下”。进入陪学携带project/module/objective/deck_version/slide_id、当前课件内容、引用及阅读位置；同一项目下已有会话优先接续，未完成的原任务保留，不由新页覆盖。

默认流程：阅读知识点PPT → 学生选择核查 → 津津按目标出新的诊断任务 → 作答 → 反馈/提示/补讲 → 更新证据 → 推荐下一知识点或返回具体页。

PPT中的讲解例题可以完整展示答案，因为它是教学内容；津津独立核查使用新任务，不能把刚看过答案的原题记为独立作答。翻页、观看时间和“学完了”按钮只记学习活动，不授予掌握。

## 版本、质量与验收

生成签名基于目录项/知识点定义、目标、相关资料版本和课件生成规则，不因任意聊天或诊断版本更新就全部失效。目录变动只标记受影响课件待更新，旧版仍可读；正在学习者不突然切页。资料删除/权限变化需重新校验可读范围。

验收必须包含：目录与课件映射完整；一个知识点可跨多页；未生成完的内容不称完成；例题有完整步骤和解释；网页/PPT/PDF均有真实图形和正确公式；逐页检查重叠、溢出和可读性；无上传主题和有上传资料各完成一次真实生成；津津能接到精确页面并用新题核查；阅读不直接更新掌握。

## 实施顺序

1. 改为读取原目录及按章节/知识点生成，取消重复目录确认和短课页数限制；保留旧课堂可访问。
2. 增加结构化视觉课件契约与详尽内容规划，接入适配后的渲染/导出；以实际项目的一章做端到端验证。
3. 把同一PPT内容与位置接到津津陪学，再同步PDF、语音和视频。不能为了兼容旧媒体而继续沿用纯文本模型。
4. 逐章展开，并完成目录变更、失败继续、跨会话和下载自学的验收。
