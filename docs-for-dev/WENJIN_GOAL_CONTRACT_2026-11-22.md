# 桂子问津：学习目标、达标标准与支持调整

日期：2026-11-22。此文记录本轮已落地的目标驱动学习能力及本地验证边界，不代表原始架构的所有能力已经完成。

## 学生如何使用

1. 打开学习入口 http://127.0.0.1:3782/learning，登录本人账号并打开学习项目。
2. 项目页的「学习目标」中选择希望达到的程度，写下希望自己能做什么；学习时间可选。也可以先和津津讨论，让它提出目标建议。
3. 点击「确认目标与标准」。智能体提出建议不等于学生已确认。已有项目首次显示待确认，学习记录仍然保留，可以先继续学习。
4. 在津津陪学中继续学习和作答，在「独立核查」完成新任务和到期复习；在学习诊断、学习支持页面查看同一份目标与当前进度。
5. 随时调整目标或参考目标历史重新填写。只改学习时间不清空能力依据；改变验收目标后使用新任务核查，原作答、对话和未答题仍可追溯。

目标面板在确认后收起为简短摘要、进度和调整入口，不在对话中铺开全部设置。

## 三种目标及核查方式

| 目标程度 | 对应能力 | 当前达标判定 |
| --- | --- | --- |
| 理解概念 | 辨认、解释 | 至少两个不同新任务，覆盖两种能力的有效独立表现 |
| 独立应用 | 解释、应用 | 至少两个不同新任务，覆盖两种能力的有效独立表现 |
| 迁移解决问题 | 应用、迁移 | 满足独立任务条件，还需完成延迟复习和迁移核查轮次 |

只看资料、听课、说「我会了」或有较高 BKT 概率都不直接代表目标达标。受助作答保留为学习过程，不能冒充独立表现。后续错误会触发重新核查，不沿用旧成功覆盖新困难。

独立核查的初次和延迟阶段随目标选择解释或应用；迁移目标额外要求迁移任务。延迟检查尊重实际到期时间，测试使用受控时间验证，没有把真实学生的等待时间人为提前。

模型评分可以作为有来源、可复核的学习反馈；界面会提示其局限。它不构成已经校准的真实能力证明，也不能作为 RSI 策略自动晋升的确定性结果。

## 智能体与系统各自负责什么

- 智能体：结合学生目标、当前回答、偏好、诊断和资料，提出目标建议，选择下一教学动作，解释理由，提出或恢复学习支持计划。
- 学生：确认学习目标与达标标准，选择是否先听讲、先试或请求帮助，随时修改目标、暂停和恢复。
- 系统：固定并保存已确认版本、题目版本、作答时的支持信息和证据来源；校验并发、权限和证据条件，防止把建议说成确认、把受助成功说成独立能力。

新增原生工具 `mastery_goal_propose` 只保存建议。它不能代替学生确认。若工具引用学生原话，该原话必须来自当前学生消息；工具不会凭建议写入能力分数。

目标进入陪学状态、跨对话交接、独立核查、诊断和个人训练后的规划输入。BKT 仍是参考，大模型在证据约束下判断教学动作。

## 脚手架如何逐步减少

自动减少一步支持，需要当前目标已确认，至少两个不同新任务的独立正确表现，并有跨对话或跨天的依据。最新表现有困难时先保持支持。

减少到「先独立尝试」还需目标能力已核查齐全并完成延迟核查轮次。一次受助成功不自动减弱支持。学生主动选择独立尝试或恢复帮助始终可用，这种选择不是能力认证。

目标改变后，旧目标下的自动减少依据失效，接续时恢复较多支持；版本比对不依赖系统时钟一定向前。当前题已经交付的帮助不会被抹去。目标改变会归档当前策略试用和比较结果、回到基线重新收集，旧曝光和证据保留，但不能拿来充当新目标的晋升依据。

## 数据与工程实现

核心入口：

- `deeptutor/learning/goal_models.py`：目标、建议的持久化类型。
- `deeptutor/learning/goal_contract.py`：确认、建议、版本、能力标准、证据筛选的统一接口。
- `web/components/learning/GoalContractPanel.tsx`：项目、诊断和学习支持页复用的目标面板。
- `GET/POST /api/mastery-paths/topics/{project_id}/goal-contract`：已有登录及账号范围内的查询和学生确认接口。

目标随现有项目事务持久化，复用 PostgreSQL 资源映射和账号隔离，没有另造一套全局目标数据库。真实 PostgreSQL 回归使用临时独立 schema，清理后不会改写原 SQLite 数据源。

区分两种版本：

- `version`：每次确认修改的编辑版本，用于历史回顾。
- `assessment_version`：验收目标变化才递增。新题及作答快照绑定此版本；只改时间保持不变。

还保存确认时间、证据起算时间、请求编号、确认来源、目标历史和建议的会话/轮次来源。确认使用项目修订号并发校验与请求编号重试，不允许旧页面静默覆盖新目标。

题目在登记时绑定目标版本，保留或恢复旧题不重新绑定。课堂随堂练习本来就属于受助学习，提交时保存目标上下文；后台补写证据沿用首次回执，重试后不冒充新目标下的独立任务。

学习时间沿用已有自述；调用方不提供时间时保留，显式空字符串才清空。学习支持页不再提供第二套独立的目标编辑表单。

## 界面、语言与验收边界

中文和英文目标文案齐全。补齐了原有项目列表/练习页面缺失的翻译键；其他语言保留已有原生译文，新桂子问津文案暂使用明确的英文回退，尚未声称完成这些语言的人工本地化。

前端覆盖学生点击确认、版本冲突保留输入、历史目标重新填写、切换项目时忽略旧请求等情形。后端覆盖建议不能确认、伪造确认字段拒绝、请求重试、目标改变后旧证据和未答题保留、延迟核查、旧策略失效、时钟回退、课堂异常补写和 PG 往返。

本轮验证的是本地工程行为。没有用测试账号的合成作答冒充真实学生效果，没有替学生确认真实项目目标，没有调用真实学生密钥做付费教学实验。长期教学效果、多人容量、远程 CI/Linux 部署和跨项目迁移效果仍需独立验收。

## 后续架构工作

目标驱动达标是 PBL 与自主学习闭环的基础，不等于完成了 PBL 工作区。仍需继续建设任务与作品的版本评审、任务完成和个人能力的分开呈现、长期画像与跨项目经历、教师侧能力，以及更完整的 RSI 技能改进和实证验证。详见架构审计和 PBL 差异化方案。
