## 1. 结论与范围

先集中做诊断接入，暂停我教 AI、独立尝试新页面、互动课堂及多模态资料扩展。既有陪学、阅读与上传继续可用。诊断范围先做到：收集证据、识别未知、提出可验证的薄弱假设、选择下一步学习行动，并支持外部结果接入。

老师建议「先使用诊断的属性和字段」方向部分成立：可以借鉴事实数据、知识点估计、先修关系、来源追踪的数据契约；仅复制字段不能运行诊断，更不能证明结果可靠。推荐采用「统一诊断证据层 + 桂子问津形成性诊断 + 可选外部诊断适配器」。不整体迁移对方 Django/Vue 系统，也不强制用户参加一次完整考试。

依据：用户提供《学生诊断属性与字段清单_当前代码版.md》《诊断推荐系统说明文档_当前代码版.md》，以及本仓库 models.py、wenjin.py、policy.py、service.py、mastery/tools.py。外部系统结论来自这两份文档，本轮没有拿到其代码、模型、映射、真实样本与接口响应进行独立验证。文档不是部署实测证明；文档中列举的 URL 也不是已验证可用的数据接口契约。

## 2. 两套系统的不同边界

对方以考试逐题成绩为核心：已有评分 → 固定题目和知识点映射 → KT 概率向量 → 图谱/薄弱链 → 规则推荐。当前 KT 为 434 维，200 长度切分；新题或知识点映射失败会被跳过。题库能保存题目不等于模型能处理它；业务有学科字段不等于模型跨学科有效。

桂子问津允许任意主题、用户上传材料或纯主题学习、动态大纲与生成题目。现有 LearnerProfile 记录自述目标/基础/时间/偏好；QuizAttempt 与 LearningEvidence 保存作答和辅助情况；objective_evidence 汇总识别、解释、应用、迁移；teaching_decision 和 policy 决定探测、教学、提示与撤架。已有这些代码基础，不代表已拥有经过测量验证的通用诊断模型。

不能把对方考试模型直接挂到任意聊天答案上；不能把聊天顺序等同于训练时考试序列。文档还说明对方重建序列按题号字符串排序，实际作答时间并不充分，模型适用性需进一步验证。

## 3. 字段复用判断

| 外部概念 | 桂子问津处理 | 决策用途 |
| --- | --- | --- |
| student_uuid / student_code | 当前账号内部 ID 为主体；外部系统+外部永久 ID 建独立绑定表，学号作为可变别名 | 身份关联，不作为掌握特征 |
| 年级、学科、班级 | 年级和学科按场景选填；班级不是个体陪学前提 | 内容范围、难度和群体边界 |
| Exam / Attempt | 泛化为诊断会话/任务尝试，保留考试来源；每次尝试有独立 ID | 同题重做不覆盖历史 |
| 题目 ID、题干、答案、评分标准与版本 | 复用为有版本的任务快照，生成题使用内部 UUID | 结果可复核、去重 |
| 知识点 ID / 名称 / vector_index | 建标准知识标识和映射，不拿名称或数据库主键当向量下标 | 跨系统对齐 |
| 题目得分 / 满分 / 答案 | 分别存原始事实，明确未答/缺失/未批改/有效得分 | 形成诊断证据 |
| 概率与状态 | 保存外部模型估计、模型/图谱/映射版本、测量时间、覆盖范围 | 学习起点参考，不能直接写已掌握 |
| 薄弱链 / prerequisite | 作为有依据的先修假设，验证后用于规划 | 优先核查上游基础，不直接判原因 |
| 五类标签 | 可做临时支持建议，不做永久学生类型 | 解释当前策略，允许修正 |
| IRT theta、排名和聚类 | 首期不接；需要足够同场群体和可解释量尺 | 不用于单人聊天诊断 |
| 推荐分数与反馈 | 推荐记录与结果验证分开，保留算法版本 | 点击完成不是掌握提升 |
| 家校、社区、积分、PDF 报告等 | 本次不迁移 | 不属于诊断核心链路 |

不额外要求姓名、性别、家庭收入、身份证、人脸等属性；不根据语气推测智力、人格或学习风格。学生的目标与偏好仍由本人表达和修正。

## 4. 建议的数据契约

以下是拟新增逻辑实体，不是已存在数据库表；实现时优先复用现有记录，以投影方式汇总，避免把同一次作答保存为两份相互矛盾的事实。

- DiagnosticSession：owner_id、workspace_id、project_id、purpose、subject/domain、scope_version、status、started_at、completed_at；purpose 可为初次了解、过程核查、复习、外部考试。
- TaskAttempt：attempt_id、task_id/version、session_id、objective_ids、answer、response_status、score/max_score（可空）、grading_method/version、rubric_version、assistance_state（independent/assisted/unknown）、hint_events、occurred_at、recorded_at、source_event_id。
- KnowledgeMapping：namespace、external_id、external_name、taxonomy_version、local_objective_id、relation（exact/partial/unmapped）、mapping_method/version、verification_status；向量位置另外绑定模型映射版本。大模型只提出候选，不自动批准关键映射。
- DiagnosisSnapshot：snapshot_id、owner/workspace/scope、as_of、evidence_ids、method/model_version、mapping_version、coverage、per_objective_states、conflicts、limitations、supersedes。
- ObjectiveEstimate：knowledge_id、measurement_status（unmeasured/observed/estimated/conflicting）、external_probability（可空）、external_status、四类能力证据、evidence_count、last_observed_at、support_state、next_probe。不制造看似精确但未经校准的本地掌握概率。
- DiagnosticDecision：decision_id、snapshot_id、action、target_objective、reason_codes、support_level、evidence_refs、learner_override、policy_version；区分建议和实际执行。

证据来源：学生自述、系统内核查、导入考试、外部模型推断必须可区分。外部数据未知是否用提示时标 unknown，禁止默认为独立完成。知识状态不能用一个总分代替。

## 5. 智能体怎样真正使用诊断

诊断服务负责验证、汇总与规则约束，智能体负责交互、选择适合的探测任务、解释和执行下一步。

流程：学习目标 → 对齐本项目知识范围 → 读取已有证据和外部快照 → 发现缺口/冲突 → 选择教学或一个小探测任务 → 保存原始作答与评分 → 更新诊断快照 → 选择下一步 → 后续再验证。

拟提供能力接口（名称为方案）：

1. diagnostic_get_state：只读当前主体、工作区和项目范围的事实与估计，返回缺口及来源。
2. diagnostic_propose_probe：针对一个目标或先修假设选择任务；动态生成任务需先核对答案与评分标准。
3. diagnostic_record_observation：由受控作答流程写入，服务端校验真实会话/任务/作答关联；模型不能凭口头声明自行制造成功证据。
4. diagnostic_get_recommendation：输出下一步及理由，接入 teaching_decision / next_objective；优先让现有服务共用一个诊断投影，而非另外维护一套掌握状态。

约束：没有证据时是未知，不是薄弱；请求帮助允许继续学习；学习者可选择先讲解；每次只呈现一个清楚的下一步。外部高概率只建议用更具区分度的任务核实，不能自动跳过本地学习目标；外部低概率也不能覆盖当前新的独立表现。冲突应展示并安排小范围复核。

撤架：根据任务范围、辅助程度及新的独立表现渐进减少帮助；必要时恢复帮助。外部概率和学生标签不能单独决定撤架。本地现有能力门控也需增加来源、时效、任务有效性等约束，不能把实现中的最低证据条件称为长期效果已经验证。

RSI：诊断快照供策略评估读取，策略试验不得修改原始证据、评分规则和掌握门槛；若评分方法随策略一起变化，应记录并防止用不可比指标宣称策略提升。

## 6. 两类用户的体验

### 没有考试记录，也不上传资料

输入主题 → 简短说明想达到什么程度 → 可选择先试一题或先听讲 → 在陪学中逐步收集证据。起初允许所有状态为未知，避免填长表或先做整套测验。默认给出少量探测，提供跳过/继续核查；数量上限是交互设计，不是测量准确率保证。没有题库映射时走本地形成性诊断，不伪装使用外部 KT。

### 有既有诊断或逐题成绩

可选导入 → 展示身份、范围和映射预览 → 校验/生成诊断 → 摘要展示有覆盖的知识点 → 学生确认学习重点 → 对重要或冲突结果补充核查。

分两条导入路径：已有结果导入不要求重新提交完整原始成绩，但必须有可信来源、知识点及模型映射版本、测量日期和覆盖说明；重新推理则必须满足模型所需原始输入、映射和权重要求。学生自己上传的结果标自上传，不等同受认证诊断服务签发。

界面：学习项目增加「了解我的起点」轻入口；陪学侧栏按需展开「当前依据、哪些尚未确认、为什么建议这一步」。不默认展示 434 节点图谱、排名、标签、IRT 和报告全集，不增加管理端人工审批。

## 7. 外部模型接入路径与准入条件

先定义 DiagnosticProvider 接口，具备 supported_scope / validate / infer / normalize 方法。首期可以实现只导入既有结果的适配器，不应做一个永远返回假数据的模型接口。

取得外部源码、TorchScript 权重、题目/知识点映射、知识图谱和匿名样例后，再选择服务 API 或独立进程调用；优先与当前应用隔离重计算依赖。服务凭据仅后端保管，学生身份绑定不能靠前端传入学号直接信任。共享登录不作为接入前提。

准入：确认知识维数与映射一致，逐题 ID 命中率、知识点命中率、有效交互覆盖、无效/丢弃原因可报告。零可用交互拒绝推理；部分覆盖输出 partial 并列出未覆盖项，不宣传完整诊断。概率区间和模型异常值分开校验，模型零值按该版本未测约定处理。

明确三种零：答题 0 分是有效事实；缺失分数为 null；旧向量 0 的未测语义仅适用于其版本适配器，不扩散为通用约定。

KT 正误为得分率严格大于 0.6；数据库/IRT 满分判断是另一口径，两者并存记录、不得互相覆盖。external_probability 不等于得分率，也不等于本地独立能力证据。

暂不直接复制五类标签阈值、推荐权重、群体聚类及跨考试 theta 趋势。需要先验证样本适用性、缺失处理及跨次可比性。不得对未校准概率做简单平均或与本地证据线性加权。

## 8. 分阶段交付与验收

A. 契约与基线：选定一个实际支持的范围，准备匿名样例、模型与映射清单；记录当前系统证据、边界案例和兼容约束。产出数据字典、状态口径、映射规则及黄金样例。

B. 本地诊断闭环：接现有作答事实、自述和辅助日志，建立诊断快照，接通智能体决策与轻界面。无外部服务也能工作。验收：无证据不误判、错误任务可撤销、提示后作答不冒充独立、决定可追溯。

C. 外部结果导入：身份绑定、字段校验、映射预览、导入版本与来源、幂等和撤销。先导入已生成结果，不宣称已经运行外部模型。验收：范围不支持可说明原因，重复导入不重复计权，外部估计不直接授予掌握。

D. 受支持范围的真实模型连接：有资源后运行匿名基准样例，核对预处理、序列顺序、输出向量与逐知识点解释；处理超时、任务恢复和覆盖缺失，输出实际模型与映射版本。验收：与原系统同输入对照结果可解释，固定模型不会误处理任意新题。

E. 教学与持续验证：目标/先修建议真正影响陪学，保留学生选择和纠错；补延迟任务与迁移证据。验收：弱点假设能被后续证据修正，不用点击完成代替学习效果；RSI 评价保留独立性。

全阶段共同验收：跨账号/工作区拒绝访问，授权绑定与导入来源可审计；同名不同学科不误映射，同日多考与重做分开；ID 前导零保留；分数有限且范围合法；过期诊断不作为最新事实；缺失值不变零分；未测不变不会；模型失败本地陪学仍可用。

## 9. 下一步所需材料与决策

可以立即推进 A/B 的代码设计；C/D 必须先确认真实对接资源。需要外部诊断项目所在目录或 API 契约、模型及映射版本、至少一份匿名逐题样例与对应诊断结果、支持学科/知识范围、身份绑定办法。当前文档未提供可验证的部署地址、完整接口响应字段和权重，不能据此直接宣布外部模型已可接入。

第一项实施建议：统一诊断证据模型和现有 QuizAttempt/LearningEvidence 的投影，接入 teaching_decision；随后做已有诊断结果导入。保持纯主题学习与不上传资料可用。
