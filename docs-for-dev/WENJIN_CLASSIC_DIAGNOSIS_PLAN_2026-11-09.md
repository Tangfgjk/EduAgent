# 桂子问津经典诊断算法方案（替代原第四步）

日期：2026-11-09。状态：调研与设计，尚未安装、训练或上线新模型。

## 1. 范围调整

不再获取、调用、复制原诊断系统的专有模型、权重、算法脚本或接口。原第四步「等待对方模型资源并接入」被本方案替代。已有通用诊断事实、能力门、结果 JSON 导入和来源审计继续使用；模拟结果仍是模拟参考，不迁移为模型训练标签或初始化参数。

推荐：经典 BKT 为持续知识追踪主线，pyBKT 优先用于拟合和对照校验；现有独立能力证据规则保留为教学边界。PFA 是数据积累后的预测基线。DINA/G-DINA 是有合格题库、Q 矩阵及标定数据后的可选专项诊断。IRT 用于经标定题库的能力/选题，不作为任意主题聊天的首个知识诊断模型。算法选型为结合当前代码与数据形态的工程判断，不是已做本项目实测排名。

## 3. 为什么优先 BKT，以及它做不到什么

BKT 通过初始已知、学习转移、猜对和失误等参数解释按技能发生的对错序列。它可以在每次合格作答后更新，符合现有「真实任务 → 记录 → 下一步教学」架构。pyBKT 提供拟合、预测、交叉验证与参数固定功能，适合研究和校准。[来源](https://github.com/CAHLR/pyBKT)

但有四个前提：

- 经典形式通常使用二值作答；开放回答必须先有可靠评分，不能把聊天直接变成 BKT 输入。
- 固定参数可让新学生开始计算，但参数来自假设还是拟合必须明确标记；软件不自带适用于所有学科/年级的通用诊断权重。
- 基础无遗忘模型不表示时间过去就自动遗忘；初期用独立延迟任务观测保持情况，后续才验证带遗忘扩展，不凭任意天数修改概率。
- 隐状态掌握概率与下一题正确概率是不同量，二者均受模型假设约束。不能用一个数替代辨别、解释、应用、迁移的独立证据。

## 4. 新的运行链路

学习目标与知识范围 → 任务及评分标准 → 真实作答/辅助记录 → 证据质量检查 → BKT 状态更新 → 独立能力证据汇总 → 教学策略 → 下一任务或延迟复习。

LLM 负责理解开放回答、提出题目与解释建议；确定性计算/评分工具尽可能核验答案。BKT 负责统计更新，不负责判断自由文本含义。策略层负责选择何时教学、核查、帮助、撤架；算法不自行修改作答事实、评分规则或能力门。

没有资料、没有外部报告仍可学习。普通话语、看完章节、点击完成不成为正确作答；学生自述用于目标与安排，不直接变成统计成功。

## 5. 观察准入与知识粒度

先从一个小范围数学主题、已验证任务族开始。保留任意主题入口；不具备可信技能映射的主题继续使用证据规则，清楚标示未启用统计模型。

- 稳定 skill_id、namespace、技能版本；知识点改名/拆合不得沿用同一概率序列。同名跨项目不自动合并。
- 第一批统计更新采用一个明确主技能的探测任务。多技能大题保留完整映射，但不能把一次失败复制成所有技能都失败；待验证多技能建模后再使用。
- 独立性、评分方法、题目有效性与映射质量在看结果前定义准入规则。符合规则的正确和错误都入序列，不能只收成功样本。
- 有辅助或未知辅助的记录不冒充无辅助表现。初期单独保存，不送入独立表现的标准 BKT 观察流；以后有数据再验证多资源/多发射参数模型。
- 部分正确、缺失、未批改、评分不确定不强行套一个 0.6 阈值；另行保留，标准二值 BKT 暂不更新，并报告被排除原因与覆盖。
- 记录题目/题族、难度声明与校准状态、任务指纹、作答顺序、评分规则/模型版本。反复回答同一题、看过答案后的成功不当作新的独立测量。

技能层统计趋势与四类能力证据平行保存。初期不把每个动态目标机械拆成四条需要分别拟合的稀疏 BKT 链，也不因技能概率高就宣称解释或迁移已通过。

## 6. 冷启动方案

区分三种状态：

1. 没有本地观察：显示「尚未核查」。即使内部有数学先验，也不能显示为测得的学生能力。
2. 少量观察、参数未校准：可以运行先验参数版，标 prior_driven/experimental，提供来源与敏感性记录；不向学生输出看似精确的掌握百分比，不以其单独决定跳课或撤架。
3. 有独立验证的范围参数：标 calibrated，才作为选题和核查优先级的统计参考，能力确认仍需解释/应用/迁移等证据。

不随意规定收集多少条就视为模型可靠；按技能/题族覆盖、参数稳定性、评分一致性、预测和校准表现决定。公开数据用于工程正确性和算法复现，不作为本地适用性的证明。新学生可使用经验证的范围级参数，不要求每个学生先积累大量数据或从头训练模型。

## 7. 数据与代码衔接

复用现有 DiagnosticFacts、DiagnosticContext、QuizAttempt/LearningEvidence。新数据采用可重放派生状态，不建另一个可随意手改的真相表。

拟增加：skill_namespace、skill_version、primary_skill_id、observation_eligibility、exclusion_reasons、question_family、grading_validation、model_family、model_version、parameter_set_id、parameter_origin、training_scope、trained_until、p_known、p_correct_next、n_eligible、last_observation_id、replay_revision、calibration_status。具体迁移时允许旧数据缺省并保守处理。

诊断运行接口：validate_observation / update / replay / get_state / explain。撤销错误评分、纠正知识映射、迟到记录和更换参数时，从有效事实按事件顺序重放，幂等处理，不能只做加减概率。离线训练可用 pyBKT；在线更新采用锁定参数的轻量适配器，使用相同序列与 pyBKT 核对，避免擅自改算法。先做本机 Python/Windows 安装与依赖验证，再确定运行方式，本轮尚未安装验证。

已有 JSON 导入保留为通用可选外部参考，不依赖原专有系统；导入的概率不直接作为 BKT 的 p_known 初始值，也不把模拟报告作为真实训练数据。

## 8. 决策与界面

学生看到「当前依据、尚未确认、为什么建议这一步、下一步选择」，不默认堆出参数图表。

- 尚无证据：先讲解或一个小任务，保留学生选择。
- 本地独立表现不足：补能力缺口；模型只提供统计参考。
- 模型高概率但缺解释/迁移证据：继续核查，不能跳过。
- 模型低概率但新的独立证据充分：检查题目、评分、技能映射和参数，不直接否定学生。
- 连续困难：先了解理由，再提供帮助；BKT 不能据错题确定认知错误根因。
- 撤架必须有真实表现依据，允许恢复帮助；延迟和迁移任务优先用于验证，而非只看当场分数。

## 9. 新第四步的实施阶段

A. 冻结知识与观察契约，准备小范围有效题族及匿名核对样例，建立评分检查与准入测试。
B. 安装/锁定 pyBKT；完成基础更新、对照、幂等、重放、缺失/作废/辅助排除测试。先验参数运行标记为实验。
C. 影子运行：与当前规则同时计算，不覆盖能力门；积累合格序列，按技能范围拟合参数。构建简单成功率基线，PFA 在数据支持后加入。
D. 离线验证：按学生及时间拆分，避免同题/同会话泄漏；评估 log loss、Brier、校准曲线、适用时的 AUC、各技能与任务族覆盖；用人工/确定性核验样本评估 LLM 评分一致性。单一全局 AUC 不作为上线依据。
E. 限定范围上线：模型建议进入选题与核查优先级，保持证据门和手动选择；监控异常、支持回退和版本对照。后续验证遗忘扩展；成熟专项题库才评估 DINA/G-DINA 或 IRT。

## 10. 必须通过的验收

同输入同参数可复现；概率合法且 p_known/p_correct_next 区分；初始先验不冒充测量；同一事件不重复更新；错题与对题在同一准入规则下处理；辅助、未知、无效和缺失不错误入模；撤销/改标/乱序可重放；知识范围变化不串数据；账号工作区隔离；模型不可用时陪学继续；模拟数据不进训练；未经校准不输出精确能力结论；参数与证据版本可追溯。

验收是模型工程与本项目数据验证，不能用公开论文的实验效果代替本系统教学效果。长期是否改善学习仍需延迟/迁移任务与适当对照。
