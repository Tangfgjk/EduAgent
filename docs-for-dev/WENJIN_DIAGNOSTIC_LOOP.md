# 本地诊断闭环：第二步实现说明

日期：2026-11-08。依赖第一步统一诊断事实层。没有接入外部 KT、考试导入、IRT 或新画像标签。

## 已接通的链路

原生任务注册与作答评分 → DiagnosticFacts → objective_evidence → teaching_decision → next_objective / mastery_status → 智能体下一步执行；下一次真实作答再进入相同链路。既有任务、流式会话和持久化入口继续使用，不增加一套聊天模型端点。

wenjin.enabled 路径的能力门、能力覆盖显示和教学决策共用统一事实。旧流程未开启证据模式的路径继续使用原判定。原始作答与旧分数不删除、不重写；旧默认 independent=true 不再在证据模式中自动授予能力，因此部分已有目标可能重新显示需核查。学生显式自述跳过仍按原有 learner 来源区分，不冒充系统确认。

## 决策口径

- 无依据：未知，提供一个小探测或先讲解的选择，不认定薄弱。
- 辅助情况未知：建议新任务核查独立性，可选择先讲解。
- 第一次未通过：先问理由，不直接断言错误根因。
- 连续有效任务有困难：征求是否需要最小方向提示。
- 借助帮助成功：新任务减少一级帮助，不更改本次辅助标记，不关闭求助。
- 已有部分独立能力：核查缺失的解释/应用/迁移等能力，避免刷已确认部分。
- 作废、来源冲突、目标名称变化：不授予能力，说明限制后核查；后续替代任务有有效证据后，不反复卡在旧无效题。
- 新的未通过表现与过去成功矛盾：对应能力需要再核查，不只保留过去成功。
- 先修建议只来自显式 prerequisite_ids 且有未通过记录；作为可选核查方向，不能认定为当前错误的因果根因。

policy_version=diagnostic-v1；输出 source_revision、reason_code、证据引用、学习顺序选择及可选先修建议。事实能解释决定依据，不输出未经校准的掌握概率。能力门仍是本地工程判定，不是长期学习效果的验证结论。

## 学习者选择和界面

在津津陪学的可展开说明区域使用「先听讲，稍后核查」或「先试一个小任务」。按钮保存项目内 teaching_strategy，并向当前会话发送相应学习请求；不更改成绩或掌握证据。可随时切换、暂停。先讲解偏好会持续生效，学生愿意尝试时可切回核查；智能体也可在讲解后征求是否愿意核查，不强制起点测试。

PUT `/api/mastery-paths/topics/{path_id}/wenjin/preference`，body.strategy 只允许 teach_first/probe_first，沿用登录与工作区隔离。修改由既有 profile 服务保存并产生可追溯事件。没有新增管理审核。

已有待答题仍由原协议优先返回 answer_pending，诊断不能自动替换题目。先教的请求若影响当前题，应先确认如何处理；实际提示仍必须通过现有原生留痕流程。

## 智能体执行与 RSI

中英文教学提示明确要求：注册探测任务、取得真实回答、评分、刷新 mastery_status，再按新 decision 行动。状态工具和评分工具已有接入位置现在返回统一事实驱动的决定。界面显示决定理由、能力证据与版本。

RSI 评估的独立样本口径同步为归一化事实，不用旧默认独立标记为策略提升背书。策略不能写入伪造证据或更改能力门。

## 验收边界

测试包含实际原生评分到持久化后下一步决策、状态工具暴露相同决定、无数据/自述/未知辅助、提示后成功、能力变化、作废替代任务、待答题优先、先修建议、偏好切换及账号隔离。界面与真实 API 验证未登录返回 401、已登录偏好保存及 teach/verify_independence 决策切换。没有在本轮把完整大模型多轮教学效果当作已经验证；实际内容质量与长期有效性需要持续验收。
