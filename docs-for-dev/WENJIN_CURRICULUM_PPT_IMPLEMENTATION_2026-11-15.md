# 原项目目录驱动的视觉自学PPT：实现与验收

日期：2026-11-15。

## 已落地

1. 新课件默认curriculum_ppt模式，直接读取原LearningProgress的modules/knowledge_points及排序，可选择全部、某章或单一知识点。章节与学习新增“学习本章PPT”入口。不再调用原课堂大纲生成，不需再次确认一套目录，不强制插入测验。旧课堂保留访问和原交互。
2. 后台按知识点生成连续批次，每批最多4页只是单次调用大小；objective_complete决定继续同一知识点还是下一个，没有产品总页数/短课分钟限制。真实输出页数因知识点而异，不能把示例4页说成上限。生成失败可重试、取消后恢复。
3. 课件保存content/panels/layout/formula/notes/source_ids和目录项ID；支持概念、对照、流程、例题和坐标图。正文及讲解区保存必要解释，备注作补充，不靠备注藏必要知识。
4. slide_visuals作为共享画布，网页SVG、原生PPT形状/连线、PDF、视频画面消费相同元素结构；公式由MathText渲染图片，不再导出原始LaTeX。PPT文字与图形可编辑，公式图片不是可编辑OMML。未复制整套OpenMAIC；本轮使用适合现有Python服务的语义版式与渲染适配。
5. 新课件的导出使用新缓存版本，避免继续下载旧的纯文字文件；旧PPT不会原位覆盖。语音使用内容与讲解区文本；视频支持新画布缩放到1280×720。
6. 生成签名包含选定目录定义、来源、目标与相关章节材料；相同请求复用缓存，并通过PG事务锁保护并发创建。目录/目标/来源改变后新生成不同版本，旧版保持可读。
7. 当前页提供向津津提问/检查理解入口；服务端记录精确课件、页、知识点、版本、引用和阅读内容，跨对话handoff读取；有未完成任务时优先回到原会话，否则进入新的study对话。阅读不改变掌握，不覆盖原任务；核查要求使用未展示答案的新题。

## 使用

项目→章节与学习→学习本章PPT；或互动课堂→准备区域选择章节/知识点→“按已有目录生成详解PPT”。若打开旧课堂仍看到旧确认页，应从新生成入口创建课件；不会自动重写旧课件。新课件准备后可读，整份就绪后可导出PPT/PDF或生成配音视频。

## 边界与后续验证

- 当前已用1知识点完成真实模型验收，跨多章节长课件/复杂证明的真实内容覆盖仍需进一步测试；模型objective_complete是生成判断，不能等同专家评审的完备性。
- 坐标图为受控ax+by=c线型，公式支持MathText子集；未接入自由图像生成、任意动画导演或复杂化学排版。
- 课件目录变更通过新签名生成新版；尚未实现旧课件逐页标记受影响范围、人工合并更新的完整界面。
- 总页数无产品上限，但每次生成有输出预算和超时；不宣称无限资源。长篇课堂应分章生成，过程可取消。
- 原多模态资源功能继续保留，但尚未对新课件视频作完整真实渲染回归；导出和画布已验证。


## 2026-11-15 公式兼容与失败恢复修复

原 MathText 渲染不支持 `cases` / `aligned`，且公式中的中文出现缺字，导致课件整批校验失败。现改用本地 MathJax 4.1.3 + Sharp 0.34.5，字体数据固定并本地安装，中文使用系统字体，不调用在线公式服务。

- 运行需 Node.js 与 `web` 依赖（`npm ci --legacy-peer-deps`）；Linux 部署需安装 Noto Sans CJK 字体。
- 公式通过 stdin JSON 传给固定 Node 脚本，不执行模型生成的 JS、shell、文件或 URL 指令。仅加载必要 TeX 包，限制长度、宏展开、输出尺寸、内存和执行时间。
- 浏览器、PDF、PPTX、视频共享公式 PNG；资源缓存版本更新为 `media-v3-mathjax`，点击生成/导出会准备新版资源，原下载入口保留旧版文件。
- 生成失败按公式、内容/版式、超时和服务分类，重试时向模型传递安全的修正提示；重试耗尽后明确显示已停止。
- 进度展示为已准备页数和知识点课件数，不把生成进度等同于学习掌握。
- 验证：后端 24 项、前端 15 项相关测试通过；实际方程组、分步推导、中文公式均可渲染与导出。
- 用户课堂 `89964031702245de9909c0277335bfec` 保留原有页面，从失败位置恢复，已验证继续生成至 8 页及以上；全部课件仍按目录在后台准备。
