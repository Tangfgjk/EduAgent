## 三、P0：先完善现有主流程

### P0-01 生成语言与缓存一致性

代码依据：`deeptutor/learning/projects.py` 使用回答语言设置生成正文，但缓存签名未包含语言和模型设置。此前实际生成出现中文界面、英文正文。

改进：创建或生成时明确展示内容语言，默认中文且允许用户调整；将影响生成的语言、版本等纳入缓存策略。改变设置后保留旧版本，提供明确的重新生成操作。

验收：中文默认生成中文，切换语言后不会静默复用另一语言的内容；界面文字与内容语言设置有清晰说明。

### P0-02 长资料真正按章节检索

代码依据：`projects.py` 当前章节生成取前 4 份可读来源、每份前 16000 字符；上传解析最多 120000 字符。当前读取路径可用，但不能据此宣称已经对整份长文档完成 RAG。

改进：按页/段切分并记录定位信息，基于章节目标检索、筛选片段，生成时展示实际引用。说明截断范围；上传可选，无资料时仍可按主题学习，外部搜索不可用时如实说明。

验收：文档后半段的知识可被对应章节召回；能打开引用位置；不虚构页码和来源；不同账号和工作区检索隔离。

### P0-03 章节生成任务可靠性

代码依据：当前由页面发起 POST 并等待模型，提交时检查大纲和资料是否变化，但缺少独立任务生命周期和同规格请求的生成合并。

改进：任务持久化、进度、取消、失败重试、超时提示、刷新恢复、并发请求去重；记录费用与模型。失败不覆盖成功版本，修改目标后避免展示过时章节。

验收：刷新或断网后可恢复任务；多次打开不会重复计费生成；大纲调整后旧资料有明确状态，陪学不把旧版当最新资料。

### P0-04 手机端与阅读布局

依据：上一轮移动端截图存在侧栏挤占阅读空间的问题；本轮代码中目录默认展开，选中文字主要依赖 onMouseUp。尚需完整触屏验收。

改进：手机端主侧栏和章节目录使用抽屉，正文优先；桌面可折叠目录；支持触屏选区、长公式、键盘访问、加载和错误状态。

验收：390px 宽度无整页横向溢出，正文不被导航遮挡；无需鼠标也可对选区提问。

### P0-05 阅读、章节与陪学恢复

代码依据：`LearningProject.tsx` 将提问写入待发送输入框，恢复时优先使用最新会话 sessions[0]；不能保证最新会话就是该章节的学习会话。

改进：显式保存项目—章节—会话关联、模式、阅读位置；进入大纲与进入陪学意图区分；跳转提示问题需要检查后发送。离开页面、失败重试、多个标签页的保存冲突要有处理。

验收：从某章进入陪学后准确定位该章；返回继续阅读位置正确；大纲会话不会误成为学习恢复目标；保存失败有反馈。

### P0-06 对话式规划的可见闭环

改进：项目首页明确展示「目标待确认 / 起点了解中 / 大纲待确认 / 可按章学习」，从大纲对话提供明确返回目录操作；解释诊断目的，允许先学习再逐步了解学生。

验收：首次用户不用理解系统术语即可完成目标到第一章；不知道掌握程度时不假定学生已经会，也不因缺少上传或诊断而锁死流程。

## 四、P1：新增核心教学功能

### P1-01 我教 AI（下一主要开发项）

从当前项目或章节进入；学生讲解，AI 扮演初学者，针对遗漏、推理断点和含糊之处追问。区分学生独立表达与获得提示后的表达，结束时反馈并关联现有学习证据。

页面：对话为主、资料按需侧开、结束后反馈；不把评分、图谱、设置同时铺满首屏。

验收：能引用本章材料核对，能追问理由与反例；学生不会因说了一段话就直接被判掌握；有具体不足和下一步入口。

### P1-02 独立尝试与学习建议

复用现有题目、知识点和证据机制；支持解释、应用、迁移任务；提交前不显示答案。请求帮助后保留学习入口，但标记本次不再属于无辅助完成。

验收：一次答对不直接宣布全面掌握；反馈落到具体目标；能回到对应章节或陪学；支持延迟复习和迁移验证。

### P1-03 学生画像、目标与撤架可解释性

已有画像、能力证据、反思和提示策略基础，还需系统验证长期效果。画像应由自述和行为证据逐步构建，记录来源、时间与置信程度，允许修正。

验收：能说明为何给提示、为何撤去提示、还缺哪些证据；短期做对不直接推断长期掌握；不同主题不盲目继承熟练程度。

### P1-04 资料管理与知识库衔接

补充原文预览、分页定位、资料移除/替换、解析状态、索引重建、重复文件与孤立上传清理。扫描 PDF 的 OCR、图片/公式解析应独立呈现支持范围与失败原因。

验收：用户能知道资料处理到了哪一步；移除资料后，相关章节和索引的更新规则清楚；不把片段预览冒充全文读取。

## 五、P2：多模态课堂与智能体完善

### P2-01 章节互动课堂

在已确认章节与资料上生成教学脚本，再派生 PPT、讲解音频、视频/互动活动。先验收内容和 PPT/音频，再扩展视频；允许只选需要的形式。

验收：多种产物共享同一章节目标及版本，失败可重试，能够预览、导出并进入陪学；核查复用组件的许可证和依赖。

### P2-02 智能体过程可观察

保留模型自主选择资料和工具、根据反馈调整行动的能力；向用户展示简短状态、来源、下一步和取消入口，不暴露内部推理。多 Agent 应按检索、规划、内容、质量核对等明确职责设计，先验证收益再扩展。

验收：能追溯工具输入输出和任务结果；工具失败有恢复路径；不能把多个角色名称或固定流程当成自主智能体实现证据。

### P2-03 RSI 质量评估

加强真实独立结果、延迟表现、任务难度差异和失败样本评估。已有模板检查与候选评估是基础，不能代替教学效果的对照验证。

验收：用户同意后才试验；有足够证据才采纳；低样本时不声称有效；保留策略版本、评价依据和一键回滚，掌握判定规则不被策略自行放宽。

## 六、面向多人部署前必须验收

- 容量与并发：当前主要是 SQLite 加文件存储；不能仅设置 DATABASE_URL 就认为已切换数据库。先做并发、锁冲突、索引和任务队列压测，再决定是否迁移服务端数据库及对象存储。
- 账号与权限：验证普通学生的完整主流程，不只验证管理员；账号恢复、密码修改、登录限流、会话过期和数据导出/删除需要逐项核查。学生日常功能不引入管理端人工审核。
- 资源与成本：模型密钥保密、额度/速率限制、上传总量和生成任务并发上限；界面只在必要时提示。
- 数据可靠性：数据库与文件一起备份；演练恢复，覆盖账户、资料、对话、能力证据和生成产物。
- 发布验收：从全新学生账号完成注册 → 主题/上传 → 大纲确认 → 章节 → 陪学 → 我教 AI → 独立尝试 → 下次恢复的端到端测试；同时检查跨账号、跨工作区权限。
- 开发交付：当前工作区仍有未提交修改和新增文件。用户要求后再统一整理提交，不覆盖现有改动；本轮没有创建新版本分支。
