# 现有功能可用性与缺陷修复

日期：2026-11-23。范围：项目工作区、对话列表、学习画像、诊断中心、练习记录、个人训练及日历/看板实时连接。本轮优先修正已有功能，不新增 PBL 或其他业务模块。

## 检查结论

已有功能具备可继续使用的基础，但不能宣称所有功能已经完善。本轮发现的问题集中在异步状态、失败提示和后台连接生命周期：通常正常操作可以通过，切换项目、网络失败或多标签页时则会出现误导状态。

## 已修复的问题

| 场景 | 修复前的可观察问题 | 修复后的行为 |
| --- | --- | --- |
| 切换项目 | 画像/诊断的旧请求晚返回，覆盖新项目内容；项目对话可能暂时显示旧列表 | 按项目重建页面状态，忽略过期结果；刷新结果也按请求版本校验 |
| 项目对话读取失败 | 被当成没有对话历史；用户可能重复新建 | 显示读取失败及「重试读取对话」，与真正空列表分开 |
| 练习分页和失败 | 新项目沿用上一项目的页码；失败同时提示无练习；最后一页刚好30条仍能点下一页 | 切换项目从第一页开始；失败提供重试；按服务端总数控制下一页 |
| 个人训练初次加载 | 状态未读取便显示默认参数、无训练记录，训练按钮已可点 | 先读取已有任务与模型；读取成功后才开放提交；失败可重新读取 |
| 训练任务轮询 | 慢请求可能重叠，较旧响应可能覆盖刚提交的任务 | 上轮读取结束后再安排下一次；提交操作使旧读取结果失效，并主动刷新状态 |
| 后台标签页 | 日历、看板连接持续占用；开多个标签页容易累积连接 | 隐藏时关闭实时连接和回退轮询；返回时重新连接并补读最新状态 |
| 重复信息 | 画像中重复展示目标，容易与已确认目标混淆 | 画像只保留学习起点与偏好；诊断中的知识点明确标作「当前核查知识点」 |

没有把后台连接问题宣称为此前所有浏览器卡顿的唯一原因；本轮验证的是连接确实会释放、返回时会恢复，网关/HTTP协议与真实多标签页压力仍需进一步实测。

## 首屏与检查工具的额外优化

路由预算检查发现两个旧假设：根地址仍要求跳到 `/chat`，而系统实际入口已经是 `/today`；多用户登录开启后，检查拿到登录重定向，无法测量实际业务页面。现已对齐实际入口，并让没有可用业务后端的独立测量进程显式关闭页面登录拦截。此设置不修改真实运行服务的登录保护。

实际测量发现陪学页原始首屏脚本为1099KB，略超1090KB预算。没有提高预算或移除功能，改为只在打开详情时加载导入诊断说明，并在需要时加载完成提示动画。对应新增用例先复现「详情未打开就已挂载」，修复后通过；陪学与诊断说明的8项相关交互测试通过，陪学路由7项Node检查通过。

## 工程处理

- 复用原业务接口、登录、账号范围和 PostgreSQL 数据，没有修改诊断模型或真实学生记录。
- 为日历与看板提取 `web/lib/visible-event-stream.ts`，统一可见性、重连、错误回退和清理，避免两套不同的连接生命周期。
- 关闭的旧连接即使回调迟到，也不会继续提交消息；停止操作可重复调用，不破坏共享订阅计数。
- 项目页面按项目建立状态边界；项目数据、会话列表和诊断刷新分别使用请求版本，防止旧结果回写。
- 练习页将「正在读取、读取失败、有结果、确实为空」分别表达；重试保留在当前页。
- 对修改的界面和测试进行了格式整理。保留原有功能入口和数据含义。

## 回归方法与边界

先运行隔离的真实 React 组件和存储同步测试，复现旧画像覆盖、错误空列表、页码沿用、后台连接未关闭等问题，再修改实现。

专项命令：

```powershell
node node_modules/vitest/vitest.mjs run tests/project-practice.spec.tsx tests/learning-support.spec.tsx tests/diagnosis-center.spec.tsx tests/live-sync-visibility.spec.ts tests/learning-project-state.spec.tsx tests/personal-training.spec.tsx tests/calendar.spec.tsx tests/task-board-scope.spec.tsx tests/task-board.spec.tsx --maxWorkers=2
```

上述专项 **40 项通过**。分页加载状态的最终整理另外通过其 **3 项**回归，不重复累计测试数。

新增回归覆盖切换项目的延迟请求、错误重试、训练初始状态、隐藏标签页初次启动、重复可见事件、旧连接消息、回退轮询暂停和共享订阅清理。测试使用明确标注的隔离夹具，不把合成作答当作学生学习效果。

真实 HTTP/browser 检查仅验证本机页面可达与未登录访问跳转；没有替学生确认学习目标、提交真实作答或启动收费生成任务。不能将组件模拟网络验收写成真实学生完整学习效果验收。

## 如何减少同类问题

请求失败与空结果分别建模；项目范围变化时重建该范围内的状态；异步读取使用失效标识；轮询先等上一轮结束；共享连接只有一个明确的生命周期所有者。后续新增项目页面应复用这些约束，避免依赖「通常网络很快」来保证正确性。

## 仍需继续完善或独立验收

1. 真实学生使用自己的模型完成无资料建项目、目标确认、陪学、跨对话接续、核查和诊断回看的完整流程。
2. 课堂配音/视频、导出在真实提供方和长任务下的失败恢复；不只检查按钮和模拟响应。
3. 阅读位置的跨标签页并发、工作区切换中的在途操作，以及多个学习页面之间的实时同步需要单独压力验收。
4. 键盘操作、小屏布局、无障碍和中文表达继续逐页打磨；本轮没有宣称完成所有页面视觉重设计。
5. 历史 lint 警告、Linux/TLS部署、容量、公平调度、文件与数据库联合恢复及长期教学效果仍需推进。
